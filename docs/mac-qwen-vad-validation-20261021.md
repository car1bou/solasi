# Mac 설치 앱: Qwen 자동 보류·원음·수동 재인식

2026-10-21 · Apple M4 / 16GiB · macOS 27.0.1 · Solasi **0.3.25/build35**

## 적용 범위

[Qwen VAD 비교와 소스 변경](qwen-vad-20261020.md)을 실제 설치된 Solasi에 반영했다. 이전 보고서의 설치 앱 미검증 항목을 이번에 확인한 후속 기록이다. 새 모델·서버·스키마·기본 전사 엔진은 추가하지 않았다.

설치 전 정상 종료와 보관함 백업을 거쳤다. 기존 보관함·런타임 경로를 유지하고 새 화면과 내장 엔진을 패키징했다. 설치된 화면·엔진 manifest의 일치, 관련 백엔드 4개 모듈의 컴파일 코드 일치, 앱의 strict 서명 검사를 확인했다. 기존 앱 백업도 남겼다.

grilling에서는 이미 합의한 ‘성공한 빈 VAD 결과는 자동 후보만 보류하고 수동 요청은 원음 전체로 실행’ 정책을 재확인했다. UI UX Pro Max의 구체적인 오류 설명·복구 동작 기준으로 화면을 점검했고, ponytail 기준으로 정상 동작한 제품 경로에 추가 코드를 넣지 않았다. 이번 소스 변경은 설치 버전 정보와 검증 문서다.

## 실제 조작과 결과

별도 검증 앱이 아닌 **설치된 Solasi**의 새 검증 과목에서 진행했다. 실제 파일 선택창으로 공개 서울코퍼스의 동일 PCM 원음 두 개를 연결했다. 최초 전사·VAD·작업 상태를 DB에 주입하거나 모의 실행하지 않았다.

| 확인 항목 | 실제 실행과 결과 |
|---|---|
| 자동 재인식 보류 | 사람이 SIL로 주석한 약 2.913초 비영점 원음에서 실제 Whisper 최초 전사가 비었고, VAD가 `[]`를 반환했다. 자동 후보가 `skipped_no_speech: true`로 종료됐으며 Qwen 추론을 생략했다. |
| 보류 표시 | ‘자동 재인식 보류’와 ‘발화 미검출 · 원음 확인 필요’를 표시했다. 원음 버튼·수동 재인식·편집 입력이 남았고, 빈 후보의 적용 버튼은 비활성 상태였다. |
| 원음 재생 | 네이티브 플레이어가 재생/일시 정지 상태로 전환되고 2.9초 끝까지 진행했다. 오류 없이 종료됐으며 재실행 후에도 같은 원음을 다시 재생했다. 스피커 출력을 사람이 청취한 검사는 아니다. |
| 수동 다시 인식 | 입력란에서 Shift+Tab으로 ‘원음 다시 인식’에 이동하고 Enter로 실행했다. 진행 중 버튼은 비활성이었으며 실제 내장 Qwen worker가 10토큰을 생성했다. VAD 보류를 우회했고 후보는 적용하지 않았다. |
| 입력 보호 | 자동 보류 카드에 작성한 검증용 임시 입력이 수동 작업 완료 후에도 유지됐다. 검사가 끝난 뒤 그 임시 입력만 지웠다. 기존 사용자 입력은 수정하지 않았다. |
| 실제 발화의 연결 재생 | 사람이 전사한 약 27.337초 한국어 인터뷰 원음에서 실제 Whisper가 확정 문장 2개를 생성했다. 문장 선택 → ‘선택 구간 듣기’로 네이티브 재생 위치가 진행하고 선택 구간 끝에서 종료됐다. 앞선 SIL 원음의 누적 시각과 현재 원음의 로컬 재생 시각을 구분했다. |
| 작은 창·두 테마 | 네이티브 메뉴로 680×480을 설정했다. 라이트·다크에서 안내문이 줄바꿈되고, 스크롤로 원음·재인식·편집 영역에 접근할 수 있었다. 버튼이 잘리거나 겹치지 않았고 키보드 포커스도 표시됐다. 검사가 끝난 뒤 기존 라이트 모드와 1200×820으로 복원했다. |
| 정상 재실행 | ⌘Q로 종료하고 설치 앱을 다시 열었다. 보류 카드·수동 후보·확정 문장·원음 연결이 유지됐다. 재실행 전후 검증 과목의 녹음·전사·작업 결과 전체가 같았다. |

수동 인식은 SIL 원음에서도 잘못된 문장을 생성했다. 이는 VAD 우회의 품질 한계를 실제로 확인한 사례이며, 새로운 정확도 개선으로 계산하지 않는다. 두 후보는 모두 `applied: false`이고 해당 SIL 구간의 확정 전사는 비어 있다. 자동 보류와 수동 결과를 혼동하거나 자동 채택하지 않았다.

## 기존 자료 보존

설치 전 정상 종료 후 보관함의 APFS 복사본과 일관된 SQLite 백업을 만들었다. 기존 원음·연결 자료·필기 파일은 삭제하지 않았다.

- 최종 대조: 보호 대상 **31개 테이블의 기존 13,434개 행** 모두 동일하게 남았다. 원음·전사·필기·초안·과거 출처·용어 근거 이력 등을 포함한다.
- 기존 파일과 연결 원본 **1,523개**의 바이트 수·SHA256이 모두 같았다.
- 실제 DB의 `integrity_check`는 `ok`, 외래 키 오류는 0개였다.
- 검증을 위해 새 과목·기록·연결 원음·작업 이력만 추가했다. 기존 기록과 후보는 덮어쓰지 않았다.
- 새 검증 기록은 앱에 남겨 다시 확인할 수 있게 했다. 검증 후 앱은 홈 화면·대기 상태로 두었다.

행 수 대조는 새 검증 행의 추가를 허용하면서 기존 행의 값 전체가 남았는지 검사했다. 잡 큐·색인 같은 운영 상태의 모든 행이 불변이라고 주장하지 않는다. 원음이나 개인정보가 들어 있는 로컬 DB·raw 결과·화면은 공개 저장소에 넣지 않았다.

## 재현 순서

1. 기존 편집·녹음을 저장하고 정상 종료한 뒤 보관함과 연결 원본의 기준을 보존한다.
2. 같은 VAD 수정본으로 화면·내장 엔진을 빌드하고, 기존 경로를 유지해 앱을 교체한다.
3. 설치 앱의 새 강의에 SIL 주석이 있는 원음을 파일 선택창으로 연결한다. 실제 최초 전사와 VAD가 빈 경우 자동 보류 표시를 확인한다. 음성 파일이 다르면 같은 결과를 보장하지 않는다.
4. 원음을 재생하고, 입력란에 임시 문구를 쓴 뒤 키보드로 ‘원음 다시 인식’을 실행한다. 작업 중 중복 요청이 막히고 기존 임시 입력이 유지되는지 확인한다. 결과는 적용하지 않는다.
5. 실제 발화 원음도 연결해 문장 선택 재생을 확인한다. 680×480의 두 테마에서 스크롤·포커스·버튼 접근을 점검한다.
6. 정상 종료·재실행 후 결과와 원음 연결을 비교하고, 기존 행·파일 해시·DB 무결성을 다시 검사한다.

원본 자료의 출처·조건과 전체 VAD 비교는 [이전 보고서](qwen-vad-20261020.md)를 따른다. 이번 두 파일의 설치 앱 검사를 별도의 독립 정확도 벤치마크로 합산하지 않는다.

## 회귀 검사

- 새로 실행한 전체 Python 검사: **637개 중 632개 통과·선택 검사 5개 생략**, 실패 0. 생략은 별도 모델/네이티브 fixture를 요구하는 선택 검사다. 기존 loopback 연결 검사를 실행할 수 있는 권한으로 진행했다.
- 관련 전사·Qwen·비교 도구 검사 **51/51**, 설치·초안 검사 **16/16** 통과.
- 프런트엔드 **104/104** 통과, TypeScript·Vite 빌드 통과.
- 최종 앱 strict 서명 검사, 재실행 전후 결과 일치, 기존 행·파일 보존, DB 무결성 검사를 통과했다.

단위·통합 검사의 성공을 네이티브 GUI 시험으로 계산하지 않았다. 위 실제 조작 표는 설치 앱의 접근성 트리·화면·네이티브 입력과 로컬 작업 결과를 함께 확인한 범위다.

## 남은 한계

수동 우회는 작은 목소리를 다시 확인할 경로지만, 소음·비발화에서 잘못된 문장을 생성할 수 있다. 원음 확인과 사용자 적용이 필요하다. 이번에는 새 장시간 마이크 녹음·절전·강제 종료 복구, 자연스럽게 작은 목소리가 VAD에서 빠지는 상황을 재시험하지 않았다.
