# PDF 글상자·필기 내보내기 — Mac 검증

Solasi 0.3.30/build40에서 원본 PDF 전체와 저장된 T 글상자·펜·형광펜을 새 PDF로 내보낸다. 페이지 밖 메모와 OCR 검토 결과는 포함하지 않는다. 앱 안의 원본 필기와 수정 이력은 유지한다.

## 실제 설치 앱 확인

별도 검증 과목에 3쪽 PDF를 연결하고 다음 내용을 UI에서 입력했다.

```text
한글 확률 P(A)>0
E = mc² · x ≤ 3

조건을 보존합니다.
```

- 글상자 1개, 펜 획 2개, 형광펜 1개를 v3으로 저장했다.
- 정상 종료·재실행 후 저장 버전, literal text, 글상자 좌표, 획 배열이 전부 동일했다.
- 실제 앱의 PDF 저장 창에서 내보내기 완료를 확인했다. 출력은 25,755바이트이며 3쪽 모두 600×800pt였다. 필기 없는 2·3쪽도 원문 텍스트를 유지했다.
- 한글·부등호·위첨자·명시적 줄바꿈·빈 줄·펜 위치·형광펜 투명도를 렌더링해 확인했다. 화면과 PDF를 같은 배율로 맞춘 세 줄의 글자 영역은 세로 위치 차이가 최대 3픽셀(약 1.45pt)이었다. 저장 좌표는 동일하며, WebKit/CoreText의 글자 윤곽까지 픽셀 단위로 같다는 의미는 아니다.
- 원본 PDF SHA256은 전후 동일했다. 기존 보관함의 11개 기록·필기·초안·출처 테이블과 원음·원본 파일 55개, 보관함·모델 실행 경로를 대조해 보존을 확인했다. 검증 과목의 새 행은 별도로 허용했다.
- 저장 취소와 기존 이름의 OS 교체 경고에서 취소를 확인했다. 교체는 누르지 않았으며 기존 출력 해시는 유지했다. 앱의 배타적 최종 저장은 native bridge fixture로 따로 검사했다.

## 발견하고 수정한 문제

- PDFKit 전체 페이지 그리기가 작은 원본 이미지를 보간해 흐리게 만들었다. 원본 PDF 페이지는 CoreGraphics로 그리고 기존 주석을 별도로 합성해 위치와 원래 이미지를 유지했다.
- 기본 URL PDF consumer는 디스크 쓰기 실패를 종료 코드 0으로 처리할 수 있었다. 512바이트 파일 제한에서 재현한 뒤 쓰기 callback·sync·close 오류를 직접 확인하도록 바꿨다. 실패하면 부분 파일을 제거한다.
- PDF 내보내기 링크에 버튼의 테두리·배경이 적용되지 않았다. 기존 노트 버튼과 같은 스타일을 적용했다.
- 취소 뒤 이전 성공 문구가 남던 경로에서, 새 작업 시작 시 상태를 지우고 취소를 별도로 표시하도록 수정했다.
- 저장 창 취소·포커스 복귀에서 공유 SQLite 연결을 파일 검사 스레드로 넘기는 페이지 조회가 실패했다. 해당 문서 조회와 내보내기 마지막 대조는 요청 스레드에서 처리하도록 바꿨고, 파일 worker에 DB 연결이 넘어가면 실패하는 회귀 검사를 추가했다. 최종 설치 앱에서 취소→포커스 복귀→새 이름으로 재내보내기를 통과했으며, 새 실행 로그에 SQLite·요청 처리 오류가 없었다. 최종 PDF의 3쪽 렌더링도 앞서 확인한 결과와 동일했다.

## 범위

새 PDF는 정적인 페이지 내용 사본이다. 앱의 편집 가능한 필기와 JSON 내보내기는 별도로 유지한다. 원본 PDF의 링크·목차·폼 동작·전자서명 같은 상호작용이나 메타데이터를 그대로 옮기는 기능은 이번 범위에 포함하지 않는다. Windows·모바일 이식, 외부 API·새 AI 모델 변경은 포함하지 않았다.
