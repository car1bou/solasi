# macOS 680px 필기 도구 검증

2026-10-17. [기존 UI 설계](orbit-ui-design.md)에 이어 PDF 필기 도구의 좁은 창 배치, 선택·비활성 상태, 키보드 조작과 화면 모드 전환을 확인했다.

## 조건과 수정

- 실제 macOS 네이티브 앱의 검증용 사본에서 초기 창 폭 한 줄만 1200px에서 680px로 바꿨다. 나머지 네이티브 소스와 최소 창 크기 설정은 유지하고, 실제 680×820 논리 픽셀 창에서 확인했다.
- 실제 사용자 보관함과 분리된 검증 보관함을 사용했다. 검증 앱의 프런트엔드 정적 파일은 최종 `frontend/dist`와 바이트 일치를 확인했다.
- 화면과 접근성 트리(AX)는 CUA로 관찰했다. 캡처는 도구 응답에 있으며 별도로 저장한 PNG 파일은 없다.

[styles.css](../frontend/src/styles.css)에서 일반 버튼 hover는 disabled를 제외하도록 바꾸고, 기존 선택 밑줄을 모든 `aria-pressed=true` 툴바 버튼에 적용해 폭 맞춤도 포함했다. 버튼의 배경·테두리·그림자에 적용되던 150ms transition과 이에 종속된 reduced-motion 무효 규칙을 제거했다. 버튼 크기나 툴바 배치 규칙은 바꾸지 않았다.

수정 전 실행에서는 라이트 전환 뒤 새 기록 버튼의 밝은 배경·밝은 글자와 도구 AX 선택 상태·화면 밑줄의 불일치를 관찰했다. 재시작하면 정상 표시됐다. transition 제거 후 아래 상태가 일치했지만, 이 관찰만으로 WebKit 내부 원인을 확정하지 않는다.

## 재현 순서와 관찰 결과

분리된 검증 보관함에서 과목 PDF를 열고 창을 680×820으로 맞춘 뒤 다음 순서로 확인한다. 키보드 항목은 아래 실제 관찰한 조합에 한정한다.

| 조작 | 관찰 결과 |
| --- | --- |
| Tab으로 도구에 접근해 Enter 또는 Space로 펜·형광펜·획 지우기·부분 지우기·올가미·이동을 선택 | 여섯 도구 모두 선택 가능. 캡처한 펜·형광펜·이동에서 AX 선택 상태와 화면 밑줄이 일치 |
| 이동 도구에서 Tab으로 다음 조작에 접근 | 비활성 실행 취소·다시 실행을 건너뛰고 폭 맞춤 버튼으로 초점 이동 |
| 다크 모드에서 비활성 실행 취소를 클릭 | 실행되지 않으며 페이지 저장 상태와 도구 선택 유지. 활성 버튼의 hover 강조가 나타나지 않음 |
| 펜 굵기에서 방향키로 한 단계 늘렸다가 복원 | `0.0025 → 0.003 → 0.0025` |
| 불투명도에서 방향키로 한 단계 줄였다가 복원 | `1 → 0.95 → 1` |
| 확대 선택에서 Alt+↓, Home, Return으로 50% 선택 | 50%로 변경. Shift+Tab 후 Space로 폭 맞춤을 켜면 이번 자료에서 61%로 복원 |
| 화면 모드를 라이트에서 다크로 연속 변경하고 도구 상태 확인 | 전환 후 선택 상태·밑줄 일치. 관찰한 버튼·도구 배치가 정상 표시 |
| 다크 모드에서 회전 표시 270°까지 확인 | 회전 표시와 주변 도구가 겹치거나 잘리지 않음 |

위 조작 동안 680px 창에서 관찰한 툴바 컨트롤의 겹침·잘림은 없었다. 폭 맞춤 61%는 이번 자료와 창 크기의 결과이며 고정 배율이 아니다.

## CSS 토큰 대비와 회귀 검사

아래 값은 현재 CSS의 6자리 sRGB 토큰을 상대 휘도로 변환해 계산한 대비다. **실행 화면의 픽셀을 측정한 값이 아니다.** 글자·아이콘의 안티앨리어싱이나 디스플레이 색 처리는 포함하지 않는다.

| 조합 | 라이트 | 다크 |
| --- | ---: | ---: |
| 일반 도구: `--ink` / `--surface` | 16.29:1 | 14.06:1 |
| 보조 라벨: `--muted` / `--surface` | 5.60:1 | 7.14:1 |
| 선택 아이콘·밑줄: `--primary` / `--primary-soft` | 14.27:1 | 11.68:1 |
| 초점 outline / 툴바 배경: `--focus` / `--surface` | 4.77:1 | 7.64:1 |
| 초점 outline / 선택 배경: `--focus` / `--primary-soft` | 4.17:1 | 6.34:1 |
| 주요 버튼 글자: `--on-primary` / `--primary` | 16.29:1 | 14.39:1 |

선택 배경과 툴바 배경의 대비는 1.14:1 / 1.20:1, 선택 테두리와 툴바 배경은 1.77:1 / 2.59:1이다. 선택 아이콘과 같은 색의 3px 밑줄이 선택 표시를 보강한다. 비활성 버튼의 opacity는 `.5`이며 활성 컨트롤의 대비 기준과 구분한다.

```sh
cd frontend
node --test tests/notebook-toolbar.test.ts
```

[집중 회귀 검사](../frontend/tests/notebook-toolbar.test.ts) 5개 모두 통과했다. 공통 선택 밑줄, specificity를 늘리지 않는 disabled hover 제외, 버튼 색·선택 표시 transition 금지, 라이트·다크의 활성 글자·선택·초점 토큰 대비를 검사한다. transition 검사는 주석을 제거한 소스에서 global 버튼 규칙을 읽는다. 이 검사는 DOM 배치나 네이티브 키보드 조작을 대신하지 않는다.

## 설치와 보존 대조

- 전체 프런트엔드 검사 `npm test`: 93개 통과, 실패·건너뛴 검사 없음. `npm run build`의 TypeScript 검사와 Vite 빌드 통과.
- Mac 설치본을 `0.3.7 / build 17`로 갱신했다. 기존 앱 번들을 백업하고 실행 설정·기존 내장 엔진을 유지했다. 새 모델 다운로드는 없었다.
- 설치본의 strict 코드 서명 검사와 최종 프런트엔드 파일 5개의 바이트 일치 검사를 통과했다.
- 앱 종료 후 읽기 전용 보존 대조에서 DB 43개 테이블·스키마 객체 86개·원음과 연결 자료 18개의 변경·누락이 없었다. DB 무결성 검사도 통과했다.
- 설치본을 다시 실행해 홈의 기존 과목 3개와 `4 / 4 준비됨`을 확인했다. 검증 앱의 화면 모드는 기존 시스템 설정으로 복원하고 종료했다.

## 한계

680×820 창의 이번 PDF·도구 상태를 확인한 기록이다. 최소 높이 480px, 다른 화면 배율·운영체제, 모든 키 조합, VoiceOver 전체 탐색, 실제 펜·터치 입력은 이번 검증에 포함하지 않는다. 키보드 확인은 위 조합의 결과이며 모든 항목을 양 테마에서 반복한 전체 접근성 감사는 아니다.
