# 단일 로컬 AI 검증 — 2026-10-27

## 적용 범위

Solasi 0.3.26/build36은 로컬 생성·이미지 입력을 Qwen3.5 4B로 통일한다. 로컬 모델 ID 입력, 다른 생성 모델 다운로드, Gemma 수식 대조 버튼과 제품 실행 adapter를 제거했다. 외부 API 제공자·모델 입력, Whisper/VAD·Qwen3-ASR 전사, EmbeddingGemma 검색, Apple Vision OCR은 유지한다. Qwen이 모든 작업에서 가장 정확하다는 결론은 아니다. 기존 Mac 비교의 메모리·지연·품질과 사용자의 단일화 결정을 반영한 제품 정책이다.

예전 로컬 설정은 새 요청에서 Qwen으로 해석하며 저장된 과거 요청을 재작성하지 않는다. 삭제된 모델의 같은 모델 재시도는 거절한다. **현재 로컬 AI로 새로 실행**은 새 작업 ID를 만들고 현재 근거를 사용한다. 과거 작업·출처·모델 표시는 남는다.

## 실행 확인

- 정책 회귀: 다른 로컬 설정·다운로드·Gemma OCR 거절, 이전 설정의 유효값 정규화, 외부 API 모델 유지, 과거 실패 작업 불변과 새 Qwen 작업을 검사했다. 새 검사는 변경 전 실패하고 변경 후 통과했다.
- 고정 소스의 전체 Python 검사 679개 중 675개 통과·선택 검사 4개 생략, 실패 0개였다(69.671초). 프런트엔드 105개 통과, TypeScript 검사와 Vite 빌드도 성공했다. 필기 승인·검색 제외·초안·원음 복구의 기존 회귀 검사도 포함한다.
- frozen 엔진 자체 검사가 성공했다. 배포 엔진에서 Gemma adapter가 빠지고 Mac 필기 adapter가 포함된 것을 확인했다.
- 별도 보관함에서 기존 Gemma 실패 작업으로부터 새 Qwen 답변이 만들어져 완료됐다. 기존 작업은 실패 상태·Gemma 요청을 유지했다. 이 한 번의 답변 생성은 약 11.12초였으며 성능 비교 수치로 일반화하지 않는다.
- 같은 실제 혼합 손글씨 이미지를 새 frozen 엔진의 Qwen으로 인식했다. 사용량 metadata를 제외한 출력·engine digest·페이지 표시가 이전 Qwen 기준 결과와 일치했다. 이는 동작 보존 검사이며 OCR 정확도가 새로 향상됐다는 주장이 아니다.
- 실제 설치 앱을 정상 종료·교체·실행했다. 설정 화면에서 로컬 모델 ID가 없고 Qwen 4B·의미 검색만 준비 항목으로 표시되며 전사 엔진이 준비된 것을 확인했다.

별도 GUI 시나리오는 API 모델 입력의 표시·복귀와 새 로컬 실행까지 진행했으나 작업 응답을 기다리다 검증 프로그램의 제한 시간에 도달했다. DB의 생성 완료와 별도 순차 native 호출 성공은 확인했지만, 그 시나리오의 후속 필기 편집·승인·검색·재실행 전체를 통과했다고 기록하지 않는다. 설치 앱의 추가 클릭도 화면 도구에서 반응을 확인하지 못해, API 제공자 변경·PDF 재열기까지의 직접 조작 검증에는 제한이 있다. 이번 변경으로 새 녹음·절전·강제 종료 시험을 반복하지 않았다.

## 승인한 모델 정리와 보존

사용자가 영구 삭제를 승인한 앱 전용 Gemma 12B·E2B만 정리했다. 다른 manifest의 참조를 모두 대조한 고정 목록을 사용하고, 공유 blob·다른 실험 모델은 제외했다. 삭제 전 파일 현재성·해시·사용 중 여부와 보관함 잠금을 확인했다. 독립 검토에서 발견한 manifest 디렉터리 symlink 누락은 실패 재현 검사 후 수정하고 정리 전에 재검증했다.

| 항목 | 관찰 결과 |
| --- | --- |
| 삭제한 전용 blob | 2,802개, 논리적 합계 15,159,102,368 bytes |
| 제거한 모델 | Gemma 12B·E2B manifest, 검증된 12B 생성 cache view |
| 유지 모델 | 1,162개 blob의 해시·파일 정보 불변 |
| 정리 전후 보관함 | SQLite 48개 테이블 fingerprint, 무결성·외래 키 검사 유지 |
| 원음·외부 원본·ASR 등 | 보호 대상 73개 파일 해시 불변 |
| 관찰한 디스크 여유 | 29,831,929,856 → 45,001,445,376 bytes |

여유 공간 증가는 약 14.13GiB다. cache와 다른 시스템 동작도 영향을 줄 수 있으므로 논리적 삭제 크기와 동일시하지 않는다. Gemma를 다시 비교하려면 재다운로드가 필요하다.

설치 앱 시작 후에도 과목 10개·기록 13개·메모 6개·녹음 16개·페이지 문서 10개·페이지 버전 42개·필기 인식 16개·출처 1,230개·결과 11개·native 초안 14개의 fingerprint가 정리 전과 같았다. 시작 후 자동 작업의 대기·실패 횟수는 변할 수 있어 전체 DB가 계속 불변이라는 뜻은 아니다.


전체 Python 검사의 일부 기존 엔진·포트 검사는 준비된 로컬 FFmpeg와 localhost 바인딩 권한이 필요하다. 독립 소스 검증 폴더에는 해당 런타임을 연결하고 별도 Swift module cache를 사용했다. 처음 검증에서 나온 cache 경로 충돌·런타임 미연결·샌드박스 포트 거절은 검증 환경을 보완한 뒤 다시 확인했다.

같은 checkout에서 별도로 작성 중인 홈·과목·기록 화면 개편은 이 변경의 커밋에서 제외한다. 설치 시점의 앱 화면에는 그 미커밋 작업이 포함돼 있으므로, 이번 main 커밋의 UI와 완전히 같은 배포물이라고 주장하지 않는다. 모델 정책·엔진·설정·재시도·인식 변경은 별도 고정 소스에서도 검사했다.

구현 커밋 `719a592424f1f721b7a808c29d17ef55bc1c0bc1`을 일반 푸시한 뒤 원격 `main`의 같은 SHA를 확인했다. 설치 엔진과 검증 빌드의 manifest·실행 파일 해시를 대조하고, 이번에 만든 중복 빌드·컴파일 cache·검증용 소스 사본은 정리했다. 검증 로그·보호 기준·기존 앱 백업·사용자 파일은 보존했다.
