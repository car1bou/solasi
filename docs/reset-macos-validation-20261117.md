# Solasi Mac 앱 초기화 구현·검증 — 2026-11-17

## 설치 결과와 범위

**Mac 0.3.43 / build53**를 `/Users/kimhuijung/Applications/Solasi.app`에 설치했다. 설정에 **앱 초기화…**를 추가했다. 사용자가 선택한 범위는 원래 보관함·수정 이력, 앱 설정·해당 보관함의 저장 API 키, 전용 다운로드 모델·추가 엔진·캐시·로그를 초기화하고 앱을 유지하는 것이다. 실제 사용자 기록으로 초기화·키 삭제·모델 제거를 실행하지 않았다.

설치된 앱에서 새 선택창이 나타나는 것을 확인하고 그 상태로 열어 두었다. 실제 보관함에서는 **선택한 항목으로 계속**을 누르지 않았다.

사용법: [solasi-reset-usage.md](solasi-reset-usage.md).

## 동작

- 설정의 **앱 초기화…**와 **설치 삭제…**를 구분한다. 초기화는 앱·내장 기본 엔진을 남기며, 설치 삭제는 앱까지 제거한다.
- 초기화도 기존 보존/검증 절차를 사용한다. 필기·문서 / 녹음 / 전사·AI 결과를 각각 보존 또는 삭제로 고르고, 모두 보존이 기본값이다.
- 보존을 고르면 솔라시 없이 읽을 수 있는 PDF·원본 문서·텍스트·음성 사본을 먼저 만든다. 보존은 원래 보관함을 유지하는 뜻이 아니다. 실행 시 원래 보관함과 편집 이력은 제거된다.
- 검증한 보존 파일, 범위와 위치, 앱 유지, 모델·추가 엔진 재준비 안내를 최종 네이티브 화면에 표시한다. 정확한 **솔라시 초기화** 입력과 **초기화 실행**이 필요하다. **솔라시 삭제** 문구로는 초기화를 실행할 수 없다.
- **선택 변경**은 기존 준비/영수증을 취소하고 초기화 모드와 이전 선택을 유지해 돌아간다. 보존·검증과 확인 입력을 다시 진행한다.
- 도우미는 앱/작업자 종료, 잠금·파일 식별자와 보존 해시를 다시 검사한다. 초기화에서는 앱 snapshot을 검증하되 앱을 삭제 대상에서 제외한다. 빈 data/runtime 루트는 유지해 다시 시작할 수 있게 한다.
- 외부 원본·별도 백업·공유 도구·소유권 미확인 실험 파일은 유지한다. 부분 삭제 실패를 성공으로 표시하지 않고 보존 폴더에 결과 보고서를 남긴다. 성공 후 **솔라시 다시 열기**로 앱을 열 수 있다.

## 변경 파일

초기화 변경은 기존 uninstall 구현 위에 추가했다. `macos/UninstallPlan.swift`, `UninstallHelper.swift`, `Solasi.swift`, `frontend/src/UninstallSettings.tsx`, 관련 테스트와 설치 버전만 변경했다. Python 보존·계획 모듈이나 설치된 Python 엔진은 초기화 구현을 위해 변경하지 않았다. reset-only 기준 파일과 patch는 `.superpowers/sdd/2026-11-17-reset/`에 기록했다. 기존 무관한 Windows/mobile 변경은 유지했고 커밋·푸시는 하지 않았다.

## 별도 검토

구현자와 별개의 검토자가 reset-only 변경을 읽고 두 P1 문제를 지적했다. 둘 다 수정 전 실패를 확인한 뒤 고쳤다.

1. 빈 data/runtime 루트까지 제거하면 네이티브 시작 조건을 만족하지 못하는 문제 → 초기화에서는 두 루트를 유지한다. 별도 백업이 없는 fixture에서도 앱 시작에 필요한 폴더가 남는지 검사한다.
2. 앱 내부 대상만 거부하고 앱을 포함한 상위 폴더를 허용한 문제 → 앱의 상위·하위 경로를 모두 차단한다. 나중에 생성되는 OS 경로도 `os_paths` 검증에서 차단한다. 임시 runtime의 상위 대상으로 앱이 제거되는 실패를 먼저 재현했다.

수정 후 네이티브 14개가 통과했다. 이 두 수정의 독립 재검토를 받았다고 주장하지 않는다. 수정 검증은 재현 회귀와 실제 UI 확인으로 수행했다.

전체 회귀의 최초 실행은 저장 공간 부족으로 중단됐다. 별도 실행에서도 `sqlite3.OperationalError: database or disk is full`이 재현됐다. 첫 오류 전 **485개(484 통과, 1 생략)** 완료를 로그와 현재 discovery 순서로 대조했다. 작업용 중복 앱과 재생성 가능한 Swift 빌드 캐시를 정리한 뒤, 첫 오류 항목부터 나머지 **378개를 재실행하여 실패·오류 0, 8 생략**을 확인했다. 따라서 전체 범위를 검증했지만, 한 번의 중단 없는 전체 실행이 통과한 것으로 표현하지 않는다. 생략 항목은 별도 실모델/음성 fixture와 Windows 전용 API·실행 파일이 필요한 기존 항목이다.

초기 sandbox 실행에서는 테스트용 Keychain 요청에 -50 오류가 났다. 보호 검사를 약화하지 않고 임시 보관함으로만 결정되는 서비스 이름을 사용하는 테스트를 허용된 환경에서 다시 실행해 통과했다. 실제 사용자의 Keychain 서비스는 테스트에 사용하지 않았다.

가짜 데이터 전용 QA 앱에서는 모두 보존으로 5개 파일을 검증한 뒤 초기화 전용 마지막 화면에 도달했다. 잘못된 삭제 문구는 실행 버튼을 활성화하지 않고, 올바른 초기화 문구만 활성화했다. 실행 버튼은 누르지 않았다. **선택 변경** 뒤에도 초기화 모드·보존 선택이 유지됐고 취소 후 정상 UI에 복귀했다. 파괴적 실행은 임시 앱·보관함·모델 fixture에서만 테스트했다.

## 한계와 주의

실제 사용자 보관함·키·모델의 초기화는 의도적으로 실행하지 않았다. macOS만 구현했다. PDF는 열람용이며 원래 편집·이력 복원을 보장하지 않는다. 실제 초기화 실행 후 원래 보관함은 영구 삭제되고, 중간 실패 시 일부 원본이 이미 제거됐을 수 있다. 보존 파일과 결과 보고서는 유지한다. 현재 기기 저장 공간 부족이 설치·전체 검사에서 실제로 발생했으므로 보존 공간이 충분하지 않으면 준비 단계에서 중단될 수 있다.
