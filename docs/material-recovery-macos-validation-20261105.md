## 원본 복구

파일 없음과 접근 불가 상태에는 **원본 다시 찾기 / 다시 확인**을 표시한다. 열 수 없는 원본 링크는 숨긴다. 긴 파일 접근 오류의 기술 상세는 접어 두며, 파일 내용 불일치 등 복구 거절 이유는 바로 표시한다.

다시 찾기는 기존 네이티브 파일 선택창에서 고른 파일 하나의 SHA256·종류를 확인한다. 동일 원본이면 기존 자료 ID를 유지해 경로와 mtime만 변경한다. 원본 파일을 복사·삭제하거나 추출 버전을 변경하지 않는다. 다른 내용, 다른 자료에 연결된 경로, 앱 관리 폴더, 소유 범위 밖 자료, 진행 중인 추출은 거절한다. 취소는 변경하지 않는다. 손글씨 자료는 기존 승인 제한을 유지한다.

원본 변경에는 원본 확인·재추출을, 추출 내용만 이전 버전이면 검색용 원문 갱신 안내를 제공한다. 이전 메모·필기는 이전 원본 hash에 보존하며 새 문서에 자동으로 덮지 않는다.

## 확인한 결과

- 격리한 Mac 소스에서 프런트엔드 **137개 검사**, TypeScript 검사·배포 빌드 통과.
- 새 복구 API **4개**, 기존 자료 처리 **9개**, PDF·필기 **7개** 검사 통과. 최초 PDF 검사 명령의 import 경로와 제한 환경의 Swift 컴파일 문제는 실행 환경을 바로잡은 뒤 재실행했다.
- 독립 코드 검토와 기술 오류 표시 후속 검토에서 조치할 문제 없음.
- 새 내장 엔진의 동결 빌드·self-check·파일 manifest 검사·앱 서명 검사 통과. 네이티브 창 실행 코드는 유지했다. 새 모델 다운로드는 없다.
- 실제 설치 앱의 **680×480 라이트·다크**에서 복구 상태, 버튼 줄바꿈, 필기 설정 값·미리보기와 더보기 그룹을 확인했다. 최종 기술 상세 접기는 다크에서 별도로 확인했다.
- 별도 검증 과목에 PDF를 연결하고 페이지 메모를 **v2**로 저장했다. 검증 원본을 이동한 뒤 파일 없음 표시와 복구 버튼을 확인했다. 파일 선택 취소 후에도 선택·메모 v2가 유지됐다.
- 실제 파일 선택창에서 같은 내용의 원본을 다시 선택해 위치 복구를 완료했다. 자료 ID·원본 hash·추출 버전·기존 페이지와 revision이 불변이고 원본 페이지가 다시 표시됐다.
- 재실행 후 검증 파일을 잠시 이동해 최종 파일 없음 화면을 확인했다. 기술 상세에서 Space로 접기·펼치기, Tab으로 ‘원본 다시 찾기’ 이동이 가능했다. 파일을 복원하고 ‘다시 확인’을 누르면 저장 메모 v2와 원본이 돌아왔다.
- 기존 기록·필기·원음 관련 **11개 테이블의 4,147개 기존 행**, 보관함 내 기존 파일 **71개**의 크기·SHA256 불변. 기존 필기 도구와 목록 보기 설정도 유지했다. 검증 중 추가한 과목·자료는 기존 기록과 분리했다.
- 최종 설치 화면 파일은 검사한 배포 빌드와 일치한다. 관련 없는 Windows·모바일 미커밋 변경은 빌드·커밋에서 제외한다.

## 검증 한계

- 새 장시간 녹음, ASR·LLM 정확도 비교와 PDF 내보내기는 이번 원본 위치 복구 범위에서 재실행하지 않았다.
- 이 문서의 초기 위치 복구 GUI 대조는 저장 메모로 수행했다. 당시 드래그는 도구 오류로 완료하지 못했다. 이후 [실제 펜·형광펜 재연결 검증](ink-relink-macos-validation-20261105.md)에서 창 활성화 경로를 거쳐 두 획을 저장하고 이동·재연결·재실행 후의 전체 ink 일치와 두 테마 표시를 확인했다. SDK 오류 자체가 영구 해결됐다는 뜻은 아니다.
- 실제 macOS 파일 권한을 바꾸어 접근 거절을 재현하지 않았다. 해당 표시와 행동은 컴포넌트 검사로 확인했다. 파일 선택만으로 영구 권한 복구를 보장하지 않는다.
- 화면 도구가 macOS 기본 테마 선택을 확정하지 못해 다크 선택 한 번은 사용자가 수행했고, 적용 뒤 실제 화면을 대조했다. 검증 캡처·보관함·백업은 공개 Git에 포함하지 않는다.
