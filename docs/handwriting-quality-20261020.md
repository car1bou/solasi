# 한국어 혼합 손글씨 인식 비교 · 2026-10-20

이전 검증과 같은 실제 사람의 필기를 사용했다. 한국어·영문·수식·도형이 섞인 노트에서 CDF, 조건부확률, Jensen 부등식, λ-system, 분할 도형, 집합 포함 도형의 여섯 영역을 비교했다.

- [Lim Hyo Jeong의 수리통계 노트](https://github.com/lim-hyo-jeong/Mathematical-Statistics-Study/tree/cbe92f1daf60eb9f406265ea647bc7d9f4a51f49)와 [작성자의 소개](https://gagadi.tistory.com/49).
- [작성자가 공개한 π-λ 노트](https://juhongyee.tistory.com/43).
- 원본·모델·실험 응답은 로컬 검증 폴더에 보관한다. 공개 재배포 허가가 확인되지 않은 노트 이미지는 Git에 포함하지 않았다.

독립적인 이미지 판독으로 수식 표적과 판독 불가 범위를 먼저 동결한 뒤 새 OCR 결과를 읽었다. 기존 정답 텍스트에는 잘린 끝의 문장 완성, 잘못된 `if/∀`, 빠진 주석이 있어 전체 CER를 정확도 점수로 발표하지 않는다. 비교 스크립트의 CER는 기존 텍스트와의 문자열 거리 진단일 뿐이다. 도형의 의미 이해는 점수화하지 않는다. 알려진 두 작성자의 개발 표본이며 다른 필체에 대한 일반화 시험이 아니다.

## 비교한 실행 방식

Mac의 MLX 0.32.4 / mlx-vlm 0.7.8 / Transformers 5.20.0에서 한 번에 한 모델씩 실행했다. Torch와 별도 모델 서버를 추가하지 않았다.

| 모델 | 배포물·실행 | 관찰 및 채택 |
|---|---|---|
| Apple Vision | macOS accurate, 한국어·영어, 언어 자동 보정 끔 | 빠른 자동 후보 경로 유지. 수식 정답 엔진으로 간주하지 않음. |
| Qwen3.5 4B | 기존 설치 MLX NVFP4, 기존·엄격 원문 지시 비교 | 작은 입력 확대에서 일부 부호·주석 개선. 수동 후보 경로에 반영. |
| Gemma 4 E2B | 기존 설치 MLX | CDF 음수 부호와 집합 기호 오류, 포함 도형에서 출력 제한 반복. 기본 채택 안 함. |
| Gemma 4 12B | 기존 설치 MLX, 원본 및 엄격 원문 지시 | 조건부확률·Jensen·λ의 부호와 한국어가 더 충실. 선택 가능한 수식 대조 후보로 추가. |
| [PaddleOCR-VL 1.6](https://huggingface.co/PaddlePaddle/PaddleOCR-VL-1.6) | 공식 가중치, Apache-2.0, `c5630abae1d940eafe0697512a0325494b02ab42`, 1,930,462,423 bytes | 한국어·기호의 의미를 바꾸는 오류가 남아 기본 채택 안 함. |
| [LightOnOCR-3 0.8B](https://huggingface.co/lightonai/LightOnOCR-3-0.8B) | 공식 가중치, Apache-2.0, `36d8636925327c671bd8e479c517a004f7566bd9`, 1,737,771,835 bytes | 빈 프롬프트로도 설명·문장 완성·반복이 발생. 기본 채택 안 함. |

Paddle은 등록된 MLX 구현과 공식 이미지 처리 설정을 사용하고 `OCR:`로 호출했다. 이는 [Apple Silicon 실행 안내](https://www.paddleocr.ai/latest/en/version3.x/pipeline_usage/PaddleOCR-VL-Apple-Silicon.html)의 VLM 요소 인식 경로이며, 별도의 전체 문서 레이아웃 파이프라인을 검증한 결과는 아니다. LightOn은 공식 안내의 빈 프롬프트와 thinking 비활성화를 사용했다. 임의 지시문을 추가하지 않았다. 다운로드 파일별 크기·SHA256은 로컬 영수증에 남겼다.

## 전처리와 부호 비교

Qwen에 원본·확대·흰 여백·대비·이진화·문맥이 겹치는 상하 분할을 적용했다. 확대는 비율 유지, 최대 3배, 긴 변 2048픽셀이며 원본 파일은 수정하지 않았다. 새 OCR 두 종도 원본과 같은 확대 입력을 비교했다.

| 조건 | 실제로 관찰한 변화 |
|---|---|
| Qwen 엄격 지시 + 원본 | CDF `−∞`의 `−` 누락, `x+h→x+th`, `λ→π`, `A,B⊂S` 오인식. |
| Qwen 엄격 지시 + 확대 | `−∞`, `x+h`, `λ`, Jensen 존재 주석, 조건부확률의 `∩`가 복원됨. `A,B⊂S` 오류와 마지막 교집합 `∩→n`은 남음. 도형 라벨도 일부 오인식. |
| 흰 여백 | 음수 부호는 복원되지만 주석을 없는 내용인 ‘모든 속성 만족’으로 바꾸는 오류. |
| 대비 | 네 텍스트 영역에서 원본과 같은 응답. 개선 근거 없음. |
| 이진화 | CDF·λ 일부 개선과 동시에 Jensen `∞→00`, `⇔→=>` 회귀. |
| 겹침 분할 | 중복 문맥을 그대로 보존해 비교. Jensen에서 반복·출력 제한과 약 92초 지연. 자동 적용 안 함. |
| Paddle 원본·확대 | 원본에서 `P(A)>0→P(B)>0`, `≤→⊆`, `x+h→2+h`. 확대에서도 Jensen `≤→⊆`, λ의 합집합→교집합 오류와 한국어 손상이 남고 조건부확률은 출력 제한에 도달. |
| LightOn 원본·확대 | 원본 Jensen 장문 반복·출력 제한, 포함 도형을 공전 궤도로 설명. 확대에서 반복은 줄지만 CDF `X→x`, 조건에 없는 `P(A)<1` 추가, Jensen 절댓값 누락과 한국어 손상이 남음. |

### 잘린 문장

CDF 이미지 오른쪽 끝은 ‘누적분포함수가’ 뒤가 잘려 있다. Gemma 12B는 엄격한 원문 지시를 주어도 보이지 않는 ‘되기 위한’을 붙였다. LightOn 원본은 ‘되도록 하는’을 생성했다. Qwen 확대는 완성된 후속 구절을 추가하지 않았지만 끝의 `되` 한 글자는 판독 불가 경계 조각이라 정답으로 세지 않았다.

`[판독 불가]` 지시만으로 추측을 완전히 막지 못했다. 경계에 닿은 글자를 삭제하거나 두 모델 결과를 수학 지식으로 자동 합치지 않는다. 가장자리 감지는 **잘림 의심** 안내로만 사용한다. 표시가 없는 누락·추측도 가능하다.

## 제품 반영

- 빠른 자동 인식은 Vision, 로컬 Qwen은 작은 입력 확대·엄격 원문 지시, Gemma 12B는 사용자가 누르는 수식 대조 후보로 제공한다. 새 OCR 모델을 자동 선택하거나 다운로드하지 않는다.
- 가져온 작은 이미지에 펜 획이 없으면 원본 픽셀에서 한 번만 확대한다. 덧쓴 획·PDF·큰 사진은 기존의 크기 제한이 있는 네이티브 합성 이미지를 사용한다. 확장자와 실제 내용이 다른 입력도 유지한다.
- Vision의 반올림 좌표가 이미지 밖으로 약간 벗어나 정상 인식문 저장까지 실패한 문제를 수정했다. 실제 조건부확률 이미지에서 음수 y좌표를 재현한 뒤 이미지 범위와 교차한 좌표로 재검증했다. 외부 결과의 좌표 검증은 완화하지 않았다.
- 잘림 의심과 출력 길이 제한을 후보 옆에 표시한다. 원문·기존 후보·승인문은 보존하고 새 처리 방식에는 다른 엔진 식별자를 사용한다.
- 승인 전·거절·필기 변경 후 후보는 검색·요약·이전 강의 연결에 편입하지 않는다. 수식 대조 후보도 같은 승인 경로를 사용한다.

## 시간 측정의 경계

원본 여섯 영역의 Paddle은 중앙값 1.48초, LightOn은 2.82초였지만 **이미 로딩한 모델의 이미지별 처리 시간**이다. 각각 별도 모델 로딩 약 1초가 있으며, LightOn 반복 실패는 37.75초까지 걸렸다. Qwen·Gemma의 직접 실행 시간은 매 요청의 worker·파일 준비·모델 로딩을 포함한다. 서로 같은 범위의 속도 순위로 해석하면 안 된다.

같은 직접 실행 경로의 네 텍스트 영역에서 Qwen 엄격 원본은 중앙값 9.42초, 확대는 14.10초, Gemma 12B 엄격 원본은 20.50초였다. 각 조건 한 번의 개발 표본 측정으로, 메모리 캐시·파일 준비 상태에 영향을 받는다. 확대의 부호 개선에는 처리 시간 증가가 동반됐다.

비교 스크립트는 조건·입력 SHA·helper SHA·모델 파일 또는 설치 자산 식별자·런타임 버전을 기록하고, 조건 기록이 없는 기존 JSON 캐시를 재사용하지 않는다. 로딩과 이미지 처리 시간의 범위도 결과에 구분한다. 초기 비교 결과는 새 캐시 검사를 소급 적용한 결과가 아니며, 새 디렉터리에서 순차 실행한 원본 로그와 파일 영수증으로 대조했다.

## 재현 예

원본과 정답 텍스트를 각각 `DATA/images/이름.jpg`, `DATA/ground_truth/이름.txt`에 두고, 매 조건마다 새 출력 폴더를 사용한다. 정답은 잘린 글자를 추측해 완성하지 않는다.

```bash
HF_HUB_OFFLINE=1 TRANSFORMERS_OFFLINE=1 .venv/bin/python experiments/compare_handwriting.py \
  --dataset DATA --output NEW_OUTPUT --helper HANDWRITING_HELPER \
  --runtime INSTALLED_RUNTIME --model qwen3.5:4b --variant upscale --literal

HF_HUB_OFFLINE=1 TRANSFORMERS_OFFLINE=1 .venv/bin/python experiments/compare_handwriting.py \
  --dataset DATA --output OTHER_NEW_OUTPUT --helper HANDWRITING_HELPER \
  --model paddleocr-vl-1.6 --model-path OFFICIAL_MODEL_DIRECTORY
```

공식 OCR 모델은 준비된 로컬 폴더로만 로딩하고 remote code는 실행하지 않는다. 스크립트는 모델을 다운로드하지 않는다. 혼합 수식의 정답 검증은 문자열 거리만으로 대체하지 말고 `−`, `≤`, `∩/∪`, 첨자·조건과 실제 이미지 경계를 별도로 대조한다.

## 설치 앱 검증

Solasi **0.3.23 / build 33**에 반영했다. 제품 인식 함수에서 Qwen 여섯 영역과 Gemma 12B 네 텍스트 영역을 다시 실행한 열 건 모두 비교 실험과 같은 텍스트가 나왔다. 개발용 첫 Swift 실행에는 컴파일 시간이 포함되므로 설치 앱의 지연으로 집계하지 않았다. 설치 앱은 미리 컴파일한 helper를 사용한다.

실제 설치 앱에서는 기존 검증 과목의 CDF 이미지를 열고 다음을 직접 조작했다.

- Qwen과 Gemma의 새 버튼으로 각각 인식하고 결과·잘림 의심 안내를 확인했다. 같은 부호 개선과 Gemma의 경계 문장 추측을 재현했다.
- 잘린 끝을 `[판독 불가]`로 수정해 승인했다. 원래 모델의 ‘되기 위한’과 수정 승인문이 서로 다른 필드에 보존됨을 확인했다.
- 미저장 수정이 있으면 화면 이동·정상 종료를 막았다. 수정 초안의 native ACK 저장도 확인했다. 승인 후 정상 종료·재실행하여 승인문과 680×480 창 크기·다크 모드가 유지되는 것을 확인했다. 이번 시험에서 미승인 초안의 강제 종료 복구는 새로 실행하지 않았다.
- 실제 보관함에서 미승인 후보는 검색에서 제외됐고, 수정 승인문만 검색·요약 입력에 포함됐다. 같은 과목의 관련 이전 기록 두 건이 연결됐다. 이것은 근거 입력 경로 검증이며 새 요약 생성 품질 점수는 아니다.
- 680×480 라이트·다크에서 세 버튼의 줄바꿈, 내부 스크롤, 경고와 원본 보기를 확인했다. 긴 모델 해시가 가로로 잘리는 문제를 발견해 후보 텍스트의 줄바꿈을 수정했다. Tab으로 Vision → Qwen → Gemma 버튼에 이동하고 포커스가 보이는 것을 확인했다. 모드 선택은 키보드로도 적용됐으며 검증 후 원래 라이트 설정으로 돌렸다.

기존 과목 7개·강의 기록 11개·녹음 10개·전사 742개·페이지 문서 9개·페이지 버전 41개·출처 1,219개·결과물 9개·native 초안 11개는 기존 행과 대조해 보존됐다. 기존 인식 기록 12개의 원문·영역·승인문도 보존했다. 재인식을 누른 검증 후보의 상태만 이전 후보로 바뀌었다. 원음 여섯 파일의 SHA256이 같고 DB 무결성·외래 키 검사가 통과했다.

Python **591개 중 586개 통과·선택 검사 5개 생략**, 프런트엔드 **102개 통과**, TypeScript·Vite 빌드와 Mac 엔진·앱 서명 검증을 완료했다. 코드는 별도 리뷰에서 캐시·시간 범위·PDF 위장 확장자·큰 이미지 회귀 지적을 수정한 뒤 재검토했다.
