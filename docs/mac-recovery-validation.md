# Mac 녹음 복구와 한국어 음성 추가 검증

2026-10-16 · Apple M4 / 16GiB · macOS arm64. grilling으로 기존 원음 보존·복구 정책을 검토하고 ponytail로 재현된 원인만 수정했다. 별도 `Solasi Native Validation.app`과 데이터 폴더에서 실제 마이크·필기·강제 종료를 시험했다. 사용자 앱의 기존 데이터는 검증 데이터에 복사하지 않았다.

## 강제 종료 후 재실행 실패 원인

수정 전 검증 앱의 네이티브 프로세스만 SIGKILL했을 때 Python 서버가 부모 PID1로 남았다. 앱 재실행은 같은 포트를 확보하지 못해 실패했고, 로그에도 `Address already in use`가 기록됐다. 서버를 별도로 종료한 뒤에는 다시 열렸다.

네이티브 앱이 서버에 자신의 PID를 전달하고, 서버가 부모 변경을 감지하면 Uvicorn의 SIGTERM 종료 절차를 밟도록 수정했다. 종료 시 연결·작업·앱이 실행한 모델·데이터 잠금의 기존 정리 경로를 사용한다. 소유 앱을 지정하지 않은 CLI 실행에는 감시를 추가하지 않는다. 무관한 서버나 사용자 모델을 검색해 종료하지 않는다.

수정 전 강제 종료 시점에도 저장 확인을 마친 48kHz 원음 107.75초의 PCM 접두부 해시와 페이지 메모·필기 v1/v2는 보존됐다. 이는 저장 확인 전 모든 마지막 프레임이나 정전 내성을 검증한 결과는 아니다.

## 실제 절전·복귀 및 수정본 강제 종료

사용자가 직접 Mac을 잠자기했다 깨웠고, `pmset`의 시스템 Sleep/Wake 기록을 대조했다. 화면 꺼짐이나 오디오 일시 중단 모의 검사를 실제 절전으로 취급하지 않았다.

| 시험 | 실제 관찰 |
| --- | --- |
| 첫 절전 61초 | 48kHz 마이크 원음 754.067초(12분34초)를 보존했으나 자동 복구 실패. 잠들기 직전 새 구간을 열어 복구 기회를 소진했고, 새 구간은0프레임으로 종료됨 |
| 상태값만 기다린 수정의 절전 58초 | 같은 조기 복구가 재현돼 이 방법만으로 해결됐다고 채택하지 않음 |
| 새 입력을 기다린 수정의 절전 43초 | 사용자 재클릭이나 새 마이크 권한 취득 없이 새 구간 생성. 화면의 `자동 복구됨 · 녹음 중`과 실제 저장 프레임 증가 확인 |
| 복귀 후 계속 녹음 | 새 구간68.5초 보존. 앞 구간과 같은 capture 계보, 새 시작 시각, 약48.639초의 구간 사이 빈 시간 유지 |
| 수정본 네이티브 앱만 SIGKILL | 소유 서버가 약1.21초 안에 정상 종료 절차를 마치고 포트 해제. 재실행 후 저장 확인된 PCM 접두부와 페이지 v1~v5 모두 일치 |
| 서버 페이지 저장503 + 앱·서버 모두 SIGKILL | 서버는 v5 그대로인 상태에서 로컬 초안 작성. 재실행·같은 페이지 열기 뒤 메모96자·필기3획이 내보낸 초안 JSON과 정확히 일치하고 v6로 자동 저장됨. v1~v5는 그대로 보존 |

WebKit은 실제 시스템 절전 전에 오디오 처리를 멈췄다. 이때 바로 새 AudioContext를 만들면 입력이 돌아오기 전에 기존 최대1회 복구 기회를 써 버렸다. 최종 수정은 기존 컨텍스트의 resume를 요청하고, **실행 중이며 종료·음소거되지 않은 같은 마이크에서 새 입력 프레임이 도착한 뒤** 기존 원음을 마무리하고 새 구간을 연다. 상태값이 `running`인 것만으로 복귀를 확정하지 않는다. 정상적인 무음 PCM도 입력으로 인정하며, 파형 크기로 말을 추측하지 않는다.

대기 중 사용자의 종료, 마이크 종료, resume 거절은 정리 경로로 이어진다. 새 권한 취득이나 두 번째 자동 복구 시도는 추가하지 않았다. 기존 PCM 저장 확인·간격 표시·전사 후보 적용 정책을 유지한다. 페이지 초안 시험은 실제 WebKit IndexedDB와 제품 PageDraft를 사용했으며, 메모·잉크를 서버에 직접 써 넣어 복구를 대신하지 않았다. 초안 JSON도 네이티브 저장 창을 거쳐 내보냈다.

### 이번에 확인한 범위

- 실제 내장 마이크의 가장 긴 연속 저장은12분34초다. 최종 복귀 수정은 별도 짧은 녹음에서 실제 절전으로 재검사했고, 복귀 뒤 추가 녹음과 강제 종료를 이어서 확인했다. 최종 수정으로30~60분 또는 밤샘 녹음을 다시 완료한 결과는 아니다.
- 완료한 획과 입력 후 로컬 초안 저장이 끝난 메모를 검사했다. 펜을 누른 채 끝내지 않은 획, IndexedDB 저장 완료 전 즉시 프로세스 소실, 디스크 고장·실제 전원 차단을 보장하지 않는다.
- 서로 다른 전원·오디오 기기·블루투스 마이크의 모든 조합이나 반복 절전 전체를 검증한 것은 아니다. 한 번 자동 복구된 녹음의 추가 중단에는 기존 수동 재시작 정책이 적용된다.

## 정답이 있는 실제 한국어 음성 추가

[본문 없는 집계와 입력 해시](verification/mac-recovery-speech-20261016.json)에 원음·전사·모델 응답을 제외한 결과를 남겼다. 추론 전에 입력 목록을 고정했고, 정답은 사후 점수 계산에만 사용했다. 새 모델 다운로드나 외부 AI API는 사용하지 않았다.

| 자료 | 이번 추가 범위 | 해석할 때의 제한 |
| --- | --- | --- |
| [Pansori TEDxKR](https://www.openslr.org/58/) | 기존 선택에 없는 화자 ID 8개에서 원본 발화 16개 | 발표·강연 발화이며 나이 metadata는 없음 |
| [Deeply 공개 부분집합](https://www.openslr.org/97/) | 새 정답 문장 5종을 포함한 발화 조건 18개 | 기존 여성 2명·3개 방의 반복 조건. 공개 부분집합은 iPhone X·0.4m이며 전체 코퍼스의 모든 장치·거리를 시험한 것이 아님 |
| [KMSAV](https://github.com/etri/kmsav) | 이미 보관한 실제 인터뷰에서 추가 정답 구간 18개·56.144초 | 새 원음 수집이나 독립 검증용 holdout이 아님. 전체 다화자 대화의 완전한 정답도 아님 |

새로 받은 원본 파일은 34개·3,812,263바이트다. 배포 Git revision의 blob 해시·크기를 확인하고 SHA256을 기록했다. Pansori/Deeply의 CC BY-NC-ND4.0 자료는 원본을 변경하지 않은 개인 비상업 비교에 사용했고, 원음·정답을 Git이나 앱 배포물에 넣지 않았다. KMSAV 수동 주석과 원본 매체의 조건도 별도로 기록했다. 회원 등록이나 별도 이용 약관 동의가 필요한 자료를 임의로 확보하지 않았다.

### 같은 추가 52구간의 전사 비교

CER는 NFKC·소문자·유니코드 문자/숫자로 정규화한 문자 편집률이다. 삽입·삭제 편집 수를 의미적 환각·누락의 발생률로 부르지 않는다.

| 조건 | 기본 Whisper 편집/정답 글자 | CER | Qwen 재전사 후보 편집/정답 글자 | CER |
| --- | ---: | ---: | ---: | ---: |
| 새 Pansori 16발화 | 13/358 | 3.63% | 27/358 | 7.54% |
| 새 Deeply 18조건 | 12/453 | 2.65% | 7/453 | 1.55% |
| 기존 KMSAV 추가 18구간 | 47/244 | 19.26% | 45/244 | 18.44% |

Qwen 후보는 15구간에서 개선, 11구간에서 악화, 26구간에서 동률이었다. 숫자를 한글로 풀어 쓴 표기 차이도 편집에 포함된다. 이 결과로 기본 모델을 바꾸거나 긴 후보를 자동 채택하지 않았다. 짧은 일상 대화의 조사·머뭇거림 누락과 불필요한 연결어 추가가 남아 있다. 기존 후보 생성·사용자 적용 정책을 유지한다.

### 작은 음성 증폭 실험의 기각

기존 정답 음성 90조건을 다시 실행한 뒤, 같은 입력에만 FFmpeg `loudnorm=I=-23:TP=-2:LRA=7`을 적용해 비교했다. 원본은 보존했다.

- 작은 음량 5조건은 편집22/223·삭제12로 같아 해당 누락을 해결하지 못했다.
- 식당 소음 15조건은 편집28/152에서31/152로 악화했다.
- 일부 일상 발화는 개선됐지만 모든 조건의 이익이 일치하지 않아 기본 전처리에 추가하지 않았다.

이번 비교에는 독립적인 청취 정답 재작성이나 한국어 의미 오류 전수 판정이 없다. 원래 정답의 오탈자·숫자 표기와 잘린 구간의 문맥 손실이 문자 점수에 영향을 준다. 실제 마이크의 저장 안정성과 공개 음성의 전사 정확도는 별도 시험이다. 다른 검증 작업도 같은 Mac에서 실행했으므로 이 비교의 추론 시간을 모델 속도 순위로 발표하지 않는다.

## 검사와 재현

- 백엔드 367개, 프런트엔드 56개 검사 통과.
- TypeScript 검사와 Vite 프로덕션 빌드 통과.
- 소유 PID 설정 검증, 부모 변경 시 SIGTERM, 취소 시 무신호, 앱 lifespan의 감시 시작·회수를 추가 검사했다.
- 평가 스크립트의 선택 manifest 경로를 지원하고 빈 목록·중복 원음 거절과 입력 manifest 해시를 검사했다. 기존 기본 90조건은 유지한다.
- 오디오 상태값만 복귀하거나 음소거 상태의 프레임이 도착해도 복구 기회를 쓰지 않는지, 새 정상 입력 후 단1회 구간 전환, 대기 중 종료·마이크 종료·resume 거절을 검사했다.
- 설치된 Solasi.app을0.2.1(9)로 교체하고 코드 서명 검사·실제 홈 기동을 확인했다. 이전 앱 백업을 보존했으며 기존 실행 설정과 데이터베이스39개 테이블의 행 수·행 해시가 모두 일치했다. 검증 앱 데이터는 사용자 앱 데이터와 분리했다.

```sh
.venv/bin/python -m unittest discover -s tests
npm --prefix frontend test
npm --prefix frontend run build
.venv/bin/python experiments/evaluate_sentence_asr.py whisper --output /private/tmp/existing-whisper.json
.venv/bin/python experiments/evaluate_sentence_asr.py whisper --manifest /private/tmp/additional-manifest.json --output /private/tmp/additional-whisper.json
.venv/bin/python experiments/evaluate_sentence_asr.py qwen-review --manifest /private/tmp/additional-manifest.json --output /private/tmp/additional-qwen.json
```

평가 재현에는 해당 로컬 원음·정답 manifest와 설치된 엔진·모델이 필요하다. 평가 스크립트가 음원·모델을 다운로드하지는 않는다. 실제 복구 확인은 별도 검증 앱에서 다음 순서로 수행한다.

1. 마이크를 종료 후 전사 방식으로 시작하고, PDF 페이지에 완료한 획과 메모를 저장한다.
2. 저장 프레임 수·PCM 접두부 해시·페이지 버전을 보존한다.
3. 실제 Mac을 잠자기했다 깨운 뒤 전원 로그, 녹음 구간·간격, 원음·필기 보존을 대조한다.
4. 검증 앱의 정확한 PID만 SIGKILL하고 소유 서버의 종료·포트 해제·재실행을 확인한다.
5. 별도 검증 경로에서 페이지 저장만 실패시켜 초안을 만든 뒤 강제 종료·재실행한다. 기존 버전을 덮어쓰지 않고 초안이 복구되는지 확인한다.
