# Mac 전사·생성·임베딩 단계별 성능

2026-10-19. Apple Silicon Mac, macOS 27.0.1, 설치된 Whisper large-v3-turbo·Qwen3.5 4B MLX·EmbeddingGemma를 사용한 로컬 진단이다. 새 모델 다운로드나 외부 API 호출은 없다. 원음·정답·모델 응답·벡터·보관함은 공개하지 않는다.

## 변경

- 전사: 입력이 **16kHz·모노·16비트 PCM WAV**이고 마지막 프레임까지 존재하면 재변환을 생략한다. 다른 형식·잘린 WAV는 기존 FFmpeg 경로를 사용한다. 파일 전사는 구간 추출 때 이미 이 형식으로 변환하므로 그 다음의 중복 변환을 줄인다. 녹음 구간이 다른 샘플레이트라면 변환을 유지한다.
- PDF: 캐시된 페이지는 `document_metadata`의 원본 검증 두 번을 거친 뒤 반환한다. 이후 반복하던 두 번의 원본 검사를 줄여, 캐시 적중 시 전체 원본 검사를 **4회에서 2회**로 줄인다. 새 페이지 렌더링 전후 검사·문서 해시·페이지 범위 검사와 필기 버전 보호는 유지한다.
- 계측: 생성 응답의 `usage.timings_ms`에 준비·대기·추론을 기록한다. 전사와 직접 임베딩은 진단 호출에서 `timings={}`를 전달해 같은 방식으로 측정한다. 사용자 화면에 새 진단 요소를 추가하지 않는다.

## 같은 실제 한국어 음성 비교

추론 전에 기존 manifest에서 조건별 앞 두 표본을 고정했다. 총 **18개, 117.941초**, 9조건이다. 성인 인터뷰 원음·실제 사무실/식당 소음의 파생 혼합, FLEURS 원음·저음량·합성 잡음, 실내 낭독, TED 발화, 일상 인터뷰 발화를 포함한다. 합성 잡음과 실제 환경 소음을 구분하며, 완전한 다화자·겹침 대화의 정답 시험은 아니다. 정답이 있는 발화만 평가했다. 데이터 계보·이용 범위는 [기존 한국어 검증](korean-asr-validation-20261017.md)을 함께 참고한다.

각 표본의 SHA256을 확인하고 한국어·용어 힌트 없음·같은 VAD/디코딩 설정으로 비교했다. 별도 전후 실행 뒤, 각 음성에서 **기존 재변환/새 재사용의 실행 순서를 교대**하는 36회 비교를 수행했다. 교차 비교 중 Solasi 앱 시작 확인·다른 AI 검증·빌드를 동시에 실행하지 않았다. 운영체제 파일 캐시는 비우지 않았다.

| 교차 비교 | 기존 재변환 | PCM 재사용 |
| --- | ---: | ---: |
| PCM 14개 평균 음성 준비 | 12.752ms | 0.325ms |
| 전체 18개 준비 평균 | 12.439ms | 2.946ms |
| 전체 18개 전사 시간 합계 | 54.078초 | 56.229초 |
| 구간 전사 시간 중앙값 | 2.794초 | 2.739초 |
| 문자 오류 | 57 / 519 | 57 / 519 |
| 문자 오류율(CER) | 10.983% | 10.983% |

PCM 14개에서는 변환 프로세스 14회를 생략했다. 나머지 4개는 변환이 필요한 형식이었다. **전처리는 줄었지만 전체 전사 지연이 개선됐다는 결과는 아니다.** 총시간과 중앙값의 방향도 다르다. 전체 지연의 대부분은 인식 프로세스에 있다.

별도 전후 실행과 교차 비교 모두 **18/18 인식 문장·시작/끝 시각이 정확히 일치**했다. 오류 구성은 치환22·삭제32·삽입3으로 같았다. 공백·문장부호를 제외한 NFKC 문자 기준이며, 문자 정렬의 삭제·삽입 수를 실제 발화 누락·환각의 건수로 해석하지 않는다. 이번 변경은 기존 인식 오류를 교정하는 변경이 아니다.

첫 분리 실행의 전사 합계는 43.766→55.352초였다. 후반 실행 중 앱 시작 확인·회귀 검사가 일부 겹쳤으므로 이 수치는 속도 개선 판단에 사용하지 않고, 위 교차 비교를 별도로 수행했다.

## 생성·임베딩의 시간 구성

한국어 인식문에서 고정한 동일 입력을 두 단계에서 그대로 사용했다. 생성은 핵심 원문 ID 선택용 동일 schema·프롬프트·출력 예산으로 3회씩, 임베딩은 동일 한국어 입력으로 3회씩 실행했다. 정답 전사는 모델 입력이나 힌트로 전달하지 않았다.

아래 표는 개발용 Python에서 같은 직접 모델 worker를 실행한 결과다. 설치 패키지의 시작 시간과 같다고 간주하지 않는다.

| 변경 후 3회 측정 | 관찰 범위 |
| --- | --- |
| Qwen 전체 요청 | 7.739–10.764초 |
| Qwen 모델 로드 | 2.039–2.491초 |
| Qwen 입력·schema 준비 | 1.040–1.295초 |
| Qwen 생성 추론 | 2.507–2.692초 |
| 임베딩 프로세스 시작·모델/문맥 준비 | 0.358–1.267초 |
| 임베딩 계산·응답·정규화 | 0.017–0.050초 |
| 임베딩 전체 요청·정리 포함 | 0.386–1.335초 |

생성 ID 결과는 전후 3회씩 동일했고, 768차원 임베딩 벡터의 최대 차이는 0이었다. 이 작은 ID 선택 시험은 긴 요약의 중요 내용 선정·해석 품질 전체를 평가한 시험이 아니다. 생성 알고리즘·모델 상주 방식·검색 벡터 형식은 바꾸지 않았다. 초기 실행의 파일 검증과 OS 캐시 영향이 있어 이 범위를 다른 기기의 예상 시간으로 사용하지 않는다.

### 내장 패키지의 별도 확인

새로 패키징한 엔진의 첫 모델 검증 각 1회에서는 생성 전체 **14.583초**(모델 로드1.821초·입력 준비1.418초·추론3.222초), 임베딩은 정리 전 전체 **7.537초**(프로세스 시작·모델/문맥 준비7.167초·계산/응답0.076초)였다. 출력 ID·벡터는 개발 환경과 동일했다. 신규 패키지 실행·파일 캐시·라이브러리 초기화의 영향을 통제하지 않은 **단일 실행**이므로 설치 앱의 반복 지연이나 전후 향상으로 해석하지 않는다. 패키징된 worker의 시작 비용도 다음 측정 대상이다.

### 계측 경계

- 전사: 자산 검증, 음성 준비, 전사 프로세스 왕복, 결과 파싱을 구분한다. `-np`가 내부 시간을 숨기므로 Whisper의 모델 로드/인코딩/디코딩은 별도로 확인하지 못했다. 전사 스케줄러 대기는 이 함수의 시간에 포함되지 않는다.
- 생성: 모델 잠금 대기, 확정 전사 대기, 자산 준비, worker 왕복, 전체를 구분한다. worker 내부의 모델 로드·입력 준비·추론은 **worker 왕복에 포함**되므로 둘을 합산하지 않는다. 라이브러리 import·IPC·종료 시간은 worker 내부 세 항목 외에도 존재한다.
- 임베딩: ready 응답까지는 프로세스 시작·라이브러리·모델·문맥 준비를 포함한다. 이후 시간은 입력 전송·토큰화·추론·벡터 검사를 포함한다. `total_before_cleanup_ms`는 종료 정리 전이며, 실험의 `wall_with_cleanup_ms`는 정리까지 포함한다.
- 이번 호출은 직렬이어서 자원 대기가 거의 없다. 계측 필드의 존재가 동시 실행 적체 시험을 의미하지 않는다.

## 재현

[측정 도구](../experiments/measure_local_stages.py)는 기존 로컬 자료만 읽는다. manifest의 `clips`에는 `path`, `sha256`, `group`, `reference`가 필요하다. 정답·전사·응답을 포함하는 출력은 비공개 위치에만 저장한다. 새 출력 파일을 지정한다.

```sh
.venv-macos/bin/python experiments/measure_local_stages.py \
  --runtime /absolute/path/to/prepared-runtime \
  --engine /absolute/path/to/bundled-engine/engines \
  --manifest /private/path/to/fixed-manifest.json \
  --output /private/path/to/before.json

# 모델 입력 파일을 유지해 전후 생성·임베딩 입력을 고정한다.
# 코드 변경 후 새 after.json으로 같은 명령을 반복한다.

# 재변환과 재사용만 교차 비교한다. 생성·임베딩은 실행하지 않는다.
.venv-macos/bin/python experiments/measure_local_stages.py --pcm-pairs \
  --runtime /absolute/path/to/prepared-runtime \
  --engine /absolute/path/to/bundled-engine/engines \
  --manifest /private/path/to/fixed-manifest.json \
  --output /private/path/to/paired.json
```

## 다음 우선순위

임베딩은 짧은 입력 계산보다 시작·모델 준비가 더 오래 걸린다. 다음에는 색인 작업 안에서 worker를 재사용하는 방식과 전사·생성의 메모리 경쟁을 함께 측정해야 한다. 무조건 모델을 상주시켜 지연을 해결했다고 간주하지 않는다. 전사의 큰 지연 개선은 인식 프로세스와 모델 초기화를 별도 계측한 뒤 판단해야 한다.

## 회귀·설치·보존 확인

- 백엔드 **499개 실행, 오류 없음, 선택 실행5개 제외**. 최초 제한 환경의 로컬 포트 오류2건은 권한 환경에서 다시 확인했고 전체도 재실행했다.
- PCM 재사용·다른 형식·잘린 파일, 시간 수집, PDF 캐시의 문서 버전·페이지 범위·원본 변경, 새 렌더링 후 원본 재검사를 검사했다.
- 엔진 패키지 **7,826개 파일의 SHA256**과 self-check·서명 검증을 통과했다.
- 복사 보관함에서 새 내장 엔진을 실행해 파일 연결 전사 완료, 동일 생성 ID·임베딩, 미저장 메모·실제 획 데이터의 프로세스 재시작 복구를 확인했다. 기존 페이지 수정 이력31개도 동일했다. 이는 실제 앱을 필기 중 강제 종료한 새 시험과는 구분한다.
- **Solasi 0.3.14/build24**를 설치하고 실제 창에서 기존 PDF·메모·파란 펜·부분 삭제된 분홍 형광펜을 확인했다. 이전 강제 종료 시험의 복구 메모와 남아 있는 미저장 초안 안내도 유지됐다.
- 업데이트 전후 기존 보관함 **43개 테이블·원음6개 파일의 해시가 모두 동일**, SQLite 무결성 정상. 원본·이전 인식문·수정 이력·필기 초안을 삭제하거나 이행하지 않았다.
- 이번 회차는 직렬 성능 비교와 복구 회귀 확인이다. 새 장시간 마이크 녹음·실제 절전·필기 중 강제 종료는 재실행하지 않았다. 다른 Mac·Windows·깨끗한 설치 환경도 포함하지 않는다.
