# Mac 필기 adapter 분리 검증

2026-10-27 · 검증 대상: `9e8ab0d`의 결합 경로와 이미지 생성·인식 분리 경로.

이번 변경은 인식 정확도 향상 기능이 아니다. 기존 Mac의 입력·결과와 승인·검색 계약을 유지하며 다른 OS 구현을 연결할 경계를 분리했다. 새 모델·외부 API·DB 마이그레이션은 사용하지 않았다.

## 실제 이미지·Vision 대조

변경 전 Swift 소스를 별도 컴파일해 기준을 만들었다. 같은 입력으로 분리 경로를 실행하고 PNG 크기·RGBA 픽셀 SHA256 및 전체 인식 JSON을 비교했다.

| 입력 | 출력 크기 | 인식 영역 | 픽셀 일치 | 전체 Vision JSON 일치 |
| --- | --- | ---: | --- | --- |
| pen 획 | 360×240 | 0 | 일치 | 일치 |
| 실제 혼합 노트 사진 | 2400×1500 | 78 | 일치 | 일치 |
| 같은 사진과 pen 합성 | 2400×1500 | 77 | 일치 | 일치 |
| 실제 필기 PDF | 1695×2400 | 41 | 일치 | 일치 |

문장·bbox·후보 점수·revision·languages·engine·`/page`를 포함한 JSON 전체가 일치했다. 이 네 조건의 결과이며 모든 문서에 대한 보장은 아니다. Swift 렌더링 검사는 별도로 dot·위아래 방향·압력·형광펜 제외·원본 합성·잘못된 획 거절을 확인했다.

## 설치된 로컬 모델 대조

같은 실제 혼합 노트 `mixed-cdf.jpg`에 설치된 Qwen3.5 4B와 Gemma 4 12B를 한 번에 하나씩 실행했다. 최종 이미지의 크기·RGBA 픽셀, 메시지·모델·출력 상한과 결과를 대조했다.

| 모델 | 최종 이미지·메시지·옵션 | 실제 결과(usage 제외) | metadata |
| --- | --- | --- | --- |
| Qwen3.5 4B | 일치 | 일치 | digest·literal-v2/page·잘림 경고·stop 유지 |
| Gemma 4 12B | 일치 | 일치 | digest·literal-v2/page·잘림 경고·stop 유지 |

Qwen은 변경 전후 Python 조합 경로를 직접 실행했다. Gemma는 변경 전 실제 모델 결과를 보존했고, 분리 경로에서 다시 실제 모델을 실행했다. 입력 대조에는 기존 전처리의 재생 실행도 사용했다. Gemma 재시도에서는 같은 Swift 소스의 컴파일된 helper를 생성기·진단 접점에 연결했다. 정확도 점수나 성능 향상으로 해석하지 않는다. 실행 시간에 의존하는 usage는 동일성 판단에서 제외했다.

첫 Gemma 비교 도중 스왑이 약 11.6GiB까지 증가하고 디스크 여유가 약 272MiB로 줄었다. 변경 전 추론은 끝났으나 새 경로의 Vision 진단이 Foundation 오류로 실패했다. 소유 프로세스 종료를 시도했을 때는 이미 종료된 상태였다. 현재 앱·모델·사용자 캐시는 지우지 않았고 이번 시험이 새로 만든 캐시만 정리했다. 이후 스왑이 줄고 공간이 회복된 상태에서 빌드와 Gemma 재비교를 순차 완료했다. 이 기록은 자원 압박의 원인을 모델이나 새 코드 하나로 확정하지 않는다.

## 실제 Mac 실행 경로

실제 사용자 보관함과 분리한 검증 보관함을 사용했다. 새로 frozen 빌드한 제품 작업 엔진, 제품 `WorkerBridge`·`AppResources`, 빌드한 React 화면을 AppKit/WKWebView 검증 창에서 실행했다. 웹 브라우저 서버나 모의 OCR로 대체하지 않았다. 화면 조작은 검증 fixture의 DOM 이벤트로 실행했고, 백엔드 요청은 실제 native bridge를 통과했다.

1. 실제 혼합 노트와 저장된 pen 획·페이지 메모를 열고 Vision 버튼으로 인식했다. **수동 인식 job 완료**를 기다린 결과에 11개 영역과 `apple-vision-accurate-v3/bounds-v2/page`가 있었다.
2. 승인 전에는 해당 인식문이 검색되지 않았다.
3. 화면의 인식문을 수정하고 native 초안 저장 ACK를 확인했다. 창과 작업 엔진을 종료한 뒤 새로 실행해 수정문을 복구했다.
4. 화면의 승인 버튼으로 확인한 문장이 검색에 포함됐다.
5. 기존 메모와 획이 보존된 것을 비교한 뒤 검증 페이지의 획을 제거했다. 승인한 인식문은 현재 검색에서 제외됐다.
6. 과거 출처 열기로 당시 확인한 문장을 읽었고, DB의 이전 페이지 버전에 원래 획이 남아 있음을 대조했다.

검증 보관함에는 임베딩 모델을 준비하지 않아 위 실제 검색은 **키워드 검색**이다. 의미 검색·색인 관련 기존 회귀 검사는 통과했지만 이번 Mac 실행에서 임베딩 추론을 새로 측정하지 않았다. 현재 설치된 사용자 Solasi는 교체하지 않았고 실제 기록·원음·필기·초안은 검증 대상 데이터로 수정하지 않았다.

초기 검증 fixture에는 원본 ref가 빠진 페이지 metadata와 인식 job 완료 전에 기존 자동 후보를 잡는 문제가 있었다. fixture를 수정하고 새 격리 보관함에서 두 단계를 다시 통과시켰다. 초기 실패를 제품 회귀로 기록하거나 성공 실행으로 합산하지 않았다. 이번 재실행은 정상 종료 후 복구이며 새 강제 종료·절전 시험은 아니다.

## 자동 검사·배포 포함

- Python 전체: **679개 중 674개 통과, 선택 실행 5개 생략**. 생략은 별도 fixture 환경변수가 필요한 임베딩 1개·Gemma 통합 1개·실제 ASR 3개다. 위 실제 Qwen/Gemma 비교는 별도로 실행했다.
- 처음 제한된 실행에서 포트를 여는 두 검사가 권한 오류로 실패했다. 로컬 포트가 허용되는 실행에서 같은 전체 검사를 다시 통과시켰다.
- 프런트엔드: **104개 통과**, TypeScript 검사·Vite 빌드 통과.
- Mac helper 실제 컴파일·실행 검사 4개 통과(전체 Python 검사에도 포함).
- 비Mac 주입·이미지 전용 모델·실패·취소·승인·현재 검색 제외·과거 출처·`/page` 중복 방지 검사 6개 통과.
- 기존 `freeze_macos_engine.py`로 새 엔진을 빌드했다. frozen 아카이브에서 `lecture_study.handwriting`와 `lecture_study.handwriting_macos` 포함을 확인했고 `--self-check`가 frozen=true를 반환했다. 이 엔진으로 위 Mac 검증을 수행했다.
- 독립 구현 검토에서 수정이 필요한 P0–P2 회귀는 발견되지 않았다. 권고한 인식 대기 중 취소·임시 PNG 삭제·DB 보존 검사도 추가해 통과했다.

세부 로그·PNG·원문 응답은 로컬 검증 폴더에 보관하고 공개 저장소에는 원본 노트·개인 보관함·검증 화면·모델 가중치를 추가하지 않는다. 요약된 검증 결과는 [JSON](verification/handwriting-adapters-20261027.json)에 있다.

## 확장 범위와 제한

대체 생성기·인식기를 둘 다 주입하면 Mac helper를 실행하지 않는 계약을 win32/Linux 모의 환경에서 검증했다. 실제 Windows·Android 앱, 해당 플랫폼의 PNG 생성기와 OCR/모델 실행은 구현·검증하지 않았다. 연결 계약·사용 예제는 [개발 안내](handwriting-adapters.md)에 있다.

빈 대체 입력의 engine은 `empty-ink`로 구별한다. 이는 실행하지 않은 Apple 엔진을 표시하지 않기 위한 결정이며 기본 Mac의 빈 입력 표시는 유지했다. 다른 OS에서 진단을 생략하면 잘림 여부를 확인된 false로 만들지 않는다.
