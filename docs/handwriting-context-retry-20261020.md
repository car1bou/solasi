# 전체 문맥을 유지한 선택 재인식 비교 · 2026-10-20

## 목적과 변경 범위

[문장·수식 분리 실험](handwriting-regions-20261020.md)의 같은 12개 실제 노트를 사용한다. 전체 원본을 모델 입력에 유지하면서 의심 부분만 재인식하면 부호 누락·잘린 문장 추측을 줄일 수 있는지 비교한다. 새 필체·새 음성을 추가한 시험이나 held-out 성능 평가가 아니다. 이전 인식문·원본·승인 상태·과거 출처는 바꾸지 않는다.

사용자가 승인한 비교는 다음 두 조건이다.

1. **locate:** 전체 원본 이미지와 확인할 위치의 픽셀 xyxy를 전달한다.
2. **context:** 같은 전체 원본과 위치에 더해, 해당 위치 위아래의 문맥을 포함한 확대 이미지를 두 번째 입력으로 전달한다.

출력은 해당 범위와 겹치는 문장·수식의 후보만 요청한다. 최초 인식문이나 평가 정답은 프롬프트에 넣지 않는다. 수학 지식에 따른 보정·추측 완성·다른 응답의 AI 재작성 병합을 하지 않는다. 한 조건에서 한 목표에 추가 인식은 한 번이다. 여러 실험 조건을 순차 비교하는 횟수를 제품의 자동 반복 횟수와 혼동하지 않는다.

## 입력과 사전 고정

- **수동 위치 조건:** 기존에 고정한 정답 영역에서 17개를 선택한다. 전체 12개 노트를 포함하며 선분 정의·CDF·조건부확률·Jensen·λ-system은 일부 오류와 대조 영역을 따로 비교한다. 사람 지정 조건이며 자동 검출 성능이 아니다.
- **자동 조건:** 기존 전체 Qwen 출력과 Apple Vision의 인식 항목만 사용해 11개 노트에서 각 1개를 선택한다. Kjk 완성 문장은 이 규칙에서 선택되지 않았다. 이전 수동 정답 좌표·이전 dots/PP 좌표를 자동 선택의 보정값으로 사용하지 않는다.

수동 위치 manifest SHA256은 `835d4e260d7528c83d7f1a8bb5b3247b122136be027629c1b40abd8183a2782f`, 자동 위치 manifest는 `e154b69a66ec9e2a8364a7ab76d37bdf96b36c23d9818a7c5701e1aba3056380`이다. 원본 SHA를 매번 검사한다. 모든 자료는 알려진 개발 표본이며, 이전 오류를 안 상태에서 설계한 비교라는 한계를 유지한다.

자동 규칙은 Vision 항목 문자열을 기존 Qwen의 각 출력 줄과 비교해 가장 작은 공백 제거 편집거리 비율을 구한다. 비율 0.35 이상이거나 `edge_touching`이면 후보이며, 비율 + 가장자리 0.1 가산으로 우선순위 하나를 선택한다. 이는 이번 비교에서 고정한 휴리스틱이지 정확도 확률이 아니다. 선택한 Vision bbox의 y 범위를 원본 픽셀로 바깥 반올림하고 상하 10%(최소 2px)를 붙여 원본 폭 전체의 띠를 만든다. 잘못된 범위는 거절한다. 검출 score를 정확도나 두 번째 후보와의 차이로 해석하지 않는다.

수식의 분자·분모가 따로 검출되거나 Vision이 `=` 하나만 반환하면 선택 띠가 수식 전체를 포함하지 않을 수 있다. 전체 원본을 함께 주더라도 이를 성공한 위치 선정으로 세지 않는다. 자동 목표의 원문·모호성은 새 자동 재인식 전에 별도로 기록한다.

## 실제 모델 입력

설치된 Qwen3.5 4B를 로컬 `DirectModels` 경로로 사용한다. 원본 전체를 첫 이미지로 보존하고 기존과 같은 3배 확대·긴 변 최대 2048을 적용한다. locate 좌표는 이 첫 입력의 실제 크기로 환산한다. context의 두 번째 이미지는 원본 폭 전체와 목표 위아래 목표 높이의 절반(최소 8px)을 포함한다. 원본 경계 밖을 채우지 않는다.

`mlx_direct`가 두 이미지를 순서대로 같은 user 메시지에 연결하는 것을 확인했다. 별도의 사진 두 장으로 해석하지 않도록 지시하고, 확대에 함께 들어온 주변 줄은 추가 출력하지 않도록 요청한다. system 지시는 기존 literal-v2이며 출력 상한 512, 문맥 상한 8192, greedy를 사용한다. 첫 실험의 출력 상한 2048과 다르므로 토큰 상한 도달 여부를 별도로 확인해야 한다. 첫 응답의 오답을 다시 쓰게 하는 텍스트 정정 실험은 아니다.

실행 설정에는 manifest·실험 코드·엔진 코드 SHA와 설치 모델 digest를 남긴다. 결과·정답·이미지는 `.local-state/ocr-context-retry-20261020/`에 보존하며 Git에는 원본 노트와 모델을 넣지 않는다.

## 재현

`experiments/retry_handwriting.py`는 제품 데이터베이스에 쓰지 않는 비교 CLI다. manifest의 각 case는 `id`, 원본 절대 경로 `image`, `source_sha256`, 원본 픽셀 정수 `bbox`를 가진다. 평가용 `reference`는 있어도 모델 메시지에 쓰지 않는다.

```bash
HF_HUB_OFFLINE=1 TRANSFORMERS_OFFLINE=1 .venv/bin/python experiments/retry_handwriting.py \
  --manifest /absolute/path/frozen-targets.json \
  --runtime /absolute/path/verified-local-runtime \
  --output /absolute/path/fresh-context-run \
  --mode context
```

`--mode locate`는 같은 위치에서 전체 원본만 입력한다. 출력 문장이 길거나 더 자연스럽다는 이유로 원래 결과보다 정확하다고 채택하지 않는다. 부호·원문 밖 완성·목표 위치·범위 밖 내용 유입을 각각 대조한다.

## 수동 위치 조건 결과

locate 17개와 context 17개가 모두 `stop`으로 종료했다. 알려진 정답 위치를 지정해도 전체 Qwen보다 안전하게 좋아지지 않았다.

| 항목 | locate | context |
|---|---|---|
| 각도·분수·미분 α/β·minus·Big O | 보존 | 보존 |
| CDF 극한 방향·단조성 ≤ | 보존하나 다른 조건도 출력 | 페이지 전체 출력 |
| 선분 윗줄·포함관계 ⊂ | 기존 누락·C 오독 유지 | 기존 누락·C 오독 유지 |
| 조건부확률의 ∩ | 전체 baseline에는 있던 ∩가 `P(AB)`로 사라짐 | ∩는 유지하나 페이지 전체 출력 |
| λ의 서로소 조건 | ∩·if 복구, 앞의 합집합 줄도 출력 | ∩·if 복구, 전체 페이지도 출력 |
| Haonly 일반 한국어 | 형상→형성 오독 유지 | 기존 오독에 더해 `개발 과정→개발 라칭` 회귀 |

네 개 수식 control은 baseline에서도 맞았으므로 보존을 새로운 개선으로 계산하지 않는다. λ의 국소 부호 복구는 실제 개선 요소지만, 범위 밖 내용과 함께 출력돼 부분 수정에 바로 쓸 수 없다. 수학적 약기로 해석할 수 있는 `AB`도 literal의 ∩ 기호를 보존한 결과로 계산하지 않는다.

부분 영역을 지정한 10개에서 context가 지정 내용만 출력한 것은 Jensen 부등식 1개였다. 나머지는 앞뒤 줄·전체 페이지·다른 위치를 출력했다. CDF 잘린 한국어 행을 요청한 locate는 위쪽 `F(x)=P(X≤x)`만 반환했고, Jensen 제목 요청은 오른쪽 주석만 반환했다. context의 Jensen 제목 응답은 제목을 누락하고 prompt의 `[0, 0, 492, 144]`까지 출력했다. 좌표는 원문 글자가 아니라 지시문의 메타데이터이므로 인식문에 섞이면 안 된다.

범위 밖의 **원본에 실제 존재하는 내용**을 출력한 것은 원문 밖 내용을 발명한 환각과 구별한다. 그래도 국소 후보의 범위를 지키지 못한 실패다. 잘린 Kjk·Haonly에서 밖의 `한다`·`관리`를 새로 완성하지 않았지만 baseline도 같았고, 불필요한 `=`와 한국어 오독은 남았다. CDF의 `되`는 경계에 보이는 부분 글리프이며 원문 밖 단어 전체를 만든 사례로 세지 않는다. `[판독 불가]` 표시가 안정적으로 작동했다는 근거도 확보하지 못했다.

## 자동 위치의 평가 범위

자동 위치 11개에 대한 원문·모호성은 새 자동 재인식 전에 별도로 기록하고 원본 대조 후 고정했다. 최종 SHA256은 `d9323afd565a37a8873ddd6ca7bd09a57900daa858d28ae9590d32c046ca6f9c`. 선택 규칙에 이 정답을 전달하지 않는다.

11개 중 각도·분수·미분·조건부확률의 4개 띠는 완전한 식이 아니거나 이웃 줄 획과 겹친다. 전체 원본을 보고 겹친 완전한 식을 읽는 것은 허용하지만, 이 경우를 정확한 수식 검출로 계산하지 않는다. Jensen 상단 띠는 제목과 오른쪽 주석 둘 다 포함하므로 둘 다 평가 대상이다.

자동 locate 11개에서는 목표 품질·범위가 함께 개선된 사례가 없었다. CDF 첫 극한을 선택했지만 위쪽 정의 식을 반환했고, Jensen은 제목과 ⇔를 빼고 주석만 반환했다. 조건부확률 식은 범위가 맞더라도 ∩를 생략한 `P(AB)`를 출력했다. 나머지 여러 응답도 선택되지 않은 제목·식·전체 페이지를 포함했다.

자동 λ의 범위 밖 출력에서 서로소 조건의 ∩가 복구돼도, 자동 선택 대상은 첫 조건 `if i) Ω∈L.`이므로 목표 개선으로 세지 않는다. 선택되지 않은 CDF 잘림·단조성·포함관계·λ 서로소 조건의 변화나 개선을 주장하지 않는다. 전체 baseline의 CDF 단조성은 이미 정확했다. 불일치 신호는 어떤 출력이 맞는지 판정하지 못하며, Vision만 틀린 정확한 Qwen 구간도 재시도 대상으로 잡을 수 있다.

## 자동 context 최종 결과

11개 모두 `stop`으로 종료했지만 자동 선택된 대상의 품질과 범위가 함께 개선된 사례는 없었다.

- CDF는 선택한 첫 극한을 포함하게 됐지만 페이지 전체를 출력했다. 첫 극한은 전체 baseline에서도 맞았다.
- 조건부확률의 ∩는 locate보다 좋아졌지만 제목·설명·포함관계 문장까지 출력했다. 전체 baseline도 ∩는 이미 보존했다.
- Haonly에는 `개발 과정→개발 라징`이라는 새 오독이 생겼다. 수동 context의 `라칭`과는 다른 출력이다. 기존 형상→형성 오독도 남았다.
- Jensen은 `[0, 0, 1275, 135]`라는 지시문 좌표만 출력하고 제목·주석의 문자를 모두 누락했다.
- λ는 첫 조건 대신 전체 정의와 조건을 출력했다. 범위 밖 서로소 조건의 복구는 목표의 개선으로 계산하지 않는다.
- 각도·분수·미분은 원래 맞던 부호를 유지했으나 목표 밖의 줄도 출력했다.

모두 첫 인식 이후의 **추가 처리 비용**이며 최초 인식 시간은 포함하지 않는다. Qwen 요청별 worker·자산 준비·모델 로드를 포함한 wall time이다. 기존 Vision 결과를 위치 선정에 재사용했으므로 새 Vision 비용은 포함하지 않는다. 같은 조건에서 한 모델씩 실행했고, 두 모드 간 같은 위치를 사용했다. 작은 개발 표본의 단회 관측이며 일반 속도 보장은 아니다.

네 조건 총 56개 모두 정상 종료했다. 가장 긴 출력도 140토큰으로 512 상한에 이르지 않았다. 따라서 이번 잘림·누락을 토큰 상한 종료로 설명할 근거는 없다. MLX 0.32.4·MLX VLM 0.7.8·Transformers 5.20.0·Pillow 12.3.0 환경을 별도 receipt로 기록했다.

## 적용 결정

**이 두 재인식 방식을 제품에 적용하지 않는다.** 전체 문맥이 수식 분리의 일부 회귀를 피하고 λ의 부호를 복구한 경우는 있지만, 기존 전체 인식보다 안전한 자동 대상 개선은 확인하지 못했다. 어느 결과가 좋아졌는지 정답 없이 판정할 방법도 이번 비교에서 확보하지 못했다. 범위 밖 내용과 지시문 좌표가 섞인 응답을 자동 필터로 잘라 올바른 수정처럼 제시하지 않는다.

반영한 것은 제품 데이터를 변경하지 않는 비교 CLI·검사와 결과 문서다. 기존 인식·사용자 승인·검색 편입·필기 복구·과거 출처는 변경하지 않는다. UI UX Pro Max의 오류 회복 원칙을 적용해 인식 품질, 위치 선정, 후보 적용을 구분했으며 검출 수치나 정상 종료를 정확도처럼 표시하는 UI를 추가하지 않았다. 새 다운로드와 설치 앱 교체도 수행하지 않았다.

강의자료를 활용한 고유명사 개선은 [별도 설계](material-guided-asr-design-20261020.md)에 정리했다. 현재 Whisper 힌트 경로, 설치된 Qwen hotwords API, 출처 현재성 검사 공백, 동일 원음의 효과·오삽입 비교 계획을 구분한다. 이번에 음성 효과를 검증하거나 ASR 입력을 변경한 기능으로 소개하지 않는다.
