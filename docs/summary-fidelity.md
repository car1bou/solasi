## 녹음 종료 후 처리 기본

새 녹음은 `after_stop`이 기본이다. 원음·PCM 저장 확인은 즉시 하고 전사 계획·ASR 호출은 종료 후 시작한다. **전사 방식 → 실시간 전사**를 녹음 전에 고르면 기존 잠정/확정 경로를 사용한다. 녹음 도중 선택은 잠긴다. 요약·메모 보강은 확정 전사가 준비된 뒤 사용자가 실행한다.

- 자동 복구의 새 구간은 같은 처리 방식·capture 그룹을 이어받는다. 이전 원음과 누락 표시를 유지하며 마지막 구간 종료 후 함께 전사한다. 장치 sample rate가 달라도 별도 구간으로 허용한다.
- 탭/연결이 예기치 않게 종료되면 받은 원음을 중단 상태로 마감한다. 30초 동안 복구 구간을 기다린다. 같은 그룹에 활성 녹음이 있으면 기다리고 복구하지 못하면 저장된 부분을 처리한다. 앱 재시작은 보존된 후처리를 이어간다. 취소·실패한 작업은 직접 재시도한다.
- 기존 행은 realtime/해제 상태로 이관한다. 전사 ID·수정·출처·이전 답변은 재작성하지 않는다. 손상된 원음 하나 때문에 앱 전체 시작을 막지 않는다.
- 종료 후 처리만으로 정확도가 높아지는 것은 아니다. 모델·최대30초 확정 구간·VAD·최종 디코딩 설정은 유지하며 잠정 호출과 녹음 중 자원 경쟁을 줄인다. Whisper의 파일 전사도 내부적으로30초 창을 사용한다. [공식 README](https://github.com/openai/whisper#python-usage)

재현 예:

```sh
.venv/bin/python experiments/serve_long_recording_fixture.py /private/tmp/new-offline-check .local-state/runtime/conversation-20261014/s12m23f1-office.wav single qwen3.5:4b after-stop
```

출력 링크에서 엔진 연결·녹음 시작을 누른다. 공개 음원을 스피커 출력 없이 MediaStream으로 흘리고 실제 캡처/worklet/저장/Whisper/Ollama를 사용한다. 실제 마이크 공기 전달 경로 시험은 아니다. 파형 정렬을 별도로 검사한다.

## 강의와 회의의 차이

| 맥락 | 보존할 내용 | 표시 예 |
|---|---|---|
| 강의 | 개념의 주어, 명확한 가정·조건, 적용 범위, 예시·반례, 정정 | “마찰이 없다고 가정하면 …” → 조건. 명확한 전제라는 이유로 확인 경고를 붙이지 않는다. |
| 회의 | 제안, 검토, 확정 결정, 담당 후보·확정, 미결 | “김민수는 담당 후보” → 확정 담당자가 아니다. “제안을 검토한 뒤 이서연으로 확정”은 결정으로 보존한다. |
| 공통 | 직접 뒷받침하는 원문, 타인의 발언·기대·상상, 주어 관계 | 근거가 없는 해석은 원문 발췌와 해석 확인 필요 표시로 남긴다. |

`원문상 진술`은 녹음에서 실제 일이라고 진술했다는 분류다. 외부 사실 확인 결과가 아니다. 명확한 가정과 주어가 불명확한 해석도 서로 다르다.

## 처리 방식

1. 요청 시점의 원문 버전을 고정하고 기존 문맥·입력 예산으로 구간을 만든다. 긴 원문은 문장·최대320자 단위의 정확한 부분 문자열로 나눈다.
2. 구간 모델이 주어, 발언 성격, 제목·설명과 최대4개 직접 근거를 작성한다. 모델은 인용 문장을 새로 쓰지 않는다. 서버가 선택한 실제 원문 구절을 연결하고, 저장·캐시를 읽을 때도 원문 부분 문자열과 ID를 검사한다.
3. 주어가 직접 인용에 없거나 가정이 실제 사건으로 바뀐 징후, 회의의 명시적 미확정·담당 부정을 발견하면 해당 설명을 인근 원문 발췌로 대체한다. 같은 기록의 인근 전사는 최대2개씩·15초 이내에서 문맥을 보완한다. 처음 생성한 설명은 metadata에 보관한다.
4. 충분한 길이의 원문을 시간순 앞·중간·뒤로 나누고, 인용이 없는 범위는 원문 발췌로 남긴다. 빈 결과도 실제 내용이 있는 노트라면 그대로 사라지게 하지 않는다. 짧은 한 문장 작성 요청은 요청 동사·원문 대조 표현이 명확하고 명시적 주어·숫자·과거·부정 표현이 없는 경우에만 빈 결과를 허용한다. 이 요청 판정도 휴리스틱이며 모든 한국어 문장 의도를 증명하지 않는다.
5. 최종 모델은 기존 구간 항목의 ID만 선택한다. 주어·사건 상태·설명을 다시 쓰지 않는다. 선택 입력에는 제목·설명·주어·상태·구간 범위만 넣고, 보존된 인용과 긴 출처 ID를 중복 전달하지 않는다. 원문 인용은 서버가 그대로 유지한다.
6. 확인 필요 원문 발췌와 가정·조건·예시·기대·제안·결정·미결은 선택에서 제외되지 않도록 서버가 항상 보존한다. 나머지 일반 설명의 항목 예산은 기본 `max(6, 내용이 있는 구간 수 × 3)`이다. 일반 설명이 이 예산 안에 들면 별도 최종 모델 호출 없이 모든 항목을 보존한다. 각 구간의 앞·중간·뒤 근거가 선택되지 않으면 해당 선택만 최대1회 재시도한다. 그래도 빠지거나 선택 입력이 예산을 넘으면 해당 구간의 원래 항목을 함께 표시하고 불완전을 알린다. 모델·토크나이저 변경 오류는 예산 초과로 숨기지 않는다.
7. 화면과 Markdown에 주어·발언 성격·확인 필요·원문 구절을 남긴다. 원래 구간 요약과 실패 작업의 완료 구간도 열 수 있다.

정확한 인용은 해석이 원문에 함의된다는 증명이 아니다. 주어 이름이 맞아도 서술어·수치의 대상이 틀릴 수 있다. 길이와 위치로 나눈 범위 검사는 중요한 모든 사건의 의미 보존을 보장하지 않는다. 이 때문에 같은 실제 자료의 알려진 오류와 후반 사건을 별도로 대조한다.

## 검증 자료

같은 성인 한국어 인터뷰+실제 사무실 소음 파생 혼합과 같은 한국어 낭독의 기존 확정 Whisper 전사를 사용한다. 원음·전사 비교와 새 요약 실행은 구분한다. 이 자료는 실제 강의나 현장 회의 정답 자료가 아니며 인터뷰어의 전체 정답이 없어 전체 CER를 계산하지 않는다.

- 초기 인터뷰 실행 (로컬 검증 자료·공개본 미포함): 주어 칸에 제목을 쓰는 경향으로 대부분 원문 발췌가 되었고, 인용·메타데이터를 중복 전달한 선택 입력이 예산을 넘었다. 결과를 성공적인 요약 품질 개선으로 취급하지 않고 주어 지시·필드 순서와 선택 입력을 보완했다.
- 중단한 초기 낭독 실행 (로컬 검증 자료·공개본 미포함): 위 문제를 확인하고 완료 전에 명시적으로 중단했다. 완료 시간·실패율 비교에서 제외한다.
- 요약 UI 증거 (로컬 검증 자료·공개본 미포함): 작성 데이터·모델 대역으로 실제 UI/API/DB의 주어·발언 성격·후반 정정 발췌·원문 펼침을 확인했다. 실제 모델 품질 증거와 구분한다.

## 긴 브라우저 녹음 중단

중단 원인 증거 (로컬 검증 자료·공개본 미포함)는 서로 다른 두 사건을 나누어 보존한다.

- 이전 시험: 호스트의 녹음 탭 제거·렌더러 파괴 직후 연결이 종료됐다. 마지막 PCM부터 서버의 중단 처리까지81.571ms였고 최대 패킷 간격은1.669249초로15초 서버 idle 한도 미만이었다. 탭 제거를 요청한 주체, 수동/자동 여부, crash/OOM 원인은 확인되지 않았다.
- 이번 초기 재현: 첫 녹음의285.36초 원음은 남았지만 복구 녹음은0프레임이었다. 시험 도구가 매번 같은 재생용 AudioContext를 반환해 닫힌 객체로 worklet을 다시 준비한 결함을 확인했다. 재생은 MediaStreamDestination에 연결하고 실제 캡처는 별도 native AudioContext를 갖도록 수정했다.
- 이번 재현의 최대ACK5.8322초·telemetry 지연19.664초·호스트 지연 로그는 높은 부하를 보여 준다. 최초 watchdog 사유·최초 context close 요청자는 기록이 부족해 확정하지 않는다. 과거 탭 제거를 이번 사건 원인으로 재사용하지 않는다.
- 서버는 예상하지 못한 연결 종료의 불투명 녹음 ID·close code·reason 유무만 기록한다. 시험 도구는 socket/context/lifecycle과 최초 복구 상태 전이를 남긴다. 음성·토큰·reason 본문은 진단 로그에 추가하지 않는다. 페이지 파괴 시 마지막 telemetry가 저장되지 않을 가능성은 남는다.
