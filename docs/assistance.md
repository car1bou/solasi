# 메모 보강·요약 병합·질문 후보

2026-10-14. 원문과 확정 전사의 버전을 요청 시 고정한다. AI 결과는 검토할 초안이다.

기본 녹음은 종료 후 전사한다. 실시간 전사는 녹음 전에 선택한다. 녹음 시점에 저장한 메모는 전사가 완료되면 같은 시점의 확정 전사로 보강한다.

## 메모 보강

1. 녹음 중 노트를 저장하면 받은 원음의 시점을 함께 저장한다. 과거 노트는 **전사로 메모 보강 → 메모 시점**에 녹음의 초 위치를 입력한다.
2. 저장한 메모와 해당 시점 앞뒤 90초에 겹치는 가까운 확정 전사 최대 8개를 시간순으로 정렬해 보강안을 요청한다. 원래 메모의 추측을 사실로 승격하지 않도록 지시하고 확정 전사 인용을 검사한다.
3. 보강안을 수정하고 **확인하고 메모에 추가**를 누른다. 기존 텍스트 뒤에 보강문을 붙인 새 노트 버전을 만든다. 적용 전에 원본 노트가 바뀌면 거절한다. 같은 보강안을 반복 적용하지 않는다.

적용한 수정문을 확인된 결과·Markdown에 사용한다. 원래 AI 보강문은 metadata에 보관한다. 적용 요청을 기다리는 동안 편집기에 입력한 초안은 덮어쓰지 않는다. 녹음 시각을 알 수 없는 과거 노트에 생성 시각을 대신 넣지 않는다.

## 요약과 회의록 병합

2026-10-15 새 일반 요약은 주어·발언 성격·정확한 원문 구절을 보존하고 최종 단계에서 구간 항목만 선택한다. 강의의 명확한 가정·조건·예시는 그대로, 회의의 제안·결정·담당은 구분한다. 앞·중간·뒤 누락 재시도·발췌 표시와 실측은 [주어·가정 보존](summary-fidelity.md)을 따른다. 아래의 과거 모델 결과는 당시 경로의 기록이다.

- 새 요청은 시간순 원문을 문맥·실제 직렬화 입력 예산에 맞춰 묶고 완료한 구간을 병합한다. 반복을 줄이되 수치·날짜·부정·조건·제안·정정·미결과 수치의 대상·단위를 보존하도록 요청한다.
- 앱의 고정 Qwen4B MLX는 검증한 토크나이저를 사용하고 다른 모델은 byte 예산을 사용한다. 출력 예약·실제 출력 한도는 동일하다. 모델 변경 또는 입력 계산 불일치는 저장 전에 거절한다.
- 새 일반 요약의 **처리한 원문·시간 범위**는 최종 항목의 **실제 사용한 인용**과 별도로 보존한다. 최종 인용에 모든 원문 ID를 나열하는 조건은 완화하고, 없는 ID와 시각은 거절한다. 이전에 고정한 작업 정책은 유지한다.
- 전사·자료 구간은 최소 한 요약 항목을 요구한다. 작성 요청만 있는 메모 구간은 빈 결과를 보존할 수 있다. 회의록은 모든 원문 인용 및 결정·담당자·기한 검사를 유지하고, 명시적 담당 후보·미정·부정 표현을 확정 담당자로 지정하지 않는다.
- 모델 입력의 짧은 인용 기호는 저장 전에 원래 출처 ID로 복원한다. 본문에 섞인 임시 ID 목록은 원문에 같은 변수 표기가 없는 경우 제거하고 원래 생성문은 metadata에 남긴다. 구간·병합 결과를 DB에 보존하고 같은 작업 재시도에서 사용한다. 병합 입력·schema·인용 매핑의 digest가 바뀌면 해당 병합 결과를 재사용하지 않는다.
- 학습 화면의 **원래 구간 요약** 또는 실패한 작업의 **완료 구간 보기**로 완료한 문장과 인용을 연다. 일부 명확한 좌우·기간/온도 불일치는 경고로 표시한다. 인용 ID 통과는 의미·정정의 보존을 보장하지 않는다. [현재 실측과 내용 대조](conversation-robustness.md).

## 질문 후보

- 기본은 꺼짐. **로컬 자동 추출**을 켜면 최근 120초의 확정 전사 최대 16개를 사용한다. 최소 30초 간격이며 같은 기록에 활성 후보 작업은 하나만 허용한다. 동일 근거·모델의 반복 요청은 기존 작업을 반환한다.
- 확정 전사가 밀리면 새 로컬 후보·보강·답변 요청은 기다린다. 이미 실행 중인 로컬 생성은 계속한다.
- API는 **후보 추출**을 직접 누를 때만 전사를 보낸다. 자동 API 추출은 거절한다. 답변은 카드의 **답변 실행**을 눌러 별도로 요청한다.
- 원문과 정확히 일치하는 인용만 허용하며 후보가 없을 수도 있다. 질문은 수정·고정·무시할 수 있다. 답변을 실행한 질문 문구는 고정해 제목과 실제 답변 요청이 어긋나지 않게 한다.
- 고정 카드를 먼저 표시한다. 최근 20개를 넘으면 **나머지 질문 보기**로 연다. 전사를 수정했을 때 손대지 않은 옛 후보는 숨기고, 고정·편집·답변한 후보는 당시 근거 버전과 함께 보존한다.

## 실제 로컬 모델 결과

전체 기능 실행 JSON (로컬 검증 자료·공개본 미포함)은 같은 작성 전사 네 구간과 메모를 Qwen3.5 4B·Gemma4 E2B에 제공한 결과다. 20초 PCM은 시점 등록용이며 이 시험에서 ASR는 실행하지 않았다. 실제 음성 정확도·장기 동시 실행은 각각 [모델 비교](new-local-models.md)와 [장기 녹음](long-human-recording.md)을 따른다.

| 항목 | Qwen3.5 4B | Gemma4 E2B |
|---|---|---|
| 보강안 구조·전사 인용 / 시간 | 통과 / 15.904초 | 통과 / 16.224초 |
| 질문 후보 원문 인용 / 시간 | 거절 / 24.037초 | 통과 / 15.776초 |
| 전체 요약·병합 구조 / 시간 | 통과 / 137.414초 | 통과 / 40.609초 |
| 실패 뒤 재시도 | 두 구간 캐시를 유지하고 전체5구간·병합1단계 완료 | 동일 |
| 보강안 명시 적용 | 원래v1 보존·새v2 | 동일 |

요약 시간에는 앞서 완료한 두 구간과 실패 주입 뒤 재시도를 포함한다. 출력 길이·내용이 달라 모델의 고정 속도 차이로 일반화하지 않는다. 처음 실행의 실패도 원자료 (로컬 검증 자료·공개본 미포함)에 보존했다. 구간 요약에서 요청문을 원문처럼 요약한 사례가 있어, 동일한 지시문을 입력 분할 예산과 실제 생성 양쪽에 반영하고 원문의 수치·정정을 보존하도록 보완했다.

수동 대조에서는 Gemma의 일정 구간이 ‘월요일 세 대·검토 중·미확정·담당 미정’을 보존했다. 그러나 메모 구간에는 요청 지시를 옮긴 문장이 여전히 있었고 후보 일부는 질문 형태로 바뀌지 않았다. Qwen도 정정 구간을 남겼지만 뮤텍스를 ‘뮭드/뭘드/뭘스’로 바꾸거나 노트에 없는 정리 계획을 덧붙였다. Qwen 후보의 인용문 변형은 저장 전에 거절됐다. 같은 단어가 정확히 보존되는지까지 schema만으로 확인할 수 없다.

반복 감소·의미 정확도·질문 유용성을 통과했다고 판정하지 않는다. 자동 원문 덮어쓰기·자동 답변·기본 모델 교체를 하지 않으며, 원래 구간·출처와 편집 가능한 초안을 보여 준다. 인용 검증 실패는 재시도할 수 있다. 실제 장시간 강의·회의 정답과 대조한 평가는 남아 있다.

## 검증 구분

UI 확인 자료 (로컬 검증 자료·공개본 미포함)는 작성한 검증 데이터와 모델 대역으로 실제 브라우저/API/DB를 확인한 결과다. 메모 적용을 5초 지연시킨 중간 편집, 원본·적용문 보존, 기본 꺼짐, 질문 수정·고정·무시·명시 답변, 원래 구간 요약 표시를 확인했다. 실제 모델의 생성 품질과 구분한다.

질문 카드 편집·고정·명시 답변 (로컬 검증 자료·공개본 미포함)

재현은 기존 개발 환경에서 실행한다. 임시 폴더는 새 이름을 사용한다.

```sh
npm --prefix frontend run build
.venv/bin/python experiments/serve_assistance_fixture.py /tmp/assistance-ui-check
.venv/bin/python -m unittest tests.test_assistance tests.test_candidate_api tests.test_merging -q
```

UI fixture는 출력한 로컬 URL에서 동작하며 외부 API·마이크·실제 모델을 사용하지 않는다. 실제 메모에는 모델 대역을 연결하지 않는다.
