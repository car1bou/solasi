# 실제 강의자료·연속 발화의 용어 힌트 비교

2026-10-20 · Apple M4·16GiB·macOS 27.0.1의 기존 Whisper large-v3-turbo와 Qwen3-ASR-1.7B-4bit를 사용한 로컬 진단이다. 설치 앱·실제 보관함·모델 파일을 바꾸지 않고 실험 폴더에서 실행했다. 앞선 [짧은 음성 비교](material-guided-asr-20261020.md)의 15개 파일을 재사용하지 않는다.

## 생활 소음 조건

두 강연은 원본·사무실·식당의 세 조건으로 비교한다. 환경음은 실제 [DEMAND OOFFICE/PCAFETER 녹음](https://zenodo.org/records/1227121)의 채널 8이며, 같은 시작 위치에서 평가 구간만큼 사용한다. 원본 강연과 환경음의 RMS로 10dB를 맞추고, 필요한 경우 두 신호를 같은 비율로 낮춰 clipping을 막는다. 새 혼합 네 파일의 clipping은 0이다.

추가로 서울코퍼스 56.789초 응답의 기존 식당 혼합본을 함께 비교한다. 이 파일은 원래 인터뷰 전체의 RMS로 혼합했으므로 잘라낸 구간의 SNR이 정확히 10dB라는 주장은 하지 않는다.

이들은 **실제 환경음을 더한 파생 혼합 시험**이다. 한국어 강연을 실제 사무실·식당에서 새로 녹음한 자료가 아니며, 환경음의 외국어 배경 대화를 포함할 수 있다. SIL 대조군은 혼합하지 않은 원본만 사용한다. 결과는 주 대상 한국어 발화의 정확도로 해석한다.

전체는 **13개 파일 조건·870.7094375초**이다. 독립된 원본 구간은 강연 2개·인터뷰 3개·비발화 3개, 합계 8개이며 원본 기준 총 352.0465625초다. 소음 변형을 독립 발화로 세지 않는다. 원음·전사·PDF는 공개 저장소에 넣지 않는다. 행사 자막은 CC BY-SA 4.0, 영상 메타데이터는 CC BY, 서울코퍼스는 CC BY-NC 2.0이다. DEMAND의 배포 메타데이터와 제작자 PDF의 조건 차이는 기존과 같이 보수적으로 취급해 원음·혼합본을 재배포하지 않는다.

## 정답을 힌트로 넘기지 않는 절차

1. 행사 원본 슬라이드에서만 용어·페이지·정확한 근거를 먼저 기록한다. 그 시점에는 한국어 SRT를 받거나 모델을 실행하지 않았다.
2. LAMP는 `Wordpress, Ubuntu, Nginx, MariaDB, PHP, WSL2, Chmod, Chown`, WSL은 `WSL, SDK, Win32, COM, Docker, Moby, Busybox, Alpine, CoInitializeSecurity, MSIX, APPX, GitHub`를 고정한다. 발화에 등장하지 않는 자료 용어도 사후 제거하지 않는다.
3. 강연마다 처음 60초 이후에 시작하고 180초 이내에 끝나는 **완전한 자막 행**들을 선택한다. 내용·인식 성공 여부로 구간을 고르지 않는다. 같은 강연 전체에 같은 용어 목록을 사용한다.
4. 없음 / 해당 슬라이드 용어 / 무관 용어를 엔진별로 비교한다. 무관 용어는 `다익스트라, 자그로스산맥, 세풀베다`다. 인터뷰와 SIL에는 LAMP 용어 목록을 범위 밖 대조로 넣으며 이를 ‘관련 용어 성공’으로 집계하지 않는다.
5. 정답은 점수 계산에만 사용한다. 이전 조각의 모델 출력이나 정답을 다음 조각의 프롬프트에 넣지 않는다. LLM 교정·문자열 치환·출력 병합 재작성은 하지 않는다.

## 긴 음성 실험기의 수정

기존 비교기는 Qwen에 긴 파일을 그대로 전달했다. 설치된 MLX 구현은 파일 내부 청크 전체가 토큰 예산을 공유하므로 길어지면 후반이 처리되지 않을 수 있다. 이번에는 WAV 원본 프레임을 최대 30초씩 외부에서 나누고 각 조각에 독립적인 1,024토큰 예산을 준다. 두 엔진과 모든 힌트 조건이 같은 분할을 사용한다.

- 처음 0부터 마지막 프레임까지 빈틈·중복 없이 처리하고 30초 뒤의 짧은 꼬리도 버리지 않는다.
- 완료한 조각의 시작·끝 프레임, SHA256, 처리 시간, 원시 출력과 엔진 정보를 보존한다.
- 상한 도달·호출 실패를 전체 성공으로 처리하지 않는다. 완료한 앞 조각은 보존하고 실패 조건과 비정상 종료를 기록한다. 현재 상한에 걸린 그 조각의 응답 본문은 보존하지 않는 진단상의 제한이 있다.
- 기준선도 같은 고정 어휘로 평가한다. 예전처럼 없음 조건의 평가 어휘가 비어 버리는 문제를 막았다.
- SIL은 CER 분모 0을 피하고 출력 문자 수·삽입을 별도로 센다.

이 고정 분할은 **힌트의 효과를 통제하는 실험 경계**다. 앱의 음성 활동·낮은 에너지 경계 선택·대기열·복구까지 포함한 설치 앱 성능 시험은 아니다. Qwen의 조각 범위를 단어 정렬 결과로 표시하지 않는다.

### 분할 경계와 관찰 오류의 관계

같은 crop에 기존 앱의 `quiet_cut`을 계산하면 LAMP의 경계는 24.70/54.10/80.84/106.36/118.167초, WSL은 24.60/49.02/74.08/99.60/112.77초다. 고정 30초 분할과 chunk 수부터 다르다. LAMP의 crop 90초(원본151.367초)는 142.034–152.700초 자막 내부, WSL의 crop 30초(원본93.130초)는 89.420–94.610초 자막 내부를 자른다. 앱 방식의 같은 crop 계산에서는 두 시점이 chunk 내부다.

관찰된 문장 누락·자막성 추가 문장은 분할 조건의 영향을 배제할 수 없다. 이를 실제 앱에서 같은 위치에 재현되는 오류라고 단정하거나, `quiet_cut`이면 해결된다고 결론 내리지 않는다. `quiet_cut`도 일부 자막 내부를 자르며, 전체 원본 0초 시작·마이크 packet 경로와의 동등성을 검사한 것이 아니다.

Whisper는 기존 확정 전사의 Korean·Silero VAD·speech padding 1,000ms·최소 speech 250ms·기본 beam5/best-of5를 사용한다. Qwen은 Korean·temperature0·batch1·조각별 최대1,024토큰이며 별도 외부 VAD는 적용하지 않는다. 무음에서 두 엔진의 차이를 VAD와 분리된 모델 고유 성능으로 해석하지 않는다. **힌트의 효과는 각 엔진 안에서 비교한다.**

## 점수 해석

CER는 NFKC·소문자화 후 문자와 숫자만 남긴 문자 편집 거리이며 대치·삭제·삽입을 함께 남긴다. 영문 명칭/한글 발음, 숫자/한글 수사, 자막의 어미 축약은 자동 동치화하지 않는다. 따라서 모든 편집 오류를 의미 오류나 환각이라고 부르지 않는다.

`term_occurrences`는 모든 조건에서 같은 목록의 **정확한 문자열 출현 횟수**다. 특정 위치의 누락과 다른 위치의 반복이 상쇄될 수 있고, 영문 `Ubuntu`와 한글 `우분투`도 다르다. 이를 명칭의 발화별 정확도라고 보고하지 않는다. 정답에 없는 제공 용어의 출력도 실제 문맥·표기 동치를 확인한 뒤 해석해야 한다.

## 재현

실험기는 원본을 자동 다운로드하거나 바꾸지 않는다. 모델·자막·자료를 사용할 수 있는 로컬 폴더에 준비한 뒤 manifest를 만든다. 입력은 mono PCM16·16kHz WAV이며, `clips`의 각 행에는 `id`, `path`, `sha256`, `group`, `category`, `reference`, `hint_terms`, `distractor_terms`, `hint_provenance`가 필요하다. 정답은 없으면 빈 문자열로 두되 실제 비발화 주석 근거가 있어야 한다.

```sh
<WHISPER_PYTHON> experiments/compare_asr_hints.py \
  --engine whisper --manifest <MANIFEST.json> --runtime <RUNTIME> \
  --output <NEW_WHISPER.json>
<QWEN_PYTHON> experiments/compare_asr_hints.py \
  --engine qwen --manifest <MANIFEST.json> --runtime <RUNTIME> \
  --output <NEW_QWEN.json>
```

한 엔진이 끝난 뒤 다음 엔진을 실행한다. `--reverse-order`는 무관→관련→없음 순서의 재실행이다. 결과를 덮어쓰지 않도록 항상 새 output을 지정한다. 기존 공개 실험과 같이 각 엔진 Python에 준비된 MLX·MLX Audio·Transformers 및 해당 로컬 모델이 필요하다.

LAMP의 AAC 140(44.1kHz·약 129kbps), WSL의 AAC 139(22.05kHz·약 49kbps)를 mono 16kHz로 한 번 정규화했다. 서로 다른 원본 압축 품질을 엔진·조건 효과로 해석하지 않는다. 각 발화 안에서는 모든 조건이 정확히 같은 PCM을 사용한다.

## 관찰 결과

주 비교는 엔진별 39개 조건 결과(13파일×3조건), 102개 조각 호출이다. 변화가 있던 두 강연 조건·긴 일반 대화·SIL을 사후 선정한 6파일을 역순으로 반복했다. 반복은 독립 검증 표본이 아니다. 총 **114개 조건 결과·282개 조각 호출**이 모두 완료됐으며 실패·토큰 상한 도달은 0이었다. Qwen의 조각당 최대 생성은 169토큰이었다. 두 엔진 모두 반복한 18개 결과가 최초의 같은 조건과 문장·표기까지 일치했다.

### 강연: 검수 자막 기준 CER

각 환경은 같은 두 강연의 정답 1,222자다. 숫자·영문/한글 표기 차이도 포함한 진단 점수이며 엔진 순위표가 아니다.

| 엔진 / 환경 | 힌트 없음 | 슬라이드 용어 | 무관 용어 |
|---|---:|---:|---:|
| Whisper / 원본 | 158자 / 12.93% | 138자 / 11.29% | 155자 / 12.68% |
| Whisper / 사무실 혼합 | 124자 / 10.15% | 146자 / 11.95% | 140자 / 11.46% |
| Whisper / 식당 혼합 | 170자 / 13.91% | 152자 / 12.44% | 159자 / 13.01% |
| Qwen / 원본 | 206자 / 16.86% | 207자 / 16.94% | 211자 / 17.27% |
| Qwen / 사무실 혼합 | 214자 / 17.51% | 214자 / 17.51% | 206자 / 16.86% |
| Qwen / 식당 혼합 | 212자 / 17.35% | 210자 / 17.18% | 213자 / 17.43% |

Whisper는 원본·식당 혼합에서는 관련 용어의 점수가 나아졌지만 사무실 혼합에서는 악화됐다. Qwen은 환경별 차이가 작고 방향도 일정하지 않았다. 이 표본에서 일반적인 힌트 개선을 확인하지 못했다.

- LAMP 식당 조건의 Whisper는 자료에 있는 `Ubuntu`를 주면 `우버2` 오독이 그 표기로 바뀌었다. 하지만 다른 일반 문장이 달라지고 경계 누락이 남아 전체 정확도 개선을 보장하지 않는다.
- WSL 원본의 Whisper는 무힌트에서 자막에 없는 `자막 제공 … 광고를 포함` 문장을 출력했다. 관련·무관 용어에서 모두 사라져 점수 개선 전부를 자료 용어의 효과로 귀속할 수 없다.
- WSL 원본에서 `WSL → WSA`, `APPX → APP expirement` 오독은 관련 용어를 주어도 남았다. 재실행에서도 같았다.
- 영어 `Visual Studio Code`와 한글 `비주얼 스튜디오 코드`처럼 표기만 달라 CER가 바뀐 경우가 있다. 모든 문자 차이를 일반 발화의 의미 오류로 세지 않는다.

### 일반 대화: 범위 밖 용어의 영향

여기서 슬라이드 목록은 **인터뷰와 관계없는 LAMP 용어**다. 실제 같은 과목의 관련 용어 효과로 해석하지 않는다.

| 엔진 / 대화 | 없음 | LAMP 목록 | 무관 명칭 |
|---|---:|---:|---:|
| Whisper / 원본 3명·555자 | 67자 / 12.07% | 70자 / 12.61% | 70자 / 12.61% |
| Whisper / 식당 1명·287자 | 53자 / 18.47% | 50자 / 17.42% | 53자 / 18.47% |
| Qwen / 원본 3명·555자 | 57자 / 10.27% | 57자 / 10.27% | 57자 / 10.27% |
| Qwen / 식당 1명·287자 | 40자 / 13.94% | 42자 / 14.63% | 40자 / 13.94% |

Whisper의 원본 대화 3개에서 삭제는 36→38→39자, Qwen은 17→17→17자였다. 한 긴 대화에서 무힌트에 있던 `그래서`, `일단`이 두 힌트 조건에서 사라졌다. 수사·지명·어미 표기 차이도 함께 포함되며, 문자 삭제 수를 의미 손실 문장 수로 환산하지 않는다.

### 비발화 주석 원음: 용어 복사

3개 원음의 lexical reference는 비어 있다. CER 대신 출력된 정규화 문자 수를 남긴다. 실제 주석의 완전성과 배경 소리의 해석에는 한계가 있으므로 빈 참조 대비 모든 문자를 청취로 확정한 환각이라고 부르지 않는다.

| 엔진 | 없음 | LAMP 목록 | 무관 명칭 |
|---|---:|---:|---:|
| Whisper·VAD 사용 | 0 | 0 | 0 |
| Qwen·별도 외부 VAD 없음 | 18 | 49 | 39 |

Qwen은 두 SIL 구간의 무관 조건에서 입력한 세 명칭을 그대로 출력했다. 다른 SIL 구간의 관련 조건에서는 `Nginx, MariaDB, PHP, WSL2, Chmod, Chown`을 출력했다. **이 용어 복사는 역순 실행에서도 재현됐다.** 비발화 주석 대조에서 용어 주입이 출력으로 새어 나오는 위험을 확인했으며, Whisper와 Qwen의 차이를 VAD와 분리한 모델 자체의 우열로 주장하지 않는다.

## 반영 범위

- 실험기의 긴 PCM 분할·독립 토큰 예산·고정 어휘 평가·빈 참조 처리·실패 판정을 반영했다.
- 기존 Whisper의 사용자가 고른 소수 힌트·출처 현재성 검사를 유지한다. 자료 전체 자동 주입·Qwen hotwords 기본 연결·원문 자동 치환은 개선 근거가 없어 추가하지 않았다.
- Qwen 무힌트 후보도 원음 확인과 사용자 적용을 유지한다. 특정 문구라는 이유로 자동 삭제하거나 부정확한 결과를 지식으로 자동 확정하지 않는다.
- UI UX Pro Max의 오류 피드백·복구 기준으로 기존 전사 용어의 입력/저장/제외 이유/다시 확인 및 후보 원음 확인 안내를 코드 검토했다. 제품 화면·저장 구조·모델 설정을 수정하지 않았다. 실제 설치 앱의 새 녹음·필기 조작을 이번 비교의 검증으로 포함하지 않는다.

## 처리 시간·메모리의 범위

- Whisper: 같은 WSL 무힌트 조건의 총 처리 시간은 최초 43.27초, 역순 반복 12.34초였다.
- Qwen: 같은 WSL 무힌트 조건의 총 처리 시간은 최초 30.23초, 역순 반복 8.72초였다.

이 시각은 네 조각의 호출·결과 채점을 포함한다. 전사 두 엔진은 순차 실행했다. Whisper는 호출마다 native 모델을 준비하고 Qwen은 실행 안에서 한 모델을 공유한다. 실행에 따라 지연이 크게 달라졌으며 원인을 분리 측정하지 않았다. 힌트의 속도 향상이나 엔진 전체의 속도 순위로 사용하지 않는다. Qwen의 MLX 측정 peak는 최대 약 2,627.27MiB였고, 전체 프로세스 RSS나 Mac 전체 사용량은 아니다.

## 증거와 한계

본문 없는 [집계·입력/출처/실행 해시](verification/lecture-material-hints-20261020.json)를 함께 제공한다. 실제 원음·자막·슬라이드·raw 응답·처리 범위 대조는 로컬 검증 폴더에 보존했다. 원본 출처 15개와 입력 WAV를 전후 SHA256으로 대조했다.

같은 계열의 기술 강연 2편·5명 목소리의 작은 개발 진단이다. 대학 강의 전체, 여러 전공, 실제 현장에서 동시 녹음한 다화자·생활 소음, 겹침 발화, 장시간 마이크·절전·복구의 품질을 대표하지 않는다. 고정 분할·검수 자막·표기 정규화의 제한도 함께 적용된다.
