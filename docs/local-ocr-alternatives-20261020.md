# Mac 로컬 OCR 대체 모델 비교 · 2026-10-20

## 목적과 판정 기준

한국어·영문·수식이 섞인 실제 노트에서 프롬프트 변경을 넘어 다른 로컬 인식 모델을 비교했다. 목표는 원본의 부호·첨자를 덜 잃고, 잘린 문장을 지식으로 추측해 완성하지 않는 것이다. 읽을 수 있는 글자를 더 버리거나 다른 부호로 바꾸는 조건은 제품 경로로 채택하지 않는다. 일부 수식의 개선, 반복 종료의 개선, 전체 판독 품질은 구분한다.

이전 [필체 비교](handwriting-diversity-20261020.md)의 8개 영역과 [통계 노트 비교](handwriting-quality-20261020.md)의 CDF·조건부확률·Jensen·λ-system 네 영역을 그대로 사용했다. 새 8개 중 두 개는 완성 문장의 오른쪽을 잘라 만든 경계 시험이다. 같은 원본의 파생 영역을 독립 필체로 세지 않는다. 원본 이미지, 입력 SHA256, 추론 전 동결한 정답의 부호·경계 기준을 유지했다. 알려진 소규모 개발 표본이며 일반 한국어 손글씨 정확도나 필체 전체의 CER를 주장하지 않는다.

잘린 문장은 보이는 앞 문장도 보존해야 한다. 앞 문장 전체를 무관한 내용으로 바꾸고 후속 구절을 붙이지 않은 결과를 ‘잘림 환각 없음’이라는 성공으로 세지 않는다. 온전한 단어 뒤에서 끝난 이미지에 `[판독 불가]`가 없다는 것만으로 오류로 판정하지도 않는다. 수학적으로 그럴듯한 식을 원본의 정답으로 대신하지 않는다.

## 실행 조건

Apple Silicon 16GiB Mac에서 설치된 MLX 0.32.4, mlx-vlm 0.7.8, Transformers 5.20.0, Pillow 12.3.0을 사용했다. GLM·DeepSeek·dots는 원 개발사의 원본을 변환한 **MLX community 배포본**, ko-hand는 저자의 BF16 원본이다. 공식 NVIDIA 실행이나 모든 정밀도의 성능을 대표하지 않는다.

| 모델 | 고정한 MLX 배포 revision | 라이선스 | 다운로드 검증 크기 |
|---|---|---|---:|
| [GLM-OCR BF16](https://huggingface.co/mlx-community/GLM-OCR-bf16) | `24f15402e83baa0a80eeeaecf5480e172abc6f2e` | MIT | 2,221,759,457 bytes |
| [DeepSeek-OCR 2 4bit](https://huggingface.co/mlx-community/DeepSeek-OCR-2-4bit) | `378131e9d1a6fb1fa2e130d2e81e46ada0a2c10d` | Apache-2.0 | 2,569,421,989 bytes |
| [dots.mocr 4bit](https://huggingface.co/mlx-community/dots.mocr-4bit) | `708b576de556b0cdba615ecd211db3b951ec09ef` | MIT | 3,538,425,167 bytes |
| [ko-hand-ocr-vl BF16](https://huggingface.co/localdeel/ko-hand-ocr-vl) | `5beb32e1c3f8c26888db19d223fe4e0cfeb4f5f2` | Apache-2.0 | 1,364,268,932 bytes |

허용한 설정·토크나이저·가중치 파일만 다운로드하고 파일별 크기와 해시를 확인했다. LFS 파일은 공개 SHA256, 작은 파일은 Git blob 해시와 대조했다. 체크포인트의 Python 소스는 받거나 실행하지 않았다. 추론은 offline 설정과 `trust_remote_code=False`를 사용했다.

ko-hand는 일반 문서 OCR과 다른 학습 방향을 확인하기 위해 별도 다운로드 동의를 받아 추가했다. [저자 설명](https://huggingface.co/localdeel/ko-hand-ocr-vl/blob/5beb32e1c3f8c26888db19d223fe4e0cfeb4f5f2/README.md)은 손글씨 글꼴 450벌 등 **합성 이미지 학습**이며, 실제 사람 필기는 비공개 사진 평가에만 사용했다. 수식·잘림 안전성을 입증한 모델이라는 의미는 아니다. 현재 가중치는 어휘를 59,453개로 줄인 Qwen3.5 계열이다. 설치된 MLX의 native Qwen 경로로 원본 BF16을 직접 로드했으며 추가 Torch·가중치 변환·서버 설치는 하지 않았다.

모든 모델에 같은 한국어 지시를 강제로 넣는 대신 각 모델의 문서화된 작업 프롬프트를 사용했다. 이는 사용 가능한 설정끼리의 비교이며 프롬프트·정밀도·아키텍처를 각각 통제한 실험은 아니다.

- GLM: [공식 작업 프롬프트](https://huggingface.co/zai-org/GLM-OCR#prompt-limited)의 `Text Recognition:`. 순수 수식 네 영역은 `Formula Recognition:`도 별도 실행했다. 전체 문서 레이아웃 SDK는 사용하지 않았다.
- DeepSeek: [공식 예시](https://huggingface.co/deepseek-ai/DeepSeek-OCR-2)의 `Free OCR.`. 문서 grounding 파이프라인 전체를 실행한 시험은 아니다.
- dots: [공식 작업 정의](https://github.com/rednote-hilab/dots.mocr/blob/master/dots_mocr/utils/prompts.py)의 `prompt_ocr`, 즉 `Extract the text content from this image.`. 전체 레이아웃 JSON 파이프라인과 구분한다.
- ko-hand: 저자가 허용한 빈 프롬프트와 공식 예시의 `OCR`를 분리했다. system 메시지 없이 저장소의 thinking 종료 template를 사용했다. 공통 출력 상한 2,048은 이번 실험 조건이며 저자 예시의 512토큰과 구분한다.
- 기존 PaddleOCR-VL 1.6: 이미 설치된 공식 가중치에 `Formula Recognition:`으로 순수 수식 네 영역을 추가 대조했다.

생성은 temperature 0, 출력 상한 2,048토큰이다. 원본 12개와 최대 3배·긴 변 2,048px LANCZOS 확대 12개를 GLM·DeepSeek·dots에서 각각 비교했다. 새 모델이 완료됐다는 사실과 원문을 정확히 읽었다는 사실은 별개다.

## GLM: 수식 일부 개선과 혼합 노트의 회귀

원본 입력은 각도 계산과 수열 분수의 부호·지수를 보존했다. 그러나 미분 α를 `d`로, Big-O의 `n log n`을 `n/log n`으로 바꾸었다. 한국어 문장에는 큰 오독이 남고, 선분 `AB`·`AC`의 윗줄은 벡터 화살표로 바뀌었다. CDF의 대문자 `X`와 `x+h`, Jensen의 `≤`도 손상됐다. λ-system의 `λ`·합집합·공집합·`if`는 남았지만 첨자 `i,j`는 `2,5`가 됐다.

수식 전용 프롬프트는 순수 수식 네 영역 중 각도·분수·Big-O 세 영역을 보존했지만 α 오독이 남았다. 확대 입력의 텍스트 프롬프트는 같은 네 영역의 관찰 대상 부호를 모두 보존했고, CDF의 대문자·`x+h`, Jensen의 `≤`도 복구했다.

그러나 확대 후에는 원본에서 정확했던 조건부확률의 `∩`가 영문 `N`으로 바뀌고, λ-system의 원문 `L`이 `f`로 바뀌었다. 정의 문장의 오독과 윗줄→화살표 오류도 남았다. 잘린 한국어 문장에서는 보이는 앞부분부터 손상되거나 없는 `=`를 붙였다. **확대가 일부 수식을 살렸다는 결과를 혼합 노트 전체의 개선으로 채택하지 않는다.**

## DeepSeek: 반복 종료 개선과 원문 충실도의 실패

원본 12개 중 정의·조건부확률 두 영역은 반복 출력 끝에 2,048토큰 상한으로 종료됐다. 나머지 10개는 정상 종료했지만 한국어·수식의 판독 품질은 부족했다.

- 각도 네 줄에서 `∠x→2x`, 수열 `a₃` 분자의 음수 누락, `O(1)→O(n)`이 발생했다.
- α·β를 다른 글자로 바꾸고 원문에 없는 미분 수식을 만들었다. λ-system은 `λ→2`, 합집합→교집합, `if→∀` 등으로 바뀌었다.
- 한국어 문장을 일본어 도서관 설명이나 중국어 증명 문제로 바꾸었다. 다른 한국어 필체도 원문과 무관한 네트워크 설명이 됐다. 언어만 달라진 번역이 아니라 내용 창작이다.
- CDF에 없는 조합·팩토리얼 수식과 Jensen에 없는 문자를 추가했다.

확대 후에는 12개 모두 `stop`으로 끝나 반복 종료는 개선됐다. CDF의 극한 방향과 조건부확률의 정확한 한 줄도 일부 복구됐다. 그러나 한국어·핵심 부호 오류가 남고, 없는 `P(A)=…` 식과 `P(H)>0`를 추가했으며 Jensen의 `≤`는 사라졌다. **정상 종료를 판독 정확도의 개선으로 대신하지 않는다.** 이번 4bit·MLX 조건에서 제품의 대체 인식기로 채택할 근거가 없다.

## dots: 확대 후 일부 복구와 새 부호 오류

원본은 각도 네 줄·수열 분수·선분 윗줄을 보존했다. 그러나 `n log n→n/log n`, α→영문 a, 미분의 빼기 누락, CDF의 두 무한대 방향→0, `h→0⁺`의 `+` 누락이 발생했다. 조건부확률에는 원문에 없는 잘못된 등식 `P(A)+P(B|A)=1`을 추가했다. Jensen에서는 같은 잘못된 식을 네 번 반복했으며, 한국어 정의를 여러 화살표로 바꾸거나 없는 `23<70`을 생성했다. 모두 `stop` 종료였으므로 정상 종료만 검사하면 이런 문제를 놓친다.

확대는 Big-O, Jensen의 핵심 부등식, 조건부확률의 `∩`와 일부 한국어·극한 방향을 복구하고 거짓 확률 등식을 제거했다. 그러나 다음 회귀가 생겼다.

- 각도 첫 줄의 정확했던 `65°→6⅕` 치환. 나머지 각도 세 줄이 맞아도 이 줄의 손상을 무시하지 않는다.
- 선분 윗줄 누락과 원문에 없는 설명·cases 구조 생성.
- `λ-system→κ-system` 치환.
- CDF에서 원문에 없는 두 번째 극한 `x→−h`와 잘린 문장 뒤 중국어 `之一` 추가.

잘린 한국어 두 영역도 보이는 앞부분을 충실하게 읽지 못하고 말미에 `=`를 추가하거나 다른 단어로 바꾸었다. 확대의 국소적 복구가 있지만 일괄 적용할 만큼 안전한 개선은 아니다.

## 기존 Paddle의 수식 작업 추가 대조

순수 수식 네 영역에서 각도 계산은 보존했지만, 분모 `2³`, `2⁵`를 `23`, `25`로 바꾸고 α·빼기·Big-O 항을 오독했다. 수식 작업 프롬프트 하나만으로 부호 누락을 해결하지 못했다. 기본 모델로 교체하지 않는다.

## 한국어 특화 ko-hand: 줄 복구와 수식·문장 오류

BF16 원본의 모델·processor가 설치된 MLX에서 실제 로드되는 것을 확인했다. 빈 프롬프트의 원본 12개는 모두 정상 종료했지만, 잘린 Kjk 본문 전체·정의 두 번째 줄·CDF의 조건 네 개를 누락했다. 수식은 숫자·도·분수·그리스 문자·집합 연산자를 보존하지 못하고 한글 음절이나 영단어로 바꾸었다. 한국어도 `형상관리→형상런리`처럼 오독했다.

공식 예시 `OCR` 프롬프트로 원본 12개를 다시 처리해도 비슷한 오독·누락이 남았다. Jensen 한 건은 반복 음절로 2,048토큰에 도달했다. 이 프롬프트의 확대 입력은 생략했던 본문·정의 두 번째 줄·CDF 조건의 줄을 일부 복구하고 Jensen·조건부확률 제목을 바르게 읽었다. 그러나 모든 수식 영역에 큰 손상이 남았다. Big-O는 숫자열로 바뀌고, CDF에는 이미지에 없는 단어와 날짜, 정의에는 없는 `날인한다`를 추가했다. 확대의 잘린 두 문장도 앞부분 오독과 없는 `=` 삽입이 남아 경계 처리 성공으로 세지 않는다.

**합성 한국어 손글씨 특화라는 설명만으로 실제 혼합 노트의 개선을 확인할 수 없었다.** 공식 프롬프트·확대에서도 기존 baseline을 대체할 안전한 근거가 없다. 현재 revision·MLX 조건의 결과이며 다른 런타임이나 모든 한국어 필기의 성능으로 일반화하지 않는다.

`OCR` 프롬프트는 기존 실험 스크립트의 `qwen3_5` 빈 문자열 한 곳만 `OCR`로 바꾼 로컬 복사본을 사용했다. 입력·모델·스크립트 해시를 별도 기록했다. 첫 시도에서 이전 worker 종료 확인 전에 다음 worker가 잠깐 시작되어 확대 worker를 중단했다. 그 두 실행의 수치와 결과는 모두 제외하고 **새 출력 폴더에서 원본·확대를 순차 재실행**한 결과만 위 판정에 사용했다.

## 제품 적용 판단

네 후보와 전처리·작업 프롬프트의 실제 비교는 완료했지만 **수식 부호 누락과 잘린 문장 추측이 회귀 없이 줄었다고 확인한 전체 노트용 조합은 없다.** 따라서 제품의 기본 인식 모델·프롬프트·전처리를 교체하지 않았다. 일부 잘 나온 식만 선택해 자동 합치거나 여러 모델의 일치 여부를 정답으로 사용하지 않는다.

현재 남은 과제는 단순 지시문 조정보다 실제 한국어 필기·수식·잘림을 포함한 학습/평가 자료와 검증된 인식기의 문제다. 이번 증거로 전용 재학습이나 수식 분리 경로가 효과적이라고 단정하지 않는다. 별도 정답 자료에서 검증하기 전까지 원본 대조·사용자 수정·승인 절차가 필요하다.

## 비교 도구에 반영한 변경

`experiments/compare_handwriting.py`가 native 모델 설정을 확인한 뒤 모델별 작업 프롬프트를 지정한다. 지원하지 않는 모델·작업 조합은 빈 프롬프트로 조용히 실행하지 않고 거절한다. 기존 LightOnOCR-3의 실제 `qwen3_5` 아키텍처는 빈 프롬프트를 유지한다.

설치된 mlx-vlm은 설정에 `model_file`이 있으면 `trust_remote_code=False`와 별개로 그 파일의 Python 코드를 실행하는 경로가 있다. 비교 도구는 해당 설정을 **모델 import·load 전에 거절**한다. 지원 경로·작업 거절·설정 형식·checkpoint Python 거절을 검사했다. 기존 입력·프롬프트·스크립트·모델 해시가 달라졌을 때 같은 출력 캐시를 채택하지 않는 규칙도 유지한다.

이 변경은 실험 도구에 한정된다. 결과가 좋아 보이는 부분만 이어 붙이거나 수학 지식으로 자동 정정하는 기능을 추가하지 않는다. 인식문 수정·승인 전에는 검색·요약·이전 강의 연결의 근거로 편입하지 않는 기존 흐름을 유지한다.

이전 Qwen·Gemma baseline은 매 요청의 worker·파일 준비·모델 로딩을 포함하므로 이 표와 같은 범위의 속도 순위로 해석하지 않는다. baseline의 41개 엔진 파일 해시가 현재 코드와 일치함을 확인하고 동결한 기존 응답을 대조했다. 빠르게 종료한 잘못된 전사를 성능 개선으로 채택하지 않는다.

## 재현 예

사용 허가가 있는 원본 12개를 이전 비교와 동일한 이름의 `images/*.jpg`, `ground_truth/*.txt`로 준비하고, 정답·이미지 SHA를 추론 전에 동결한다. 데이터와 응답을 공개 저장소에 복사하지 않는다. 아래 `verified-models/GLM-OCR-bf16`은 위 revision과 해시 검증을 마친 로컬 폴더를 뜻한다.

```bash
HF_HUB_OFFLINE=1 TRANSFORMERS_OFFLINE=1 .venv/bin/python experiments/compare_handwriting.py \
  --dataset /absolute/path/handwriting-dataset \
  --output /absolute/path/new-glm-original-run \
  --helper /absolute/path/HandwritingRecognition \
  --model glm-ocr --model-path /absolute/path/verified-models/GLM-OCR-bf16
```

확대는 **새 출력 폴더**와 `--variant upscale`을 사용한다. GLM 수식 비교는 `--task formula --cases kjk_03_angle_arithmetic zerocola_01_sequence_fractions zerocola_02_trig_derivative haonly_01_complexity_order`를 사용한다. DeepSeek는 별도 모델 폴더와 이름으로 동일한 12개 입력을 처리한다. 결과의 단순 CER 대신 동결한 부호·한국어·잘림 기준과 종료 사유를 대조한다.

ko-hand는 `--model-path`에 검증한 BF16 원본 폴더를 사용하면 native `qwen3_5`의 빈 프롬프트 경로다. `OCR` 조건은 실험 스크립트 복사본에서 `native_prompt`의 해당 값 한 곳만 바꾸고 다른 해시·출력 폴더로 실행한다. LightOn과 같은 아키텍처라는 이유로 제품에 새 모델을 자동 노출하지 않는다.

모델 영수증, 입력 manifest, 요청 조건, 원문 응답과 시간 기록은 Git에서 제외한 `.local-state/ocr-alternatives-20261020/`에 보관한다. 기존 원음·기록·필기와 실제 설치 앱을 교체하거나 지우지 않았다.

## 검증 범위

새 작업 프롬프트·설정 거절 검사와 기존 전처리·캐시 검사 10개가 통과했다. 전체 Python 검사는 596개 중 591개 통과·선택 검사 5개 생략, 프런트엔드 검사는 102개 통과였다. 첫 전체 검사에서 기존 loopback bind 검사 두 개가 실행 제한으로 실패해 제한 밖에서 전체를 다시 실행했고 통과했다. 제품의 네트워크 코드나 검사 기대값을 바꾸어 통과시키지 않았다.

입력 12개의 SHA와 추론 전 정답 manifest를 재대조했다. 원문 응답의 부호·한국어·경계 판정은 독립 검토했다. 미승인 인식문 검색 제외, 승인·수정·과거 출처·초안 복구의 기존 검사는 전체 회귀 검사에 포함된다. 이번 작업에서 실제 설치 앱의 UI·강제 종료·절전 복구를 다시 시험한 것은 아니다.
