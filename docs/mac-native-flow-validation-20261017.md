# Mac 실제 앱 사용 흐름 검증 — 2026-10-17

## 범위와 변경 기준

UI UX Pro Max의 오류 피드백·복구·초점 지침으로 실제 Mac 앱을 점검했다. grilling에서는 이미 합의한 로컬 보관함, 원문·연결 보존, 클릭 후 선택 재생, 보수적 중복 억제 정책을 유지했다. ponytail 기준으로 기존 저장·발췌 경로의 작은 수정만 적용했다.

실제 사용자 보관함과 분리한 새 보관함에서 네이티브 앱을 실행했다. 브라우저 합성 fixture나 API 호출을 실제 화면 조작의 대체 증거로 사용하지 않았다. 기존 모델 파일을 재사용했으며 외부 AI·웹 검색·클라우드 저장은 사용하지 않았다.

## 실제 화면에서 이어서 수행한 흐름

| 단계 | 조작과 확인 |
|---|---|
| 과목 | 입력란에서 새 과목 생성, 왼쪽 목록과 과목 화면에 반영 |
| 자료 | 실제 NSOpenPanel 취소 후 자료 없음 유지, 다시 열어 3쪽 PDF 연결·추출·원본 표시 |
| 필기·메모 | 원본 위 마우스 필기 2획과 페이지 메모 저장, 2쪽으로 이동했다가 돌아와 revision 3 복원 |
| 페이지 내보내기 | 실제 NSSavePanel에서 취소와 저장을 각각 실행, JSON의 메모·잉크가 저장 revision과 동일 |
| 강의 | 과목 안에 강의 기록 생성, 공용 자료와 연결 |
| 녹음 | 사용자 마이크 권한 허용 후 실제 입력 48.1초 저장·정상 종료. 48kHz, 원본·저장·WAV 프레임 모두 2,308,800개로 일치 |
| 전사 | 종료 후 전사 완료. 별도로 실제 한국어 인터뷰 139.05초를 NSOpenPanel로 연결해 확정 전사 48개 생성 |
| 대본 | 문장 클릭만으로 재생하지 않음. 선택 메뉴의 ‘선택 구간 듣기’로 실제 AVPlayer 재생 위치 진행 확인 |
| 요약 | 실제 Qwen3.5 4B 직접 실행으로 전사·과목 자료·메모 스냅샷 요약 생성, 원문 근거 펼침 확인 |
| 내보내기 | 대본 TXT, 시각·원음 연결 Markdown, 요약 Markdown을 실제 NSSavePanel로 저장 |
| 재시작 | ⌘Q 후 다시 실행, PDF 메모·필기와 전사·요약 유지. 저장소 integrity·foreign key 검사 통과 |

마이크 원음은 현재 환경의 입력이며 정답 전사가 없다. 한국어 인터뷰도 모든 대화의 정답이 있는 자료는 아니다. 이 결과를 전체 CER·화자 분리 정확도나 새 장시간 녹음 시험으로 해석하지 않는다. 요약 스냅샷에는 마이크 전사와 PDF·메모가 함께 있으므로 인터뷰만의 요약 품질 점수로 사용하지 않는다.

## 발견한 문제와 수정

### 내보내기 실패와 사용자 취소 구분

기존에는 새 저장 파일을 준비하지 못한 오류도 `nil`로 반환해 JSON 화면에 ‘취소됨’이 표시될 수 있었다. 저장 위치 선택 결과를 `Result`로 전달해 사용자 취소만 취소로 처리하고, 실제 실패는 JSON 오류 또는 네이티브 상태줄에 표시한다. 기존 파일 덮어쓰기 금지는 유지한다.

기록·동기화·스트림 실패 시 일부 저장 파일은 완성본으로 취급하지 않는다. 남긴 사본의 위치와 ‘일부만 저장된 사본’ 표시를 오류에 포함한다. 실제 파일 크기 제한을 사용한 쓰기 실패 검사에서 앞서 쓴 내용의 보존과 목적 파일 미생성을 확인한다. 동기화·닫기 실패 자체를 하드웨어 오류로 주입하지는 않았다.

### 겹치는 핵심 원문의 반복

실제 생성 결과는 앞 문맥 보존 때문에 인접 발췌끼리 같은 원문을 반복했다. 같은 구간 요약 안에서 인접 항목의 출처 ID·원문 단위가 유일하고 순서대로 겹칠 때만 최종 표시를 합친다. 다른 출처의 같은 문장, 모호한 반복, 검토 필요 항목, 역순·빈 구간·부분 인용은 그대로 둔다. 새 문장을 생성하거나 선택 범위를 줄이지 않는다.

기존 완료 결과를 읽기 전용 메모리에서 대조하면 18항목→7항목, 인용 출현 142회→66회, 본문 2,047자→997자였다. 고유한 출처·원문 61쌍과 모든 출처 ID·검토 필요 항목은 유지됐다. 원래 구간 요약과 `artifact_parts`는 보존하고 새 요약의 최종 표시와 내보내기에 적용한다. 기존 저장 요약은 소급 변경하지 않는다.

수정한 동결 엔진을 넣은 실제 앱에서 같은 입력으로 다시 생성해도 **7항목·66인용·997자**였으며, 원래 구간 요약 18항목·고유 원문 61쌍·출처 ID 52개·검토 필요 2항목을 보존했다. 실제 화면에서 최신 결과를 선택해 확인하고 Markdown으로 저장했다. 재생성 시간은 43,095ms였다. 이전 44,147ms와의 단일 비교를 속도 개선의 증거로 사용하지 않는다.

## 최종 빌드와 보존 확인

- **0.3.5 / build 15**를 사용자 앱으로 설치했다. 앞선 전체 흐름은 0.3.4/build14, 수정 후 요약·JSON 취소/저장·요약 Markdown 재검증은 0.3.5/build15에서 수행했다.
- 내장 엔진 v10의 SHA256은 `38384bb5b9f712e6a7e8393be1fc7118b9185950687e36c61dee101ffe022792`다. manifest 7,766파일 검증·frozen self-check·앱 서명 검증을 통과했다. 설치된 엔진과 프런트는 최종 빌드와 일치했다.
- 최종 백엔드 전체 검사 **493개 중 488개 통과·5개 선택 검사 제외**, 프런트 **88개 통과**, TypeScript·Vite 빌드 통과. Swift 브리지 fixture는 취소·준비 실패·기존 파일 보존·정상 저장·실제 쓰기 실패·스트림 중단을 검사했다.
- 사용자 앱의 기존 과목 3개와 홈 본문을 실제 접근성·스크린샷으로 확인했다. 정상 종료 뒤 **43개 테이블·86개 스키마 항목·원음과 연결 자료 18개가 설치 전과 동일**했고 누락 파일·foreign key 오류가 없었다. 기존 앱 백업·보관함·모델 경로를 유지했다.
- 검증 앱과 사용자 앱 모두 정상 종료 후 소유 엔진이 남지 않았다. 실행 중 표본에서도 앱·엔진의 TCP 리스너를 발견하지 못했다.

## 화면 도구가 본문을 읽지 못한 원인 조사

초기 실행에서 로딩 안내가 사라진 뒤에도 도구에는 회색 창과 빈 접근성 트리만 나타났다. 파일·화면·엔진을 다시 로드하지 않고 다음 순서로 비교했다.

1. 준비 후 기존 앱 연결에서 상태 확인: 본문 없음.
2. 앱을 다시 열지 않고 도구 연결만 새로 획득: 여전히 본문 없음.
3. 도구로 네이티브 앱 메뉴의 **Solasi 열기** 선택: 같은 연결에서 즉시 HTML 접근성 트리와 정상 화면이 나타남.

이 메뉴는 기존 창의 `makeKeyAndOrderFront`와 앱 활성화를 수행한다. Finder에서 이미 실행 중인 정확한 번들을 다시 여는 방법도 같은 효과였다. 따라서 관측된 장애는 초기 창 활성화와 도구의 상호작용으로 좁혀졌으며 서버·보관함·HTML 생성 실패라는 증거는 없었다. CUA 내부 원인과 전환 전 active/key 값은 측정하지 않았으므로 더 구체적인 원인을 확정하지 않는다. 도구 문제를 숨기기 위해 로딩 완료 때마다 사용자 초점을 강제로 빼앗는 코드는 추가하지 않았다.

도구에서만 빈 창이 보이면 앱 메뉴에서 `Solasi 열기`를 선택하고 같은 앱의 접근성 상태를 다시 얻는다. 정확한 번들 경로를 확인하며 이전 앱 백업을 실행하지 않는다.
