# Gemma 4 실제 Mac 비교

2026-10-14 · Apple M4, 16GiB, macOS 27.0.1 · 앱 전용 Ollama 0.40.3.

E2B QAT → E4B QAT → 12B MLX를 순차 실행했다. 기본 모델은 변경하지 않았다. 짧은 전사 진단, 연속 녹음 동시 실행, 녹음 종료 후 생성은 서로 다른 시험이다. **모델 크기가 더 크다고 한국어 전사가 더 정확하거나 녹음 중 지연이 더 작지는 않았다.**

QAT 실측은 [Google E2B](https://huggingface.co/google/gemma-4-E2B-it-qat-q4_0-gguf)·[E4B](https://huggingface.co/google/gemma-4-E4B-it-qat-q4_0-gguf)의 수정 헤더를 사용한 공식 파일이다. 기존 Ollama blob의 텐서와 공식 헤더를 결합한 뒤 **전체 파일 SHA256이 Google 공개 파일과 일치할 때만** 가져왔다. 변환·재양자화를 하지 않았다. 헤더만 수정한 E2B와 기존 Ollama QAT의 짧은 음성 결과는 20/20 같았다. 헤더 변경을 정확도 개선으로 주장하지 않는다.

앱 catalog의 `gemma4:e2b-it-qat`·`gemma4:e4b-it-qat`는 기존 **Ollama 공식 manifest** `07ea…`·`ee665…`다. Settings에서 이를 받는 것과 위 수정 헤더 실측 artifact는 구분한다. 공식 배포물은 Apache-2.0이며, 파일 저장량을 RAM·GPU 메모리 요구량으로 해석하지 않는다.

사용자 승인대로 새 QAT 모델은 비교 후 삭제하고 12B는 보관한다. 기존 Qwen3.5 4B·Gemma E2B MLX·EmbeddingGemma·EmbeddingGemma 2는 유지한다. 다운로드 (로컬 검증 자료·공개본 미포함), E2B 파일 검증 (로컬 검증 자료·공개본 미포함), E4B 파일 검증 (로컬 검증 자료·공개본 미포함), 정리 기록 (로컬 검증 자료·공개본 미포함).

## 1. 평소 말투·잡음·음량·실내 조건

추가한 **39개, 302.63초**를 모델별로 같은 순서·SHA로 한 번씩 처리했다. 고유명사 복원과 별도로 일반 단어·문장 의미 손실·실행 실패를 확인했다. 각 Gemma 실행 뒤 같은39개를 제품 Whisper로 다시 처리했으며, Whisper 인식문과 CER는 세 비교에서 같았다. 다른 추론·다운로드는 동시에 실행하지 않았다.

| 조건 | 클립 수 | E2B QAT CER | E4B QAT CER | 12B MLX CER | Whisper turbo CER(변경 전30ms) |
|---|---:|---:|---:|---:|---:|
| 깨끗한 읽기 음성 | 5 | 17/223 = 7.62% | 14/223 = **6.28%** | 15/223 = 6.73% | 15/223 = 6.73% |
| 같은 음성, 진폭 0.1배 | 5 | 21/223 = 9.42% | 18/223 = **8.07%** | 32/223 = 14.35% | 30/223 = 13.45% |
| 같은 음성, Gaussian 잡음 SNR10dB | 5 | 32/223 = 14.35% | 23/223 = 10.31% | 21/223 = 9.42% | 19/223 = **8.52%** |
| 두 화자·세 방의 읽기 음성 | 6 | 11/213 = 5.16% | 8/213 = **3.76%** | 20/213 = 9.39% | 14/213 = 6.57% |
| TED 강연 발췌 | 6 | 18/132 = 13.64% | 16/132 = 12.12% | 38/132 = 28.79% | 10/132 = **7.58%** |
| 즉흥 발화·반복·말 고침 | 12 | 140/256 = 54.69% | 44/256 = **17.19%** | **11/12 성공: 77/227 = 33.92%** | 78/256 = 30.47% |

CER의 분모는 정규화 정답 문자 수, 분자는 삽입·삭제·대치 수다. 12B는 5.249초짜리 자기 정정 발화에서 `num_predict=1024`에 도달해 완결되지 않았다(약47.167초). 해당 1건은 실행 실패로 별도 기록했다. **12B 즉흥 발화 CER는 성공한11개만의 값이며 나머지 모델12개와 동일 분모가 아니다.** 당시 부분 출력은 저장되지 않아 반복 생성이라고 단정할 수 없다. 이후 비교 도구는 미완결 부분 응답도 보존한다.

즉흥 발화는 [Seoul Corpus](https://www.openslr.org/113/) 첫 두 녹음의 **한 명, 남성16세 화자**에서 선정한12구간, 43.053초다. 인터뷰어·비공개/미상 태그·웃음 혼합 구간을 제외하고 원래 반복·말 고침·채움말은 남겼다. 일상 말투 진단을 추가했지만 다화자 성인 회의의 대표 표본은 아니다. [원 논문](https://www.eksss.org/archive/view_article?pid=pss-12-4-37)의 자료 조건과 CC-BY-NC2.0을 따른 비상업 로컬 평가이며 원음은 저장소에 배포하지 않는다. 전체 약2.589GB archive를 받지 않고 첫 두 원음·TextGrid에 필요한 약11.687MB prefix만 읽었다. 압축 항목 CRC·길이와 다시 조회한 공식 prefix의4개 파일 SHA가 캐시와 일치했다. 무결성 확인 (로컬 검증 자료·공개본 미포함).

깨끗한/음량/잡음은 같은 [FLEURS](https://huggingface.co/datasets/google/fleurs)5개에서 만든 대응 조건이므로15개의 독립적인 사람 녹음이 아니다. 잡음 SNR은 클리핑 전 RMS 기준이고 실제 카페·바람·겹침 발화가 아니다. 방 음성은 [Deeply](https://github.com/deeplyinc/Korean-Read-Speech-Corpus)의 두 화자·세 방, iPhone X 약0.4m 읽기 문장이다. 강연은 [Pansori TEDxKR](https://github.com/yc9701/pansori-tedxkr-corpus)의 기존24클립 중 일정 간격6개다. 두 NC-ND corpus는 원본 발췌만 평가했다. 이미 검사한 자료가 일부 포함되므로 보지 않은 holdout 성능으로 해석하지 않는다.

오류에는 명칭 외에 의미 손실이 있다. 12B는 ‘미성아파트요 … 중앙난방’을 ‘이 디자인 어때요? 너무 좋아요’로 바꿨다. Whisper는 ‘뭐 사람이 뭔가 딱히 궁금하지도 않고요’를 **‘감사합니다’**로 만들었다. 필러 표기·숫자 표기 차이와 이런 문장 환각을 구분해 원음·정답·인식문을 대조했다. 작은 표본에서 E4B의 일상 발화 강점과 Whisper의 잡음/강연 강점이 함께 보였으므로 모델 크기 하나로 기본 엔진을 바꾸지 않았다.

### 확정 전사의 VAD 경계 보완

같은39개를 **다른 추론 없이** Whisper VAD 여유200ms로 추가 처리했다. 변경 전39개는 모두30초 미만이어서30ms였고, 다음 표는 위 모델 비교와 구분한 설정 비교다.

| 조건 | 기존30ms 편집 수 / CER | 200ms 편집 수 / CER |
|---|---:|---:|
| 깨끗한5 / 저음량5 | 각각15/223 = 6.73%, 30/223 = 13.45% | 같음 |
| 잡음5 | 19/223 = 8.52% | **16/223 = 7.17%** |

‘감사합니다’ 환각은 ‘원하지도 않고요’로 바뀌었으나 원문의 앞부분은 여전히 빠졌다. 개선을 오류 해결로 표현하지 않는다. 앞선92개 짧은 파일의200ms 진단에서도 읽기40은99→99자, 강연24는23→24자, 실내18은29→25자, 저음량은30→30자, 잡음은19→16자였다. 두 진단의 실내/잡음 개선과 추가한 일상 발화 개선을 보고 **짧은 확정 범위에도200ms를 적용**했다. 짧은 preview의 기존옵션과 긴 녹음200ms를 유지했다. 긴 동시 실행 실측 당시에도200ms였으므로 그 지연 결과를 이 한 줄 변경의 효과로 계산하지 않는다. 읽지 않은 다른 녹음·실제 겹침에서 같은 개선을 보장하지 않는다.

200ms 실제39개 결과 (로컬 검증 자료·공개본 미포함), 이전92개 (로컬 검증 자료·공개본 미포함). 이 설정은 최소 경계 보완이며 전사 내용을 LLM 추측으로 자동 덮어쓰지 않는다.

39개 E2B (로컬 검증 자료·공개본 미포함), E4B (로컬 검증 자료·공개본 미포함), 12B와1건 실패 (로컬 검증 자료·공개본 미포함). 수집·정답 선정·SHA·라이선스 manifest는 `experiments/collect_speech_conditions.py`로 재현한다.

## 2. 고유명사 중심의 짧은 진단

같은 FLEURS 10개, **148.5초**, 정규화 정답 **545자**를 각 모델로 2회 처리했다. 명칭 포함 5개와 대조 5개로, 고유명사 우열을 확인하는 작은 진단 표본이다. 평소 대화·실내 소음·여러 화자의 전체 성능을 대표하지 않는다.

Gemma는 Ollama native `/api/chat`, 16kHz WAV, `messages[].images`, 한국어 전사 요청, `temperature=0`, `seed=42`, `num_ctx=8192`, `num_predict=1024`, `think=false`다. Whisper는 실제 제품 파일 전사 경로다. 힌트는 사용하지 않았다. 처리 시간에는 로딩·캐시 차이가 포함된다. 두 번째 실행은 독립적인 cold start가 아니다.

| 모델 | 진단 CER 1회 / 2회 | 고유명사 6개 정확 복원 | 10개 처리 시간 1회 / 2회 |
|---|---:|---:|---:|
| E2B QAT 수정 헤더 | 41/545 = **7.52% / 7.52%** | 3/6, 두 회 같음 | 26.378 / 12.270초 |
| E4B QAT 수정 헤더 | 32/545 = **5.87% / 5.87%** | 3/6, 두 회 같음 | 38.214 / 16.483초 |
| 12B MLX | 39/545 = **7.16%** / 38/545 = **6.97%** | 2/6, 두 회 같음 | 63.090 / 88.801초 |
| Whisper large-v3-turbo | 15/545 = **2.75% / 2.75%** | 4/6, 모든 비교에서 같음 | 해당 12B 대조 실행 45.576 / 29.271초 |

CER는 NFKC·소문자·Unicode 문자/숫자만 유지하고 띄어쓰기·문장부호를 제거한 진단 값이다. 숫자의 한글/숫자 표기, 괄호 안 로마자도 오류로 센다. 공식 FLEURS 정규화·벤치마크 점수가 아니다.

6개 표기는 세풀베다, 깁슨, 내셔널 트레저, 북발트해, 카탈로니아어, TMZ다. E2B는 세풀베다·내셔널 트레저·카탈로니아어, E4B는 내셔널 트레저·카탈로니아어·TMZ, 12B는 세풀베다·카탈로니아어, Whisper는 내셔널 트레저·북발트해·카탈로니아어·TMZ를 복원했다.

12B에는 북발트해→북파이프, 깁슨→깁스, 내셔널 트레저→매니얼 트레저뿐 아니라 **해상 봉쇄→대량 봉쇄**, **겨우 2주→초기에는**과 같은 의미 손상도 남았다. 고유명사만의 문제로 설명하지 않는다.

각 클립 정답·인식문·SHA·시간: E2B (로컬 검증 자료·공개본 미포함), E4B (로컬 검증 자료·공개본 미포함), 12B (로컬 검증 자료·공개본 미포함).

## 3. 연속 녹음 중 전사·생성

입력은 [LibriVox 『술 권하는 사회』 Part 1](https://librivox.org/short-stories-by-jin-geon-hyun/), 현진건, 낭독 Jessie Yun의 **878.3035초(14분 38초)**다. MP3 SHA256은 `68f07d5ca8677317590af0fc1dd5b8634ae0749ba1bbddc3965962f73086f1fc`. Public Domain Mark 1.0 / LibriVox public-domain dedication. 짧은 클립 반복이나 합성 음성이 아니다.

실제 browser AudioWorklet → WebSocket → WAV → Whisper large-v3-turbo를 사용하며 생성 모델만 바꿨다. 소프트웨어 BufferSource가 수집 AudioContext와 같은 시계를 사용한다. 실제 마이크·스피커 시험은 아니다. 생성은 예열 후 녹음 25초부터 약 60초 간격으로 15건 요청했다. 고정 질문은 프로세스·스레드 차이 3문장으로, 동시 실행 부하 시험이며 낭독 요약 품질 시험과 구분한다. 이미 시작한 생성은 유지하고 확정 전사 적체 시 다음 요청을 대기시킨다.

| 실제 재생·수집 경과 | 879.870초 | 884.103초 |
| 저장된 원음 | **878.304초** | **878.304초** |
| 생성 완료 | **15/15건** | **15/15건** |

생성 실제 추론은 `request_started→ended`, 대기는 `submitted→request_started`다. 출력 길이를 통제한 tok/s 비교가 아니다. 확정 전사 시간축 지연에는 최대30초 분할 대기와 실제 추론이 함께 들어간다.

E2B는 시작 gap **37.33ms**, 상태 `stopped`. E4B는 시작 **10.67ms**와 종료 **26.67ms**의 명시적 gap, 상태 **`interrupted`**(error 없음)였다. 두 실행 모두 전체 입력 파형이 저장됐지만, E4B를 정상 종료·gap 0으로 보고하지 않는다. 1kHz 변환 후 전역 상관은 약0.999999999957, 샘플 대조 시각 오차0, 입력 파형 미포함0초였다. 저해상도 샘플링 진단이며 48kHz 비트 동일성·단어 정확도·실제 마이크 안정성 검증은 아니다.

호스트 전체 swap 중앙값은 E2B 약7.70GiB, E4B 약8.48GiB였다. 다른 앱과 swap 상태가 통제되지 않았고 각 모델의 peak GPU 메모리가 아니다. 이전 Qwen 장기 실행과 입력·호스트·코드 상태가 달라 직접 개선율을 계산하지 않는다.

전체 E2B 집계 (로컬 검증 자료·공개본 미포함), E4B 집계 (로컬 검증 자료·공개본 미포함), E2B 완료 화면 (로컬 검증 자료·공개본 미포함), E4B 완료 화면 (로컬 검증 자료·공개본 미포함).

### 12B의 두 실패도 비교 결과에 포함

12B는 동일 긴 입력을 두 번 시도했지만 **878초 실행을 완료하지 못했다**.

| 항목 | 1차 | 2차 |
|---|---:|---:|
| 보존된 원음 | 63.253초 | 54.091초 |
| 최초 중단 | 오디오 입력 미도착 | 원음 저장 확인 지연 |
| 녹음 중 첫 생성 실제 추론 | **96.637초 / 201토큰** | **99.560초 / 252토큰** |
| 예열 생성 | 22.046초 / 212토큰 | 14.854초 / 120토큰 |

첫 실행에서 겹친 확정 ASR 호출은 46.893초와44.475초까지 늘었다. 받은 원음은 보존됐다. 전체 길이 지연 분포는 측정할 수 없으므로 QAT의 P95와 같은 표에 넣지 않는다.

모델과 전사가 경쟁하는 동안 실제 입력/ACK 지연이 관측됐지만 격리된 GPU 원인 실험은 아니다. **자동 복구 실패에는 fixture 제약도 있다.** 녹음 실패 후 capture가 닫은 공유 AudioContext를 주입 fixture가 재사용해, 복구 시 닫힌 컨텍스트/AudioWorklet 로딩 실패가 발생했다. 이를 실제 마이크에서 자동 복구가 불가능하다는 증거로 해석하지 않는다. 실패 시 fixture가 무한 대기하던 부분은 종료 상태를 명시하도록 수정했다.

1차 실패와 ASR/생성 타임라인 (로컬 검증 자료·공개본 미포함), 2차 실패 (로컬 검증 자료·공개본 미포함), 1차 화면 (로컬 검증 자료·공개본 미포함), 2차 화면 (로컬 검증 자료·공개본 미포함).

## 4. 짧은 생성 내용의 대조

같은 작성 전사에는 뮤텍스·세마포어의 차이와 **금요일 4개 제안→월요일 3개로 정정, 여전히 미확정**이 들어 있다. 실제 메모 보강·원문 인용 후보·두 요약 reducer를 실행했다. reducer는 전체 전사→구간 요약 시간이 아니다.

| 모델 | 메모 보강 | 질문 후보 | reducer |
|---|---:|---:|---:|
| E2B QAT | 5.920초 | 3.676초 | 2.910초 |
| E4B QAT | 18.827초 | 8.475초 | 5.793초 |
| 12B MLX | 14.697초 | 11.163초 | 4.806초 |

세 모델 모두 형식·인용 검사를 통과했으나 E2B 메모는 구체적인 차이·정정 수치를 빠뜨린 일반적인 문장이었다. E4B와12B는 해당 내용을 남겼다. 12B 후보는 용어 차이와 일정 상태 두 카드를 반환했다. E4B reducer는 본문에 `[s1]`을 추가해 내부 ID를 노출했다. 원문 내용 보존과 JSON/ID 검증 통과는 별개다. 작은 1회 표본에서12B의 보편적 생성 우위를 주장하지 않는다.

## 5. 실제 녹음 종료 후 요약·메모

완료한 E2B 녹음 DB를 모델마다 별도 임시 복제했다. 같은 실제 Whisper 확정 전사와 **동일한 작성 메모** ‘도입부의 인물과 상황을 정리하고 원문과 대조한다’를 사용했다. 실제 사람의 즉흥 메모가 아니다. 원래 전사 오류를 보존한 입력이며, 실제 수업/회의 품질 시험과도 구분한다. ASR·다른 생성은 동시에 실행하지 않았다.

요약은 처음120초의 **37개 전사 조각+메모1개, 총38개 근거**다. 구간 요약38회와 최종 병합1회라는 동일한 제품 경로를 사용했다. 세 모델 모두 summary 입력에서 title label을 제외하고, 인용 최소1개 schema·전역별칭을 사용한 최신 비교다. 메모는60초에 연결한 요청이며 실제 제품이 고른 가장 가까운8개 전사 조각을 사용했다. 검색창은±90초지만 선택된8개는 약50~70초에 몰려, 약17초의 ‘아내’ 소개는 포함하지 않았다.

| 모델 | 2분 자료의 요약 시도 | 메모 보강 시도 | 실제 내용 대조 |
|---|---|---:|---|
| E2B QAT | **113.732초, 최종 인용 검증 통과** | **10.070초, 통과·적용v3** | 요약38조각을 거의 그대로 남겨 압축이 약함. 메모는 실제 상처·출혈을 ‘비유·회복’으로 해석해 부정확함 |
| E4B QAT | **227.879초, 최종 병합 인용 검사 실패** | **21.175초, 통과·적용v3** | 최종 병합의 `s5`가 빠져38개 구간 요약 보존. 메모는 요청 문장을 복사하고 원본 ID를 본문에 붙여 보강 효과가 없음 |
| 12B MLX | **343.382초, 최종 병합 인용 검사 실패** | **50.893초, 통과·적용v3** |8개 요약 항목으로 압축했으나 `s7,s8`이 본문에만 있고 구조화 인용에서 빠짐. 메모는 인근8개 전사 조각을 연결해 복사하며 전사 오류·미완결 문장도 남김 |

실패한 최종 병합을 성공 artifact로 저장하지 않았다. 12B가 문장 내용을 삭제했다는 뜻으로 구조화 인용 실패를 과장하지 않는다. 한편 실제 출력의 ‘불지폈다’는 원래 ASR의 ‘불지졌다’가 불 피우기로 해석된 내용 오류다. author ‘현진권’, ‘리브박스’, ‘헝겊 오락지’ 등은 이미 전사에 있던 오류이며 모두 생성 모델의 새 환각으로 세지 않았다. 12B는 원문 메모의 계획을 요약의 ‘정리’ 항목에 넣고 영어 `Uncertainty`·본문 내부 ID도 남겼다. **인용 ID 검증·원본 버전 보존과 읽기 좋은 사실 요약은 별개이며12B 품질 우위는 확인하지 못했다.**

메모 세 비교에서 원래 메모v1과 테스트 작성본v2는 보존됐고, 보강 초안의 명시 적용만v3으로 저장됐다. 위 ‘통과’는 JSON·근거 ID·적용 계약이며 유용한 보강으로 판정한 점수가 아니다. 공유 입력의 주체 문맥 부족도 메모 품질의 한계다.

최신 사용 파일: E2B 요약 (로컬 검증 자료·공개본 미포함)의 summary와 별도 label 없는 E2B 메모 (로컬 검증 자료·공개본 미포함), E4B 최신 두 결과 (로컬 검증 자료·공개본 미포함), 12B 최신 두 결과 (로컬 검증 자료·공개본 미포함). E2B 요약 파일에 함께 저장된 이전 label 포함 note는 최신 메모 비교에 사용하지 않았다.

### 12B 전체878초 요약은 완료하지 못함

전체 실제 전사292개와 동일 작성 메모1개를 제품 경로로 처리한 시도는 **1811.420초(30분11초)** 뒤 실패했다.231개 구간은 성공해 보존됐고,232번째 출력의 별도 불확실성 Section이 `evidence_ids:[]`를 반환해 Pydantic 검증에 걸렸다. 이 실패에서 요청 schema 최소1개를 맞췄다. ‘하건만’을 사람 이름처럼 해석한 오류도 있었다. **schema 수정 뒤 전체292개 제품 요약은 다시 완료 검증하지 않았다.** 전체 시도·성공 구간·실패 응답 (로컬 검증 자료·공개본 미포함).

별도로292개 전사만 한 번에 넣는 probe(ctx32768, 작성 메모 없음, 인용 부분집합 허용)도 실행했으나 **180초 HTTP read timeout**으로 응답을 얻지 못했다. 재개 가능한 제품 map/reduce 경로가 아닌 보조 진단이며 전체 요약 결과로 제공하지 않는다. 정확한 총 경과 시간은 저장되지 않았으므로180초를 실측 완료 시간으로 쓰지 않는다. probe 실패 (로컬 검증 자료·공개본 미포함).

현재 원문별 생성의 호출 수와 최종 인용 계약 때문에 실제 전체 요약이 느리고 실패할 수 있다. 구간 보존·명시 재시도는 데이터 손실을 줄이지만 완성 속도나 의미 품질을 보장하지 않는다. 다음 개선은 단순 대형 모델 교체보다 원문 문맥을 함께 주는 요약 단위와 인용 병합을 실제 한국어 자료로 검증하는 일이다.

## 6. 반영한 수정

- **짧은 확정 전사에도 VAD200ms**: 위39개 경계 실측과 회귀 검사에 근거한 한 줄 변경. 짧은 preview·긴 녹음 설정, 무음 추론 생략·시각 clamp·원음은 보존한다.
- **요약/메모의 모델 입력에서 제목 label 제외**: 실제 모델이 ‘긴 사람 음성 검증’ 제목을 본문 내용으로 섞어 썼다. 전달용 새 딕셔너리에서만 label을 빼고 저장된 출처 이름·원문·종류·페이지·시각·ID를 유지한다. 다른 답변/vision 입력은 바꾸지 않았다.
- **요약의 인용 별칭을 요청 전체에서 고정**: 서로 다른 원문이 각 구간의 같은 `s1`로 보이지 않게 하고 병합에서도 같은 원문→같은 별칭을 사용한다. 전달되지 않은 ID와 구간/병합의 누락·추가를 검증한 뒤에만 캐시·artifact를 저장한다. 근거가 빠졌다고 임의 ID를 덧붙여 통과시키지 않는다.
- **Section schema와 검증 일치**: `evidence_ids` 최소1/최대64개를 구조화 요청에도 명시한다. 12B가 빈 인용 불확실성 항목을 생성한 실제 실패에서 발견했다. `concept_ids` 등 빈 목록이 허용된 다른 필드는 바꾸지 않았다.
- **실패 증거 보존**: Whisper 미완료 상태를 CER로 채점하지 않는다. native 미완결 응답은 부분 출력·HTTP/토큰/완결 사유를 보존한다. 긴 fixture 실패는 끝난 상태와 원음·시간 기록을 남겨 무한 대기를 막는다. 제품의 물리 마이크 복구 정책을 이 fixture 수정과 혼동하지 않는다.
- **선택 모델 catalog 추가**: 승인한 QAT2종과12B 선택 항목. macOS arm64는 MLX 우선, 다른 플랫폼은 지원 runner만 표시한다. 기존 생성·임베딩 기본값과 색인은 유지한다.

실제 여러 원문을 한 번에8개씩 요약하는 최적화와 인용 수선용 추가 모델 호출도 시험했으나, 실제 모델에서 실패·지연이 늘어 제품에 적용하지 않았다. 현재는 기존 원문별 구간과 재개 가능한 병합을 유지한다. 형식 검증 통과를 의미 정확도나 충분한 압축으로 주장하지 않는다.

## 7. 재현

앱 폴더에서, 기존 검증된 엔진과 공개 음성 cache를 사용한다. 외부 AI API로 원음을 보내지 않았다. 자료/모델 다운로드만 네트워크를 사용했다. 실행 중 다른 모델 시험을 함께 돌리지 않는다.

```bash
# 고정된 일반 발화·잡음 manifest와 파일 SHA/정답 생성
.venv/bin/python -m experiments.collect_speech_conditions

# 12B 일반 음성 비교. 제품 Whisper는 현재 확정200ms이므로
# 이 보고서 최초30ms 결과와 설정을 구분해 새 파일에 저장한다.
.venv/bin/python -m experiments.compare_new_local_models \
  --models gemma4:12b --audio-only \
  --audio-manifest .local-state/runtime/speech-conditions-20261014/manifest.json \
  --output /private/tmp/gemma4-12b-speech-new.json

# 긴 원음 fixture는 존재하지 않는 새 임시 폴더가 필요하다.
.venv/bin/python experiments/serve_long_recording_fixture.py \
  /private/tmp/new-12b-live-check \
  .local-state/runtime/long-human-20261014/sul-part1.mp3 single gemma4:12b
# 출력 URL에서 시험 시작. 실패해도 원음/trace를 확인한다.

# 완료한 E2B/E4B 녹음 DB 사본으로 같은 2분 자료 생성 비교
.venv/bin/python -m experiments.validate_recording_assistance \
  /private/tmp/gemma4-e2b-qat-validated-long-final-20261014 gemma4:12b \
  --output /private/tmp/new-12b-assistance.json
```

QAT는 비교 후 삭제했으므로 재시험 전에 다시 받아야 한다. 예를 들어 `prepare_gemma_variant gemma4:e4b-it-qat --direct`로 공식 Ollama 배포물을 받고, `refresh_gemma_qat e4b docs/verification/gemma4-e4b-qat-header-comparison.json --output /private/tmp/e4b-refreshed.json`으로 고정 공식 파일의 SHA를 확인·가져온다. 두 명령은 `.venv/bin/python -m experiments.` 뒤의 모듈명이다. 비교에는 `--models lecture-study-gemma4-e4b-qat:validated --prepared /private/tmp/e4b-refreshed.json`을 사용한다. 이 재구성에는 기존 QAT와 수정 artifact가 잠시 함께 있어야 하므로 디스크 여유 검사에 따르며 Settings의 원래 QAT tag와 혼동하지 않는다.

## 8. 현재 선택과 남은 확인

1. **녹음 전사 기본값은 Whisper turbo 유지**. 일상 말투/반복/말 고침과 잡음의 오류를 이름 오류와 함께 기록한다. E4B의 작은 즉흥 표본 강점은 추가 비교 후보이며, 전체 잡음/강연 또는 장기 안정성의 보편적 승자가 아니다.
2. **16GiB Mac에서 녹음 중12B를 기본 추천하지 않는다**. 두 실제 입력/ACK 실패와 약97~100초의 첫 생성이 관측됐다. QAT 중 E2B는 이14분 실행에서 생성·ACK 지연이 작았고, E4B는 즉흥 발화에서 좋았지만 생성 대기와 ASR 지연이 더 컸다. 출력 토큰·호스트 swap 차이가 있어 단순 모델 속도 배수는 계산하지 않는다.
3. **12B는 요청대로 보관하고 녹음 종료 후 명시 선택 후보로 둔다**. 큰 모델이라는 이유로 더 좋은 요약이라고 단정하지 않는다. 메모 원본 보존·사용자 적용과 실패 시 구간 요약 재시도를 유지한다.
4. 다음 자료는 다른 연령/화자의 성인 즉흥 발화, 실제 카페/바람/팬 소음, 여러 화자·겹침,30–60분 강의/회의다. 한 명43초·인공 Gaussian 잡음·소설 낭독을 이 조건의 검증으로 대체하지 않는다. 실제 마이크 분리·물리 절전/복귀·M5·NVIDIA·외부 API는 이번 비교에서 실행하지 않았다.

이전 label 포함 출력,8개 batch와 인용 수선 진단은 `*-batched`, `*-bounded`, `*-final`, `*-repaired`, `*-explicit`, `*-diagnostic` 등에 실패 과정을 보존한 기록이다. 최신 프로토콜의 비교표와 섞지 않는다. 파일 이름의 `final`만으로 최신·성공으로 판단하지 말고 본문의 사용 파일과 `validated`를 확인한다.
