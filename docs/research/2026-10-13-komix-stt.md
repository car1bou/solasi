# whisper-medium-komixv2 전사 후보 검토

확인일: 2026-10-13 (Asia/Seoul)

범위: 제작자 모델 카드·고정 revision의 설정·파일 메타데이터, 평가 출처, whisper.cpp 1.9.5 변환 소스. 공식 원본 가중치와 필요한 설정 파일을 고정 revision에서 다운로드했고 전체 크기·SHA-256을 직접 검증했다. 원본 safetensors 헤더와 공식 변환 map의 호환성도 확인했다. 의존성 설치와 변환·추론은 이 조사 작업에서 수행하지 않았다.

## 판단

**한국어 강의·대화 전사를 위한 비교 후보로 적합하다. 현재 기본 모델로 확정할 근거는 부족하다.** 같은 제작자 표에서 small-Komix와 평균 차이가 작고, FLEURS에서는 원본 medium보다 높은 오류율을 보인다. 표의 우열을 M4의 실제 속도나 고유명사 정확도로 바꾸어 해석하지 않는다. [제작자 카드](https://huggingface.co/seastar105/whisper-medium-komixv2/blob/752b1b5bfa0c8219bca737ea180a4ad7eed1e621/README.md)

## 로컬 비교 준비 결과

2026-10-13 공식 `model.safetensors` 다운로드를 완료했다. 완성 파일의 3,055,544,304 bytes와 SHA-256 `8ce118afc03743d449ec266c3f0ada1027ac9e51c10fe34e13846b902d47c5d0`이 예상값과 일치했다. 이미 받은 276,824,064 bytes prefix를 보존한 뒤 나머지 3개 disjoint Range를 206·정확한 Content-Range·길이 확인 후 수신했다. 전체 해시가 맞은 뒤에만 완성 파일로 바꾸고 임시 prefix·조각을 정리했다. Flax나 제3자 MLX 가중치, Torch 등 추가 의존성은 내려받지 않았다.

- 준비 폴더: `<project-root>/.local-state/runtime/models/komixv2-original`
- 준비 파일: `model.safetensors`, `config.json`, `vocab.json`, `added_tokens.json`, `provenance.json`, `safetensors-header.json`
- 기록: 검증 provenance (로컬 검증 자료·공개본 미포함)
- 공식 conv_map을 AST literal로 읽어 947개 텐서 이름을 모두 변환 규칙에 대응시켰고 미지원 key·중복 target이 없음을 확인했다. 실제 가중치 변환·엔진 로딩과 성능은 후속 비교 작업에서 확인한다.

카드가 연결한 평가 저장소는 CER, 즉 문자 삽입·삭제·대치 합을 기준 문자 수로 나눈 비율을 사용한다. 철자 전사를 우선하고 AI-Hub 이중 전사·잡음 표기 정규화의 차이를 설명한다. AI-Hub 일부는 3,000개 표본, Kspon eval은 전체를 사용한다고 안내한다. [평가 저장소](https://github.com/rtzr/Awesome-Korean-Speech-Recognition/blob/bf08fcabb2bcb4a234c71f87cf5cc4a4113ca737/README.md), [표본 목록 안내](https://github.com/rtzr/Awesome-Korean-Speech-Recognition/blob/bf08fcabb2bcb4a234c71f87cf5cc4a4113ca737/docs/README.md)

다만 해당 저장소에는 제작자 카드의 Common Voice·FLEURS 전체 평가를 재현하는 코드, decoder 설정, 정규화 설정이 없다. 모델 카드에도 beam 크기, 언어 고정, VAD, 전체 표본 수와 고유명사별 결과가 없다. 따라서 이 점수를 앱의 5개 FLEURS 클립 CER와 직접 비교하지 않는다.

표의 medium-Komix 8개 영역 점수를 단순 평균하면 7.3025로 Average 7.30과 일치한다. 이는 **표에서 계산한 추론**이며 가중 평균 전체 CER라고 공개된 값은 아니다. “평균이 large v3보다 좋다”는 말은 이 영역 묶음에 한정하며, 모든 데이터셋·고유명사·잡음 조건의 우위라는 뜻으로 사용하지 않는다.

## 현재 whisper.cpp와의 호환성

고정 config는 `WhisperForConditionalGeneration`, 80 mel, 1,024 state, encoder/decoder 각 24층·16 heads, 오디오 context 1,500, 텍스트 context 448, vocab 51,865다. 전처리는 16 kHz·30초 입력을 사용한다. 일반 vocab JSON 50,258개 항목은 조회한 OpenAI medium vocab과 동일했다. 표준 medium 구조에 해당하므로 공식 HF→GGML 변환 경로를 적용할 수 있다는 **설정·소스 기반 판단**이다. 실제 변환·로딩을 확인한 것은 아니다. [모델 config](https://huggingface.co/seastar105/whisper-medium-komixv2/blob/752b1b5bfa0c8219bca737ea180a4ad7eed1e621/config.json), [전처리 설정](https://huggingface.co/seastar105/whisper-medium-komixv2/blob/752b1b5bfa0c8219bca737ea180a4ad7eed1e621/preprocessor_config.json)

원본 safetensors 헤더 112,616 bytes만 Range로 읽어 947개 F32 텐서, shape와 offset 일치, 연속된 데이터 구간, 전체 파일 끝 3,055,544,304 bytes를 확인했다. `proj_out.weight`는 없고 `model.decoder.embed_tokens.weight`는 `[51865, 1024]`다. config에 `tie_word_embeddings` override가 없으며 Transformers 4.43 기본값은 True, Whisper 클래스는 `proj_out.weight`를 tied key로 지정한다. 따라서 출력 projection을 decoder token embedding으로 처리하는 공식 GGML 변환 방식과 맞는다. [Transformers 기본 설정](https://github.com/huggingface/transformers/blob/v4.43.0/src/transformers/configuration_utils.py), [Whisper 클래스](https://github.com/huggingface/transformers/blob/v4.43.0/src/transformers/models/whisper/modeling_whisper.py), [고정 원본 파일 목록](https://huggingface.co/seastar105/whisper-medium-komixv2/tree/752b1b5bfa0c8219bca737ea180a4ad7eed1e621)

whisper.cpp 1.9.5는 HF 파인튜닝 모델에 `convert-h5-to-ggml.py`를 안내한다. 스크립트는 torch·numpy·transformers를 가져오고, 모델 디렉터리의 config/vocab/added_tokens와 OpenAI 저장소의 mel filter를 사용해 기본 F16 GGML을 만든다. 현재 제작자 저장소에는 GGML 파일이 없다. 변환 의존성은 일회성 평가 환경에 두고 제품 실행 환경에 추가하지 않는 방향이 작다. [공식 변환 안내](https://github.com/ggml-org/whisper.cpp/blob/v1.9.5/models/README.md#fine-tuned-models), [변환 소스](https://github.com/ggml-org/whisper.cpp/blob/v1.9.5/models/convert-h5-to-ggml.py)

설치·다운로드 승인 후 사용할 변환 형태:

```bash
python models/convert-h5-to-ggml.py   /absolute/path/to/pinned-komix-hf   /absolute/path/to/pinned-openai-whisper   /absolute/path/to/komix-ggml-output
```

모델 디렉터리는 고정 revision의 safetensors와 필요한 작은 설정 파일만 구성하고, 로컬 파일로 읽어 자동 네트워크 요청과 remote code 실행을 피한다. 변환된 GGML의 SHA를 새로 기록해야 한다. 원본 safetensors의 SHA는 변환 결과의 SHA가 아니다.

HF config에는 영어 언어 토큰을 포함한 forced decoder 설정이 있으나 generation config의 첫 언어는 null이다. 앱에서는 decoder 기본값에 맡기지 않고 한국어·전사 작업을 명시한다. GGML은 `-l ko`, HF/MLX는 `language="ko"`와 전사 작업을 지정한다. HF 기본 `return_timestamps=false`도 회의록의 근거 시간 제공 조건으로 확인해야 한다. [generation config](https://huggingface.co/seastar105/whisper-medium-komixv2/blob/752b1b5bfa0c8219bca737ea180a4ad7eed1e621/generation_config.json)

공식 whisper.cpp medium 표는 디스크 약 1.5 GiB, 메모리 약 2.1 GB를 제시한다. M4 16 GiB에서 단독 실행을 비교할 만한 규모지만 이 앱·OS·생성 모델 동시 실행의 메모리나 실시간 지연을 보장하는 수치는 아니다. CPU·Metal을 각각 측정하며 base 모델에서의 속도 결과를 medium에 그대로 적용하지 않는다. 양자화는 지원하지만 고유명사 품질 비교는 F16을 먼저 기준으로 하고 Q5 등은 별도 결과로 기록한다. [버전 고정 메모리·양자화 안내](https://github.com/ggml-org/whisper.cpp/blob/v1.9.5/README.md#memory-usage)

Core ML도 HF 전용 `generate-coreml-model.sh -h5 medium <local-model-path>` 경로가 있다. 선택한다면 encoder가 같은 Komix 가중치에서 생성됐는지 확인한다. 일반 `generate-coreml-model.sh medium`은 OpenAI 원본을 읽는 경로여서 Komix decoder와 무심코 섞어서는 안 된다. 출력은 일반 medium 이름이므로 원본 medium 파일 덮어쓰기와 잘못된 encoder 선택을 피하는 별도 폴더가 필요하다. 이 경로는 아직 실행하지 않았다. [생성 셸](https://github.com/ggml-org/whisper.cpp/blob/v1.9.5/models/generate-coreml-model.sh), [HF Core ML 변환](https://github.com/ggml-org/whisper.cpp/blob/v1.9.5/models/convert-h5-to-coreml.py), [원본 모델 변환](https://github.com/ggml-org/whisper.cpp/blob/v1.9.5/models/convert-whisper-to-coreml.py)

## 배포 허가의 미확인 사항

OpenAI 원본 저장소는 코드·가중치 MIT를 명시하지만 HF 원본 medium 메타데이터는 Apache 2.0을 표시한다. 어느 쪽도 Komix 작성자가 추가 학습한 가중치에 대한 별도 허가를 대신하지 않는다. 원본 Komix 저장소의 현재 상태로 상업용 허용 또는 앱 동봉 가능을 확정하지 않는다. [OpenAI 라이선스 설명](https://github.com/openai/whisper#license), [HF 원본 모델 API](https://huggingface.co/api/models/openai/whisper-medium?blobs=true)

AI-Hub 개방 데이터 정책은 영리·비영리 연구개발 활용, 출처 고지, 데이터 제공·국외 이용 제한을 함께 명시한다. 이를 근거로 Komix 가중치의 재배포가 자동 허용되거나 자동 금지된다고 단정하지 않는다. 원저자에게 가중치 라이선스·앱 동봉·변환본 재배포 범위를 확인해야 한다. 제3자 변환본의 `other` 표시도 이 확인을 대체하지 못한다. [AI-Hub 공식 이용정책](https://www.aihub.or.kr/intrcn/guid/usagepolicy.do?currMenu=151&topMenu=105)

## 동일 조건 비교 기록 양식

1. 원본 음성·reference를 고정하고 모델에는 정답 reference를 전달하지 않는다. 현재 5개 공개 클립은 실행·회귀 진단으로 사용하고 모델 순위의 대표 평가로 표현하지 않는다.
2. 먼저 무힌트 전사를 비교한다. 다음에는 실제 과목·자료에서 얻은 같은 범위의 용어 힌트를 모든 지원 모델에 적용해 개선·오삽입을 함께 기록한다.
3. 전체 파일과 앱의 라이브 분할 경로를 각각 평가한다. 모델 차이와 분할/VAD 차이를 분리하고 동일 분할에서도 비교한다.
4. CER 정규화·기준 문자 수, 숫자/날짜 불일치, 사람·장소·전문용어별 정확한 표기, 원음에 없는 문장을 기록한다.
5. warm/cold 시간, RTF, 최초/확정 전사 지연, RAM·swap, 원본 시간 대응과 재시도 보존을 확인한다. 전사와 생성 모델 동시 실행은 따로 기록한다.

고유명사 사후 수정은 원본 ASR와 수정 후보·근거·확인 여부를 보존한다. “자그로스산맥”처럼 음성만으로 구분하기 어려운 단어를 LLM이 확신해 덮어쓰는 방식은 비교 결과에 포함시키지 않는다. 확인되지 않은 수정으로 의미가 바뀔 수 있다는 제품 판단이다.
