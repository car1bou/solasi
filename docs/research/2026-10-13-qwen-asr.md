# Qwen3-ASR 한국어 전사와 Apple MLX 실행 경로

확인일: 2026-10-13 (Asia/Seoul)

확인 범위: Qwen 공식 모델·소스·기술 보고서, MLX-Audio 구현, MLX Community 변환 모델 메타데이터. 현재 PC는 Apple M4·16GiB이며, 아래 공개 점수는 이 PC에서 측정한 값이 아니다. 로컬 평가 준비와 결과는 별도 절에 기록한다.

## 판단

**Qwen3-ASR-1.7B의 MLX 4비트판은 현재 Mac에서 실제 비교할 후보로 적합하다.** 모델 카드에 MLX-Audio 호출이 있고 구현 소스도 존재한다. 이 판단은 실행 경로와 파일 크기에 근거하며 한국어 전사가 Whisper/komix보다 우수하다고 확정하는 판단은 아니다. 0.6B 4비트판은 메모리·처리 속도 비교 후보다. [1.7B MLX 카드](https://huggingface.co/mlx-community/Qwen3-ASR-1.7B-4bit), [MLX-Audio 구현](https://github.com/Blaizzy/mlx-audio/tree/v0.5.8/mlx_audio/stt/models/qwen3_asr)

위 Qwen 원본과 MLX 변환 가중치의 카드 라이선스는 Apache-2.0이다. MLX-Audio 코드는 MIT다. MLX 변환판은 Qwen의 원본 공개 모델을 커뮤니티가 변환한 산출물이며 Qwen 공식 배포판이라고 표기하지 않는다. [고정 MLX 설정](https://huggingface.co/mlx-community/Qwen3-ASR-1.7B-4bit/blob/78a389c776a5483b2d0d4ea5494e11012e0d6159/config.json), [양자화 조건](https://github.com/Blaizzy/mlx-audio/blob/v0.5.8/mlx_audio/stt/models/qwen3_asr/qwen3_asr.py#L832)

## Apple 실행 경로와 의존성

MLX-Audio v0.5.8, commit `70f4add32911bab6f869b824864ad9f1e24dcb97`의 실제 전사·aligner 코드를 읽었다. 현재 main의 해당 두 파일과 내용이 동일함도 확인했다. 모델 카드는 MLX-Audio 0.3.1로 변환했다고 표시하므로 변환 버전과 평가 런타임 버전을 따로 기록한다. [v0.5.8 릴리스](https://github.com/Blaizzy/mlx-audio/releases/tag/v0.5.8), [변환 버전](https://huggingface.co/mlx-community/Qwen3-ASR-1.7B-4bit#mlx-communityqwen3-asr-17b-4bit)

v0.5.8의 기본 의존성은 Python>=3.10, MLX>=0.31.1, Transformers>=5.14.0, huggingface_hub>=1.0, miniaudio, NumPy, SciPy, sounddevice, tqdm이다. 기본 MLX STT 설치에 PyTorch/vLLM이 명시적으로 필요하지 않다. 한국어 forced alignment에는 별도로 `soynlp`가 필요하다. Qwen 공식 `qwen-asr` 패키지의 Transformers==4.57.6 고정과 충돌하므로 한 환경에 혼합 설치하지 않는다. [MLX pyproject](https://github.com/Blaizzy/mlx-audio/blob/v0.5.8/pyproject.toml), [한국어 토큰화](https://github.com/Blaizzy/mlx-audio/blob/v0.5.8/mlx_audio/stt/models/qwen3_asr/qwen3_forced_aligner.py#L97), [Qwen pyproject](https://github.com/QwenLM/Qwen3-ASR/blob/7c6daf77a2421100f5fb066495372c00129d39ff/pyproject.toml)

정해진 local 모델 폴더를 로드하면 본체는 MLX 구현을 사용한다. post-load에서 Transformers tokenizer/feature extractor를 읽으며 코드에 `trust_remote_code=True`가 있다. 이번 고정 q4 산출물은 `.py` 파일과 config/tokenizer `auto_map`이 없고 tokenizer는 기본 Qwen2 계열이다. 임의 repository의 remote code를 실행하도록 허용하는 앱 기능으로 확대하지 않는다. [post-load 코드](https://github.com/Blaizzy/mlx-audio/blob/v0.5.8/mlx_audio/stt/models/qwen3_asr/qwen3_asr.py#L837), [고정 파일 목록](https://huggingface.co/mlx-community/Qwen3-ASR-1.7B-4bit/tree/78a389c776a5483b2d0d4ea5494e11012e0d6159)

검토된 호출 예:

```python
from mlx_audio.stt.utils import load_model
model = load_model("/path/to/pinned-qwen3-asr-1.7b-4bit")
result = model.generate("audio.wav", language="Korean", temperature=0.0)
print(result.text)
```

## 고유명사 힌트와 시간 근거

공식 `qwen-asr`에는 `transcribe(..., context=...)`가 있고, Transformers native `-hf`판에는 `prompt`에 어휘·이름·배경 정보를 넣는 API가 있다. MLX v0.5.8도 `system_prompt` 및 `hotwords`를 실제 system prompt에 결합한다. 지원 사실과 고유명사 개선 효과는 구분한다. 힌트가 다른 이름을 잘못 추가하는지도 동일 음성으로 비교해야 한다. [공식 context 코드](https://github.com/QwenLM/Qwen3-ASR/blob/7c6daf77a2421100f5fb066495372c00129d39ff/qwen_asr/inference/qwen3_asr.py#L300), [native prompt 문서](https://huggingface.co/Qwen/Qwen3-ASR-1.7B-hf#context--hotwords), [MLX hotwords](https://github.com/Blaizzy/mlx-audio/blob/v0.5.8/mlx_audio/stt/models/qwen3_asr/qwen3_asr.py#L1333)

**MLX ASR의 `segments.start/end`는 내부 입력 조각의 범위다.** 음성에서 모델이 예측한 단어/문장 경계가 아니다. streaming 토큰의 start/end는 토큰 수에 따른 추정값이며 원음 인용의 정확한 시각으로 쓰지 않는다. 정밀 시간은 별도 forced aligner로 음성과 전사문을 정렬해야 한다. [조각 시각 생성](https://github.com/Blaizzy/mlx-audio/blob/v0.5.8/mlx_audio/stt/models/qwen3_asr/qwen3_asr.py#L1495), [streaming 추정 시각](https://github.com/Blaizzy/mlx-audio/blob/v0.5.8/mlx_audio/stt/models/qwen3_asr/qwen3_asr.py#L1647)

ForcedAligner는 한국어 포함 11개 언어와 단어/문자 시각을 지원하며 별도 가중치가 필요하다. 공식 소개는 최대 300초를 제시하나 현재 Qwen wrapper의 `MAX_FORCE_ALIGN_INPUT_SECONDS`는 180초다. MLX aligner의 확인한 `generate`는 자동 장시간 분할 없이 입력 한 건을 처리한다. 제품에서 짧은 원음 범위로 정렬하고 실제 시간 오차를 검증해야 한다. [공식 forced aligner](https://github.com/QwenLM/Qwen3-ASR#forcedaligner-usage), [wrapper 제한](https://github.com/QwenLM/Qwen3-ASR/blob/7c6daf77a2421100f5fb066495372c00129d39ff/qwen_asr/inference/utils.py#L33), [MLX aligner](https://github.com/Blaizzy/mlx-audio/blob/v0.5.8/mlx_audio/stt/models/qwen3_asr/qwen3_forced_aligner.py#L638)

## 스트리밍의 범위

| 경로 | 확인된 동작/제약 |
|---|---|
| Qwen 공식 qwen-asr | PCM16k streaming state API 제공. 현재 vLLM backend 전용이며 batch·timestamp 반환을 지원하지 않음 |
| MLX-Audio `stream_transcribe` | 전달된 파일/배열을 먼저 로드하고, 입력 조각별 생성 토큰을 내보냄. 라이브 PCM을 계속 추가하는 state API가 아님 |
| 현재 앱과 연결할 경우 | 앱이 저장한 짧은 범위를 반복 전사하는 방식으로 연결 가능성 검토. native 지속 streaming 상태를 지원한다고 표시하지 않음 |

근거: [Qwen streaming 상태 코드](https://github.com/QwenLM/Qwen3-ASR/blob/7c6daf77a2421100f5fb066495372c00129d39ff/qwen_asr/inference/qwen3_asr.py#L584), [MLX streaming](https://github.com/Blaizzy/mlx-audio/blob/v0.5.8/mlx_audio/stt/models/qwen3_asr/qwen3_asr.py#L1533).

## 한국어 점수의 해석

보고서는 한국어에 CER을 사용한다고 명시한다. Appendix A.2의 한국어 항목은 다음과 같다.

| 저자 보고 입력 | 0.6B CER (%) | 1.7B CER (%) |
|---|---:|---:|
| CommonVoice-ko | 8.48 | 5.88 |
| MLC-SLM-ko | 10.31 | 8.61 |
| FLEURS-ko | 3.72 | 2.57 |

다국어 Table 5의 평균 4.90 등은 여러 언어의 WER/CER macro-average이며 한국어 CER로 바꾸어 표기하지 않는다. 위 원본 결과는 MLX 4비트판의 결과도 아니고 현재 앱의 고유명사·강의·회의 검증도 아니다. 같은 표에는 한국어 Whisper/komix 개별 결과가 없어 이 자료만으로 한국어 우열을 확정하지 않는다. 속도 보고는 CUDA/vLLM·동시 요청 환경의 결과로 현재 M4 지연과 구분한다. [보고서 §4.1](https://arxiv.org/html/2601.21337#S4.SS1), [Appendix A.2](https://arxiv.org/html/2601.21337#A1), [속도 조건 §2.4](https://arxiv.org/html/2601.21337#S2.SS4)

## 현재 M4에서 실제 평가

2026-10-13 14:57 UTC에 시작해 Apple M4·16GiB의 Metal에서 실제 실행했다. 앱 환경과 분리된 `lecture-study/.local-state/runtime/qwen-eval-venv`에 MLX-Audio 0.5.8/MLX 0.32.3/Transformers 5.19.0/NumPy 2.5.4/HF Hub 2.2.0을 설치했다. 공식 PyPI의35개 wheel 합계는121,983,994bytes(116.3MiB)이며 SHA256을 확인해 hashlocked 오프라인 설치했다. `pip check`는 `No broken requirements found.`였다. Torch/vLLM/TensorFlow/JAX는 설치하지 않았다.

고정 q4 모델의10개 필수 파일은1,607,631,587bytes다. 기존 부분 다운로드를 보존해 정확한3개 HTTP Range(206/Content-Range 검증)로 완성한 뒤 전체 가중치 SHA256을 확인했다. metadata의 Git blob 해시 또는 LFS SHA256을 모든 파일에 적용했다. local tokenizer는 Qwen2Tokenizer이고 config/tokenizer auto_map 및 remote Python 파일이 없음을 확인했다. 실행 중에는 `HF_HUB_OFFLINE=1`, `TRANSFORMERS_OFFLINE=1`을 설정했고 앱 기본 전사 엔진과 제품 의존성은 바꾸지 않았다.

평가는 익숙한 FLEURS5개와 사전에 정한 추가20개 음성을 나누어 기록했다. 추가20개 안에는 동일 문장의 다른 녹음이 있고 기존5개와 문장이 겹치는 녹음도 있다. 모두 원음16kHz mono float32 WAV를 그대로 읽었다. `language=Korean`, `temperature=0.0`, `batch_size=1`, `max_tokens=1024`, hotwords/system_prompt 없음으로1회씩 순차 실행했다. 기준 전사는 모델에 전달하지 않고 인식 후 점수 계산에만 사용했다. 원음과 가중치의 전후 해시가 동일하며 빈 출력과 token limit 도달이 없었다.

| 표본 | 원음 길이 | 진단 CER(문자 편집/기준 문자) | 한 번 로드한 모델의 전사 합계 | 전사 시간/원음 길이 |
|---|---:|---:|---:|---:|
| 익숙한5개 | 50.88초 | 7/215 = **3.26%** | 6.270초 | 0.123 |
| 추가20개 | 261.48초 | 24/947 = **2.53%** | 17.901초 | 0.068 |
| 합계25개 | 312.36초 | 31/1162 = **2.67%** | 24.171초 | 0.077 |

패키지 import는0.200초, 모델 로딩은2.478초로 따로 측정했다. 모델은 한 번 로드해 재사용했다. 첫 음성의 전사는3.277초였고 이후 음성은0.473~1.721초였다. 모델을 매 입력마다 새 프로세스에서 로드하는 현재 Whisper CLI 측정과 동일한 로딩 조건이 아니므로 전체 서비스 지연으로 곧바로 순위를 정하지 않는다. 파일 읽기/feature 처리와 생성은 위 전사 시간에 포함되며 다운로드·설치는 제외한다.

MLX allocator 최대 peak는2,682,383,212bytes(2.50GiB), 프로세스 누적 최대 RSS는1,347,371,008bytes(1.25GiB)였다. 둘은 다른 계측이며 통합 메모리에서는 더해서 전체RAM이라고 표기하지 않는다. 다른 전사 벤치와 중첩되는 것을 피했고 LLM 동시 실행은 측정하지 않았다.

진단 CER은 기존 평가와 같은 NFKC·소문자·Unicode 문자/숫자 필터를 사용한다. 띄어쓰기·문장부호는 제외하지만 `일만/1만`, `미터/m`은 오류로 센다. 기준 전사의 괄호 로마자도 세므로, `아순시온(Asunción)`에서 한글 이름이 맞아도 괄호 부분을 출력하지 않은8글자가 오류에 포함된다. 이 점수를 순수한 발화 음소 오류율이나 공식 FLEURS benchmark 결과로 해석하지 않는다. 25개 중14개가 이 정규화 기준에서 문자 오류0개였다는 관찰도 전체 강의·회의 품질의 보장은 아니다.
