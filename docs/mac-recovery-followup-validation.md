# Mac 장시간 녹음 복구·한국어 음성 후속 검증

2026-10-16 · Apple M4 / 16GiB · macOS arm64.

grilling으로 기존 복구·원문 보존 정책과 실제 코드의 경계를 검토하고, ponytail로 재현된 원인만 수정했다. 사용자 보관함과 분리한 `Solasi Native Validation.app`에서 실제 마이크·페이지 필기·강제 종료를 검사했다. [집계와 입력 해시](verification/mac-recovery-followup-20261016.json)에는 원음·정답 문장·모델 응답·인증값을 넣지 않았다.

## 수정한 문제

### 입력이 늦게 복귀하면 자동 재연결이 거절됨

종료 후 전사 방식에서 연결이 끊긴 녹음은 유예 시간 뒤 기존 원음의 전사를 시작한다. 이보다 늦게 마이크 입력이 돌아오면, 종전 `start_recording`은 이미 전사가 시작됐다는 이유로 새 복구 구간 요청을 422로 거절했다. 프런트엔드가 실제 새 입력을 기다리는 기존 동작과 서버의 검증 조건이 충돌했다.

이전 구간이 **중단 상태일 때만**, 이미 전사가 시작됐더라도 같은 세션·전사 방식으로 새 구간을 열 수 있게 했다. 기존 원음·전사·작업 ID는 바꾸지 않는다. 새 구간은 기존 capture 계보와 시간 간격을 유지하며 종료 전까지 전사를 보류한다. 정상적으로 종료한 녹음, 다른 세션·전사 방식, 현재 녹음 중인 구간은 계속 거절한다.

- 회귀 검사에서 수정 전 422를 재현했고, 수정 후 관련 15개 검사를 통과했다.
- 실제 HTTP·WebSocket·설치된 Whisper로 15.78초 사람 음성을 처리했다. 연결 중단 후 **48.679초**가 지나 기존 전사가 완료된 상태에서도 복구 요청이 수락됐다. 기존 PCM 해시·전사 전체 행·작업 ID가 유지되고 새 구간은 종료 후에만 전사를 시작했다.
- 이 별도 시험은 원음을 WebSocket으로 재생한 것으로, 실제 마이크 하드웨어의 절전 복귀 시험과 구분한다.

### 짧은 원음 누락의 시각 표시

실제 48kHz 녹음에 약 0.165초의 초기 입력 간격이 있었다. 초 단위 표시는 이를 `0:00–0:00`으로 보여줬고, 밀리초 표시를 처음 적용했을 때는 정수가 아닌 밀리초가 `0:00.2.666…`으로 깨졌다.

기존 대본 시각 함수에서 정수 밀리초로 반올림한 뒤 표시하도록 수정했다. 실제 검증 앱에서 `0:00.003–0:00.168`, `0:00.003–0:00.051`을 확인했다. 48kHz 프레임 변환과 분 경계 반올림 검사도 추가했다. 저장 프레임이나 전사 시각을 수정하지는 않는다.

### 정리된 빌드 캐시를 참조하던 음성 비교 도구

두 비교 스크립트가 삭제된 `runtime/build/whisper/bin`을 직접 참조해 18개 입력이 모두 실행 실패했다. 제품의 기존 `engine_paths`를 재사용해 설치된 `runtime/asr/bin`을 찾게 했다. 같은 18개 입력에서 18개 모두 실제 실행이 완료됐다.

이 비교 도구의 기본 VAD 여백과 제품의 1초 문맥 여백은 다르므로, 경로 복구 전후 결과를 정확도 개선 수치로 발표하지 않는다. `compare_cpp_models.py`의 전체 모델 조합은 다시 실행하지 않았다.

### 절전 증거의 제한

사용자는 30~60초 잠자기·복귀 완료를 알렸다. 그러나 이번 시스템 로그에서 `kIOMessageSystemWillSleep`은 19:03:34.481, 외부 입력에 따른 화면 깨우기는 19:03:39.334, 화면 켜짐은 19:03:39.650에 기록됐다. 이번 시간 범위의 `pmset`에는 대응하는 Deep Idle Sleep/Wake 쌍이 없었다.

따라서 **30~60초 동안 실제 저전력 절전이 유지됐다고 주장하지 않는다.** 이번에 확인한 것은 약 5초 간격의 소프트웨어 잠자기 통지·화면 복귀와 그때의 실제 마이크 중단·자동 복구다. 이전 [별도 절전 검증](mac-recovery-validation.md)의 43초 등 결과와 이번 관찰을 합쳐 하나의 30분 이상 Deep Idle 검증으로 취급하지 않는다.

장시간 녹음 중 이 경로를 수행한 서버는 늦은 복귀 허용 조건 수정 전에 시작돼 있었다. 최종 서버는 이후 강제 종료·재실행·필기 복구에서 사용했고, 늦은 복귀 수정 자체는 위의 실제 HTTP/WebSocket/Whisper 시험으로 별도 확인했다. 최종 변경으로 다시 30분을 녹음하거나 밤샘·장기 Deep Idle 시험을 완료한 결과는 아니다.

완료한 획과 로컬 초안 저장이 끝난 메모, 서버가 저장한 PCM을 검사했다. 끝내지 않은 획, IndexedDB 저장 완료 전 즉시 소실, 아직 전송되지 않은 마지막 음성 프레임, 디스크 고장·전원 차단의 무손실을 보장하지 않는다. 검증 앱은 시험 후 정상 종료했다.

## 정답이 있는 실제 한국어 음성 추가 비교

추론 전에 입력 선택을 고정하고, 정답은 점수 계산에만 사용했다. 새 모델 다운로드나 외부 AI API는 사용하지 않았다. 모델·자료 revision, 입력 SHA256, 그룹별 편집 수는 연결된 집계 파일에 있다.

### 추가 자료

- [Google FLEURS](https://huggingface.co/datasets/google/fleurs): 한국어 test viewer 순서 68~87의 **새 원본 20개·251.64초**. 공식 revision의 TSV 및 원본 archive로 확보했고 archive SHA256과 각 파일·디코딩 샘플 수를 확인했다. 기존 캐시 65행의 ID·정답·샘플 수도 대조했다. 낭독 자료이며 화자 ID·나이가 없어 20명의 독립 화자로 표현하지 않는다. CC BY 4.0.
- [서울코퍼스 공개 음성](https://www.openslr.org/113/): 기존 성인 3명의 인터뷰에서 종전 평가 구간·문장과 겹치지 않는 **15개 새 발화 구간**을 선택했다. 새 화자나 새 원본 녹음을 수집한 것은 아니다. 원본 사용 조건은 CC BY-NC 2.0이며 개인 비상업 비교에 사용했다.
- [DEMAND](https://zenodo.org/records/1227121): 위 15개 발화를 실제 사무실·식당 소음과 각각 10dB SNR로 혼합했다. 깨끗한 조건까지 **45조건·124.02초**이며 같은 발화의 반복을 포함한다. 새로운 고유 발화량은 약 41.34초다. 혼합은 파생 조건이며 한국어 현장 회의 녹음은 아니다. 원음·혼합물을 Git이나 앱에 배포하지 않았다. 기록의 이용 조건 표기 차이가 있어 제작자 설명의 CC BY-SA 3.0을 보수적으로 적용했다.

FLEURS 자료 API의 일시적 실패에는 공식 TSV와 archive를 대안으로 사용했다. TSV는 인용부호를 실제 문자로 읽고 원본 파일명 사전 순서로 정렬해야 viewer 순서와 맞는다. 준비 단계 manifest의 미다운로드 설명은 선택 시점의 기록이며, 완료 수집·샘플·해시 대조를 별도로 검사했다.

### 같은 입력의 모델 비교

CER는 NFKC·소문자·유니코드 문자/숫자로 정규화한 문자 편집률이다. **D/I는 삭제/삽입 편집 수**이며 의미적 누락·환각의 발생률과 같지 않다.

| 조건 | 기본 Whisper 편집/정답 글자 · CER | D/I | Qwen 재전사 후보 편집/정답 글자 · CER | D/I |
| --- | ---: | ---: | ---: | ---: |
| 새 FLEURS 20개 | 50/926 · **5.40%** | 36/0 | 53/926 · 5.72% | 37/2 |
| 새 성인 발화 깨끗한 15개 | 15/271 · **5.54%** | 7/1 | 18/271 · 6.64% | 4/4 |
| 같은 성인 발화 + 사무실 소음 15개 | 16/271 · **5.90%** | 7/1 | 19/271 · 7.01% | 5/4 |
| 같은 성인 발화 + 식당 소음 15개 | 55/271 · 20.30% | 28/2 | 41/271 · **15.13%** | 15/4 |

Qwen은 새 FLEURS에서 개선 2·악화 4·동률 14개, 성인 45조건에서 개선 7·악화 9·동률 29개였다. 식당 소음에서 유리했지만 다른 조건에서는 더 나빴다. **기본 Whisper를 유지하고, Qwen은 사용자가 확인·적용하는 재전사 후보로 유지했다.**

### 같은 기존 90조건과 VAD 실험

기존 90조건의 재실행은 편집 185/1829, CER **10.11%**, D86/I11로 종전 결과와 같았다. 이 묶음은 성인 인터뷰·낭독·일상 발화·실제 소음 혼합·강연·일부 수동 정답 구간을 포함하며, 같은 발화의 반복 조건도 있다. 일부 일상 발화는 성인이 아닌 동일 청소년 화자 자료다. 90명의 독립 화자나 완전한 다화자 대화 정답으로 해석하지 않는다.

| 동일 90조건 설정 | 편집/정답 글자 | D/I | 판단 |
| --- | ---: | ---: | --- |
| 현재 최소 발화 250ms·여백 1000ms | 185/1829 | 86/11 | 유지 |
| 최소 발화 100ms | 191/1829 | 81/18 | 전체 오류 증가로 기각 |
| VAD 끄기 | 243/1829 | 62/78 | 삽입 증가로 기각 |

VAD를 끄면 작은 음량에서 일부 앞 단어가 살아났지만 짧은 발화·소음에서 관계없는 방송형 문장 추가가 발생했다. 최소 발화 시간을 줄이는 실험도 일부 삭제를 줄이는 대신 삽입을 늘렸다. 문구만으로 자동 삭제하거나 더 긴 결과를 자동 채택하지 않는다.

**특히 식당 소음과 짧은 일상 발화의 누락·추가 인식은 해결되지 않았다.** 이번 코드 수정의 효과는 복구·시각 표시·비교 도구 실행에 있으며, 모델 정확도 향상을 달성했다고 표현하지 않는다. 독립 청취 재주석·한국어 의미 오류 전수 판정·전체 대화 CER는 없고, 다른 작업도 같은 Mac에서 실행돼 추론 시간을 모델 속도 순위로 사용하지 않는다.

## 최종 검사와 재현

- 전체 백엔드 **369개**, 프런트엔드 **56개**, 네이티브 검증 fixture **5개** 검사 통과.
- TypeScript 검사, Vite 프로덕션 빌드, `git diff --check` 통과.
- 늦은 복구 422 및 소수 밀리초 시각 오류는 수정 전 실패를 확인한 뒤 수정 후 재검사했다.
- 샌드박스 안의 초기 소켓 EPERM·Metal GGML 오류는 권한을 갖춘 같은 실행에서 재검사했다. 환경 제한을 제품 버그 수정으로 취급하지 않았다.
- 새 Python 환경이나 의존성은 추가하지 않았다. 설치 앱의 `launch.json`이 가리키는 기존 Python을 사용했다.

`APP_PY`를 설치 앱 `Contents/Resources/launch.json`의 `python` 값으로 지정한 뒤 저장소 루트에서 실행한다. 원음·정답 manifest와 설치된 모델은 별도로 필요하며 이 명령이 다운로드하지 않는다.

```sh
"$APP_PY" -m unittest discover -s tests
"$APP_PY" -m unittest experiments.test_native_validation
npm --prefix frontend test
npm --prefix frontend run build
"$APP_PY" experiments/evaluate_sentence_asr.py whisper --manifest /private/tmp/fixed-manifest.json --output /private/tmp/new-whisper-result.json
"$APP_PY" experiments/evaluate_sentence_asr.py qwen-review --manifest /private/tmp/fixed-manifest.json --output /private/tmp/new-qwen-result.json
```

복구 시험은 별도 검증 앱에서 원음 저장 프레임·접두부 해시·페이지 버전 기준을 잡고, 실제 잠자기 통지·복귀·새 입력을 대조한 뒤 정확한 검증 PID만 강제 종료한다. 서버에 저장되지 않은 초안은 제품 화면에서 작성·내보낸 JSON과 재실행 후 버전을 비교한다. 운영 데이터나 DB 직접 쓰기로 이 과정을 대신하지 않는다.
