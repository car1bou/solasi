# Mac GUI 후속 검증 — 2026-10-27

## 응답 대기 조사

이전 검증에서는 Qwen 작업이 완료됐지만 GUI 시나리오가 제한 시간에 도달했다. 당시 로그는 API 경로만 남겨 worker 응답·Swift reply·JavaScript 재개 중 어느 단계가 멈췄는지 판단할 수 없다.

같은 재실행 경로에 요청 시각, frame 종류·ID·크기, HTTP 상태·작업 상태, Swift reply 호출, JavaScript await 전후, 화면 가림 상태의 heartbeat를 추가해 별도 보관함에서 실행했다. 설치 앱의 화면·엔진과 공통 WorkerBridge를 사용했다.

- 새 Qwen 작업은 약 12.91초에 완료됐다. 이전 Gemma 실패 요청은 보존됐다.
- HTTP reply 59건을 확인했다. 작업 조회에서는 queued·running·done이 전달됐고 JavaScript가 done 응답 이후 재개됐다.
- 검증 화면이 `hidden`·포커스 없음인 동안에도 heartbeat와 조회가 계속됐고 시나리오가 통과했다.
- 작업 조회는 SQLite를 매번 읽으며 별도의 상태 cache가 없다. 기존 결과 크기도 응답 제한에 못 미쳤다.

**이전 시간 초과의 정확한 원인은 확정하지 못했다.** 이번 계측과 실제 설치 앱에서는 재현되지 않았다. 일반적인 GUI 통신 결함이나 화면 가림을 원인으로 단정하지 않았고, 근거 없이 제품의 시간 제한·재시도 정책을 바꾸지 않았다. 계측 준비 과정의 중복 JavaScript 선언과 기존 로그 함수 이름 충돌은 검증 프로그램에서 수정했다. 이는 이전 제품 문제의 원인이라는 뜻이 아니다.

## 실제 설치 앱에서 확인한 흐름

기존 보관함을 백업한 뒤 새 검증 과목과 강의 기록에서 조작했다. 기존 과목·기록을 편집하지 않았다. 기존에 확보한 실제 한국어·영문·수식 혼합 손글씨 이미지를 연결했다.

| 단계 | 관찰 결과 |
| --- | --- |
| 자료 연결 | Mac 파일 선택창에서 손글씨 노트로 연결, 원본 페이지 표시 |
| 메모 | 별도 검증 메모가 자동 저장돼 v2로 표시 |
| 인식문 수정 | Vision 후보를 원본과 대조해 수정, 미승인 초안의 native 저장도 DB에서 확인 |
| 승인 | ‘확인하고 지식에 추가’ 후 확인한 손글씨와 출처 ID 생성 |
| Qwen 답변 | 약 20.52초의 생성 사용량 표시, 저장된 답변과 승인문 출처 버튼 표시 |
| Qwen 요약 | 약 17.10초의 생성 사용량 표시, 원문 2개 처리·최종 인용 2개 |
| 검색 | 실제 ‘검색·개념’에서 같은 과목 전체 검색, 확인한 손글씨·페이지 메모 2개 반환 |
| 원문 열기 | 검색 결과에서 당시 원본과 수정·승인한 문자열 표시 |

요약의 핵심 원문에는 ‘지민은 외동’이라는 주어, 부모님이 돌아가신다면이라는 가정, 실제 사망을 뜻하지 않는다는 부정, 금요일 복습과 미정인 제출 기한이 모두 그대로 남았다. 이는 짧은 검증 메모의 보존 확인이며 모든 긴 강의의 요약 품질을 입증하지 않는다.

답변의 수식 `F(x)=P(X≤x)`, `a<b이면 F(a)≤F(b)`와 승인 출처 연결은 확인했다. 다만 한국어 설명에 혼합 표기와 근거에 대한 부정확한 한계 문구가 남았다. 답변 내용을 완벽한 것으로 평가하지 않았으며 사용자는 원문 근거를 확인해야 한다.

수정본 **0.3.27/build37**을 실제 Solasi에 설치해 재실행한 뒤 같은 메모 v2·승인문·원본 페이지, 저장된 답변·요약, 검색 결과를 다시 열었다. 같은 검색을 새로 실행해 승인문·메모 2개를 다시 확인했다. 출처 창에는 당시 버전 v1과 원문 연결이 남고 잘못된 ‘변경됨’ 표시는 사라졌다. 수정본에서 새 Qwen 답변(15.70초)·새 요약(16.64초)도 화면의 ‘저장됨’까지 확인했다. 두 시각은 앱의 생성 metadata이며 시작 준비·검색을 포함한 전체 작업 시간이나 성능 개선 비율이 아니다. 새 요약에도 주어·가정·부정·후반 내용이 그대로 남았다.

설치 직전 가장 최신 화면 파일 13개의 해시를 기록하고 동일하게 복사했다. 설치 후 같은 해시와 기존 데이터·모델 경로 보존을 대조했다. 앱은 정상 종료·교체했으며 기존 앱 백업을 남겼다. 사용자 앱을 강제 종료하지 않았다. 이번 시험은 정상 재실행이며 새 강제 종료·절전·마이크 녹음 시험은 아니다.

## 확인한 오류와 수정

**메모만 바뀌어도 승인한 손글씨 출처가 ‘변경됨’으로 표시됐다.** 같은 페이지의 메모와 잉크가 하나의 페이지 버전을 공유하는데, 출처 조회가 두 종류 모두 페이지 버전만 비교했기 때문이다. 검색·승인에서는 이미 잉크 변경 여부를 별도로 검사해 같은 출처를 유효하게 사용하고 있었다.

출처 조회의 전체 페이지 버전 비교를 페이지 메모에만 적용했다. 손글씨는 기존처럼 원본 파일 현재성과 인식의 승인·stale 상태로 판단한다. 필기를 바꾸거나 지우면 기존 경로가 stale로 바꾸며 검색에서 제외한다. 원래 출처 버전·문자열·당시 잉크·원본 연결은 재작성하지 않는다.

새 회귀 검사는 수정 전 `changed != current`로 실패했다. 수정 후에는 메모 변경 뒤에도 승인문이 current·검색 가능하며, 잉크를 지우면 changed·검색 제외가 되고 과거 문자열·잉크는 보존됨을 확인했다. 집중 검사 21개가 통과했고 독립 검토에서 P1/P2 지적은 없었다.

다른 개발 작업을 제외한 고정 Mac 소스의 전체 Python 검사 680개 중 676개 통과·선택 검사 4개 생략, 실패 0개였다. 새 프런트엔드 동작은 추가하지 않았다.
