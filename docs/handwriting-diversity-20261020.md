이미지·PDF·응답·보관함 복사본은 로컬 검증 폴더에만 둔다. 이 문서나 배포 앱에 원본 이미지를 포함하지 않는다. 계정이 다른 점을 확인했으며 실제 작성자의 신원을 검증한 것은 아니다.

새 영역은 8개다. 그중 두 개는 실제 한국어 문장의 오른쪽을 잘라 만든 경계 시험이며, 원본과 파생본을 독립 표본으로 세지 않는다. 새 추론 전에 별도 이미지 판독으로 정답·좌표·SHA256을 동결했다. 동결 manifest의 SHA256은 `87d5514e7ca49625012d0881922c09d91eb5aca9f83eb8fa2c2c84baa08a4a1a`이다.

부호는 같은 수학 의미의 Unicode/LaTeX 표현을 허용하고, 공백 차이와 의미 변화는 구분한다. 온전한 단어 뒤에서 멈춘 문장에 `[판독 불가]`가 없다는 이유만으로 문장 완성 환각으로 판정하지 않는다. 단어 내부 누락, 이미지 밖 후속 구절 추가, 기호 삽입, 불필요한 판독 보류는 별도로 대조한다. 새 영역에 없는 `≤`, `∩`, `∪`는 이전 CDF·조건부확률·Jensen·λ 노트 네 영역으로 회귀 확인한다. 알려진 소규모 개발 표본으로 일반 정확도나 필체 전체의 CER를 발표하지 않는다.

## 현재 제품 경로의 재측정

기존 MLX 런타임과 설치 모델을 사용하고 한 번에 한 모델씩 실행했다. 자동 Vision 경로는 유지하며, Qwen은 기존의 작은 입력 확대, Gemma 12B는 원본 입력과 기존 원문 지시를 사용했다.

| 새 영역 | Qwen 4B | Gemma 12B |
|---|---|---|
| 옅은 한국어 완성 문장 | 한국어 보존 | 제목 `뜻과→높이와`, 본문 여러 단어 오독 |
| 같은 문장의 잘린 끝 | 보이는 한국어 보존, 말미에 없는 `=` 추가 | 한국어 오독과 말미 `=` 추가 |
| 각도 계산 네 줄 | 각도·도·가감 부호 보존 | 보존 |
| 정의와 선분 | `등호로 나타내면` 오독, AB·AC 윗줄 두 개 누락 | 같은 한국어 오독, 선분 윗줄은 보존 |
| 수열 분수 | 분수·첨자·지수·음수 보존 | 보존 |
| 미분식 | 부호·그리스 문자 보존 | `2π−α`의 빼기를 곱셈으로 오독 |
| Big-O 비교 | `<`와 `n log n`·제곱 보존 | `n log n→n/log n` 오독 |
| 형상관리 문장 잘린 끝 | `형상관리→형성관리` | `형상관리→형성력` |

새 잘림 두 영역에서는 어느 baseline도 이미지 밖의 완성 구절을 추가하지 않았다. kjk 말미 `=`는 문장 완성 환각과 다른 **기호 삽입**이다. 두 모델 모두 명시적인 잘림 marker를 남기지 않았다. 이전 CDF에서는 Gemma가 보이지 않는 ‘되기 위한’을 추가하는 문제가 계속 재현됐다.

새 8개 각 1회의 요청 전체 시간 중앙값은 Qwen **6.42초**, Gemma **15.63초**였다. worker·파일 준비·모델 로딩을 포함하며, 같은 음성의 ASR 지연이나 상시 로딩 모델의 처리 속도를 뜻하지 않는다. OS 캐시·다른 작업 부하가 통제된 반복 성능 시험도 아니다.

## 개선 조건의 채택 기준

읽을 수 있는 단어·수식 정보를 더 잃는 조건은 채택하지 않는다. 모델의 수학 지식으로 결과를 고치거나 여러 응답을 자동 합치지 않는다.

- 경계 지시 강화: Gemma 미분식의 빼기는 복구됐지만, 정확했던 `뜻`이 `[판독 불가]`로 바뀌었다. 기존 오독 ‘등호로 나타내면’의 보류 전환은 새 단어 누락과 구분한다. 이전 CDF의 완성 추측을 줄이는 대신 읽을 수 있는 `성질`도 보류해 그대로 적용하지 않았다.
- 기호 나열을 포함한 강화 지시: Qwen에서 CDF의 극한 방향 세 개가 모두 빠지고, 주의표시가 거짓 각도 기호로 바뀌었다. 기호를 강조하는 지시만으로 원문 충실도가 좋아진다고 볼 수 없다.
- 같은 기호 강화의 Gemma 비교: 제목 `높이와→뜻과`와 clipped 끝의 `=`는 개선됐지만, 한국어 본문 오독·미분의 빼기 오독·Big-O 나눗셈 오독은 남았다. 정의의 `등호로 나타내면`을 ‘등변삼각형’으로 바꾸는 것은 교정으로 세지 않았다. 이전 CDF에서도 읽을 수 있는 `성질`을 보류했다.
- Gemma 시각 토큰 280→560: 실제 입력 배열과 이미지 placeholder 수가 늘어난 것을 확인했다. 미분식의 빼기는 복구됐지만 옅은 한국어 오독이 남았다. 두 영역의 MLX peak는 약 8GB였고 모델 로딩·입력·생성 시간은 약 20초였다. worker 준비가 제외된 측정이므로 위 요청 전체 시간과 직접 비교하지 않는다.
- 1120 시각 토큰: 16GB Mac에서 첫 작은 영역이 177초 시점에도 완료되지 않아 시험을 중단했다. 당시 시스템 swap 사용량은 약 5.57GiB였으나 그 전부가 해당 요청으로 증가했다는 의미는 아니다. 완료 결과가 없어 정확도를 평가하지 않았으며 제품에 적용하지 않는다.

추가로 Gemma의 흰 여백 5%(최소 8px)와 경계 지시를 함께 비교했다. 원래 픽셀은 모두 보존하고 추론용 이미지 바깥에만 여백을 붙였다. CDF에서는 보이지 않는 ‘되기 위한’을 붙이지 않고, 읽을 수 있는 `성질`과 극한 방향도 보존했다. 그러나 새 선분 정의에서는 정확했던 `뜻`을 보류하는 회귀가 그대로였다. 보이는 온전한 단어를 보존하도록 지시를 추가한 두 조건을 CDF·선분 정의에 다시 대조했으나, 한 조건은 CDF 완성 추측이 돌아왔고 다른 조건은 정의의 불필요한 보류를 해결하지 못했다.

**이번 추가 비교에서 기존 제품 경로보다 회귀 없이 낫다고 확인한 조합은 없다.** 인식 품질 문제가 해결됐다고 보고하지 않으며, 제품의 프롬프트·전처리·시각 토큰·기본 모델을 교체하지 않았다. 선분 윗줄 누락, 옅은 한국어 오독, 일부 수식 연산자 오독, CDF 경계 추측은 미해결이다. 후보의 사용자 수정·승인과 원본 대조는 계속 필요하다.

## 실제 설치 앱의 강제 종료 복구

Solasi **0.3.23 / build 33**의 실제 보관함에서 전용 과목을 만들고 새 각도 노트 JPG를 ‘손글씨 노트’로 연결했다. 자동 Vision 후보의 원문과 별개로 한국어·`∠`·`°`·수식이 포함된 수정 초안을 입력하고 **승인하지 않았다**.

1. 후보 ID와 자료·페이지·문서 해시를 고정했다. native 저장의 canonical 행과 writer journal 행에 동일한 수정문·token·revision·`dirty=true`가 커밋된 것을 확인했다.
2. 진행 중 녹음이 없는 상태에서 실제 앱의 정확한 PID만 SIGKILL했다. 앱 소유 엔진도 종료됐다.
3. 실제 앱을 다시 실행하고 같은 과목·자료·페이지의 검토창을 열었다. textarea에 수정문이 그대로 복구됐다. 원래 Vision 인식문, 후보 ID, 원본 연결도 동일했다.
4. 후보는 계속 미승인 상태이며 `approved_text`와 `source_id`가 비어 있었다. 이 자료의 비어 있지 않은 출처와 검색용 청크는 **0개**였다. 빈 페이지·메모 출처 placeholder를 지식 편입으로 세지 않았다.
5. 시험 완료 뒤 검증 후보만 거절했다. ‘보존된 검토 초안 · 지식에 반영되지 않음’으로 수정문이 남는 것을 확인하고 정상 종료했다.

보장 범위는 **저장 ACK에 해당하는 DB 커밋을 확인한 초안의 앱 프로세스 강제 종료 복구**다. 저장 전 마지막 입력 이벤트, 전원 차단, OS 전체 장애를 확인한 시험은 아니다. 정상 동작한 복구 저장 코드를 불필요하게 교체하지 않았다.

기존 과목 7개·자료 13개·기록 11개·녹음 10개·전사 742개·페이지 문서 9개·인식 기록 14개·출처 1,220개·청크 3,176개의 이전 행이 모두 보존됐다. 기존 원음 여섯 파일의 SHA256이 같고, 복구 직후 SQLite 무결성 및 외래 키 검사가 통과했다.

## 회귀 검사와 반영 범위

`tests/test_handwriting.py`에 native upload/commit 이후 새 DB 연결로 검토 초안을 다시 읽는 검사를 추가했다. canonical·journal 내용, 원래 후보의 모든 필드, 검색 제외를 함께 확인한다. 실제 프로세스 SIGKILL 결과는 위의 설치 앱 시험으로 구분한다. 단순 DB 재연결 검사를 강제 종료 시험으로 부르지 않는다.

전체 Python **592개 중 587개 통과·선택 검사 5개 생략**, 프런트엔드 **102개 통과**를 확인했다. 독립 코드 리뷰에서 새 검사와 저장·승인·복구 코드, 로컬 증거와 이 문서의 수치를 대조했다. 제품 실행 코드가 바뀌지 않아 새 앱 빌드·교체는 수행하지 않았다. 설치 앱은 **0.3.23 / build 33**을 유지한다.

로컬 증거는 `.local-state/handwriting-diversity-20261020/`의 `targets-before-inference.json`, `baseline-*`, `boundary-*`, `symbols-*.json`, `padded-*.json`, `vision*-*`, `crash-recovery.json`, `preservation.json`에 있다. 이 경로는 Git에서 제외되며 백업·보관함·개인 앱 경로를 공개 저장소에 복사하지 않는다. 새 실험을 반복할 때는 [기존 재현 절차](handwriting-quality-20261020.md#재현-예)에 따라 새로운 출력 폴더와 원본·정답 SHA 기록을 사용한다.
