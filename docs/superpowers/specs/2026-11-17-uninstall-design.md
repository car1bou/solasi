# 솔라시 Mac 설치 삭제 최종 설계

작성: 2026-11-17 · 상태: 사용자가 grilling Q1~Q10의 추천안을 모두 승인함. 설계 의사결정 완료. 제품 구현 전.

## 목적과 확정 범위

설정에 `설치 삭제` 버튼을 추가한다. 사용자는 남길 기록을 종류별로 선택한다. 선택한 기록을 솔라시 없이 열 수 있는 파일로 내보내고, 보존 결과를 검증하고, 앱 안에서 최종 확인을 받은 뒤에만 실제 삭제를 시작한다.

이번 대상은 Mac용 솔라시다. 앱, 솔라시 전용 AI 모델·추가 엔진, OS 앱 환경설정, 이 기기에 저장된 해당 보관함의 API 키, 캐시·로그, 앱이 관리하던 원래 보관함과 수정 이력을 제거한다. 모델·엔진을 남기는 옵션은 제공하지 않는다. API 제공자 계정의 키를 폐기하지는 않는다.

외부 원본 파일, 사용자가 따로 만든 백업, 다른 앱과 공유하는 도구, 개발 소스는 삭제하지 않는다. 삭제 과정에서 만든 보존 폴더도 삭제 대상에서 제외한다. 폴더 이름이나 위치만으로 솔라시 소유권을 추측하지 않는다.

## 사용자가 선택하는 항목

세 가지 기록 범주는 모두 `보존`이 기본값이다.

| 범주 | 보존 파일 |
| --- | --- |
| 필기·문서 | 원래 페이지와 펜·형광펜·글상자를 함께 볼 수 있는 PDF, 원래 형식의 문서 파일, 문서/페이지를 식별할 수 있는 옆 메모·손글씨 인식문 텍스트 |
| 녹음 | 일반 플레이어에서 재생할 수 있는 오디오 파일 |
| 전사·AI 결과 | 일반 편집기에서 읽을 수 있는 TXT 또는 Markdown. 현재 전사·결과 내용과 그 내용을 이해하는 데 필요한 제목·시각·출처 설명 |

PDF가 아닌 자료의 필기도 보존 선택에서 조용히 누락하지 않는다. 필요한 변환을 구현하고 검증하거나, 보존 불가 사유를 표시하고 삭제를 중단한다. 현재 사용자 기록에 해당하는 항목은 누락 없이 보존 목록에 포함한다. 세션 메모와 최종 퀴즈/응답 등 기존 개별 내보내기가 완전하지 않은 항목도 기록 목록과 내보내기 범위를 대조해 처리한다.

보존 파일은 최종 내용을 읽기 위한 것이다. 솔라시에서 펜 획을 다시 편집하거나 수정 이력을 복원하는 것은 보장하지 않는다. 별도의 편집용 보관함 백업을 자동 생성하지 않는다. 사용자 선택에서 제외한 기록이 다른 범주의 파일에 불필요하게 포함되지 않게 한다. 예를 들어 전사만 보존하면 오디오를 자동 복사하지 않는다.

## 저장 위치

사용자가 위치를 선택한다. Documents 아래를 최초 제안 위치로 사용하고, 선택 위치 안에 충돌 없는 새 `Solasi 보관자료-날짜` 폴더를 만든다. 과목·회차별로 파일을 정리한다. 이름 충돌 시 별도 이름을 사용하며 기존 파일을 덮어쓰지 않는다.

삭제 대상과 겹치는 경로, 심볼릭 링크를 통해 삭제 대상 안으로 들어가는 경로, 읽기 전용 또는 공간 부족인 위치는 거부한다. 결과 폴더에는 파일 목록, 보존/제외한 범주, 원래 기록과 파일의 대응, 검증 결과와 읽는 방법을 남긴다. API 키·불필요한 OS 설정을 보존 파일에 포함하지 않는다.

## 사용자 흐름과 삭제 허용 조건

1. `설정 → 설치 삭제…`를 누르면 앱 안의 독립된 선택창을 연다. 자동 제거 항목을 표시하고, 필기·문서 / 녹음 / 전사·AI 결과 각 행에서 `보존 / 삭제`를 직접 고른다. 기본값은 모두 보존이다. 설정 화면의 체크박스를 따로 찾아야 하는 흐름은 사용하지 않는다.
2. 기록 보존 범주와 저장 위치를 선택한다. 녹음·다운로드·작업이 진행 중이면 먼저 완료/중단하도록 안내한다. 각 창의 수정과 복구 초안도 확인한다.
3. 기록 상태를 일관되게 고정하고 보존 목록을 만든다. 기존 종료/초안 저장 흐름을 재사용하되 해결되지 않은 초안이나 충돌을 임의로 버리지 않는다. 내보내기 이후의 쓰기와 새 작업은 차단한다.
4. 보존 파일을 생성하고 검증한다. 원래 보관함, 앱, 키와 모델은 이 단계에서 삭제하지 않는다.
5. 자동 검증을 모두 통과하면 보존 결과, 저장 위치, `보존 폴더 열기`, 삭제 대상과 확보할 예상 용량을 표시한다. 모델은 다른 구성요소와 중복 집계하지 않는다. 보존하지 않을 범주와 원래 보관함·편집 이력 삭제도 명시한다.
6. 마지막 확인창의 `선택 변경` 버튼으로 항목 선택으로 돌아갈 수 있다. 이 경우 기존 영수증·검증·확인을 무효화하고 새 선택으로 내보내기부터 다시 수행한다. 이미 생성된 보존 자료는 유지한다고 안내한다. 사용자가 `솔라시 삭제`를 입력하고 `삭제 실행`을 눌러야 진행한다. 기본 동작은 취소다. 모든 기록의 보존을 해제하면 앱 관리 기록 전체가 사라짐을 강조한다. 자동 검증 통과만으로 삭제하지 않는다.
7. 최종 실행 직전에 보존 파일과 삭제 대상의 상태가 검증 당시와 일치하는지 다시 확인한다. 변경되었으면 삭제하지 않고 다시 준비한다. 보존 범주·위치가 바뀌면 기존 완료 상태와 최종 확인을 무효화한다.
8. 앱과 작업 엔진 및 소유한 자식 프로세스를 종료한다. 별도 삭제 도우미가 종료와 보관함 배타 접근을 확인하고, 검증된 대상만 실제 삭제한다. 휴지통으로 옮기지 않는다.
9. 도우미는 완료 또는 남은 경로와 오류를 네이티브 안내로 표시한다. 보존 폴더를 다시 열 수 있게 한다. 도우미의 임시 파일은 작업 후 정리한다. 앱은 데이터/구성요소 삭제 후 마지막에 제거해 부분 실패를 숨기지 않는다.

보존할 기록이 전혀 없는 경우에는 내보낼 파일이 없다는 사실을 명시하고, 기존 보존 성공처럼 표시하지 않는다. 이 경우에도 경로 검증·작업 종료·명시적 전체 삭제 확인은 필요하다.

## 보존 검증

`파일이 존재한다`, `용량이 0보다 크다`, `생성 함수가 성공했다`만으로 삭제를 허용하지 않는다.

- 선택한 기록을 사전에 목록화하고 모든 항목이 보존 결과에 대응하는지 대조한다. 원본 파일이 누락되거나 수정되어 일관성을 보장할 수 없으면 실패다.
- 복사한 문서·오디오는 원본과 크기·내용 해시를 비교한다. 복사 중 원본 변경도 감지한다. 오디오는 재생 가능한 형식인지 확인한다.
- 생성 PDF는 다시 열어 예상 페이지 수·크기와 내용 포함 여부를 확인한다. 필기 있는 페이지에서 펜·형광펜·글상자가 최종 화면에 반영되는지 별도로 검증한다. 메모·인식문은 별도 파일의 문서/페이지 대응과 텍스트를 대조한다.
- 전사·AI 결과는 내보내기 입력과 텍스트/필수 항목을 대조한다. 앱 내부 링크에 의존하지 않고 읽을 수 있어야 한다. 오디오도 보존하면 해당 폴더 안의 파일로 연결하고, 보존하지 않으면 오디오가 포함되지 않았음을 명시한다.
- 검증 결과와 파일 해시를 기록하고 최종 삭제 직전 다시 대조한다. 선택 후 원래 기록이 변경되면 승인된 내보내기로 간주하지 않는다.

예상 페이지/내용 대조의 구체적인 판정 기준은 구현 계획과 테스트에서 고정한다. 자동 검증으로 확인한 범위를 넘어 시각적/의미적 완전성을 보장한다고 표시하지 않는다. 실제 사용자 데이터가 없는 형식도 합성 fixture로 검증한다.

## 실패·취소·안전 경계

내보내기, 검증, 최종 실행 전 점검 중 하나라도 실패하면 삭제를 시작하지 않는다. 앱과 원래 보관함을 유지하고 항목·원인·재시도 방법을 표시한다. 이미 생성된 보존 자료는 자동 삭제하지 않는다. 취소하면 쓰기 차단을 해제하고 앱으로 돌아간다.

삭제가 시작된 뒤의 디스크/권한/키 저장소 오류는 부분 실패로 처리한다. 실제로 남은 대상을 알려 주며 성공으로 표시하거나 이미 삭제한 것을 복원했다고 주장하지 않는다. 보존 폴더에는 영향을 주지 않는다.

사용자 화면이 임의의 삭제 경로를 전달하는 범용 파일 삭제 API를 만들지 않는다. 네이티브 UI의 신뢰한 사용자 입력을 요구하고 앱 실행 설정, 보관함 식별자, 소유권, 정규 경로·파일 식별자, 모델/엔진 설치 기록으로 대상을 고정한다. OS 루트·홈·상위 개발 폴더·공유 폴더 전체를 삭제하지 않는다. 링크를 따라 외부 파일을 삭제하지 않는다. 다른 프로세스가 쓰는 보관함/구성요소는 삭제하지 않는다.

현재 확인했던 런타임에는 실험 결과와 평가 오디오도 섞여 있다. 루트 전체를 재귀 삭제하지 않고 솔라시 전용 하위 항목만 제거한다. 소유권이 불확실한 항목은 남기고 경로/사유를 표시하며 완전 삭제 성공으로 보고하지 않는다. 별도로 생성된 백업은 원래 보관함 안에 있어도 자동 삭제 대상에서 제외한다.

## 기존 코드에서 확인한 제약

- 기존 Mac PDF 내보내기는 저장된 필기는 그리지만 옆 메모·인식문·초안·이력은 담지 않고 PDF 원본만 지원한다. `macos/NotebookPDF.swift`, `lecture_study/notebook_pdf.py`를 재사용·보완한다.
- 기존 전사 Markdown의 원음 링크는 솔라시에 의존하며 오디오를 포함하지 않는다. `lecture_study/transcription.py`의 독립 내보내기 경로가 필요하다.
- 기존 AI Markdown은 모든 결과/퀴즈/시도의 완전한 보존이 아니다. `lecture_study/outputs.py`, DB 기록 종류를 대조해 보완한다.
- 문서와 오디오의 외부 원본은 보관함 밖에 있을 수 있다. 보존 선택 시 복사하되 원본 경로 자체는 삭제하지 않는다.
- 전체 보관함의 휴대 가능한 복원 기능은 확인되지 않았다. 이번 기능이 이를 지원한다고 약속하지 않는다.
- 설치 앱은 이전 확인에서 0.3.41, 현재 작업 폴더 설치 스크립트는 0.3.40이었다. 구현/배포 시 다시 확인하고 최신 설치의 기능·보안 변경을 보존해야 한다. 무관한 수정이 다수 있으므로 섞어 되돌리거나 이전 버전으로 덮어쓰지 않는다.

## 변경 범위와 검증 환경

설정 화면, macOS 네이티브 브리지·종료 흐름, 기록 내보내기·검증 서비스, 삭제 도우미, 앱 패키징, 관련 테스트와 사용자 안내가 대상이다. 기존 스타일과 설치된 라이브러리를 재사용한다.

파괴적 실행은 가짜 앱·보관함·모델·키 저장소로만 검증한다. 실제 사용자 보관함에서 마지막 삭제 실행을 시험하지 않는다. 기본 전부 보존, 각 범주의 단독/혼합/전체 미보존, 초안·누락 원본·손상/변경된 출력·용량 부족·권한 거부·심볼릭 링크·동시 실행·취소·삭제 도중 실패를 검증한다. 앱을 종료한 뒤에도 보존 파일이 표준 도구로 열리는지 확인한다.
