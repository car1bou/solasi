# 대화 이어가기와 과목별 학습 기억

날짜: 2026-11-17 (Asia/Seoul)
상태: 구현 전 검토안. 사용자는 두 기능의 구현을 요청했다. 세부 동작은 아래 제안이며 설계 확인 전 제품 코드를 변경하지 않는다.

## 목적과 요청 범위

솔라시를 다시 열어도 이전 질문과 답변을 이어가고, 같은 과목에서 어디까지 공부했으며 무엇을 어려워했는지 다음 대화에 활용한다. 기존 세컨드 브레인의 원문 검색·인용을 유지하면서 대화 맥락을 추가한다.

사용자가 명시한 요구는 (1) 이전 대화 이어가기, (2) 과목별 학습 지점과 어려움 기억이다. 아래 저장 방식, 화면 배치, 자동 정리·삭제 정책은 구현을 위한 제안이다. 전역 사용자 성향 분석, 진단, 계정 동기화는 요구에 포함하지 않는다.

성공 예:

- 오늘 확률 과목에서 베이즈 정리의 분모를 물었으면 앱을 재실행한 다음 “어제 헷갈린 부분부터 이어서 설명해 줘”를 이해한다.
- 다른 과목의 대화를 열면 확률 과목의 대화와 어려움이 입력에 섞이지 않는다.
- “이제 분모는 이해했어. 다음은 조건부 독립을 공부하자”를 말하면 이전 어려움을 확정된 현재 상태처럼 반복하지 않는다.
- 기억이 틀리면 사용자가 수정하거나 지우고 다음 답변부터 그 변경이 적용된다.

## 현재 구조와 연결 지점

- `QuestionView.tsx`는 질문·해설·요약·퀴즈 등에 공통 사용된다. 질문은 개별 job/artifact로 저장되고 대화 흐름을 나타내는 식별자는 없다.
- `answers.py`는 요청 시 검색 근거를 고정하고 실행 전후 원문 유효성을 확인한다. 현재 `messages_for`는 현재 질문과 근거만 보낸다.
- 로컬 `answer`는 `answer-grouped-evidence-v2` / `excerpts-v1` 경로에서 근거 원문을 선택하는 기능이다. 대화형 튜터를 이 경로의 프롬프트 수정만으로 구현하지 않는다.
- `jobs`, `artifacts`, `ai_attempts`와 재시도·취소·입력 예산 검사를 재사용한다. 과목/회차 소유자와 검색 범위 검증을 유지한다.
- `second_brain.py`와 서버의 knowledge loop는 유휴 로컬 작업을 처리한다. 녹음·전사·사용자 요청을 우선하는 정책을 그대로 따른다.
- 모바일 전송 계층은 변경 API를 제한한다. 공유 Python/React 기능을 추가하더라도 모바일 허용 경로·브리지 검증을 함께 고려해야 한다.
- 보존 내보내기는 원문·녹음·결과 선택을 지원한다. 대화와 학습 기억도 독립적으로 읽을 수 있는 결과에 포함해야 한다. 병행 중인 초기화 기능과 삭제 안전성 요구를 공유한다.

## 접근 방식 비교

1. **기존 로컬 DB와 세컨드 브레인 확장 — 권장안.** 대화·학습 기억을 과목에 묶고 기존 작업 큐·근거 검색을 사용한다. 앱의 데이터 보존·삭제 정책을 함께 적용할 수 있다. 대화 저장과 기억 갱신 구현이 필요하다.
2. **claude-mem을 별도 서비스로 연결.** 자동 압축·검색 방식을 재사용할 가능성은 있지만, 개발 작업 중심의 기록 구조를 과목·원문·승인·삭제 정책에 맞추는 추가 통합이 필요하다. 서비스 실행과 데이터 저장 위치도 늘어난다.
3. **최근 대화만 모델에 전달.** 가장 작지만 긴 대화·다른 대화·재실행 후의 과목별 학습 상태를 충분히 다루지 못한다.

권장안으로 구체화한다. claude-mem 자체를 솔라시에 설치하거나 개발용 claude-mem 메모리를 학습 자료로 가져오지 않는다. 신규 외부 의존성과 별도 벡터 DB를 추가하지 않는다.

## 사용 동작

### 대화

- 과목의 질문 화면에서 대화 목록과 최근 대화를 다시 열 수 있다. 새 대화는 명시적으로 시작한다. 앱 재실행 후에는 해당 과목의 마지막 대화를 복원한다.
- 강의 회차에서 시작한 대화는 과목에 속하며 시작 회차를 보존한다. 과목에서 다시 찾아 이어갈 수 있다. 과목이 없는 기록의 대화는 그 기록 안에서만 이어가고 과목별 학습 기억을 만들지 않는다.
- PDF 페이지에서 질문하면 자료·페이지·원본 버전과 검색 범위를 해당 턴에 남긴다. 대화에 참여한 다른 페이지를 근거로 쓸 때도 현재 요청 범위를 임의로 넓히지 않는다.
- 기본 질문은 대화형 답변으로 이어지며 원문 인용과 일반 해설을 구분한다. 기존 원문 발췌 질문·저장된 답변은 별도 실행/열람 경로로 유지한다. 요약·퀴즈·회의록·필기 인식의 기존 의미는 바꾸지 않는다.
- 대화에는 사용자 발화와 답변뿐 아니라 생성 중·실패·중단 상태를 표시한다. 사용자 입력은 먼저 저장하여 생성 실패 때문에 사라지지 않게 한다.
- 과거 대화는 스크롤/페이지 단위로 모두 열람할 수 있다. 모델에는 입력 예산 안에서 최근 대화와 관련 있는 오래된 맥락만 전달한다. 모든 대화를 매번 넣지는 않는다.

### 과목별 학습 기억

- 같은 과목의 여러 대화에서 활용할 수 있게 최근 학습 주제, 마지막으로 명시한 학습 위치, 해결되지 않은 질문, 사용자가 표현한 어려움을 정리한다.
- “PDF 20쪽까지 공부했어”, “독립과 상호배타가 헷갈려” 같은 사용자 발화가 기억의 근거다. 단순히 페이지를 열거나 AI 답변이 생성됐다는 이유로 학습 완료·이해 완료를 기록하지 않는다.
- 퀴즈 결과는 “이 문제에서 오답/부분 정답”이라는 관찰로만 활용한다. 한 번의 오답으로 능력을 단정하지 않는다. 사용자가 평가를 수정하면 원래 평가가 현재 사실처럼 남지 않는다.
- 기억마다 종류, 내용, 근거 대화/문항, 발생 시각, 현재 상태를 저장한다. 추출 요약은 “자동 정리”, 직접 입력·수정한 상태는 “내가 확인한 기억”으로 구분한다.
- 서로 모순되는 상태는 조용히 덮어쓰지 않는다. 명확한 사용자 정정은 우선하고, 자동 추출끼리 모호하면 확인할 내용으로 남긴다. 같은 질문의 반복 횟수로 취약점을 확정하지 않는다.
- 과목에서 기억 목록과 근거를 열어 보고 수정·삭제하거나 어려움을 해결됨으로 바꿀 수 있다. 개별 삭제, 대화 삭제, 과목 기억 비우기는 구분한다.

## 저장 및 실행 구조

세부 함수 이름·모듈 경계는 구현자가 주변 코드에 맞춰 정한다. 다음 불변 조건은 유지한다.

1. 대화는 과목 또는 과목 없는 기록 중 한 곳에 속한다. 각 메시지는 대화, 순번, 역할, 원문, 시각, 상태 및 관련 job/artifact를 가진다. 메시지 순서와 중복 저장 방지는 DB 제약으로 보장한다.
2. 학습 기억은 과목 소유이며 출처 메시지/퀴즈 시도와 연결한다. 직접 수정한 기억은 배경 작업이 다시 덮어쓰지 않는다. 원본 사용자 발화를 보존하고 요약만 원문인 것처럼 취급하지 않는다.
3. 메시지 저장, job 등록, 턴 예약을 원자적으로 처리한다. 한 대화에는 동시에 한 답변만 실행한다. 재시도는 같은 사용자 턴의 새 시도로 표시하고 메시지를 복제하지 않는다.
4. 요청을 접수할 때 과거 메시지·학습 기억의 ID와 버전·현재 검색 범위를 고정한다. 작업 재시도 때 새 기억이 예전 요청에 몰래 섞이지 않게 한다.
5. 기존 자료 검색에는 현재 질문과 관련 과거 질문의 제한된 맥락을 활용할 수 있다. “그 공식”의 지시 대상을 찾는 데 도움이 되지만 대화 텍스트를 교재 근거로 승격하지 않는다. 답변에는 원문에서 확인한 사실과 대화만으로 아는 사항을 구분한다.
6. 과거 답변의 인용은 당시 출처 정보로 보관한다. 다음 답변의 사실 근거로 재사용할 때는 기존 원문·승인·변경 검사를 다시 통과해야 한다. 삭제되거나 바뀐 PDF를 과거 인용 때문에 유효한 현재 자료로 취급하지 않는다.
7. 대화용 생성 경로를 명시적으로 추가한다. 기존 원문 발췌 경로의 출력 형식과 검증은 보존한다. 근거가 없는 “지난번 어디까지 했지?”에는 대화 출처로 답할 수 있고, 자료의 사실 설명은 유효한 원문 근거에 연결한다.
8. 기존 모델 입력 예산에 현재 질문·시스템 지시·출력 예약·원문 근거·기억을 모두 포함한다. 오래된 맥락부터 줄이고 생략 여부를 남긴다. 현재 질문이나 최근 핵심 턴도 넣을 수 없으면 명확히 알리고 범위 축소를 요청한다. 무음 잘림은 허용하지 않는다.

### 기억 갱신

- 대화 원문과 마지막 대화 복원은 모델 추가 호출 없이 즉시 작동한다.
- 긴 대화 요약과 학습 기억 추출은 기존 로컬 생성 잠금과 유휴 정책을 사용한다. 로컬 모델이 준비되지 않았거나 사용자 작업이 진행 중이면 대기하며 대화 자체는 유지한다. 전용 모델을 자동 다운로드하지 않는다.
- 추출은 사용자 발화·실제 퀴즈 시도에 근거하는 제한된 구조를 반환한다. 인용 범위와 소유자, 결과 형식·길이를 코드에서 검증한다. assistant 답변을 사용자의 이해 상태로 추출하지 않는다.
- 마지막으로 처리한 메시지 위치와 입력 버전을 저장하여 재실행 후 이어서 처리하고 같은 기억을 중복 생성하지 않는다. 실패는 재시도 가능하며 기존 기억과 대화를 잃지 않는다.
- 긴 대화의 이전 내용을 찾는 초기 구현은 같은 대화의 메시지 검색과 최근 맥락 요약을 사용한다. 장기 학습 기억은 같은 과목에 한정한다. 다른 과목을 넘나드는 전역 기억 검색은 추가하지 않는다.

## 개인정보와 제어

- 원문 대화·학습 기억은 솔라시의 로컬 보관함에 둔다. 자동 기억 정리에 외부 API를 호출하지 않는다.
- 사용자가 외부 API로 대화할 때는 선택한 대화 맥락·과목 기억도 전송 대상임을 입력 화면에서 알린다. 요청별로 **이전 대화·과목 학습 기억 함께 보내기**를 선택하며 외부 API에서는 기본 해제한다. 해제하면 두 종류 모두 모델 입력·검색어 확장·자료 선택에 사용하지 않고 현재 질문과 현재 요청의 자료만 사용한다. 선택은 서버에서 검증하고 기존 자료 전송 안내와 함께 표시한다.
- **이전 맥락 사용·자동 정리 일시 정지**와 데이터 삭제는 구분한다. 정지 시 이전 대화 맥락과 과목 학습 기억 모두 새 답변·검색어 확장·자료 선택에 적용하지 않고 배경 요약·추출도 하지 않는다. 기존 대화와 기억은 보존하고 새 대화 원문은 계속 저장한다. 재개하면 정지 중 쌓인 대화를 사용/정리할 수 있음을 설명한다. 이는 대화 기록 저장 중지나 삭제 기능이 아니다.
- 대화 삭제는 그 대화의 메시지, 파생 자동 요약, 관련 검색 기록과 그 대화에서 유래한 학습 기억 내용을 제거한다. 여러 대화가 함께 근거인 기억은 삭제한 출처에서 얻은 부분을 제거하고 남은 유효 출처로 다시 검증하며, 분리할 수 없으면 기억 전체를 삭제한다. 직접 고친 기억도 이 규칙을 적용하고 함께 지울 내용을 미리 표시한다. 삭제 전 내용을 포함한 합성 요약은 재사용하지 않는다.
- 과목 기억만 비울 경우 기존 대화는 남고, 삭제 이전 대화를 자동 재분석해 지운 기억을 부활시키지 않도록 처리 경계/세대를 남긴다. 새 발화부터 다시 쌓을 수 있다.
- 삭제·정정 시 진행 중인 작업을 취소하고 기억 세대를 무효화한다. 고정된 job 입력과 파생 캐시에 남은 삭제 대상 텍스트도 정리한다. 실행 직전·저장 직전 세대를 검사해 오래된 작업이 삭제한 기억을 다시 저장하거나 재시도에서 재전송하지 않게 한다. 이미 외부 제공자에게 전송된 내용은 로컬 삭제로 회수되지 않는다는 한계를 안내한다.
- 기존 저장 답변 자체를 지우는 작업과 학습 기억만 지우는 작업의 차이를 삭제 안내에 표시한다. 현재 기억 삭제를 과거 답변 원문의 자동 삭제로 해석하지 않는다.

## 기존 데이터·배포·보존

- DB는 추가 마이그레이션으로 확장한다. 기존 질문·답변·노트·녹음·필기·모델은 변경/삭제하지 않는다. 기존 artifact는 열람할 수 있게 유지한다.
- 과거 질문 기록 전체를 자동으로 대화나 사용자 프로필로 변환하지 않는다. 사용자가 선택한 기존 답변에서 새 대화를 시작할 수 있게 하되 출처와 당시 시각을 유지한다.
- 결과 보존을 선택한 내보내기에 대화와 과목 학습 기억을 UTF-8 Markdown/JSON 등 독립 열람 형식으로 포함한다. 삭제 전 검증은 메시지/기억 수와 내용 해시까지 확인한다. 새로운 자료가 내보내기 선택에서 조용히 빠져서는 안 된다.
- 초기화/제거 준비 동안 새 대화 저장·자동 기억 갱신을 차단하고 진행 중 작업 정지와 보존 스냅샷이 일관되게 작동하도록 통합한다. 이 저장소에서 병행하는 초기화 변경을 덮어쓰지 않는다.
- 먼저 공유 서버/프런트엔드와 Mac 패키지에서 검증한다. 모바일은 허용 경로/공유 테스트까지 확인하되 실제 설치·실기기 성능은 별도 검증 결과로 구분한다. Windows·iPad 배포 완료를 Mac 검증으로 대신 주장하지 않는다.
- 개발 검증은 임시 DB/테스트 보관함으로 수행한다. 실제 앱의 설치·재시작은 사용자 기록 보존을 확인한 뒤 별도 단계에서 진행한다. 실제 초기화·제거는 이 작업에 포함하지 않는다.

## 영향 범위

- 저장: `schema.sql`, `db.py`, 신규 대화·학습 기억 모듈, 모델 입력 검증.
- 생성: `answers.py`, `server.py`, 입력 예산, job 재시도·취소·종료 처리, 원문 검색의 대화 맥락 입력.
- 화면: 질문/해설 진입점, 과목 화면의 대화 복원과 기억 관리, 설정의 기억 사용 제어. 공통 `QuestionView`의 요약·퀴즈·회의록 회귀를 확인한다.
- 네이티브/보존: 모바일 API 경로 허용 목록, 결과 보존 내보내기, 초기화/제거 중 쓰기 정지, 패키지에 신규 모듈 포함.
- 문서: 사용 안내의 기억 범위·정정·삭제·외부 API 전송 설명.

## 수용·검증 기준

1. 앱/프로세스 재실행 후 같은 대화를 열어 이전 질문을 지칭하는 후속 질문을 처리한다. 새 대화에서도 같은 과목의 진도·명시적 어려움을 활용한다.
2. 서로 다른 과목·기록의 ID를 바꿔 전달해도 대화/기억을 읽거나 수정하지 못한다. 페이지·회차 검색 범위를 우회하지 못한다.
3. “20쪽까지 공부했다”와 “20쪽을 열었다”, 질문 반복과 어려움 명시, 오답과 학습 능력, AI 설명과 사용자 발화를 구분한다.
4. 정정·해결됨·삭제가 다음 답변에 반영된다. 진행 중 생성/추출/재시도와 경합해도 지운 기억이 다시 생기지 않는다.
5. 생성 실패·취소·중복 요청·재실행 후에도 사용자 메시지가 남고 답변이 중복 저장되지 않는다. 작은 모델 입력 예산에서 근거와 최근 맥락을 올바르게 제한한다.
6. 로컬 모델/임베딩이 없을 때도 기록 열람·수정·삭제와 대화 저장이 가능하다. 자동 외부 호출·암묵적 모델 다운로드는 없다.
7. 외부 제공자 모의 클라이언트에서 기억 포함/제외에 따른 실제 요청 본문을 검사한다. 중지·삭제 후 배경 작업이 외부 호출하지 않는지 확인한다.
8. 기존 보관함의 마이그레이션 전후 원문·파일 해시와 기존 행을 대조한다. 원문 발췌·요약·퀴즈·필기 승인 검증이 유지된다.
9. 결과 보존 내보내기의 대화·기억 수/내용 검증 및 초기화/제거 준비 동안의 쓰기 차단을 임시 데이터로 검사한다.
10. 질문 화면에서 대화 재개, 다른 대화 선택, 기억의 근거 보기·수정·삭제, 오류/빈 상태, 키보드 조작을 검증한다. 모의 모델 검증과 실제 로컬 모델 검증을 구분해 기록한다.

## 구현자에게 남긴 결정

기존 테스트 도구·UI 구성요소·작업 큐를 우선 사용한다. 모듈/테이블 세부 명칭, 페이지당 메시지 수, 요약 갱신 간격, 고정된 입력 예산 내 기억 배분, 테스트 fixture 구성은 구현자가 정한다. 새 의존성·전역 성향 분석·자동 클라우드 기억 동기화·새 모델 설치는 추가하지 않는다.
