# 로컬 질문의 원문 우선 답변

## 결정과 적용 범위

지침·반복 억제 비교에서 다른 질문의 회귀를 확인한 뒤, 사용자가 **원문 우선 답변·추가 해설은 선택**을 승인했다. 새 내부 로컬 AI의 질문 답변은 모델이 구간 ID만 고르고 앱이 원문과 출처를 그대로 표시한다. 자유 해설은 접힌 ‘추가 해설’ 영역에서 사용자가 생성 버튼을 눌렀을 때만 실행한다. 세부 비교는 [실행 기록](../../local-answer-grounding-20261027.md)에 남긴다.

현재 Mac의 provider가 local인 새 answer 작업에 적용한다. 외부 API·과거 Ollama 경로·이미지 설명·원문 발췌 요약·회의록·메모 보강은 유지한다. 추가 해설은 기존 explain 경로와 지침을 사용하고 ‘추가 해설 · AI 생성’으로 구분한다. 지침 시험에서 실패한 자유 답변 후보나 반복 패널티를 적용하지 않는다.

## 원문 선택과 표시

검색으로 확보한 자료·확정 전사·저장 메모·승인한 손글씨를 기존 원문 단위로 나누고 짧은 ID를 붙인다. 모델은 ID를 최대 8개 선택하며 빈 배열도 허용한다. ID와 원문의 연결은 앱이 관리한다. 존재하지 않는 ID·중복·생성 문장이 섞인 선택 응답은 거절한다.

기존 요약의 원문 문맥 보존 함수를 재사용해 앞선 주어·가정·조건과 이어지는 문장을 함께 복사한다. 원래 수식·부호·이름·부정·시각을 바꾸지 않는다. 경계가 불완전하면 기존 구간 확인 표시를 사용한다. 원문 선택을 증명·정답·작성자·결정이라고 새로 명명하지 않는다.

화면에는 ‘관련 원문’과 원본 연결을 표시한다. 선택이 없으면 ‘선택된 원문이 없습니다’와 확보한 근거를 보여준다. 이는 요청한 사실이 전체 기록에 없다는 단정이 아니다. 선택의 관련성·누락은 여전히 검사해야 한다.

## 추가 해설과 입력 보호

원문 결과에 원래 질문과 검색 범위를 함께 저장한다. 추가 해설 입력은 그 질문·범위로 시작한다. 기존 QuestionView와 작업·재시도·저장·내보내기 경로를 재사용하며, 접힌 영역을 여는 것만으로 추론을 실행하지 않는다. 사용자가 선택한 현재 모델로 생성 버튼을 눌러 실행한다. 자유 해설이 원문과 같은 정확도를 보장한다는 표시는 하지 않는다.

부모 질문과 추가 해설은 서로 다른 미저장 입력 보호 이름을 사용한다. 다른 결과로 이동하거나 창을 닫을 때 미저장 입력·진행 작업 보호를 유지한다. 기존 결과와 새 원문 결과는 별도로 보존하며 Markdown에서도 원문과 생성 해설을 구분한다.

## 작업 고정과 호환성

새 로컬 질문은 제출 시점의 snapshot에 실제 system·정책 ID·원문 형식·출력 예산 512를 고정한다. 근거 고정과 실행은 같은 선택 입력·schema·예산을 계산한다. 문장 단위로 늘어나는 ID와 출처 정보도 포함하며, 긴 근거는 실제 입력 비용을 확인하면서 발췌한다.

새 필드가 없는 과거 snapshot·고정 요청은 변경 전 SYSTEM과 출력 경로를 사용한다. 정상적인 snapshot의 근거 고정 과정에 새 정책을 소급 주입하지 않는다. 과거 결과·수동 수정·원음·필기·승인문·출처·키는 변경하지 않는다. 과거 모든 버전의 미저장 프롬프트를 복원하는 설계는 아니다.

## 검증

동일 실제 자료의 정의·부등호·주어·가정·후반 일정과 정보가 없는 질문을 대조한다. 원문 복사 검증과 구간 선택의 유용성을 별도로 보고한다. 새 작업 고정·과거 snapshot·API/요약 유지·긴 입력 예산·출처·내보내기 회귀를 검사하고, 실제 Mac의 기본 질문·추가 해설 수동 실행·저장·원문 열기·재실행을 확인한다. 다른 Windows·UI 개발 변경은 보존하고 이번 커밋에서 제외한다.
