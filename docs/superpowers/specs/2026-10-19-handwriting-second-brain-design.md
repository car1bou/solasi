# 손글씨 지식 편입과 세컨드 브레인 자동 갱신

날짜: 2026-10-19. 상태: 정책·상세 설계·구현 계획 사용자 승인 및 Mac 핵심 구현 완료. 실제 검증 범위와 남은 조건은 [검증 기록](../../handwriting-second-brain-20261019.md)을 따른다.

## 목적과 합의

Mac 내장 앱에서 강의 자료·확정 전사·노트·손글씨를 같은 과목의 검색 근거로 연결한다. 사용자 확인 전의 인식문을 사실로 사용하지 않으면서, 저장 뒤 검색과 연결이 따라오는 흐름을 만든다.

사용자가 승인한 정책:

- 저장된 필기를 로컬에서 인식하고 페이지·위치에 연결된 검토 후보로 표시한다.
- 사용자가 확인·수정한 인식문만 답변·요약·개념 연결 근거에 편입한다.
- 원본 획과 텍스트 메모를 유지하며 문자 인식과 AI의 수식·도형 해석을 구분한다.
- 자료·확정 전사·저장 메모·승인한 인식문 변경 뒤 로컬 유휴 시간에 의미 색인을 자동 갱신한다.
- 같은 과목의 관련 이전 기록과 개념 연결을 후보로 제시한다. 개념을 자동 확정·병합하지 않는다.
- 원음 저장·전사·사용자 생성 요청을 우선한다. 외부 API 후보 생성은 사용자 버튼 실행으로 제한한다.
- Exa 신규 검색·키 설정·실행 경로를 제거한다. 과거 인용·답변은 보존한다.

각 기기 독립 로컬 저장, Mac 우선, 포트 없는 내장 엔진 구조를 유지한다.

## 설계 당시 기반과 선택한 대안

`save_page_document`는 PDF 해시·페이지·버전별로 텍스트와 획을 저장하고 텍스트만 색인한다. `InkPoint`에는 좌표·압력·선택적 기울기가 있으며 점별 시각은 없다. 직접 모델 실행은 이미지 입력 경로를 갖고 있다. 이 시점에는 한국어 손글씨의 정확도·지연 비교 전이었다. 이후 공개 산문 필기 6장으로 비교했고, 자동 후보는 Vision·수동 재인식은 설치된 Qwen을 사용한다.

1. **추천: 잉크 이미지 인식과 기존 출처·작업·SQLite 확장.** 기존 필기를 재사용하고 Mac에서 바로 비교할 수 있다. 인식문 버전·검토 흐름이 추가된다.
2. 획 기반 인식 전면 도입: Android/iOS의 ML Kit 한국어 모델은 후보이나 공식 Mac 런타임이 아니며 현재 데이터에 점별 시각이 없다. Mac 우선 작업에서 먼저 채택하지 않는다.
3. PDF와 필기를 통째로 VLM에 주고 지식 자동 생성: 구현 입력은 간단하지만 인쇄 글자·손글씨 혼동과 생성 해석 전파를 구분하기 어렵다. 기본 경로로 채택하지 않는다.

Apple Vision accurate 기본 revision 3의 런타임 지원 언어 33개 중 `ko-KR`를 이 Mac에서 확인했다. 이는 한국어 지원 확인이며 손글씨 정확도 증거가 아니다. Vision과 설치된 로컬 이미지 모델을 같은 필기로 비교한 뒤 기본 인식 엔진을 정한다. 새 대형 모델 자동 다운로드는 하지 않는다.

## 1. 인식 입력과 표시

- 저장을 마친 필기 버전만 처리한다. 미저장 초안은 기존 복구 경로로 보존하고 자동 인식에 넣지 않는다.
- 필기 영역을 묶어 잉크만 렌더링한다. 동일 위치의 PDF 배경은 문맥용 별도 입력으로 취급한다. 이미지의 회전·배율과 정규화 좌표 변환을 고정한다.
- 형광펜만 있는 영역은 손글씨 OCR 대상에서 제외한다. 강조 영역과 PDF 본문 연결은 별도 후보 유형이며 승인한 문자 인식문으로 둔갑시키지 않는다.
- 후보는 페이지 옆 검토 영역에 원본 영역, 인식문, 적용·수정·다시 인식 동작을 표시한다. 필기 도구와 원본 PDF는 가리지 않도록 접을 수 있게 한다.
- 필기·도형을 해석한 설명은 문자 인식 결과와 별도 필드 및 표시를 사용한다. 첫 구현에서는 생성 해석을 자동 검색 근거에 넣지 않는다.
- 거절한 후보는 같은 필기 내용에서 자동 재생성하지 않는다. 사용자가 다시 인식하거나 내용이 바뀌면 새 후보를 만들 수 있다.

## 2. 출처와 버전

기존 페이지 메모에 OCR 텍스트를 덧붙이지 않고 인식 전용 레코드를 둔다.

- 연결: 과목, asset, 원본 PDF 해시, 페이지 문서 ID와 버전, 필기 내용 해시, 관련 획 ID·경계 상자.
- 결과: 인식 원문, 사용자 수정문, 엔진·모델 식별, 생성 시각, 검토 상태(candidate/approved/rejected/stale), 승인 시각.
- 승인 결과는 별도의 `ink_note` SourceRef와 불변 텍스트 스냅샷을 만든다. 검색·인용·내보내기에서 일반 입력 메모와 구분한다.
- 확률로 보장하지 못하는 엔진 점수는 정확도 백분율로 표시하지 않는다.
- 적용은 트랜잭션에서 현재 PDF 해시·획 내용·버전을 재확인한다. 변경됐으면 적용하지 않고 최신 필기 재검토를 안내한다.
- 획 변경·지우기·부분 지우기는 해당 인식 결과를 stale로 만들고 현재 검색에서 제외한다. 텍스트 메모만 바뀌고 획 내용 해시가 같으면 인식을 반복하지 않는다.
- 과거 답변에 사용한 승인 출처·필기 버전은 유지한다. SourceLink에서 당시 위치와 현재 버전 차이를 보여준다.
- `SourceRef`, 검색 view·scope·라벨, 근거 검증, SourceLink, 내보내기, 자료 삭제 수명 주기까지 새 출처 종류를 연결한다.

## 3. 자동 의미 색인

저장 이벤트마다 별도 전체 재색인을 시작하지 않는다. 최신 상태 기준으로 대기 작업을 합친다.

- 식별 키는 출처 버전과 텍스트 내용, 모델 식별, 전처리 형식이다. 모델·형식이 다르면 기존 벡터를 섞지 않는다.
- 새 chunk만 임베딩하고 삭제·구버전은 현재 검색 대상에서 제외한다. 변경되지 않은 벡터는 재사용한다.
- 한 번에 하나의 색인 작업이 처리한다. 처리 중 도착한 변경은 다음 묶음으로 이어간다.
- 기존 전체 재색인 버튼은 초기 구축·모델 변경·복구용으로 유지한다. 전체 교체는 성공 후 활성 색인을 바꾸고 실패하면 기존 색인을 유지한다.
- 시작할 때 실제 searchable_chunks와 벡터를 대조해 강제 종료로 빠진 대기 항목을 복원한다. 중단된 작업을 완료로 표시하지 않는다.
- 모델이 준비되지 않았으면 키워드 검색을 유지하고 준비 상태를 표시한다. 자동 다운로드나 외부 임베딩 호출을 하지 않는다.

## 4. 관련 기록·개념 후보

- 저장된 원문과 승인한 인식문을 쿼리로 같은 과목의 관련 기록을 검색한다. 현재 출처 자체와 같은 내용의 복제본을 먼저 제외한다.
- 같은 과목의 다른 회차를 연결할 수 있게 하되 다른 과목·회의를 자동 혼합하지 않는다.
- 관련 기록은 원문 발췌·페이지/시각과 함께 표시한다. 유사도만으로 인과·동일 의미·선후 관계를 확정하지 않는다.
- 로컬 개념 후보 추출은 검색 후 필요한 원문만 전달하며 근거 ID와 정확한 발췌를 검증한다. 사용자가 승인하면 기존 개념 저장·버전 관리 경로를 사용한다.
- 후보는 원문 내용·버전으로 중복을 막는다. 기각한 후보는 같은 입력에서 반복 제시하지 않는다.
- 외부 API를 선택한 경우에도 백그라운드 후보 생성을 외부로 보내지 않는다. 버튼 실행 시 대상 자료가 전송됨을 표시한다. 로컬 인식·임베딩 경로는 별도 유지한다.
- 주어·가정·조건·예시·제안·결정·상반된 진술을 보존한다. 같은 용어라는 이유로 서로 다른 주장을 합치지 않는다.

## 5. 일정·취소·복구

우선순위는 원음 저장과 기존 녹음 복구 → 확정 전사 → 사용자 요청 → 자동 인식·색인·후보 처리다. 이미 실행 중인 모델 호출은 강제 선점하지 않고 호출 사이에서 우선순위를 확인한다. 자동 작업은 실행 중인 녹음 또는 전사 적체가 있으면 시작하지 않는다.

기존 DirectModels 잠금·generation_slot·DirectEmbeddings를 재사용한다. 임베딩 worker는 작업 내에서 재사용하되 전사 대기·생성 양보·취소·종료 때 해제한다. 장기 상주 모델이나 별도 HTTP 서버를 추가하지 않는다.

설정에서 로컬 자동 처리를 일시 정지할 수 있게 한다. 정지·취소는 원문이나 이미 승인한 인식문을 삭제하지 않는다. 일시 정지 중 새 변경은 대기로 유지하고 재개할 때 최신 상태로 합친다. 실패 항목은 오류를 표시하고 사용자 재시도를 제공하며 무한 재시도하지 않는다.

## 6. 구현 구분과 확인 항목

다음은 설계의 확인 기준이다. 항목별 실제 실행 여부와 측정 한계는 검증 기록 및 구현 계획의 완료 표에서 구분한다.

1. 한국어/영어/숫자/혼합 필기, 작은 글씨, 수식·도형·화살표·형광펜에서 Vision/기존 VLM의 인식 정확도·누락·환각·처리 시간·메모리를 비교한다. 사용자 자료를 모델 카드 성능으로 대체하지 않는다.
2. 미승인·거절·stale 인식문이 질문·요약·개념 후보 근거에 들어가지 않는지 확인한다.
3. 승인·수정·필기 변경·원본 PDF 변경·재실행·강제 종료에서 출처와 검토 상태를 확인한다.
4. 원음·전사·필기·미저장 초안의 기존 보존·복구 경로를 대조한다.
5. 변경 청크만 처리하는지, 동일 모델 검색 순위가 전체 재색인과 맞는지, 모델 변경·취소·동시 저장에서 누락이 없는지 확인한다.
6. 긴 녹음·전사·생성 동안 자동 작업이 원음 저장을 막지 않고 작업 경계에서 대기하는지 확인한다.
7. 680×480 라이트·다크에서 후보 검토·키보드·원문 위치 이동·내보내기를 확인한다.
8. Exa 신규 호출·키 UI·키 조회가 사라지고 과거 인용이 열리는지 확인한다.

## 범위 밖

전체 노트 지식 그래프 DB, 모델 재학습, 자동 개념 확정·병합, 새 클라우드/동기화, 타 OS 구현, 필기 전체를 무조건 외부 API로 보내는 처리는 포함하지 않는다.

## 예시

운영체제 PDF 8쪽에 쓴 ‘교착 상태: 상호 배제 …’를 저장하면 로컬 인식 후보가 생긴다. 검토 전에는 답변 근거로 쓰이지 않는다. 사용자가 ‘상호 배제’를 확인하면 해당 영역과 승인 인식문이 연결되고 의미 색인 갱신 대상으로 들어간다. 유휴 시간에 처리한 뒤 같은 과목 이전 강의의 mutex 설명을 관련 기록으로 제안한다. 개념을 저장하거나 합치는 것은 사용자가 결정한다. 이후 해당 획을 부분 지우면 기존 인식문은 현재 검색에서 빠지고, 과거 답변에 붙은 당시 근거는 남는다.
