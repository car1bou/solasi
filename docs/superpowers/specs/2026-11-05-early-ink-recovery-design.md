# 진행 중 필기 복구 설계

상태: 2026-11-05 사용자 승인. 미완성 획은 별도 복구 후보로 표시하고 사용자가 적용한다.

## 현재 경계

펜·형광펜은 pointerup 등으로 획을 마칠 때 `PageDraft.change()`에 전달된다. 그 전에는 진행 중 획 전체가 화면 메모리에만 있다. 완료 뒤에도 native upload 생성·조각 전송·commit 사이에는 마지막 durable 초안으로만 복구할 수 있다. UI 프로세스가 종료돼도 이미 접수된 worker 쓰기가 끝날 수 있으므로 worker 종료 뒤 상태로 판정한다.

## 제안

- 펜·형광펜의 첫 점과 진행 중 최신 좌표를 별도 writer별 복구 journal에 기록한다. 기존 canonical 초안·확정 페이지·메모·이전 출처를 덮어쓰지 않는다.
- 첫 요청은 즉시 시작하고 이후 좌표는 제한된 주기로 합친다. 한 번 실행 중인 쓰기와 최신 대기 값 하나만 유지해 느린 디스크·bridge에서 대기열이 누적되지 않게 한다. 화면 그리기는 저장 응답을 기다리지 않는다.
- 재실행하면 기존 복구 UI에 ‘그리던 획 복구 후보’와 원문 메모·획 미리보기·적용 동작을 제공한다. 사용자가 확인하기 전 확정 페이지·인식·검색에는 편입하지 않는다. 기준 revision이 달라지면 기존 conflict 보호를 유지한다.
- 정상 완료는 기존 commit·undo 경로를 한 번만 실행한다. 최종 완성 획의 durable 초안이 확인된 뒤 해당 임시 journal을 정리한다. Escape·pointercancel의 취소 의미도 유지하며, 다른 창의 수정으로 오래된 부분 획이 최신 내용을 덮지 않게 한다.
- 작은 native 초안은 검증된 한 번의 원자적 쓰기로 처리해 upload 생성·조각·commit 왕복을 줄이는 방식을 비교한다. 큰 초안은 기존 분할 전송·크기 검증·실패 보호를 유지한다. 완성 초안과 부분 journal의 쓰기 의미를 명시적으로 구분한다.

## 검증과 보존

실제 설치 앱의 별도 QA 페이지에서 라이트·다크·680×480으로 펜·형광펜을 비교한다. 종료 직전 partial journal과 확정 페이지를 기록하고, 정확한 앱 PID를 강제 종료한 뒤 worker 종료까지 기다려 최종 durable 상태를 확인한다. 재실행 후보의 전체 geometry·색·굵기·불투명도를 대조한다. 도구가 실제로 누름 상태인 증거 없이 종료한 시도는 진행 중 획 검증으로 세지 않는다.

자동 검사는 부분 획의 서버 저장 방지, 정상 완료의 단일 undo, 취소, 전송 지연·실패, 오래된 응답, 다른 창 conflict, 복구 후보 적용을 포함한다. 원본 기록·필기 revision·초안·내부 파일 해시를 기준 백업과 대조한다. 기존 미승인 복구 사본은 삭제하지 않는다.

## 보장하지 않는 범위

첫 durable journal 전 입력과 마지막으로 기록된 위치 뒤의 점은 유실될 수 있다. 기록 주기만으로 유실 시간 상한을 보장하지 않는다. 부분 획을 자연스럽게 이어 그린 것처럼 추측하거나 완성하지 않는다. 실제 스타일러스 필압·전원 차단·저장 장치 고장은 별도 시험이다.
