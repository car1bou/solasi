# 저음량 한국어·생활 소음의 VAD 진단

2026-10-21 · macOS 27.0.1 · Apple Silicon · 기존 Whisper large-v3-turbo / Qwen3-ASR 1.7B 4bit

## 결론

**음량을 낮추는 조건과 소음이 발화를 가리는 조건의 결과가 달랐다.** 저음량 6개 조건은 모두 발화가 검출됐지만, 소음 혼합 36개 중 8개 조건은 통째로 미검출됐다. 또 ‘발화가 하나라도 검출됐다’는 결과만으로 문장 앞부분의 누락을 배제할 수 없었다.

검출기에만 음량 보정을 적용하면 일부 미검출은 줄었으나, 대부분 잘못된 후보가 나왔고 SIL·환경음 대조 조건에서 추가 출력을 허용했다. **이 증폭 방식은 제품에 적용하지 않았다.** 기존의 자동 후보 보류·원음 보존·수동 원음 재인식·사용자 적용 정책을 유지했다. 가이드에는 생활 소음 속 발화의 미검출과 수동 후보의 오인식 가능성을 명확히 설명했다.

## 자료와 한계

[서울코퍼스 공식 배포](https://www.openslr.org/113/)의 성인 인터뷰 3명과 수동 `utt.ortho.` 전사를 사용했다. 같은 인터뷰의 2~7초·태그 없는 발화 중 화자별 최저 RMS 구간과 중앙 RMS 구간을 VAD/ASR 실행 전에 고정했다. **서로 다른 발화 원본은 6개, 참조 문자는 106자**다. 반복·머뭇거림을 참조에서 지우지 않았다.

원본의 RMS는 약 −40.15~−17.34dBFS였다. 낮은 녹음 레벨은 확인했지만 마이크 거리·기존 배경음도 영향을 주므로, 모두 실제로 작게 발성했거나 속삭였다고 단정하지 않는다. 원본을 20dB 낮춘 조건도 별도로 표시한다. [실제 한국어 속삭임을 포함한 ASMR-WS 연구](https://www.frontiersin.org/journals/neuroscience/articles/10.3389/fnins.2023.1120311/full)는 확인했으나 이번 조사에서 바로 사용할 수 있는 원음·축어 정답 묶음을 확보하지 못했다.

생활 소음은 [DEMAND 공식 배포](https://zenodo.org/records/1227121)의 사무실·식당·주방 채널이다. 주방 채널은 이번에 추가 수집했다. ZIP 앞부분 약 6.93MB에서 채널 한 개를 CRC·크기 검증 후 추출했으며, 전체 ZIP의 MD5를 검증했다고 주장하지 않는다. 환경음에는 배경 발화가 있을 수 있다.

| 조건 | 수 | 구성 |
|---|---:|---|
| 원본 | 6 | 수동 주석 경계의 실제 사람 발화 |
| 저음량 | 6 | 같은 원본을 20dB 낮춤 |
| 소음 혼합 | 36 | 6발화 × 사무실·식당·주방 × 0/−10dB SNR |
| 환경음 단독 | 6 | 3환경 × −40/−30dBFS, 목표 한국어 발화 없음 |
| SIL 주석 원음 | 3 | 사람이 SIL로 표시한 실제 비영점 원음 |

총 **57개 조건·166.348초**다. 같은 6개 발화를 조건별로 반복한 수치이며 57개 독립 발화가 아니다. 소음 혼합은 현장에서 한국어 대화를 녹음한 자료가 아닌 파생 조건이다. 혼합에서는 **원본 녹음 성분**의 RMS를 −40dBFS로 맞췄다. SNR도 원본에 이미 있던 배경음을 포함한 녹음 성분 대 추가 환경음의 RMS 비율이며, 고립된 성대 음성의 비율은 아니다.

원본·수동 전사는 CC BY-NC 2.0, DEMAND 제작자 설명은 CC BY-SA 3.0이다. 원음·전사·혼합물은 공개 저장소에 재배포하지 않고 집계·해시만 남겼다. 같은 세 화자·같은 인터뷰이므로 중앙 RMS 표본도 독립 화자 검증 세트로 부르지 않는다.

## 비교 방법

- 현재 native Silero v6.2.0 / pinned whisper.cpp 유틸리티: threshold 0.5, 최소 발화 250ms, 최소 무음 100ms, padding 0ms, CPU 1 thread.
- Whisper: 원본 PCM, 힌트 없음, 기존 VAD 사용, 확정 파일 전사의 1초 padding.
- 수동 Qwen: 같은 원본 PCM 전체, 한국어, temperature 0, batch 1, 최대 1,024토큰, hotwords 없음. 현재 준비된 짧게 실행하는 worker를 실제로 호출했다.
- 대안: 검출기 입력만 RMS −20dBFS를 목표로 최대 +24dB 증폭했다. 증폭 시 peak 0.95FS 상한을 두되 원본을 감쇠하지 않는다. **ASR에는 계속 원래 PCM을 제공했다.** 파라미터는 VAD/ASR 실행 전에 고정했다.
- `자동` 비교값: VAD가 비었으면 보류, 아니면 같은 수동 Qwen 결과를 후보로 제공하는 조건부 정책 재생이다. 동일 모델 호출을 중복 실행하지 않았다. 모든 입력에서 실제 앱의 자동 후보 조건·작업 큐가 충족됐다는 뜻은 아니다.

Python 3.12.14, Qwen worker의 MLX 0.32.3 / mlx-audio 0.5.8 / transformers 5.19.0을 사용했다. 설치 앱 build35의 frozen worker와 런타임 버전이 다르므로 이 비교를 설치 앱 GUI 재검증으로 부르지 않는다. 새 모델·서버·API는 사용하지 않았다.

## 발화 조건 결과

CER는 NFKC·소문자화 뒤 문자/숫자만 비교한 문자 오류율이다. 각 행은 같은 참조 106자를 사용하는 6개 조건의 합계다.

| 조건 | VAD 통째 미검출 | Whisper CER | 수동 Qwen CER |
|---|---:|---:|---:|
| 원본 | 0/6 | 11.32% | 6.60% |
| 원본 −20dB | 0/6 | 16.98% | 6.60% |
| 사무실 0dB | 0/6 | 16.04% | 13.21% |
| 사무실 −10dB | 0/6 | 47.17% | 38.68% |
| 식당 0dB | 1/6 | 93.40% | 64.15% |
| 식당 −10dB | 6/6 | 100.00% | 96.23% |
| 주방 0dB | 0/6 | 27.36% | 25.47% |
| 주방 −10dB | 1/6 | 60.38% | 55.66% |

미검출 8개 조건에는 원본의 목표 발화 신호가 들어 있다. 다만 혼합 뒤 사람에게 모두 명료하게 들린다고 청취로 판정한 검사는 아니다. 환경·화자·발화가 적으므로 이 수치를 보편적인 VAD 누락률이나 엔진 순위로 일반화하지 않는다.

### 자동 보류와 수동 후보

통째 미검출된 8개 조건의 참조 합계는 139자다. 조건부 자동 후보는 보류되어 0자를 제공했고, 수동 Qwen은 38자를 출력했다. 수동 결과는 치환 29자·삭제 101자·삽입 0자, **CER 93.53%**였으며 정확히 일치한 조건은 없었다. 출력이 생겼다는 사실을 내용 복구 성공으로 계산하지 않았다.

보류는 기존 전사나 원음을 삭제하지 않는다. 보류를 빈 문자열로 계산한 삭제/CER는 **후보 가용성 비교**이며 저장된 전사를 삭제한 문자 수가 아니다. 문자 편집 정렬의 삭제·삽입 수를 의미 누락·환각 사건 수로 해석하지 않는다.

### 발화가 검출돼도 앞부분이 빠진 사례

약 2.569초 발화는 원본이 −40.15dBFS, 20dB 낮춘 입력이 약 −60.15dBFS였다. 원본의 VAD 범위는 0.130~2.569초였지만 낮춘 입력에서는 **1.950~2.569초만 검출**됐다. ‘빈 목록이 아님’ 검사만으로는 앞부분 누락을 찾지 못한다.

이 저음량 입력의 Whisper는 참조 14자 중 치환 1자·삭제 6자, CER 50%였고, 수동 Qwen은 CER 7.14%였다. 따라서 ‘저음량 6개 모두 검출’은 모든 단어를 검출했거나 최초 전사 누락이 없다는 뜻이 아니다. 수동 Qwen의 6개 저음량 출력은 각각 원본 조건의 출력과 같았다.

### 후속 진단: Whisper VAD 해제·입력 증폭

앞부분 누락을 확인한 뒤, **저음량 6개 전체와 대조 9개 전체**에 두 대안을 추가 실행했다. 이 단계는 최초 결과를 본 뒤 수행한 탐색이며 독립 검증이 아니다. VAD 해제는 원래 PCM 그대로, 입력 증폭은 위와 같은 고정 보정 후 기존 VAD를 사용했다.

| Whisper 방식 | 저음량 6개 CER | SIL 원음 3개의 출력 문자 | 환경음 단독 6개의 출력 문자 |
|---|---:|---:|---:|
| 현재 | 16.98% | 0 | 5 |
| VAD 해제 | 14.15% | 24 | 30 |
| 입력 증폭 + 기존 VAD | 11.32% | 7 | 4 |

앞부분 누락 사례는 두 대안 모두 CER 50→7.14%로 개선됐다. 그러나 VAD 해제는 다른 저음량 발화 한 개를 6.25→25%로 악화시켰고, 두 대안 모두 SIL 원음에서 새 출력을 만들었다. 평균 CER 감소만 보고 기본값으로 적용하지 않았다. 입력 증폭의 소음 혼합 36개에 대한 ASR 효과까지 검증한 단계도 아니다. 검출기 증폭 시험과 실제 ASR 입력 증폭 시험을 구별해야 한다.

## 증폭 대안을 적용하지 않은 이유

검출기 증폭은 발화 조건의 통째 미검출을 **8→5개**로 줄였다. 추가로 검출한 3개 조건의 수동 후보 CER는 각각 94.12%, 100%, 96.30%였다. 원음을 증폭해 검출하는 것만으로 소음에 가려진 문장의 내용을 복원하지 못했다.

| 대조 조건 | 현재 조건부 자동 출력 문자 | 검출기 증폭 후 조건부 출력 문자 | 수동 전체 입력 출력 문자 |
|---|---:|---:|---:|
| SIL 주석 원음 3개 | 0 | 12 | 18 |
| 환경음 단독 6개 | 3 | 6 | 34 |

증폭은 SIL 원음 한 개와 환경음 단독 한 개에서 추가 추론을 허용했다. SIL은 빈 lexical reference 대비 출력을 기록했으며, 환경음 단독의 출력을 모두 의미 환각으로 확정하지 않았다. 배경 발화가 있을 수 있기 때문이다. **발화의 미검출 감소만 보고 기본 VAD를 바꾸면 불필요한 출력도 늘어난다.**

현재 원음·원래 전사·과거 출처를 보존하고, 자동 보류 뒤 수동 확인을 허용하는 정책을 유지했다. 추가 증폭·자동 적용·새로운 VAD 설정 항목은 만들지 않았다.

## 실제 제품 함수와 보존 검증

미검출 사례 두 개를 별도 QA DB의 PCM 녹음 경로로 재생했다. 최초 전사를 미리 넣지 않고 실제 `process_chunk()`의 Whisper·VAD를 실행한 뒤 다음을 확인했다.

1. 실제 최초 전사와 VAD가 비어 자동 후보가 보류됐다.
2. 같은 구간의 두 번째 자동 요청이 차단됐다.
3. 수동 요청은 실제 Qwen worker를 실행했고 최초 비교와 같은 문자열을 반환했다.
4. 두 후보 모두 적용하지 않았으며 원래 전사와 저장 PCM이 같았다.
5. QA DB 무결성과 외래 키 검사를 통과했다.

이 두 경로는 실제 설치 앱의 버튼·마이크 시험이 아닌 제품 함수 통합 시험이다. 실제 설치 앱 0.3.25/build35와 사용자 보관함은 변경하지 않았다. 이전 [설치 앱의 원음·수동 재인식 검증](mac-qwen-vad-validation-20261021.md)과 범위를 구분한다.

## 검증·재현 기준

모든 57개 입력의 해시·프레임 수를 대조했다. 원본 녹음·라벨·환경음·SIL 원음 12개 파일의 전후 SHA256이 같았다. 혼합 36개는 원본·고정 gain·offset으로 다시 계산해 PCM 반올림 결과가 모든 샘플에서 같았고 clipping이 없었다.

재현 시에는 위 선택 규칙과 조건표를 출력 확인 전에 고정한다. 같은 PCM으로 현재 VAD와 검출기 증폭을 비교하고 ASR PCM은 바꾸지 않는다. 원음·참조·출력 본문은 비공개로 보존하며, 빈 참조에는 CER를 계산하지 않는다. 기존 자료가 바뀌면 해시 검사에서 중단해야 한다.

관련 Python 회귀 검사 **51/51**, 프런트엔드 **104/104**를 새로 실행해 통과했다. 이번 문서 변경을 전체 앱·마이크·절전 복구의 새 검증으로 계산하지 않는다.

본 비교 57개 각각에서 Whisper·Qwen을 실행했고, 제품 함수 확인 2개에서 각각 다시 실행했다. 후속 진단은 Whisper 30회다. **Whisper CLI 실행 89회·Qwen 모델 생성 59회**, 실패·Qwen 토큰 상한 도달 0회였다. VAD가 막은 Whisper 실행까지 실제 디코딩 횟수로 해석하지 않으며, 조건부 정책 재생 값도 추가 추론 횟수로 합산하지 않았다.

[조건별 집계·입력/출력 해시·VAD 시각](verification/quiet-korean-vad-20261021.json)을 제공한다. raw 원음·전사·모델·사용자 보관함은 포함하지 않는다.
