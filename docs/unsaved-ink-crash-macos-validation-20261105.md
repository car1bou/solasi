# Mac 미저장 펜·형광펜 강제 종료 복구 검증

2026-11-05, 실제 설치된 **Solasi 0.3.39 / build 49**에서 검증했다. 창은 **680×480**, 캡처는 **1360×960**이며 라이트·다크를 모두 확인했다. 별도 검증 과목의 기존 3쪽 PDF 중 1쪽만 사용했다. 제품 코드·엔진·설치 버전은 변경하지 않았다.

## 무엇을 미저장으로 판단했는가

필기는 저장 버튼 외에도 약 650ms 뒤 자동 저장된다. 따라서 저장 버튼을 누르지 않았다는 사실만으로 미저장 복구 시험을 통과했다고 판단하지 않았다.

각 시험은 실제 앱에서 마우스로 한 획을 완성한 뒤 다음 조건을 모두 확인해 진행했다.

1. 페이지의 확정 revision은 획 입력 전과 같다.
2. 새 획을 포함한 `dirty: true` 초안과 동일 내용의 writer journal이 SQLite에 반영돼 있다.
3. 기존 획·메모는 그대로이고, 새 도구의 획 하나만 추가됐다.
4. 확인한 실제 Solasi 실행 파일의 PID·시작 시각을 다시 대조한 뒤 해당 프로세스 하나에 `SIGKILL`을 보낸다. 정상 종료 저장 경로는 실행하지 않는다.
5. 강제 종료 직후와 앱 소유 작업 엔진이 종료된 뒤에도 확정 revision이 바뀌지 않았고 같은 dirty 초안이 남았는지 다시 확인한다.

페이지 자동 저장이 먼저 끝나면 해당 시도는 미저장 시험으로 인정하지 않도록 감시 절차를 구성했다. 실제 성공한 두 시험 모두 위 조건을 충족했다. 실행 중인 별도 녹음이 없음을 확인했고, 다른 앱·프로세스에 종료 신호를 보내지 않았다.

## 실제 결과

| 시험 | 종료 전 확정 페이지 | 종료 후 남은 초안 | 실제 앱 재실행 결과 |
| --- | --- | --- | --- |
| 다크 · 펜 | v4 · 기존 2획 | v4 기준 dirty 초안 · 3획 | 같은 PDF를 열자 새 펜 획 자동 복구, v5 · 3획으로 저장 |
| 라이트 · 형광펜 | v5 · 기존 3획 | v5 기준 dirty 초안 · 4획 | 같은 PDF를 열자 새 형광펜 획 자동 복구, v6 · 4획으로 저장 |

두 시험에서 강제 종료 뒤 작업 엔진이 끝날 때까지 확정 페이지는 각각 v4·v5였다. 재실행 전에 이미 저장된 결과를 복구 성공으로 센 것이 아니다.

복구 후의 메모와 전체 ink를 종료 전 dirty 초안과 대조했다. 기존 획과 새 획의 **ID·도구·색·굵기·불투명도·입력 종류·점 좌표·pressure 값이 모두 일치**했다. JSON 직렬화 순서 차이는 허용하고, 파싱한 값 전체를 비교했다. 기존 v4와 새 v5·v6 이력도 남았다.

최종 네 획이 있는 같은 페이지를 라이트·다크 양쪽의 680×480에서 확인했다. PDF 위의 펜·형광펜 위치와 반투명 표시, 도구 선택, `저장됨 · v6`, 저장 버튼의 비활성 상태가 확인됐다. 도구가 겹치거나 잘리는 문제는 이 화면에서 재현되지 않았다. 원래 다크 모드·지우개 선택·과목 목록 상태를 복원했다.

## 기존 데이터 보존

시작 전에 일관된 SQLite 백업과 보관함 파일 해시 목록을 만들었다. 종료·복구 뒤 기록·출처·필기 관련 **12개 테이블의 기존 4,187행**을 대조했다. **4,184행은 그대로**이며, 바뀐 세 행은 검증 페이지의 예상 변경으로 제한됐다.

- 검증 페이지의 현재 revision: v4 → v6.
- 해당 페이지의 저장 초안 값: 복구한 네 획·v6·`dirty: false`.
- 해당 페이지 v4의 이전 OCR 후보 상태: `candidate` → `stale`. 승인이나 새 지식 편입을 수행하지 않았다.

기존 페이지 revision·과거 출처 행은 삭제하거나 다시 쓰지 않았다. 검증 PDF의 자료 행과 외부 원본 SHA256도 유지됐다. 보관함 내 기존 **73개 파일**의 크기·SHA256이 전부 같았다. 이 목록은 페이지 PNG·추출 JSON·녹음 WAV 등 내부 보관 파일이며 외부 연결 원본 전체를 뜻하지 않는다. 외부 검증 PDF는 별도로 해시를 대조했다. 기존 native 도구·화면 모드·노트 보기·목록 설정도 기준값과 같고, SQLite 무결성 검사는 `ok`였다.

검사한 테이블은 `courses`, `sessions`, `sources`, `notes`, `recordings`, `transcript_ranges`, `transcripts`, `page_documents`, `page_document_revisions`, `native_drafts`, `ink_recognitions`, `assets`다. 백그라운드 색인·작업 큐 전체를 정지하거나 불변으로 검증했다는 의미는 아니다.

## 적용과 증거

이번 조건에서 복구 유실이나 표시 오류가 재현되지 않아 제품 코드를 수정하거나 앱을 다시 설치하지 않았다. 변경은 이 검증 기록이다. UI UX Pro Max의 좁은 화면·상태 표시 기준, grilling의 저장 경계 확인, ponytail의 최소 변경 원칙을 적용했다.

로컬 증거는 `.local-state/unsaved-ink-crash-20261105/`에 보관한다. 각 `*-killed.json`에는 종료 전 초안과 종료 후 revision 검사가, `*-recovered.json`에는 재실행 결과가 있다. `FINAL-VERIFICATION.json`은 보존 대조 결과다. 캡처는 `pen-dark-recovered.jpg`, `highlighter-light-recovered.jpg`, `final-dark-recovered.jpg`다. 보관함 백업·초안 원문·캡처는 공개 Git에 포함하지 않는다.

## 검증 경계

이번 시험은 **획을 완성해 native dirty 초안이 반영됐지만 페이지 저장은 끝나지 않은 상태**를 검증한다. 마우스를 누른 채 그리는 중인 획, native 초안 반영 전 메모리에만 남은 입력, 저장 장치 고장·전원 차단은 검증하지 않았다. 그 범위까지 무손실이라고 주장하지 않는다. 실제 입력은 마우스 직선 두 개이며 스타일러스 곡선·실제 필압 시험은 아니다.

ScreenCaptureKit `-3811` 캡처 오류가 일부 조작 중 발생해 창을 재획득·활성화하고 현재 상태를 확인한 뒤 계속했다. 입력 후 캡처 실패가 입력 실패를 뜻하지는 않아 같은 획을 무조건 반복하지 않았다. 이 도구 오류 자체를 영구 해결한 것은 아니다. 장시간 녹음·절전·OCR 정확도·PDF 내보내기는 이번 시험에서 다시 실행하지 않았다.
