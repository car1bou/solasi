# Mac 색인 작업의 임베딩 worker 재사용

2026-10-19. Apple M4·16GiB·macOS 27.0.1에서 [단계별 성능 측정](local-stage-performance-20261019.md)의 후속 개선을 수행했다. 전사 모델·벡터 형식·검색 점수 계산은 바꾸지 않았다.

## 적용 범위

**색인 작업 한 건의 연속 청크에서만** 임베딩 모델 실행 프로세스(worker)를 재사용한다. 검색 질의의 일반 단일 호출은 기존처럼 처리 후 종료한다. C++ 엔진은 이미 여러 프레임을 처리하고 요청마다 KV 메모리를 비우므로, 바이너리·모델 변환 없이 Python의 수명 관리만 변경했다.

- 청크마다 기존 모델 잠금과 전사 우선 확인을 유지한다. 색인 전체 동안 잠금을 잡지 않는다.
- 녹음·전사로 색인이 대기하면 worker를 종료한다. 잠금을 기다리는 사이 녹음이 시작된 경우도 **색인용 admission에서 다시 확인**한다. 질문·요약의 기본 대기 조건은 넓히지 않았다.
- 로컬 생성이 모델 잠금을 획득하면 임베딩 worker를 종료한 뒤 생성 모델을 준비한다. 색인은 나중에 새 worker로 재개한다.
- 완료·취소·실패·정상 앱 종료 때 소유한 프로세스를 회수한다. 정리 도중 취소가 반복돼도 회수가 끝난 뒤 취소를 전달한다.
- 서로 다른 클라이언트의 worker를 빌리지 않는다. 이전 작업의 뒤늦은 종료가 새 작업의 worker를 종료하지 않게 소유자를 구분한다.
- 모델 digest와 엔진 receipt signature를 작업에 고정한다. 요청 전후와 최종 상태 확인에서 변경을 거절하며, 실패한 새 색인으로 기존 활성 색인을 교체하지 않는다.
- 비치명적인 문맥 길이 오류만 같은 worker에서 분할 재시도한다. fatal 오류·잘못된 벡터·중단된 응답·타임아웃·취소는 worker를 닫는다.

모델을 앱 실행 내내 상주시키는 방식은 아니다. 녹음·전사·생성이 자주 끼어들면 재로드가 늘어 이득이 줄어들 수 있다.

## 고정 한국어 입력 비교

이전 음성 검증에서 인식한 한국어 텍스트6개와 고정 한국어 질의2개를 사용했다. 같은 텍스트·모델·엔진·입력 접두사로 입력8개를 직렬 처리하고, 개별 시작/재사용 순서를 바꿔 **각각3회** 실행했다. 정답 전사를 힌트로 전달하거나 새 음성을 내려받지 않았다. 초기 별도 비교 외에 아래 반복 비교를 수행했다. OS 파일 캐시는 비우지 않았다.

| 입력8개 전체 시간 | 요청마다 시작 | 작업 내 재사용 |
| --- | ---: | ---: |
| 1회 | 3.588초 | 1.595초 |
| 2회 | 3.400초 | 1.971초 |
| 3회 | 3.400초 | 0.845초 |
| 중앙값 | **3.400초** | **1.595초** |
| 매 실행의 worker 시작 | 8회 | 1회 |
| 작업 종료 후 worker | 0개 | 0개 |

이 작은 직렬 입력 묶음의 시간 중앙값은 **53.1% 감소**했다. 전체 앱·전사·긴 요약의 속도 향상률을 뜻하지 않는다. 개발용 Python 부모 프로세스에서 설치된 C++ 임베딩 엔진을 사용한 비교이며, 새 내장 패키지의 통합 흐름은 별도로 확인했다.

전후 모든 비교에서 768차원 벡터의 최대 원소 차이는 **0**, 문서6개에 대한 두 질의의 전체 순위도 동일했다. 서로 연관된 작은 표본이므로 의미 검색 정확도 전반이나 다른 데이터의 순위를 보장하지 않는다. 보관하는 모델 프로세스의 종료를 확인했으며, OS 캐시·GPU 메모리의 잔류량을 별도 수치로 측정하지는 않았다.

## 새 내장 엔진의 통합 실행

실제 내장 엔진을 격리된 검증 보관함에서 내부 IPC로 실행했다. 반복 부하는 같은 한국어 인식문을 반복한1,024개 청크와 생성용 검증 원문1개다. 실제 강의1,025개나 독립 발화1,025개의 품질 시험은 아니다.

1. 색인이 시작돼 임베딩 worker가 살아 있는 상태에서 녹음 세션을 시작했다. 색인이 대기하고 worker가 종료됐다.
2. 이전 검증과 동일한 **실제 한국어 음성17.52초**를16kHz PCM으로 재생해 녹음 프로토콜에 전달했다. 실제 마이크 입력이나17.52초 동안의 실시간 녹음 시험은 아니다.
3. ACK 뒤 저장된 **280,320프레임**의 PCM 바이트가 입력과 같았다. 종료 후 확정 전사가 처리되는 동안 색인이 대기했다.
4. 최종 전사 문장·시작/끝 시각은 이전0.3.14 내장 엔진의 같은 음성 파일 처리 결과와 동일했다. 새 ASR 정확도 개선을 주장하지 않는다.
5. 색인이 재개된 뒤 Qwen3.5 4B의 로컬 핵심 원문 요약을 요청했다. 실제 생성 worker가 있는 동안 임베딩 worker가 없었고 요약이 완료됐다.
6. 색인이 다시 재개돼1,025개 벡터를 저장하고 완료됐다. 관찰된 임베딩 PID는 총3개로, 초기 실행·녹음/전사 후 재개·생성 후 재개를 구분했다. 작업 종료 후 남은 임베딩 worker는 없었다.

색인 시작 이후 새로 생긴 전사2개 청크는 이번 색인의 최초 대상에 포함하지 않는 기존 정책을 유지한다. 결과는 신규 미색인2개를 별도로 보고했으며, 새 전사를 이번 색인에 들어간 것으로 표시하지 않았다.

확정 문장이 저장돼 전사 범위의 적체가 사라진 뒤에는 선택적 VAD 후처리와 색인이 겹칠 수 있다. `transcribe` 작업의 완료 표시만으로 인식 프로세스가 계속 실행 중이라고 판단하지 않고, 확정 전사 범위의 queued/running 상태와 구분했다. 최초 진단의 이 두 상태를 혼동한 검사는 수정한 뒤 새 보관함에서 다시 실행했다.

## 회귀와 기록 보존

- 백엔드 **513개 실행, 오류 없음, 선택 실행5개 제외**. 재사용·소유권·문맥 분할·fatal 오류·모델/엔진 변경·생성 양보·녹음 중 새 admission·전사 대기·취소·타임아웃·반복 취소·최종 상태 검사를 포함한다.
- 별도의 실제 보관함 복사본에서 메모와 실제 필기 획을 미저장 초안으로 저장하고 새 내장 엔진을 재시작해 같은 내용을 복구했다. 기존 페이지 수정 이력31개도 동일했고 SQLite 무결성이 정상이었다. 새 필기 중 강제 종료 시험은 아니다.
- 패키지7,826개 파일의 해시와 self-check를 확인했다. 모델 가중치·원음·DB·원문·개인 경로·실험 벡터는 공개하지 않는다.
- **Solasi0.3.15/build25**를 설치하고 실제 창에서 기존 PDF·펜·부분 삭제된 형광펜·복구 메모·보존된 미저장 초안 안내를 확인했다. 업데이트 전후 실제 보관함 **43개 테이블과 원음6개 파일의 해시가 모두 동일**하며 DB 무결성·앱 서명도 정상이다.

## 재현

[비교 도구](../experiments/measure_embedding_reuse.py)는 기존 모델만 사용한다. `inputs.json`에는 `texts`와 `queries` 문자열 배열을 제공한다. 두 실행에 같은 파일을 사용하고, 출력에는 벡터가 있으므로 비공개 위치의 새 파일을 지정한다.

```sh
.venv-macos/bin/python experiments/measure_embedding_reuse.py \
  --runtime /absolute/path/to/prepared-runtime \
  --engine /absolute/path/to/bundled-engine/engines \
  --inputs /private/path/to/inputs.json \
  --output /private/path/to/single.json

.venv-macos/bin/python experiments/measure_embedding_reuse.py --reuse \
  --runtime /absolute/path/to/prepared-runtime \
  --engine /absolute/path/to/bundled-engine/engines \
  --inputs /private/path/to/inputs.json \
  --output /private/path/to/reuse.json
```

## 남은 경계

생성과 전사의 worker·모델 초기화 반복은 이번에 바꾸지 않았다. 새 장시간 마이크·절전·실제 강제 종료·외부 API·다른 OS도 재검증하지 않았다. 정상 앱 종료와 작업 취소의 회수 경로를 확인했으며, 설정의 수동 연결 해제와 새 요청 발생이 정확히 겹치는 기존 경쟁 조건은 별도 개선 대상이다.
