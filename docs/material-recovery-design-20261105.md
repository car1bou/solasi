# 원본 상태와 복구 동선

2026-11-05 UI 개선 후보 6~8번 중 남은 자료 복구 범위다. 설정의 오류 집계·상세 접기, 필기 값·미리보기, 더보기 메뉴 그룹은 기존 구현을 유지한다.

## 동작

- 파일 없음·접근 불가에는 저장된 필기·출처 보존 안내와 ‘원본 다시 찾기’, ‘다시 확인’을 제공한다. 열 수 없는 원본 링크는 표시하지 않는다.
- 다시 찾기는 기존 네이티브 파일 선택창을 사용한다. 한 파일만 선택하며, 검사한 SHA256과 파일 종류가 마지막 원본과 일치할 때만 기존 asset의 경로·mtime을 변경한다. 자료 ID·원본 hash·추출 버전·필기·승인·과거 출처는 변경하지 않는다.
- 다른 내용, 앱 관리 폴더 파일, 다른 asset에 이미 연결된 경로, 연결되지 않은 자료, 추출 작업이 진행 중인 자료는 변경하지 않고 오류를 알린다. 취소는 기존 상태를 유지한다.
- 다른 파일로 바꾸려면 기존 ‘자료 연결’을 사용한다. 새 내용에 과거 필기를 자동으로 덮지 않는다.
- 원본 변경에는 원본 확인과 재추출을 표시한다. 이전 필기는 기존 문서 hash에 남는다. 새 원문 추출이 필요한 상태도 PDF 보기와 검색 갱신을 구분해 안내한다. 가져온 손글씨 자료의 승인 절차는 유지한다.
- 다시 확인·위치 복구 전에 기존 navigate guard를 통과한다. 미저장 입력을 버리거나 원본 파일을 삭제·이동·복사하지 않는다. 파일 선택만으로 macOS 접근 권한의 영구 복구를 약속하지 않는다.

## 검증 계획

1. 같은 원본 이동·취소·내용 불일치·소유 범위·기존 연결 충돌·추출 중 변경을 API에서 검사하고 기존 출처/페이지 revision 불변을 대조한다.
2. 프런트엔드의 상태별 행동·승인 제약과 기존6~8번 검사를 실행한다.
3. 관련 없는 미커밋 작업을 제외한 Mac 소스로 엔진·화면을 빌드한다.
4. 실제 앱의680×480 두 테마에서 복구 상태·파일 선택·취소·원본 복구와 기존 필기/설정/메뉴를 확인하고 기존 행·파일 hash를 대조한다.
5. 검증 결과와 적용 파일만 main에 커밋·푸시한다.
