## 사용자 화면과 삭제 범위

설정 → 설치 삭제…를 누르면 다음 세 행에 각각 **보존 / 삭제** 선택이 나타난다. 세 항목 모두 기본값은 보존이다.

| 선택 항목 | 보존 시 만들어지는 자료 |
| --- | --- |
| 필기·문서 | 필기를 그려 넣은 열람용 PDF, 원본 문서, 페이지 메모·인식문·세션 메모 등 텍스트 |
| 녹음 | 일반 도구로 재생할 수 있는 원음 파일 |
| 전사·AI 결과 | 현재 전사, 수정된 결과·퀴즈/응답/채점, 저장된 부분 결과를 TXT/Markdown으로 내보낸 파일 |

**보존**은 앱 밖에서 읽는 사본을 만든다는 뜻이다. 삭제 실행 시 원래 앱 보관함과 수정 이력은 제거된다. **삭제**를 고른 범주는 보존 사본을 만들지 않는다. 모두 삭제를 선택하면 보존할 기록이 없다는 문구와 전체 원본 손실을 최종 화면에 표시한다.

앱, 솔라시 전용 모델·추가 엔진, 앱 설정, 해당 보관함의 기기에 저장된 API 키, 관리하는 캐시·로그는 삭제 대상이다. 보존 폴더, 앱 밖의 원본, 별도 백업, 공유 도구, 소유권이 확인되지 않은 실험 자료는 남긴다. 혼재한 경로는 폴더 전체를 지우지 않고 소유가 확인된 파일만 계획한다.

사용자가 지적한 최초 UI의 모호함을 수정했다. 선택을 네이티브 삭제 흐름 안에 명시적으로 배치했으며, 최종 화면의 **선택 변경**은 이전 선택을 유지해 돌아간다. 이때 이전 영수증·삭제 준비를 취소하고 새 보존·검증과 새 확인 문구 입력을 요구한다. 이미 만들어진 보존 폴더는 유지한다.

## 삭제 차단 조건

1. 네이티브 화면에서 범위와 저장 위치를 선택한다. 다중 창의 미저장 내용을 처리하고 충돌하는 작업·녹음을 확인한다.
2. 원본을 지우지 않고 새 보존 폴더를 만든다. 공간, 누락 원본, 미해결 임시 필기, 파일 내용·해시·크기, PDF 재열기·페이지와 필기 렌더링 등을 검사한다. 준비 중 자동 지식 처리 쓰기도 멈춘다.
3. 검증한 파일 수·위치, 보존/삭제 범주, 원래 보관함과 전용 구성 요소 삭제, 예상 용량을 최종 네이티브 화면에 표시한다. 정확히 **솔라시 삭제**를 입력하고 **삭제 실행**을 눌러야 다음 단계로 진행한다.
4. 실행 직전 원본 상태와 보존 파일을 다시 검증한다. 앱 밖의 도우미가 앱·소유한 엔진 종료를 기다린 후 잠금, 파일 식별자, 경로와 보존 영수증을 다시 검사한다. 심볼릭 링크 치환, 다른 사용 프로세스, 변경된 원본·보존 파일은 차단한다.
5. 허용 목록에 있는 대상만 제거하고 앱을 마지막에 제거한다. 성공·실패 결과 보고서를 보존 폴더에 남긴다. 부분 삭제 실패를 성공으로 표시하지 않는다.

준비·검증·최종 확인 전 취소 또는 실패 시 원래 앱·기록은 삭제하지 않는다. 실제 삭제가 시작된 뒤 파일시스템 오류가 발생하면 이미 삭제한 일부 원본은 되돌릴 수 없다. 보존 파일은 유지하고 실패를 보고한다.

## 별도 검토와 수정

구현자와 별도의 검토자가 전체 변경을 읽고 8개 Important 문제를 지적했다. 모두 재현 테스트를 추가하고 수정했다.

- 수정된 최신 AI 결과·채점이 아닌 최초 값이 내보내지는 문제
- 중단된 요약의 저장된 부분 결과 누락
- 모델 캐시 내부의 별도 백업까지 넓게 삭제할 가능성
- 내용을 모두 지운 미해결 임시 필기의 오판
- 보존 준비 중 자동 지식 처리의 DB 쓰기
- 없는 선택적 OS 상위 폴더 때문에 삭제가 중단되는 문제
- 녹음 내 위치 대신 세션 시각만 남는 전사 링크
- 최종 확인에서 보존하지 않는 범주가 빠지는 문제

추가한 네이티브 선택/선택 변경 UI도 별도로 범위를 지정해 검토받았다. 도우미 파일이 없을 때 준비 상태가 풀리지 않는 P2 문제 1개를 찾아 실패 테스트로 재현한 뒤 수정했다. 기존 8개 수정 사항을 별도 검토자가 재검토했다고 주장하지 않으며, 수정 검증은 해당 회귀 테스트와 전체 회귀로 수행했다.

## 검증의 한계

이 구현은 macOS 대상이다. 실제 사용자 보관함의 파괴적 삭제와 실제 사용자 Keychain 자격 증명 제거는 의도적으로 시험하지 않았다. 임시 데이터에서 삭제 동작을 검사했으며 실제 설치에서는 교체·서명·기록 불변을 확인했다. 내보낸 PDF는 열람용이고 원래 편집 이력을 복원하는 백업이 아니다. 실제 삭제는 최종 확인 이후 영구적이며, 실행 도중 실패 시 보존 파일과 오류 보고서를 기준으로 확인해야 한다.
