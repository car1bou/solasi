# 원문 선택·추가 해설의 실제 강의자료 비교

## 범위와 자료

2026-10-28, 기존 Qwen3.5 4B와 Mac에 설치된 내장 `solasi-engine model-worker`로 비교했다. 외부 API와 새 모델은 사용하지 않았다. 한국어 한 과목과 영어 두 과목에 한국어 질문을 사용했다.

자료 전체를 검색하는 성능 시험은 아니다. 고정한 페이지를 검색 결과로 전달한 뒤 입력 예산·원문 단위화·모델 선택·표시를 비교했다. 임베딩 검색 순위나 전체 자료의 검색 재현율을 측정했다는 뜻이 아니다. 원본 SHA256과 추출 문자열·질문·실제 요청·출력·사용량·시간은 비공개 검증 폴더 `.local-state/answer-relevance-20261028`에 보존한다. 자료 원문과 모델 파일을 Git에 넣지 않는다.

## 비교 조건

초기 진단은 동일한 PDFium 텍스트를 고정해 질문 여섯 개에서 기존·후보의 원문 선택과 해설을 각각 비교했다. 원문 선택의 출력 한도는 512, 해설 진단은 양쪽 모두 1024다. 제품의 기존 자유 해설 한도 4096과 같지 않으므로 이 진단을 제품 전체의 성공률이나 속도 개선으로 보고하지 않는다.

이후 실제 설치 앱의 `material-worker parse`로 원본 94쪽을 읽었다. 세 PDF 모두 `ready`였지만 수식의 추출 순서와 기호는 별도 대조가 필요했다. 확률론 자료에서는 합 기호와 아래첨자가 분리되어, 모델이 확률 하나가 무한대인 것처럼 잘못 설명할 수 있는 입력이 됐다. 이 오류를 프롬프트만의 문제나 OCR 개선 성과로 해석하지 않는다.

최종 확인은 실제 앱 추출문과 `freeze_request`의 8192 입력 예산, 과거/새 정책별 실제 선택 입력을 사용한다. 질문 여섯 개에 후속 질문 세 개를 추가한다. 반복해서 같은 질문을 사용한 개발 비교이며 통계적 일반화나 독립 평가 세트의 정확도 수치가 아니다.

## 발견한 원인

- 기존 원문 단위는 줄마다 나뉜다. 슬라이드의 제목·번호·줄바꿈이 각각 ID가 되어 8개 선택 한도를 먼저 소모한다. 교착상태 질문에서는 뒷부분 조건과 예방 방법이 빠졌다.
- 표시 단계는 요약용 문맥 보존을 사용하므로 ID 선택 뒤 주변 문장이 더 붙는다. 선택 ID의 관련성과 화면에 보이는 전체 문장의 관련성은 다르다.
- 입력 예산이 앞쪽 근거에서 소진되면 뒤쪽 출처는 제외될 수 있다. 실제 정규화 페이지를 이용한 예산 비교에서 기존 방식은 19쪽과 47쪽 일부를 보존하고 48쪽을 제외했다. 단위화 후보는 세 쪽을 모두 보존했다. 이는 고정 검색 결과에 대한 예산 비교다.
- 기존 해설의 검사는 출처 ID·쪽·시각의 일치 검사다. 설명의 논리나 정보의 누락을 보증하지 않는다.

## 적용에서 제외한 후보

| 후보 | 실제 관찰 | 결정 |
|---|---|---|
| 선택 ID만 그대로 표시 | 정규화의 1NF 전제 누락 | 제외 |
| 앞뒤 한 문장으로 문맥 축소 | 줄바꿈된 역방향 조건의 뒷부분 절단 | 제외 |
| 길고 상세한 원문 선택 지침 | 없는 증명 질문에 MIT 제목 선택, 순환 대기 예방의 후반 누락 | 제외 |
| 길고 상세한 해설 지침 | 정규화의 정보 손실 설명은 개선됐지만 질문하지 않은 한계 생성, 수식 부호 누락 | 제외 |
| 짧은 해설 지침 | 한계는 줄었지만 1NF 조건 누락과 수식 오독 잔존 | 제외 |
| 원문 단위만 묶기 | 교착상태 범위는 개선됐지만 없는 증명에 다른 정리 선택 | 단독 적용 제외 |
| 같은 Qwen으로 생성 해설 재검사 | 정규화의 반대 설명·교착상태의 반대 설명·조건 누락·중단된 설명까지 모두 supported 판정 | 자동 검증기로 적용 제외 |

해설 재검사의 결과는 품질 보증이 아니다. 기존의 잘못된 답변에 모델 한 번을 더 호출하는 것으로 이 문제가 해결되지 않았다. 생성된 한계 문구를 사후 문자열 규칙으로 삭제하거나, 근거 부족을 빈 문자열로 강제하지 않는다.

## 적용한 변경

새 로컬 질문의 `answer-grouped-evidence-v2` 정책에는 다음 두 변경만 적용한다.

1. 원문 단위·ID·내용은 그대로 두고, 모델 입력에서 출처의 종류·쪽·라벨이 줄마다 반복되는 것을 출처별로 묶는다. 자료가 포함된 질문은 evidence 뒤에 question을 둔다. 기존 구간 선택·인용 schema와 상한 8개는 유지한다.
2. 같은 자료 출처에서 실제로 맞닿은 선택 범위는 표시 전에 합친다. 문장이 같다는 이유로 삭제하지 않는다. 원문 자체의 반복은 남기고, 앞 문맥을 각각 붙여 생긴 중복 표시만 줄인다.

320자 단위로 **원문 자체를 크게 묶는 후보는 철회했다**. 독립 검토에서 올바른 첫 구간을 골라도 무관한 공지가 기존 3문장에서 36문장으로 늘어나는 회귀를 재현했다. 최종 구현은 원래 문장 단위와 공용 요약 함수를 유지한다. 동일한 ID를 선택했을 때 metadata 묶기가 표시 범위를 바꾸지 않는 검사를 추가했다.

작업 제출 시 새 정책을 고정하고 예산 계산과 실행에 동일한 입력 형식을 쓴다. 이전 `answer-excerpts-v1` 작업과 정책 필드가 없는 과거 작업은 이전 형식으로 재시도한다. 이미 저장한 답변을 재작성하지 않는다. 자료 없는 메모·확정 전사·승인한 손글씨만의 요청은 이전 선택 입력과 동일하다. 외부 API·추가 해설·요약은 변경하지 않는다.

## 실제 Mac 추출문으로 확인한 결과

실제 앱 추출문을 고정해 기존 정책 9회와 최종 metadata 묶기 정책 9회를 실행했다. 최종 9회는 모두 형식 검사를 통과했고, 각 인용이 전달한 원문의 정확한 부분 문자열이며 쪽·시각이 일치함을 확인했다. **이는 9개 질문의 내용이 모두 정답이라는 뜻이 아니다.**

| 확인 항목 | 결과 |
|---|---|
| 2NF 조건·natural join 질문의 입력 | 기존 19쪽 전체와 47쪽 일부 → 새 방식은 19·47·48쪽 전체 보존. 출력에 1NF와 원문 설명 보존 |
| 5NF까지 반드시 분해해야 하는가 | 기존은 47쪽의 정규화 단계 선택 → 새 방식은 48쪽의 불필요하다는 예외 원문 포함 |
| 교착상태의 복수 요구 | 27쪽의 잘리던 후반도 입력에 보존. 그러나 모델이 예방 방법까지 선택하지 못하는 누락은 남음 |
| 없는 시험 날짜·페르마 증명 | 모두 빈 선택. 다른 정리를 해당 증명으로 바꾸지 않음 |
| 독립 가정 | 원문의 가정과 가정 없이는 성립하지 않는다는 설명 보존. 수식 추출 오류는 별개로 남음 |
| 조건부 확률의 전제 | 실제 앱 추출문에서 정의의 전제가 누락되어 기존·새 방식 모두 충분히 답하지 못함. 성공 사례로 세지 않음 |

2NF 질문의 실제 입력과 schema 합계는 기존 7,366바이트에서 새 5,869바이트로 줄면서 더 많은 원문을 담았다. 이는 앱의 보수적인 바이트 예산에서 확인한 결과이며, 모델 토큰 수나 일반적인 속도 개선 비율이 아니다. 같은 실행 부하를 통제한 속도 시험은 하지 않았다.

인접 범위 병합은 최종 9회의 저장된 실제 모델 응답에 적용해 재검증했다. 모델 메시지와 schema가 원래 실행과 완전히 같음을 확인한 후 표시만 재구성했다. 교착상태의 한 결과는 912자에서 599자가 됐고, 아홉 결과 모두 원문 인용의 서로 다른 `(출처, 문자열)` 집합은 같았다. 별도 회귀 검사에서는 원문 자체에 두 번 나오는 반복 문장이 두 번 남았다. 추가 모델 추론을 한 결과로 세지 않는다.

## 해설의 현재 한계

추가 해설의 품질 개선은 이번 비교를 통과하지 못했다. 짧은 지침이 한계를 줄여도 필수 조건을 빼먹었고, 긴 지침은 원문에 없는 한계를 붙였다. 같은 모델의 재검사도 이 오류를 안정적으로 찾지 못했다. 따라서 새 해설 지침이나 자동 검증기는 적용하지 않았다. 사용자가 승인한 ‘자료로 뒷받침되는 설명만’이라는 목표는 아직 충족했다고 주장할 수 없다.

또한 입력을 더 보존해도 모델이 필요한 구간을 모두 고르는 것은 아니다. 넓은 주변 원문을 고르거나 복수 요구의 일부를 빠뜨리는 문제가 남는다. 일반 답변 정확도·전체 자료 검색 재현율·다른 과목이나 모델의 성능으로 일반화하지 않는다.

## 검증과 보존

기존 기록·원음·필기·승인문·초안을 수정하는 코드나 DB 마이그레이션은 추가하지 않았다. 실험은 별도 폴더와 임시 DB에서 실행했다. 실제 설치 앱의 자료 추출 worker와 모델 worker를 사용했으며 GUI 설치·재실행을 새로 검증한 것은 아니다. 다른 Windows·UI 작업은 이번 커밋에서 제외한다.

격리한 Mac 소스의 최종 회귀 검사는 697개 중 696개 통과·환경 선택 검사 1개 생략이다. 현재 작업 폴더에서도 관련 검사 17개를 통과했다. 새 metadata 입력을 다시 평탄화하면 이전 근거의 모든 필드·ID·문자열과 같고, 전사·승인 손글씨만의 입력은 이전 메시지와 완전히 같다. 과거 정책 재시도·실제 입력 예산·출처·반복 보존을 포함한다. 최종 커밋과 원격 main 대조 증빙은 비공개 검증 폴더의 `git-result.json`에 보관한다.
