# 긴 한국어 음성의 구간 겹침·문맥 보존 비교

2026-10-23 · 기존 Mac 로컬 Whisper large-v3-turbo

## 적용 판정

**항상 앞뒤 원음을 겹치는 두 방식은 제품 기본 경로에 적용하지 않았다.** 소음 일부에서는 오류가 줄었지만, 수동 정답이 완전한 원본 응답과 일반 강연에서 오류·중복이 늘었다. 긴 대화에서도 같은 시간대의 부분 문구 반복 후보가 남았다. 모델 문장 전체의 중간점만으로 소유권을 나누는 방식은 안정적인 병합을 보장하지 못했다.

기존 전사·수정·과거 출처·원음·필기는 바꾸지 않았다. 이번 main 반영은 실험 도구·검사·집계·보고서이며, 기본 전사 품질이 개선됐다는 판정이 아니다.

## 비교 범위

기존 VAD 여백 비교와 달리 **전사 구간 바깥의 실제 PCM**을 앞뒤로 더 읽었다. 제품의 `file_boundaries()`·`quiet_cut()`로 각 파일을 한 번 분할해 경계를 고정하고, 같은 소유 구간에 앞뒤 0·1·2초를 포함한 입력을 비교한다. native VAD는 기존 1초 여백·최소 발화 길이를 유지하고 용어 힌트는 모두 비웠다. 새 모델·서버·음성 전처리·외부 API는 사용하지 않았다.

소음에 따라 제품의 조용한 지점 선택이 달라질 수 있어 원본과 혼합본의 분할 경계는 서로 다르다. 같은 파일 안의 세 겹침 조건에서는 경계가 동일하다. 다른 파일 간의 분할 수 차이를 겹침 효과로 계산하지 않는다.

## 시간과 소유권

- 원래 소유 구간은 서로 겹치지 않는다. 실제 추론용 입력만 같은 연속 원음 범위 안에서 확장한다.
- native가 반환한 문장 시각을 현행 파서의 입력 길이 제한·ms 반올림을 거쳐 선택 입력 WAV의 시간축으로 환산한다. 이 시각은 자른 원본 영상 전체의 시각이나 단어별 정렬이 아니다.
- 문장 시작·끝의 중간점이 들어가는 반열린 소유 구간에 문장 전체를 배정한다. 경계에 중간점이 정확히 닿으면 뒤 구간 소유다.
- 문장 일부를 글자 수로 나누거나 시각을 core 경계에 맞춰 자르지 않는다. 모든 원래 모델 출력과 배정 후 출력을 구분해 보존한다.
- 배정 후 정렬 전 시작 시각 역전·구간 간 시간 겹침·텍스트 겹침 후보를 기록한 후, 출력은 실제 시작 시각 순으로 나열한다.
- 텍스트 겹침 후보는 서로 다른 소유 구간의 **시각이 실제로 겹치고**, 정규화한 suffix/prefix가 4자 이상 일치하는 경우다. 단순 문구 반복만으로 자동 삭제하지 않는다. 후보 수가 실제 중복 사건 수는 아니다.

중간점 배정은 검증할 실험 정책이다. 왼쪽 인식은 긴 문장, 오른쪽 인식은 짧은 두 문장으로 나눌 수 있어, 서로 다른 분절을 조합하면 부분 중복·부분 누락이 남을 수 있다. 원음을 겹쳐 준 것만으로 이 문제가 해결됐다고 전제하지 않는다.

실제 입력은 연속 파일만 사용했다. 불연속 입력 선언은 거절하고 범위 함수는 같은 연속 run을 넘지 않게 검사한다. 절전으로 생긴 실제 PCM 수집 공백을 재현한 추론 시험은 아니다. 현재 제품의 live source frame와 stored frame가 공백 뒤에 달라진다는 점 때문에, 단순 저장 인덱스 확장을 live 녹음에 적용하지 않는다.

## 실제 자료와 정답 범위

자료·원음 해시·분할 경계를 모델 실행 전에 고정했다. 기존에 확보한 [강연·인터뷰·생활 소음 자료](lecture-material-hints-20261020.md)를 재사용하며 원음·참조 전사·인식문·모델은 공개 저장소에 넣지 않는다.

| 자료 | 조건 수 | 어휘 정답 범위 |
|---|---:|---|
| 실제 한국어 기술 강연 2개, 각 약 2분 | 원본·사무실·식당 6 | 검수한 자동 자막과의 차이. 완벽한 축어 정답 아님 |

| 자연스럽게 이어진 10.5분 대화 | 원본·식당 2 | 응답자 수동 정답은 있으나 인터뷰어 `<IVER>` 미전사. 전체 CER 금지 |

총 16파일 조건·2,272.811125초(약 37.9분)이며 소유 구간은 91개다. 같은 원본의 소음 대응본을 다른 사람이나 독립 자연 녹음으로 세지 않는다. 타깃 사람 음성을 짧게 잘라 반복 연결한 긴 발화는 사용하지 않았다. 65초 환경음도 각 원음의 연속 부분이며 반복하지 않았다.

강연 혼합과 인터뷰 식당 조건은 실제 환경음을 섞은 파생 조건이다. 실제 소음 현장에서 새로 녹음한 한국어 강의·회의라고 부르지 않는다. 10.5분 대화의 환경 소음은 기존 혼합본에서 300.004초마다 반복되며, 선택한 대화의 혼합 clipping은 0이다. 원래 실제 사람 대화 자체는 반복하지 않았다.

## 측정 정의

완전 수동 정답과 검수 자막은 별도로 묶어 기존 NFKC·소문자·문자/숫자 정규화의 문자 편집 거리·삭제·삽입·치환을 계산한다. 숫자 표기·영문 병기·머뭇거림의 자막 편집 차이도 포함되므로 모든 증가를 청각적 오류나 의미 환각으로 해석하지 않는다. 최소 편집 정렬의 문자 삭제·삽입 수는 실제 누락·중복 사건 수와 다르다.

10.5분 대화의 `edits`, `reference_chars`, `cer`는 `null`이다. 전체를 불완전한 응답자 정답과 대조해 오류율을 만들지 않는다. 시간상 겹치는 모델 문장들을 이어 수동 정답의 완전한 구절이 있는지 별도 확인한다. 기존에 일치했던 구절의 일치가 사라지거나 반복되는 수는 부분 진단이며, 다른 올바른 표기·분절·시각 차이도 영향을 주므로 실제 누락 사건 수나 전체 정답률로 해석하지 않는다. 원래 chunk 출력에 있던 구절이 최종 출력에서 연속 일치하지 않는 경우도 기록하지만, 중간에 중복 문구가 끼어 일치가 깨질 수 있어 그 단어들이 전부 삭제됐다는 뜻은 아니다. 반환 시각 유효성·겹친 원음 범위·중복 의심 문구·주석과 모델 출력의 부분 대조를 위한 구조 진단으로 쓴다.

짧은 SIL 3개는 단일 구간이라 앞뒤로 새로 읽을 이웃이 없다. 이 결과만으로 긴 비발화 경계에서의 안전성을 입증하지 않는다. 긴 환경음 대조의 생성 문자 수와, 긴 대화의 SIL 주석 안에 반환된 시각을 별도로 조사한다. 환경음에는 배경 발화가 있을 수 있어 출력을 모두 의미 환각이라고 확정하지 않는다.

시간은 입력 준비를 포함한 조건 전체와 기존 디코더의 세부 시간(자산 확인·오디오 준비·native 프로세스·파싱)을 구분한다. 최초 엔진·모델·VAD 해시는 조건 시간 측정 전에 확인했다. 고정 0→1→2초 순서로 한 번씩 실행했으며 초기에는 회귀 검사가 함께 돌아갔다. GPU 최초 준비·캐시·호스트 부하가 통제된 반복 속도 시험은 아니다.

## 실제 결과

16조건 × 3겹침 = 48행을 완료했고 실패 0행이었다. 273개 확장 입력 WAV의 SHA256을 원본 PCM과 고정 범위에서 독립적으로 다시 구성해 대조했다. 반환 문장의 범위·중간점 소유권도 전부 검사했다. [본문·경로 없는 집계](verification/chunk-overlap-20261023.json)에 입력 해시·경계·코드·모델·실행 결과 해시와 개별 지표를 보관한다.

같은 8개 유참조 조건을 개별 비교했다. 서로 다른 녹음과 소음 대응본의 합계를 섞어 악화를 숨기지 않는다.

## 코드·보존 검증

- 새 비교기는 모델 원문·배정 문장·확장 범위·원음 해시·native 세부 시간을 별도로 기록하고, 완료 전에는 `completed:false`로 저장한다.
- 원음 변경·소실은 실패 행으로 남기며 이미 끝난 구간 출력도 보존한다. 변경된 원음은 다음 조건의 추론 전에 거절한다. 원음 변경 회귀 검사의 실패를 확인하고 수정했다.
- 같은 연속 run 경계 제한·중간점 소유권·실제 문구 반복 보존·시간 역전·불완전 참조 CER 금지·실패 부분 결과 검사 9개 통과.
- Python 전체 660개 중 655개 통과·선택 검사 5개 생략. 프런트엔드 104개·TypeScript·CLI 도움말·diff 공백 검사를 확인했다.
- 별도 QA 보관함의 실제 파일 등록·구간 계획·저장 경로에 이미 실행한 기준 디코더 출력을 재생했다. 실제 PCM 구간 5개, 저장 문장 21개의 텍스트·시각이 일치했고 새 QA 수정 뒤 과거 출처 21개가 보존됐다. DB integrity `ok`, FK 오류 0이다. 추가 ASR 실행이나 설치 앱 GUI 검증으로 부르지 않는다.
- UI UX Pro Max의 실제 재생 범위·복구 경로·사용자 제어 기준을 유지했다. 단어별 정렬이 없는 상태에서 글자 수로 선택 재생 시각을 만들지 않는다.

제품은 현재 문장이 소속 core 안에 있어야 한다는 저장·수정·후보 검사를 한다. 이 실험의 core 밖 native span를 제품에 쓰려면 실제 decode 범위와 출처를 함께 보존해야 하며, 저장 검사만 느슨하게 바꾸면 안 된다. 이번 결과는 채택 기준을 통과하지 못해 제품의 해당 경로를 수정하지 않았다.

## 재현

연속 mono PCM16/16kHz와 고정 manifest를 준비한 뒤 새 출력 경로로 실행한다. manifest에는 `completed:true`, 파일별 `id`, `path`, `sha256`, `frames`, `group`, `continuous:true`, `boundaries`(0과 전체 프레임 수 포함), `reference_kind`, `reference`가 필요하다. 경계는 세 조건에 공통으로 고정한다. `reference_kind`는 `manual-complete`, `reviewed-captions`, `partial-conversation`, `silence`, `target-absent-noise` 중 하나이며, 참조는 모델 입력으로 주지 않는다.

```sh
.venv/bin/python experiments/compare_chunk_context.py \
  --manifest /absolute/path/to/fixed-manifest.json \
  --runtime /absolute/path/to/prepared-runtime \
  --overlap-ms 0 1000 2000 \
  --output /absolute/path/to/new-overlap-results.json
```

실제 설치 앱·현재 보관함·원음·필기·초안·완료 전사·수동 수정·과거 출처는 수정하지 않았다. 실제 새 마이크·절전·수집 공백을 재시험하거나 모든 경계를 직접 청취한 결과가 아니다. native 문장 시각의 보존·범위 검사와 단어별 시간 정확도는 구분한다.
