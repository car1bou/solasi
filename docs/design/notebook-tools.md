# 필기 도구 · A outline

펜·형광펜·지우개·올가미·이동·실행 취소/재실행은 A 시안을 기준으로 정리한 SVG를 사용한다. 24×24 좌표계, 1.65 선 두께, 둥근 선 끝·연결, `currentColor`를 사용하며 실제 툴바는 20px다. 선택 도구는 옅은 채움과 얇은 테두리로 표시하고, 굵은 아래선과 버튼 그림자는 사용하지 않는다.

- 다른 도구를 누르면 선택한다. 선택한 펜·형광펜·지우개를 다시 누르면 설정창이 열린다.
- 펜·형광펜: 색, 굵기, 불투명도. 지우개: 획/부분 지우기와 크기.
- Escape 또는 닫기 버튼은 도구 버튼으로 포커스를 돌려준다. Tab과 방향키로 슬라이더를 조절할 수 있다.
- 설정창 밖을 누르면 닫힌다. 페이지 위 첫 입력은 닫기에만 사용해 의도치 않은 필기·삭제를 막는다.
- 기존 설정을 그대로 읽고, 다음 도구 설정 저장부터 선택 항목 `eraserMode`를 함께 저장한다. 다른 도구를 사용 중이거나 앱을 완전히 종료해도 마지막 지우개 방식을 복원한다. 구형 설정에 이 항목이 없으면 선택된 부분 지우기를 이어받고, 그 외에는 획 지우기로 시작한다.

## SVG

원본 파일: `frontend/public/icons/notebook/`. 앱 경로와 동일한지 자동 검사한다. [20·24px 라이트·다크 비교](notebook-icons-a.svg).

## Mac 확인 · 2026-10-19

설치 앱 0.3.9/build19에서 PDF 페이지의 20px 아이콘, 라이트·다크 설정창, 첫 클릭 선택/재클릭 설정, 지우개 방식 전환, 펜 굵기 변경, Tab·방향키 조절, Escape 포커스 복귀를 확인했다. 비교 시트의 20·24px는 브라우저 SVG 렌더링으로 확인했다. 기존 43개 DB 테이블은 검증 후 원본과 동일했다. 프런트엔드 94개 검사와 프로덕션 빌드가 통과했다.

이번 변경은 필기 UI에 한정한다. 실제 펜 타블렛 입력과 전사·생성 성능은 재측정하지 않았다.

## 재시작·실제 필기·680px 확인 · 0.3.10/build20

- 지우개 방식은 보관함의 기존 설정 레코드에 저장하며 DB 테이블을 추가하지 않는다. 잘못된 값은 저장 전에 거부한다.
- 펜을 선택한 채 종료한 후 부분 지우기 복원, 형광펜을 선택한 채 종료한 후 획 지우기와 크기0.02 복원을 확인했다.
- 실제 Mac 마우스 입력으로 빈 PDF 페이지에 펜과 형광펜 획을 작성했다. 저장된 펜 굵기0.003, 형광펜 굵기0.02/불투명도0.45가 설정과 일치했다. 두 도구의 저장 색상도 획에 적용됐다.
- 획 지우기는 형광펜 한 획 전체만 지웠다. 실행 취소 후 부분 지우기는 같은 획의 중간을 잘라 두 조각을 남겼다. 원래 펜 획과 형광펜 조각의 색·굵기·불투명도가 유지됐고 앱 재실행 뒤에도 결과가 복원됐다.
- 동일한 제품 코드에서 초기 창 폭만680px로 지정한 별도 Mac 검증 앱과 보관함 복사본을 사용했다. 680×820 라이트·다크에서 설정창의 가로·하단 전체 표시를 확인했다. 열릴 때 전체 범위를 화면에 맞추고, 짧은 창에서는 높이를 제한해 내부 스크롤을 허용한다.
- 프런트엔드95개 검사와 네이티브 설정·작업 엔진28개 검사가 통과했다. 새 frozen engine의7826개 파일 해시와 자체 검사를 확인했다.

실제 펜 타블렛의 압력·기울기와 macOS 기본 색상 팔레트의 모든 색상 선택 동작은 이번 검증 범위에 포함하지 않았다.

## 색상 직접 입력·짧은 창 확인 · 0.3.11/build21

- 기본 색상 팔레트와 함께 `#RRGGBB` 입력을 제공한다. Enter 또는 ‘색 적용’으로 확정하며, 잘못되거나 불완전한 코드는 기존 색을 바꾸지 않는다. 닫기·도구 전환은 미적용 입력을 버린다.
- Tab이 설정창 밖으로 나가면 창을 닫아 다음 버튼의 포커스를 가리지 않는다. Escape는 선택 도구로 돌아간다.
- 높이600px 이하에서는 설정창 높이를60dvh로 제한하고 내부 스크롤을 사용한다. 스크롤 끝에서 페이지로 스크롤이 넘어가지 않게 한다. 오류로 높이가 늘어날 때도 전체 설정창을 화면 안에 맞춘다.
- 동일한 Mac 제품 코드에서 초기 창 크기만680×480으로 지정한 검증 앱과 보관함 복사본을 사용했다. 실제 키보드 입력으로 펜을#2563eb, 형광펜을#e11d48로 바꾸고 획을 작성했다. 종료·재실행 후 두 설정과 기존 획이 복원됐고, 새 획에도 같은 색이 적용됐다. 총4획의 저장 값으로 확인했다.
- #12와#ZZZZZZ는 오류 안내만 표시하고 저장 색상을 유지했다. 라이트·다크에서 오류로 생긴 내부 스크롤, 하단 슬라이더 Tab·방향키 조절, Tab으로 창 밖 이동 시 닫기, Escape 포커스 복귀를 확인했다.

이번 색상 변경 검증은 승인된 코드 입력 경로를 사용했다. macOS 기본 팔레트는 유지했으며 팔레트 자체의 색 선택은 화면 도구의 조작 한계로 확인하지 못했다. 실제 펜 타블렛의 압력·기울기도 이번 범위에 포함하지 않았다.

## macOS 기본 팔레트 선택 확인 · 0.3.11/build21

- 같은 프런트엔드와 내장 엔진을 사용하는 680×480 Mac 검증 앱에서 보관함 복사본으로 확인했다. 화면 도구가 네이티브 팔레트의 색상 버튼을 조작하지 못해, 사용자가 팔레트에서 펜 초록색과 형광펜 노란색을 직접 선택했다. 색상 코드 입력과 ‘색 적용’은 사용하지 않았다.
- 선택 후 화면의 색상 표시와 저장된 설정이 펜 `#77bb41`, 형광펜 `#f5ec00`으로 일치했다. 실제 마우스 필기로 두 획을 작성하고 저장했다.
- 앱을 완전히 종료·재실행해 같은 PDF를 다시 열었다. 기존 여섯 획이 그대로 복원됐으며, 추가한 두 획에도 같은 팔레트 색상이 적용됐다. 총 여덟 획의 저장 값을 대조했다. 펜 굵기0.0035/불투명도1, 형광펜 굵기0.02/불투명도0.45도 유지됐다.
- 이 선택·저장·복원 경로에서 수정이 필요한 오류는 재현되지 않아 제품 코드는 변경하지 않았다. 실제 사용자 보관함은 변경하지 않았다.

이번 검증은 기본 팔레트에서 직접 고른 두 색에 한정한다. 팔레트의 모든 탭·스포이트·색 공간과 실제 펜 타블렛의 압력·기울기는 확인하지 않았다.

## 설치된 Mac 앱의 연속 사용 확인 · 0.3.11/build21

- 실제 설치된 `~/Applications/Solasi.app`과 실제 보관함에서 새 검증 과목·별도 PDF를 사용했다. 시작 전에 보관함의 일관된 백업을 만들었다. 파일 선택창의 경로 입력과 최소 폭 조절은 화면 도구의 한계로 사용자가 직접 완료했다.
- 캡처 크기680×820에서 라이트·다크 툴바와 설정창을 확인했다. 도구 선택·설정 열기, 선택 밑줄, 비활성 실행 취소/재실행 표시가 겹치거나 잘리지 않았다. Tab·방향키로 굵기/지우개 크기를 바꾸고, Escape로 도구 버튼에 복귀했으며, Tab이 설정창을 벗어나면 창이 닫혔다.
- 이번 설치 앱의 색 변경은 코드 입력 경로를 사용했다. 펜 `#2563eb`/굵기0.002/불투명도1, 형광펜 `#e11d48`/굵기0.018/불투명도0.35로 실제 마우스 획을 그리고 저장 값을 대조했다. 네이티브 팔레트 직접 선택은 위의 별도 검증 앱 결과와 구분한다.
- 획 지우기는 형광펜 한 획 전체만 제거했다. 실행 취소로 복원한 뒤 부분 지우기는 중간을 잘라 두 조각을 남겼고, 펜 획과 형광펜 조각의 색·굵기·불투명도를 보존했다.
- 메모까지 저장한 뒤 앱을 완전히 종료·재실행했다. 메모·3개 획·저장 버전6·펜/형광펜 색·부분 지우개 방식과 크기0.015가 재실행 전과 동일했다. 창은 재실행 시 기본1200×820으로 열렸으므로,680px 확인은 재실행 전에 수행했다.
- 실제 JSON 내보내기 버튼과 macOS 저장 창으로 파일을 저장했다. `solasi-page-notebook-v1`의 메모·획·저장 버전·과목·자료·페이지·PDF 해시가 보관함과 일치했다.
- 검증 후 공용 도구 설정과 화면 모드를 원래 값으로 복원했다. 기존41개 논리/내용 테이블의 모든 원래 행이 보존됐고 DB 무결성·외래 키 검사가 통과했다. 자료 추가로 재구성되는 FTS 내부 세그먼트/색인2개 테이블은 바이트 단위 보존 비교에서 제외했다. 검증 과목과 PDF·필기·내보내기 파일은 결과 확인용으로 남겼다.

이 흐름에서 제품 수정이 필요한 오류는 재현되지 않았다. 설치 앱을680×480으로 줄인 시험, 실제 펜 타블렛 입력, 강제 종료 중의 미저장 필기 복구는 이번 범위에 포함하지 않았다.

## 최소 창·미저장 초안 복구 · 0.3.12/build22

- 주 창에만 AppKit의 `setFrameAutosaveName`을 연결했다. 시작할 때마다 기본1200×820으로 돌아가던 동작을 수정했다. [Apple 창 프레임 저장 API](https://developer.apple.com/documentation/appkit/nswindow/setframeautosavename(_:))를 사용하며 추가 창은 주 창의 저장 이름을 공유하지 않는다.
- 실제 설치 앱을 사용자가 최소 크기로 줄인 후 캡처로680×480을 확인했다. 정상 종료 후1회, 아래 강제 종료 후2회 모두 재실행 시680×480이 유지됐다.
- 라이트·다크 각각 펜·형광펜·지우개 설정과 툴바의 선택·비활성 상태를 확인했다. 긴 오류 안내가 생기면 설정창 안에서 스크롤할 수 있고, 하단 슬라이더에 키보드로 접근할 수 있었다. Escape 포커스 복귀와 Tab 이탈 시 닫힘도 확인했다. 이 배치에서 추가 UI 수정이 필요한 오류는 재현되지 않았다.
- 검증 과목의 별도 PDF2쪽에서 미저장 획과 미저장 메모를 서로 다른2회 시험으로 확인했다. 읽기 전용 감시로 해당 페이지의 초안이 기록됐으나 정식 페이지 내용과 다른 시점을 확인해 실제 설치 앱 프로세스만 `SIGKILL`로 종료했다. 종료 직후 정식 페이지가 여전히 이전 버전인 것도 대조했다.
- 획 시험: 정식 페이지v0에는 획이 없고 초안에만 펜1획이 있는 상태로 종료했다. 재실행 후 같은 페이지를 열자 초안의 획 ID·좌표·색·굵기·불투명도가 그대로 복원돼v1으로 저장됐다.
- 메모 시험: 정식 페이지v1의 메모는 비어 있고 초안에만 `UNSAVED-MEMO-20261019`가 있는 상태로 종료했다. 재실행 후 원문과 기존 획이 정확히 복원돼v2로 저장됐다. 복구 기능 자체는 기존 코드로 통과해 변경하지 않았다.
- 검증 전 앱 실행 파일·서명·설정과 보관함을 백업했다. 검증 후 공용 도구·시스템 화면 모드를 원래 값으로 복원했다. 기존41개 논리/내용 테이블의 모든 원래 행 보존, DB 무결성·외래 키 검사를 확인했다. FTS 내부 세그먼트/색인2개 테이블은 물리적 행 비교에서 제외했다.
- arm64 네이티브 빌드, 설치 앱의 서명 검사, 설치·네이티브 초안 관련16개 회귀 검사가 통과했다. 내장 엔진·프런트엔드·보관함 경로는 변경하지 않았다.

복구 시험은 입력을 마친 획과 메모의 초안 기록이 완료된 뒤, 정식 페이지 저장 전 종료한 조건이다. 펜을 떼지 않은 진행 중 획, 초안 기록 자체가 끝나기 전 종료, 전원 차단, 실제 펜 타블렛 압력·기울기는 확인하지 않았다.

## 평평한 선택 표시 · 0.3.13/build23

- 승인된 디자인에 따라 필기 툴바의 굵은 아래선과 버튼 그림자를 제거했다. 라이트는 옅은 회색 채움과 짙은1px 테두리, 다크는 차콜 채움과 밝은1px 테두리를 사용한다. 툴바 버튼 모서리는8px로 통일했다.
