# 손글씨 지식 편입·자동 색인 검증

확인일: 2026-10-19. Mac Preview 구현·검증 기록. 이 파일은 제품 사용 가이드가 아니라 측정 근거다.

## 공개 실제 손글씨 비교

출처: https://github.com/jkf87/korean-handwriting-ocr-benchmark

고정 커밋: `3a81a6f4b57ea91602a5f7740337a438431b8230`. 공개 수동 정답·실제 손글씨 6장과 인쇄 대조군 2장을 로컬에서 비교했다. 별도 데이터 라이선스 파일이 확인되지 않아 이미지·정답 원문은 앱이나 Git에 포함하지 않는다. 파일 출처·크기·SHA256 manifest는 `.local-state/handwriting-20261019/public-korean-manifest.json`에 있다.

측정: 공개 정답과 페이지 전체 출력을 NFC 정규화하고 공백을 제거한 문자 편집 거리/CER. 머리글·쪽 번호·비선형 배치도 입력에 포함하며 정답을 이 실험에 맞춰 임의 보정하지 않았다. 교과목 전문 필기·수식·벡터 획의 대표 벤치마크로 일반화할 수 없다. 연구소의 기존 성능 수치를 재사용하지 않고 실제 로컬 출력을 측정했다.

| 로컬 엔진 | 실제 손글씨 6장 가중 CER | 처리 시간 중앙값 | 표본별 CER 범위 |
|---|---:|---:|---:|
| Apple Vision accurate revision 3 | 19.59% | 0.712초 | 4.82–47.78% |
| 설치된 Qwen3.5 4B | 11.88% | 55.828초 | 1.51–36.65% |

CER는 낮을수록 좋다. Vision 첫 페이지의 초기 준비 시간은 15.20초였으며 위 중앙값으로 첫 실행 지연을 가리지 않는다. Qwen은 각 요청에 모델을 준비하고 추론·종료하는 실제 경로의 시간이다. 회귀 검사·빌드도 같은 Mac에서 수행 중이었으므로 전용 장비에서의 격리 성능 수치가 아니다.

인쇄 대조군 두 장의 CER는 Vision 3.57%·0.32%, Qwen 3.06%·5.06%였다. 공개 저장소는 `03_일란성쌍둥이`를 손글씨로 분류했지만, 실제 이미지 8장을 모두 확인하니 해당 파일은 인쇄된 책 페이지였다. 이를 인쇄 대조군으로 정정했다. 이전 분류의 손글씨 집계 16.00%·9.90%를 현재 표의 19.59%·11.88%로 바로잡았으며 원본 이미지·정답·엔진 출력은 바꾸지 않았다. Qwen도 항상 더 정확하지 않았고 거친 필기는 두 엔진 모두 오류가 컸다. 자동 후보는 가벼운 Vision을 사용하고, 사용자가 로컬 Qwen 재인식을 선택할 수 있다. 어떤 엔진의 결과도 확인 전에는 검색·답변·요약 근거로 편입하지 않는다.

재현 스크립트: `experiments/compare_handwriting.py`. 실제 저장 획의 helper 렌더링과 사진 이미지의 인식은 다른 입력 조건으로 구분한다. 현재 사진 비교는 수식·도형의 의미 해석 정확도를 증명하지 않는다.

## 구현된 보존·처리 기준

- 승인한 `ink_note`만 검색한다. 후보·거절·stale는 제외한다.
- 획이 A→B→A로 돌아와도 새 후보를 만들며 이전 승인 출처는 보존한다.
- 같은 자료가 여러 과목에 연결되어도 작업·개념 후보·승인을 과목별로 분리한다.
- 같은 과목의 검색 대상이 바뀌면 기존 관련 기록도 갱신한다. 거절한 개념은 같은 원문에서 되살리지 않는다.
- 증분 벡터는 완성된 chunk 단위로 저장한다. 새 모델·전처리의 색인은 완성 후 활성화하고 중간 재개를 지원한다.
- 자동 작업은 녹음·전사·사용자 요청과 충돌할 때 새 호출을 시작하지 않고 대기로 돌아간다. 외부 API를 자동 호출하지 않는다.
- Exa 신규 검색과 키 설정은 제거했다. 과거 웹 인용은 읽을 수 있다.

## 실행 결과와 남은 확인

- Python 전체 검사: 572개 중 567개 통과, 선택 검사 5개 생략. 프런트엔드 검사 98개 통과, TypeScript/Vite 빌드 성공.
- 별도 Mac 검증 앱에서 과목·PDF 원본·기존 필기·인식 검토 패널을 열고 Vision 인식을 실행했다. 시험 획은 글자가 아닌 선이므로 빈 인식문이 나왔고, 사용자가 확인하는 절차로 `검증용 선`을 입력·승인하여 출처로 저장했다. 이는 승인 UI 검증이며 실제 손글씨 정확도 수치에 포함하지 않는다.
- OCR 영역이 없는 수동 확인 출처도 원래 필기를 표시하도록 수정하고, 빈 필기의 로컬 Qwen 경로가 모델 준비 전 변수를 참조하던 오류를 회귀 검사로 수정했다.
- 실제 화면에서 관련 기록 API의 누락된 함수 import를 발견해 수정했다. 기록·과목 페이지 양쪽의 API 회귀 검사를 추가했고, 수정한 번들에서도 해당 API 응답을 확인했다.
- 최종 번들 IPC 시험(`experiments/validate_knowledge_pipe.py`): 자동 인식 후보 → 승인 → 검색 근거 연결, 관련 기록 API, 녹음 중 자동 처리 양보, 한국어 실제 음성 17.52초 전사와 요약 완료. PCM 280,320프레임이 원본과 일치했다. 이후 8,000프레임 저장 중 검증 엔진을 강제 종료·재시작하여 중단 상태·WAV 해시·메모·획·승인 출처 보존을 확인했다. 전체 경과 61.98초는 이 여러 작업과 초기화·복구를 포함하며 전사 속도 수치가 아니다.
- 이 시험은 별도 복사본에서 파일 PCM을 입력한 시험이다. 새 물리 마이크의 장시간 녹음·실제 Mac 절전, 680×480 두 테마 확인은 별도 완료 증거가 필요하다. 공개 이미지의 정확도, 벡터 시험 획의 승인 흐름, 실제 음성 재생 시험을 서로 구분한다.

## 실제 설치 앱과 창 이동 수정

사용자의 저장·종료 확인 후 원본 보관함 파일 41개의 로컬 백업과 SHA256을 대조하고 실제 `~/Applications/Solasi.app`을 교체했다. 설치 후 일관된 SQLite 백업을 만들어 위 표의 기존 모든 행이 그대로 남았는지 비교했다. 과목·기록·녹음·전사·페이지 문서·버전·초안·출처 모두 기존 행을 보존했고, 저장 원음 6개 파일의 SHA256도 일치했다. 외래키 오류 0개, 스키마 v18이다. 별도 설치 검증 과목 1개를 추가하고 PDF 연결 및 페이지 메모 저장을 실제 화면에서 확인했다.

사용자가 창 크기 조절과 이동이 불가능하다고 보고했다. `.fullSizeContentView`로 웹 본문이 기본 제목 막대 이동 영역까지 차지하는 설정을 제거하고, 숨긴 앱 이름·투명 제목 배경·기본 창 버튼은 유지했다. 실제 `AppWindow` 생성 코드를 컴파일하는 AppKit 검사에서 수정 전 제목 영역 점유 조건을 실패로 재현했고, 수정 후 이동·크기 조절 설정과 680×480 프레임 수용을 확인했다. 수정 앱 버전은 0.3.17/build27이다. 이 네이티브 구성 검사는 사용자의 실제 드래그 성공이나 680×480 두 테마의 시각 검증을 대신하지 않는다.

이동 수정은 사용자가 실제로 해결됐다고 확인했다. 이후 모서리 조절 영역이 너무 작다는 피드백을 받아 0.3.18/build28에 32×28px 크기 조절 손잡이와 윈도우 메뉴의 작은 창/기본 크기를 추가했다. 손잡이는 드래그와 클릭 후 방향키를 지원하며 최소 크기에서 멈춘다. 메뉴 단축키는 ⌥⌘1 / ⌥⌘2다.

실제 설치 앱에서 메뉴·단축키로 680×480을 만들고, 손잡이를 클릭한 뒤 오른쪽·아래 방향키로 700×500이 되는 것을 캡처 크기와 저장된 창 프레임으로 확인했다. 680×480 라이트·다크의 손글씨 검토 패널, Tab 포커스·스크롤, 비활성 저장 버튼을 확인하고 원래 시스템 테마로 복원했다. 설치 검증 과목의 메모가 앱 교체·재실행 뒤 남았고, 네이티브 저장 창으로 새 JSON을 내보낸 뒤 메모 본문과 `ink`·`handwriting` 필드를 확인했다. 이 페이지에는 새 필기 획을 성공적으로 입력하지 못했으므로 실제 설치 앱의 새 획 입력·승인 내보내기까지 검증했다고 보고하지 않는다. 별도 검증 앱·IPC의 승인/획 보존 결과와 구분한다. 손잡이의 실제 마우스 드래그 성공은 별도 확인 대상이며 메뉴·방향키 경로는 실제 확인했다.


## 완료 점검과 추가 수정 — 0.3.20/build30

설계와 Tasks 1–6의 핵심 구현은 승인된 범위로 연결되어 있다. Task 7의 통합 확인을 추가 진행하면서 다음 문제를 수정했다.

- **색인 재시작 재사용:** 앱 시작 시 모든 `building` 색인을 실패로 바꾸던 처리를 제거했다. 청크의 모든 part는 한 트랜잭션으로 저장하고 재개 전에 모델 digest·전처리 형식을 대조한다. 중간 색인을 활성화하지 않으며 완료한 청크부터 이어서 처리한다. 실제 시작 경로를 사용하는 회귀 검사에서 수정 전 중복 임베딩을 재현하고 수정 후 재사용을 확인했다.
- **인식 검토 초안:** OCR 수정 입력을 기존 ACK 기반 네이티브 초안 저장소에 연결했다. 후보별로 분리해 저장하며 승인 전에는 지식에 포함하지 않는다. 저장 실패를 표시하고, 오래된 후보의 보존 초안은 승인한 인식문과 구분한다. 별도 네이티브 검증 앱에서 `교착 상태 · 재실행 복구 검증`을 입력하고 ACK 저장을 대조한 뒤 앱을 SIGKILL했다. 재실행한 검토 입력란에서 같은 문자열이 복구됐으며, 그 뒤 승인했을 때만 지식 출처가 생성됐다.
- **색인 진행 표시:** 설정에 현재 검색 가능한 전체 청크와 완료한 청크 수를 표시한다. 한 청크에 여러 part가 있어도 중복 집계하지 않는다.
- **짧은 원문 창의 배율:** 680×480 원문 팝업에서 이미지의 높이 제한 때문에 PDF만 작아지고 SVG 필기·영역이 크게 남던 문제를 실제 화면에서 확인했다. 원본과 덧씌움이 같은 크기를 사용하도록 스타일을 수정했다. 새 실제 설치 앱의 같은 창에서 필기와 영역이 페이지 안에 맞는 것을 확인했고 아래 인식문·원문 링크까지 스크롤했다.

### 실제 입력·승인·내보내기

실제 설치 앱의 별도 검증 과목에서 펜으로 `교착`을 입력했다. 14개 획이 v4로 저장됐고 Vision이 `교착` 후보를 만들었다. UI에서 승인하고 당시 원문을 열어 필기·OCR 영역을 확인했다. 네이티브 저장 창으로 JSON을 내보낸 뒤 14개 획, 원문 버전 4, 원래 인식문, 승인문 `교착`, 원문 연결을 대조했다. 이것은 자동화 도구로 그린 두 글자의 입력 흐름 확인이며 사람 손글씨 CER 표본에 더하지 않았다.

### 검증의 범위

- Python 전체 검사 574개 중 569개 통과·선택 검사 5개 생략. 프런트엔드 101개 통과, TypeScript/Vite 빌드 성공.

- 복사본 시험에서 페이지 캐시 디렉터리를 빠뜨려 원본 미리보기가 실패했다. 번들 worker의 원본 렌더링은 별도 실행에서 통과했고, 빠진 복사본 디렉터리를 복원하자 UI의 원문·필기 표시도 정상 동작했다. 재현 스크립트는 assets 디렉터리를 함께 복사하도록 보완했다.
- 여러 독립 앱·AI 검증 엔진을 동시에 띄운 부하 시험에서는 요약이 모델 제한 시간을 초과하고 실제 마이크 녹음이 저장 대기 한도를 넘겼다. 원음·중단 정보가 남고 새 구간으로 자동 복구됐으나 이를 연속 무손실 녹음 성공으로 보고하지 않는다. 단일 앱 조건 검증과 구분한다.

### 실제 마이크·절전과 단일 엔진 재검증

검증 앱 하나에 저장된 마이크 원음은 두 구간 합계 **678.7초(11분 18.7초)**다. 첫 구간은 앞서 설명한 여러 독립 엔진 부하에서 저장 대기 한도를 넘겼고 새 구간으로 자동 복구됐다. 이 중단의 시간축 갭은 남겨 두었다. 사용자가 실제 잠자기·복귀를 수행했으며 macOS 로그에서 22:11 소프트웨어 절전과 연이은 thermal emergency 절전을 확인했다. 복귀 후 기존 원음 payload의 prefix SHA256, 페이지 버전, 승인 출처·인식문이 모두 일치했다.

이 캡처는 앞선 자동 복구 1회를 이미 사용한 상태여서 절전 뒤에는 ‘중단됨’으로 종료됐다. 따라서 이번 결과는 ‘매번 자동으로 이어지는 녹음’ 성공 증거가 아니다. 재시작 버튼과 원음 보존, 기존의 자동 복구 1회 제한을 유지한다. 원음 WAV의 프레임 수와 저장 DB 프레임 수가 일치했고 최초 전사 작업 2개·확정 전사 범위 25개가 완료됐다. 정답이 없는 이 마이크 녹음에서 CER나 환각률을 발표하지 않는다.

검증 과정에서 이전 복구 구간의 중단 사유를 후속 구간의 절전 사유로 덮는 문제도 재현했다. `AudioCapture`가 deferred 구간의 원래 사유를 함께 보관하고 종료 처리에 사용하도록 수정했다. 실제 Swift 복구 fixture에서 수정 전 실패·수정 후 통과를 확인했다. 복구 횟수나 적용 정책은 바꾸지 않았다.

다른 앱·독립 검증 엔진을 모두 종료한 단일 엔진 재실행은 **36.02초**에 전체 흐름을 완료했다. 자동 후보→승인→검색, 한국어 파일 PCM 280,320프레임 일치, 전사·요약 완료, 별도 8,000프레임 저장 중 SIGKILL 후 원음 해시·필기·메모·승인 출처 보존이 모두 통과했다. `.local-state/handwriting-completion-20261019/pipe-isolated/results.json`에 결과를 남겼다. 이 시간도 전체 통합 흐름의 시간이며 ASR 단독 성능 수치가 아니다.

네이티브 검증 앱에서는 전사 적체가 처리된 뒤 동일 요약을 재시도해 완료했다(생성 사용 기록 43,008ms). 화면의 핵심 원문에 승인한 `교착 상태 · 재실행 복구 검증` 인식문이 원문 인용으로 포함됐다. AI 선택이 충분하지 않은 항목은 ‘구간 선택 확인 필요’로 남겼다.


### 보충 조건: 혼합 문자·수식·도식

공개 원본을 직접 확인해 한국어 손글씨에 날짜·숫자·영문 단어, 교사의 작은 글씨, 강조색과 비선형 배치가 포함됨을 확인했다. 인쇄 책 페이지를 손글씨로 섞지 않도록 `experiments/compare_handwriting.py`의 분류도 수정하고 기존 엔진 응답으로 다시 실행했다. 검토한 결과는 `.local-state/handwriting-completion-20261019/reviewed-comparison/results.json`이다.

추가로 실제 앱에서 입력한 `교착` 획에 제어용 영문 `PDF`, `X=2`, 작은 X, 원→사각형 도식과 형광펜 획을 합친 동일 입력을 두 엔진에 주었다. 이는 절차적으로 만든 제어용 벡터이며 사람 필기 CER에 합산하지 않는다.

| 경로 | 시간 | 관찰 |
|---|---:|---|
| Vision | 0.302초 | `교착`, `POF`, 도식을 `0->`, 작은 X로 반환. `X=2` 누락 |
| 설치된 Qwen3.5 4B | 34.031초 | `PDF`, `X=2`를 반환했지만 `교착`을 `고.착`으로 바꿈. 도식을 `O → □`로 출력 |

형광펜 획은 렌더링 입력에서 제외됐다. 도식이 문자 기호로 반환되거나 수식이 누락되는 한계를 실제로 확인했으며, 자동 지식 편입·수식 의미 해석을 추가하지 않았다. 수식·도형의 정확한 구조가 필요하면 원래 획을 보고 검토·수정해야 한다.

[공식 TrOCR 문서](https://huggingface.co/docs/transformers/model_doc/trocr)의 별도 영어 문장 예시도 조사했지만 원본 이미지 호스트의 TLS 인증서 만료로 다운로드가 실패했다. 인증서 검증을 끄지 않았고, 영어 문장 전체의 추가 비교를 통과로 표시하지 않는다. 현재 영어 확인 범위는 공개 한국어 필기의 혼합 영문과 위 제어용 문자다.

최종 설치본은 **0.3.20/build30**이다. 실제 앱의 프런트엔드 파일 해시가 최종 빌드와 일치하고 코드 서명 검사를 통과했다. 680×480 라이트에서 최종 원문·필기 위치를 확인했으며 같은 스타일의 다크도 확인했다. 기존 보관함의 9개 보호 테이블 모든 기존 행과 원음 6개 해시를 재대조해 보존됐고 외래키 오류 0개, 앱·엔진의 HTTP 리스너 0개다. 검증 후 창은 1200×820으로 되돌렸고 라이트 모드로 열려 있다. 자동 지식 처리는 활성화되어 있으며 기존 자료의 관련 기록·개념 후보 backfill은 유휴 시간에 계속 처리한다.

## 설치된 Mac 앱의 손글씨 지식 흐름 — 0.3.21/build31

실제 `Solasi.app`의 별도 설치 검증 과목에서 UI로 이전 강의·현재 강의를 만들고 아래 순서를 수행했다. API 호출만으로 대체하지 않았으며, 화면 결과와 저장 DB를 함께 대조했다.

1. 이전 강의에 교착 상태·자원 대기·부정 조건이 있는 노트를 저장했다.
2. PDF 1쪽에 펜 획을 추가해 v5로 저장했다. Vision의 원래 후보는 `교착`이었다. 검토 입력란에서 검증용 설명과 `만약 … 발생할 수 있지만 … 성립하지 않는다`라는 조건문으로 수정한 뒤 승인했다. 긴 승인문은 이 시험에서 사람이 수정하는 동작을 재현한 입력이며, Vision이 전체 문장을 정확히 읽었다는 뜻이 아니다.
3. 현재 강의의 ‘같은 과목 전체’ 검색에서 이전 강의 노트와 ‘확인한 손글씨’가 각각 표시됐다. 손글씨 버튼을 열어 v5 PDF·필기·승인문을 확인했다.
4. 과목 자료·메모 요약을 실행했다. 승인 손글씨를 포함한 원문 5개를 인용했고, 가정·부정 조건이 원문 그대로 표시됐다. 로컬 생성 사용 기록은 25,208ms다. 이는 이번 작은 검증 자료의 결과이며 긴 요약 전체의 품질 보증이 아니다.
5. 지우개로 추가했던 획을 지워 v6로 저장했다. 이전 승인문은 ‘필기 변경됨’, 새 인식문은 ‘확인 대기’로 바뀌었다. 재검색은 6개에서 5개로 줄고 이전 손글씨 출처가 빠졌다.
6. 저장된 옛 요약의 손글씨 근거를 다시 열었다. ‘출처 · v5 · 변경됨’ 표시와 함께 지우기 전 획·승인문이 보존돼 있었다.
7. 수정본에서 v6 후보를 다시 수정·승인했다. 해당 승인 손글씨를 기준으로 자동 생성된 관련 기록에 이전 강의 노트가 표시됐고 버튼으로 원문을 열었다.
8. 지우개로 남은 14획을 모두 지워 v7로 저장했다. 실제 페이지 획 수와 검색 가능한 손글씨 청크 수 모두 0개였다. 재검색에 손글씨 출처가 없었고 새 요약은 남은 원문 4개만 인용했다(생성 사용 기록 15,260ms). 과거 요약·필기 버전은 유지했다.

### 발견한 지연과 표시 수정

- 자동 연결 큐는 모든 일반 자료를 FIFO로 처리해 승인 손글씨가 기존 자료 약 400건 뒤에서 대기했다. 화면에도 관련 근거가 비어 있었다. 자동 작업 안에서 손글씨 인식 → 승인 손글씨 연결 → 저장 노트·페이지 메모 연결 → 일반 자료 연결 → 개념 후보 순으로 처리하도록 보완했다. 같은 분류 안의 FIFO, 녹음·전사·사용자 작업 우선, 로컬 유휴 시간 실행은 유지한다.
- 실제 설치 수정본에서 승인 시각과 연결 작업 완료 시각의 차이는 **3.18초**였다. UI에도 이전 강의 원문과 인용이 표시됐다. 전체 초기 처리가 완료됐거나 모든 환경에서 같은 시간이 나온다고 주장하지 않는다.
- 검색 화면은 마지막 검색 작업을 복원하므로 원문 수정 전 결과가 다시 보일 수 있다. ‘검색을 실행한 시점의 결과입니다. 필기나 원문을 바꿨다면 다시 검색하세요.’ 안내를 추가했다. 재검색은 최신 검색 가능 출처로 실행하고, 저장된 과거 결과의 출처는 보존한다.

### 검사와 보존 범위

- 큐 순서 회귀 검사는 수정 전 `material != approved`로 실패하고 수정 후 통과했다. 기존 사용자 작업 우선·과목 범위·변경 출처 무효화 검사도 통과했다.
- Python 전체 575개 중 570개 통과·선택 검사 5개 생략. 첫 제한 환경 실행의 2개 오류는 기존 임시 로컬 포트 bind 검사에서 발생했으며 같은 전체 검사를 Mac 권한으로 다시 실행해 통과했다. 프런트엔드 101개 통과, TypeScript·Vite 빌드 성공.
- 교체 직전 보관함을 백업했다. 기존 과목 6개·기록 9개·녹음 10개·전사 742개·페이지 버전 37개·출처 1,194개의 모든 기존 행과 검증 페이지 밖의 초안 8개를 대조 보존했다. 의도적으로 지운 검증 페이지의 현재 초안과 인식 상태만 달라진다. 원음 6개 SHA256 일치, 외래키 오류 0개.
- 로컬 증거는 `.local-state/handwriting-workflow-20261019/`에 보관한다. 원본 녹음·개인 보관함·모델 파일을 공개 저장소에 포함하지 않는다. 이번 시험은 수정·승인·검색·인용·버전 수명 주기의 검증이며 새 사람 필기 정확도 표본이나 수식 의미 해석 시험이 아니다.

최종 0.3.21/build31 설치본을 재실행해 검색 시점 안내가 실제 화면에 표시되는 것을 확인했다. 프런트엔드 13개 파일이 빌드 결과와 바이트 단위로 일치하고 코드 서명 검사를 통과했다. 앱과 내장 엔진 두 프로세스에 HTTP 리스너는 없었다. 재실행 후에도 검색 가능한 손글씨 0개, 새 요약의 손글씨 제외, 옛 요약의 손글씨 인용 보존을 대조했다. 별도 변경 검토에서는 추가 조치가 필요한 결함을 발견하지 않았다.

| 누적분포함수·극한 | 0.257초 | 12.453초 | Vision은 식을 `F(2)=P(X스x)`로 읽었다. Qwen은 `F(x)=P(X≤x)`를 읽었지만 첫 극한의 `−∞`를 `∞`로 바꾸고, 오른쪽 연속 성질을 원문에 없는 `오목과 편평성 없음`으로 출력했다. |
| 조건부확률·분수 | 0.253초 | 8.715초 | Qwen이 일부 한국어를 보존했지만 `A,B⊂S`를 `A,B,C,S`로 바꿨다. `P(A∩B)`를 `P(AB)`로 쓰는 차이는 기록하되 후자가 관례상 교집합일 수도 있어 수학적 오답으로 단정하지 않는다. |
| Jensen 부등식 | 0.216초 | 8.944초 | Qwen은 convex와 핵심 부등식을 보존했지만 제목을 `먼센`으로 바꿨다. Vision은 영문·수식이 불안정했다. |
| λ-system 정의 | 0.243초 | 10.021초 | Qwen이 원문의 λ-system을 π-system으로 바꿨다. 자연스러운 문장이라도 다른 정의로 오인할 위험이 있다. |
| 분할·교차 도형 | 0.145초 | 5.600초 | 문자 조각만 반환했고 도형 관계를 검증할 수 없었다. |
| 포함 관계 도형 | 0.129초 | 5.443초 | Qwen이 `1`, `3a`를 출력했다. 관계 해석의 정확도를 평가할 정답은 없다. |

시간은 이 Mac에서 한 번 실행한 영역별 경과다. 첫 Qwen 입력의 모델 준비·로딩도 포함되며 지속 처리 성능으로 일반화하지 않는다. Qwen이 일부 문자·식을 개선해도 항상 더 정확하다고 판단하지 않았다. 모델·프롬프트의 기본값을 교체하지 않았다.

**집계 CER는 발표하지 않는다.** 추론 전 GT와 이미지 해시는 고정했지만, 모델 응답을 보지 않은 별도 원문 검토에서 Jensen의 파란 주석 누락, CDF 오른쪽의 잘린 문장 복원, lambda의 `if`를 `∀`로 치환한 문제를 발견했다. 수식의 Unicode·분수·첨자 선형화도 고정되지 않았다. 초기 비교 JSON의 CER와 `whole public page` 자동 라벨은 검증된 성능 주장에 사용하지 않는다. 도형 관계는 채점 불가로 두고, 가시적인 기호·문구의 변화만 위 표에 적었다.

### 가져온 손글씨의 지식 편입 수정

기존 일반 자료 추출기로 실제 수리통계학 PDF를 처리했을 때 한국어·수식이 깨진 기존 텍스트층도 `ready`로 반환됐다. 앱에서 직접 그린 필기의 승인 절차가 가져온 PDF·사진에는 적용되지 않는 문제다. 사용자가 승인한 설계에 따라 아래처럼 기존 인식·검토 경로를 확장했다.

- 파일 연결 시 **손글씨 노트**를 지정한다. PDF·PNG·JPEG의 원본 위치를 연결하고 같은 물리 파일의 분류를 공유한다. 일반 강의자료의 추출은 유지한다.
- 지정한 원본의 일반 OCR은 검색·요약·관련 기록에서 제외한다. 분류 전에 고정한 생성 요청과 직접 이미지 설명도 실행 시 거절한다. 기존 OCR·벡터·출처를 지우지 않는다.
- 연 페이지의 원본과 덧쓴 펜 획을 함께 렌더링해 기존 Vision/Qwen 후보에 넣는다. 펜 획이 없는 사진·PDF도 처리한다. 자동 인식은 유휴 시간의 Vision이며 Qwen은 직접 실행한다.
- 확인 전·거절한 후보는 지식이 아니다. 수정·승인한 문장만 기존 `ink_note` 출처로 추가한다. 원래 인식문과 승인문은 별도로 보존한다.
- 원본이 바뀌거나 접근할 수 없으면 승인문을 새 검색·생성에서 제외한다. 이미 계산한 관련 기록 카드에도 같은 유효성 검사를 적용했다. 수정 전 검사에서 변경된 원본의 옛 카드가 남는 문제를 재현하고 수정 후 제외를 확인했다.
- 원본 페이지 디코딩은 확장자가 아닌 실제 내용을 따른다. JPEG 내용의 `.pdf`와 PDF 내용의 `.png`를 각각 실제 Mac helper에 넣어 인식 완료를 확인했다.

회귀 검사에서는 실제 Qwen 오류 문구 `오목과 편평성 없음`을 후보로 저장하고 요약 입력·이전 강의 연결에 포함되지 않음을 확인했다. 올바르게 수정·승인한 `F(x)=P(X≤x)`와 오른쪽 연속 성질만 전달되고 이전 강의의 CDF 노트가 연결됐다. 거절한 π-system 후보도 제외됐다. 사용자가 오인식문을 그대로 승인하는 경우까지 자동 판별하는 기능은 추가하지 않았다.

### 실제 설치 앱의 흐름과 재실행

최종 **0.3.22/build32**를 기존 보관함을 보존해 설치했다. 실제 Mac UI의 별도 `10 20` 검증 과목에서 다음을 확인했다.

1. 손글씨 옵션을 체크하고 원래 17쪽 PDF를 네이티브 파일 선택창으로 연결했다. PDF 페이지와 덧쓴 필기의 공용 메모 화면이 열렸다. 1·2쪽에서 펜 획 없이도 자동 Vision 후보가 생겼다.
2. 승인 전 과목 요약은 근거가 없다는 오류로 종료됐다. 이전 강의의 CDF 노트를 저장한 뒤 현재 강의에서 같은 과목 전체를 검색하자 이전 강의 노트 **1개**만 나왔다. PDF의 미승인 OCR은 검색에 포함되지 않았다.
3. PDF 2쪽 후보를 원본과 대조해 CDF 정의·극한·오른쪽 연속 성질·단조성의 6개 줄로 수정하고 승인했다. 이것은 해당 부분만 사람이 확인한 승인문이며, Vision이 전체 페이지를 정확히 읽었다는 뜻이 아니다. 재검색은 **2개**로 늘어 이전 강의 노트와 승인 손글씨가 각각 표시됐다.
4. 페이지의 관련 기록에 이전 강의 노트가 자동으로 표시됐고 버튼으로 원문을 열었다. 개념은 승인문을 인용한 후보로 남아 자동 확정되지 않았다.
5. 과목 자료·메모 요약을 실행했다. 저장된 근거는 승인 손글씨 출처 **1개**이며 수정 전 OCR은 없다. 로컬 생성 사용 기록은 **8,585ms**다. 모델이 제목만 선택해 내용 선택 검사에 걸렸으므로, 수식이 포함된 전체 승인문도 **구간 선택 확인 필요** 원문 발췌로 보존했다. 이를 완전한 AI 요약 선택 성공으로 표시하지 않는다. 요약에서 원본 2쪽과 승인문을 다시 열었다.
6. 같은 CDF 크롭 JPG를 손글씨 노트로 추가 연결하고 실제 앱의 **로컬 Qwen으로 인식**을 실행했다. 페이지용으로 렌더링한 이미지와 제품의 기존 전사 프롬프트를 사용하는 이 경로는 직접 이미지 비교와 조건이 다르다. Qwen 작업 내부 `total_ms`는 **16,186ms**이며 렌더링·UI 시간 전체는 아니다. 이 실행은 `−∞`와 오른쪽 연속성 성질을 읽었지만 잘린 설명을 `되려면`으로 완성했다. 직접 비교 때보다 나아진 구절이 있더라도 모델·렌더링·프롬프트 효과를 분리한 시험은 아니다. 이 사진 후보는 UI에서 거절했고 검색 가능 청크 **0개**, 지식 출처 없음으로 대조했다.
7. 앱의 크기 조절 핸들·방향키로 680×480을 만들었다. 라이트에서 새 연결 옵션·요약, 다크에서 사진·검토 버튼·수정창 스크롤을 확인했다. 체크박스는 Space로 전환됐다. 원본과 저장된 필기 색은 바꾸지 않았다. 이후 라이트·원래 창 크기로 복원해 정상 종료·재실행했고 PDF 2쪽의 승인 상태와 `≤`, `−∞`, 극한·조건 문구 보존을 화면에서 확인했다.

### 최종 검사·보존

- Python **579개 중 574개 통과·선택 검사 5개 생략**, 프런트엔드 **101개 통과**, TypeScript·Vite 빌드 성공. 캐시 관련 기록의 원본 변경 누락은 회귀 검사에서 수정 전 실패·수정 후 통과했다.
- 별도 코드 검토에서 확장자와 내용이 다른 파일의 호환성 문제를 발견해 수정했으며, 최종 검토에서 추가로 조치가 필요한 결함은 발견하지 않았다.
- 교체 전 DB 백업과 비교해 기존 과목 6개·기록 9개·녹음 10개·전사 742개·페이지 문서 6개·페이지 버전 38개·출처 1,196개·인식 기록 9개·결과물 8개·네이티브 초안 10개의 모든 기존 행을 보존했다. 원음 6개 SHA256 일치, 외래키 오류 0개다. 검증용 새 과목·기록·승인문은 별도로 추가됐다.
- 설치된 프런트엔드 13개 파일이 최종 빌드와 바이트 단위로 일치하고 코드 서명 검사를 통과했다. 원본 PDF·JPG·개인 보관함·모델 파일은 공개 저장소에 추가하지 않는다. 상세 로컬 증거는 `.local-state/mixed-handwriting-20261020/`에 보존한다.

한계: 두 작성자의 6개 영역은 광범위한 한국어 필체 벤치마크가 아니다. 원시 OCR의 수식·도형 의미 이해를 완성한 것으로 주장하지 않는다. 일반 자료를 손글씨로 자동 분류하지 않으므로 연결 시 직접 지정해야 하며, 사용자가 틀린 인식문을 승인하면 그 텍스트가 지식에 포함될 수 있다.
