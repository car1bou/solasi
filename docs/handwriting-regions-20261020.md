# 한국어 문장·수식 분리 인식 비교 · 2026-10-20

## 범위와 사전 고정

[대체 OCR 비교](local-ocr-alternatives-20261020.md)에 사용한 실제 혼합 노트 12개를 그대로 사용한다. 새 필체나 음성을 추가한 시험이 아니다. 12개 중 두 개는 완성 문장의 오른쪽을 자른 파생 조건이며, 원본에서 잘린 바깥 단어를 가져오지 않는다.

실험 전에 원본을 보고 **35개 영역(text 11·formula 10·mixed 14)**의 위치·배열 순서·보이는 정답·모호성을 기록하고 실제 crop을 검토했다. manifest SHA256은 `a0feeb7a5d57fe905aecf7afd9703f934a8a41ff3bf2e4d244a95455e5527830`이다. 기존 원본·정답 manifest는 수정하지 않았다. 이 좌표를 사용한 조건은 **사람이 정확히 위치를 지정한 비교 조건(manual oracle)**이며 자동 분리 성능을 뜻하지 않는다.

CDF의 세 극한은 본체와 아래 방향을 하나로 유지하고 파란 주석은 별도로 보존했다. 조건부확률의 분자·분모·좌변은 한 영역으로 두고 옆 조건도 별도 mixed 영역으로 남겼다. Jensen의 가정과 문장 안 수식은 mixed, 상자 부등식은 formula다. 선분 정의 둘째 줄과 영문·수식이 붙은 λ-system의 줄도 mixed로 유지했다. 두 종류로 강제 분류해 문맥을 버리지 않았다.

원본 좌상단 기준 정수 `xyxy`를 사용하고 PNG로 저장해 crop 픽셀을 보존했다. 제품의 정규화 `xywh` 좌표와 혼동하지 않는다. 결과를 원본으로 연결할 때는 manifest 배열 순서를 사용한다. 수식의 분자·분모·첨자를 독립 글자처럼 정렬하거나 여러 모델의 문장을 AI가 다시 써서 합치지 않는다.

## 비교 조건

- **전체 Qwen:** 같은 원본 12개를 기존 Qwen3.5 4B·원문 지시·작은 입력 확대 경로로 새로 인식한다.
- **분리 Qwen:** 고정한 35개 영역을 같은 Qwen·지시·확대 방식으로 읽는다. 이 조건으로 영역 분리 자체의 효과를 구분한다.
- **분담 GLM / Paddle:** text·mixed 25개는 분리 Qwen 결과를 그대로 사용하고 formula 10개만 각 native `Formula Recognition:` 결과로 대체해 대조한다. 두 결과 중 그럴듯한 식을 임의 선택하지 않는다.
- **자동 분리:** 이미 설치된 dots.mocr의 layout-only 기능을 같은 12개에 적용한다. 자동 좌표·분류·순서를 그대로 평가하고 수동 정답으로 고치지 않는다.

후속 사용자 동의를 받아 전용 레이아웃 검출기만 추가 다운로드했다. 원본 이미지·필기·인식문과 이전 출처를 보존한다. 모든 비교 응답은 연구용이며 미승인 결과를 검색·요약·이전 강의 연결에 편입하지 않는다.

## 자동 좌표와 실패 처리

dots의 [공식 layout-only 작업](https://github.com/rednote-hilab/dots.mocr/blob/master/dots_mocr/utils/prompts.py)은 영역 bbox와 `Formula`, `Text`, `Title` 등 category를 반환한다. 좌표는 [공식 복원 코드](https://github.com/studio-dots-ai/dots.mocr/blob/main/dots_mocr/utils/layout_utils.py)에 따라 모델이 처리한 이미지 픽셀 크기에서 원본 크기로 옮긴다. 0–1000 정규화 좌표로 가정하지 않는다.

실제 processor의 `image_grid_thw`와 patch 크기 14로 처리 크기를 기록했다. 원본 좌표 복원은 좌상단을 내림, 우하단을 올림 처리한다. 잘못된 JSON·빈 목록·미완료 출력·알 수 없는 category·범위 밖/역전 좌표는 검출 실패다. 잘린 JSON에서 그럴듯한 일부 bbox를 복구하지 않는다. Picture·Table도 이번 분담 인식 범위 밖이므로 전체 이미지 fallback으로 남긴다.

유효 좌표와 안전한 분리는 별개다. 원본 입력의 첫 자동 검출에서는 **7/12건이 범위 밖 좌표로 fallback**, **5/12건·25개 영역이 좌표 형식만 통과**했다. 유효한 crop을 다시 검토했을 때 다음 문제가 있었다.

- conditional 설명 끝의 원획 절단과 다른 줄의 윗획 조각 유입.
- Jensen 가정의 `E`·대괄호 하단 절단. 연결 화살표만 독립 Page-header로 분리하고 상자 부등식을 Text로 분류해 문맥·작업 분담이 손상됨.
- λ-system의 ii·iii 영역 겹침으로 이전 줄의 꼬리 획 중복 유입.
- 미분 전개 줄의 마지막 괄호 끝 절단.

확대 dots의 Big O 좌표 `[100,17,654,54]`는 첫 항 `O(1)` 전체와 뒤 부등호·일부 윗획을 놓쳤다. CDF 세 번째 극한은 옆 한국어 주석까지 Formula로 묶어 수식 전용 작업에 한국어를 함께 전달하게 됐다. 확대 조건에서도 안전한 자동 분담은 확인하지 못했다.

각도 네 줄의 주요 기호는 포함됐지만 경계 여유가 작았다. 위 문제가 있는 결과를 성공한 자동 분리로 세지 않는다. 자동 crop OCR의 정답은 **실제 예측 crop에 보이는 내용**으로 별도 고정했다. 원본 전체 정답으로 잘린 글자의 완성을 요구하지 않으며, 화살표 단독 영역은 텍스트가 아닌 연결 표시로 남긴다.

## 도구 변경과 재현

`experiments/compare_handwriting.py`는 JPG와 손실 없는 PNG를 같은 입력 해시 목록에 포함하고 중복 ID를 거절한다. `--helper`를 생략하면 보조 Apple Vision을 호출하거나 가상의 Vision 점수를 만들지 않는다. 이번 분리 모델 비교에 불필요한 보조 인식의 반복 실행을 줄이기 위한 변경이다.

전체 Qwen 측정 중 남은 여섯 보조 Vision 결과는 이전 실행의 결과를 재사용했다. 재사용 전에 원본 SHA, 확대 입력의 크기·RGB 픽셀, 동일 helper SHA를 대조했다. **Qwen 모델 응답은 모두 새 실행**이다. 보조 Vision의 과거 시간은 모델 지연의 비교 수치에 포함하지 않는다. 분리 조건은 helper를 생략한다.

`experiments/handwriting_regions.py`의 최소 도구는 원본 영역 crop과 자동 레이아웃 좌표 검증이다. 제품용 수식 분류기나 검출 신뢰도 보증 기능은 아니다. 사용 허가가 있는 이미지와 아래와 같은 사전 고정 manifest를 준비한다.

```json
[
  {"id":"heading","kind":"text","bbox":[0,0,600,80]},
  {"id":"equation","kind":"formula","bbox":[0,90,600,220]},
  {"id":"condition","kind":"mixed","bbox":[0,230,600,300]}
]
```

`crop_regions(image, rows)`는 배열 순서로 `(메타데이터, PNG로 저장할 PIL 이미지)`를 반환한다. 이 예의 좌표는 예시용이며 실제 이미지에서 획·첨자·잘림 경계를 검토한 좌표로 대체해야 한다. 모델별 crop은 새 dataset의 `images/*.png`, `ground_truth/*.txt`로 만들고 기존 비교 도구를 실행한다.

```bash
HF_HUB_OFFLINE=1 TRANSFORMERS_OFFLINE=1 .venv/bin/python experiments/compare_handwriting.py \
  --dataset /absolute/path/region-dataset \
  --output /absolute/path/new-qwen-region-run \
  --runtime /absolute/path/verified-local-runtime \
  --variant upscale --literal
```

GLM·Paddle 수식 조건은 `--runtime` 대신 검증한 `--model-path`, `--model`과 `--task formula`를 지정한다. 결과의 단순 CER는 수식 정확도가 아니다. 고정한 문자·부호·경계·문맥 연결을 별도로 대조한다.

로컬 증거·정답·응답은 `.local-state/ocr-regions-20261020/`에 두고 Git에 원본 노트나 모델을 포함하지 않는다.

## 인식 품질 결과

모든 응답이 `stop`으로 끝났다(전체 Qwen 12·분리 Qwen 35·GLM 수식 10·Paddle 수식 10·자동 crop Qwen 25·자동 crop GLM 수식 10). 정상 종료는 내용의 정확성을 뜻하지 않는다. LaTeX/Unicode 표기 차이와 문맥·부호 오류를 구분해 원본과 대조했다.

| 원본의 핵심 | 전체 Qwen | 수동 분리 Qwen | 수식 전용 분담 |
|---|---|---|---|
| 선분 정의 첫 줄 | `뜻: 두변의 길이가 같은 삼각형` | `답: 두변의 길이가 같을 때`로 변형 | mixed/text이므로 유지되는 오류 |
| CDF 단조성 `≤` | 보존 | `⊆`로 오독 | mixed이므로 유지되는 오류 |
| 조건부확률 분자 `A∩B` | 보존 | `A n B` | GLM은 `∩`로 복구하지만 전체 대비 개선 아님 |
| CDF 정의 `P(X≤x)` | 대문자 X 보존 | 보존 | GLM·Paddle 모두 `P(x≤x)`로 오독 |
| Jensen 부등호 `≤` | 보존 | 보존 | Paddle은 `subseteq`로 오독 |
| λ-system 명칭 | lambda-system | π-system | mixed이므로 유지되는 오류 |
| 미분 전개 `α`·괄호·`2π−α(t)` | 보존 | 동일 전체 입력에서 보존 | Paddle은 α를 d로 바꾸고 `2π−α(t)`의 마이너스를 누락 |
| Big O의 `n log n`, `n²` | 보존 | 동일 전체 입력에서 보존 | Paddle은 `ln log n`, `η²`로 오독 |

CDF의 세 극한 방향과 각도 계산은 전체 Qwen에서도 이미 맞았다. 분리 후 유지된 결과를 새 개선으로 세지 않는다. 네 개 수식 control은 전체 영역을 그대로 사용하는 동일 입력이다. `f(X)`/`f(x)`처럼 원본 주석에서 모호하다고 기록한 글자는 확정 회귀 집계에 쓰지 않는다.

잘림 조건에서도 개선은 확인되지 않았다. Kjk는 기존에 없던 말미 `=`를 계속 추가했고 Haonly의 `형상→형성` 오독도 남았다. CDF의 잘린 끝 `되→소`는 경계의 일부 글리프 오독이다. 원본 밖 단어 전체를 완성한 환각으로 과대계상하지 않는다. 이번 조건에서 `[판독 불가]` 정책이 안정적으로 지켜졌다는 근거도 없다.

자동 crop 인식 역시 문맥 손실을 해결하지 못했다. 원본 dots 25개 crop은 Qwen 25회와 formula만 GLM 10회로 읽었다. 미분 둘째 줄의 Qwen `α/β→a/b`, GLM의 `f′(β(t))` 앞 괄호를 `/`로 바꾸는 오류가 생겼고 λ-system은 π-system으로 바뀌었다. 자동 λ-system의 서로소 조건 `A_i∩A_j=∅ if i≠j`는 전체/수동 분리에서의 오독을 국소적으로 바로잡았다. 다만 같은 노트의 π-system 오독과 L/F 불일치가 남아 노트 전체의 개선으로 채택하지 않는다. 자동 위치가 틀린 crop을 수동으로 고친 뒤 성공으로 계산하지 않았다.

## 확대 검출과 전용 검출기

| 검출 조건 | 원본 수 | 좌표 형식 통과 | 검출 추론 합계 | 해석 |
|---|---:|---:|---:|---|
| dots 원본 | 12 | 5 | 25.91초 | 위에 기술한 절단·분류·문맥 손실 존재 |
| dots 3배 확대·긴 변 최대 2048 | 12 | 10 | 114.55초 | Big O 첫 항·부등호·윗획 누락, CDF 한국어를 Formula에 합치는 오류 |
| PP-DocLayoutV3 | 12 | 1 | 6.35초 | 11개는 0–1000 범위 밖 좌표가 있어 엄격한 검증에서 전체 이미지 fallback |

위 fallback은 모델 실행 실패가 아니다. 검출 결과의 조건부 사용 거절이다. PP는 12개 모두 실제 로컬 추론을 마쳤다. 범위 이탈에는 `−0.8`, `1000.1`처럼 작은 것도 포함되며, 이 수치만으로 검출기 자체가 11개 원본을 읽지 못했다고 평가하지 않는다. 원본 범위로 임의 clamp하지 않는 이번 실험의 보수적 정책이다. CDF의 좌표 형식이 정상인 18개 영역도 text/formula의 동일 좌표·중첩 결과가 있으며 극한 본체만 포함한 좁은 영역이 별도로 생겼다. 단순 배열 연결은 중복·방향 누락을 만들 수 있다. 겹침을 임의 삭제하거나 정답을 보고 특정 bbox만 고르는 후처리를 적용하지 않았다.

공식 [PP-DocLayoutV3 배포물](https://huggingface.co/PaddlePaddle/PP-DocLayoutV3_safetensors)의 고정 revision은 `e4f489dc536556fc1be02b973ba06756e0d4a2ac`이다. README·설정·가중치·전처리 파일 총 133,289,670바이트를 검증 폴더에 내려받아 receipt/hash를 보존했다. 가중치 SHA256은 `5ea422c6cc5fe759a47e1357c35639b58173508e025a3131cbe4b6ac59e2b85e`이다. Apache-2.0이며 Torch 설치·변환·HTTP 서버·원격 Python 코드를 사용하지 않았다.

설치된 `mlx-vlm 0.7.8`의 `load_model(..., lazy=False, strict=True, trust_remote_code=False, local_files_only=True)`와 `model.detect(image, conf=0.3, img_size=800)`를 사용했다. 800 입력은 [GLM-OCR 공식 파이프라인 설정](https://github.com/zai-org/GLM-OCR/blob/main/glmocr/config.yaml)에 맞췄다. 반환된 0–1000 yxyx 좌표를 xyxy로 바꾸고 reading_order 순서로 기록했다. raw detection도 보존한다. 이 native 경로가 공식 전체 polygon 후처리와 동일하다고 주장하지 않는다. 반환 label의 두 수식 클래스가 모두 `formula`이므로 display/inline을 따로 정확도 평가하지 않았다. score는 정확도 확률로 표시하지 않는다.

## 지연과 측정 범위

| 인식 조건 | 호출 수 | 관측 시간 합계 |
|---|---:|---:|
| 전체 Qwen | 12 | 132.65초 |
| 분리 Qwen | 35 | 279.88초 |
| GLM 수식 부분 | 10 | 추론 16.32초 + 최초 로드 0.33초 |
| Paddle 수식 부분 | 10 | 추론 13.95초 + 최초 로드 0.46초 |
| 원본 dots 자동 crop Qwen | 25 | 276.10초 |

Qwen은 요청별 worker·자산 준비·모델 로드를 포함하고, GLM/Paddle은 모델을 한 번 로드한 뒤 재사용한 추론 시간이다. 이 수치로 모델 자체의 속도 순위를 만들지 않는다. 수동 분담은 기존 Qwen text/mixed 25개 응답 192.14초와 수식 응답을 단순 연결하므로 관측 구성요소 합계는 GLM 208.79초, Paddle 206.55초다. 실제 제품 통합 실행을 별도로 재측정한 수치가 아니며 자동 검출 시간도 포함하지 않는다. 합계 기준으로도 전체 Qwen보다 빠르지 않았다. 모든 모델은 한 번에 하나씩 실행했다.

## 적용 결정과 한계

**문장·수식의 자동 분리나 수식 모델 교체를 제품 기본 경로에 적용하지 않는다.** 알려진 개발 표본에서 수동 위치를 줘도 부호·한국어 회귀와 추가 호출이 발생했으며, 자동 분리는 별도의 영역 안전성 문제를 만들었다. 부호 누락과 잘린 문장 추측을 줄였다고 결론낼 근거가 없다.

반영한 변경은 비교 도구의 PNG 지원, 엔진 선택 검증, 불필요한 Vision 실행 생략과 엄격한 영역 좌표 검증이다. 미승인 OCR을 지식에 넣지 않는 기존 승인 정책과 원본·출처·복구 동작은 그대로다. UI UX Pro Max의 검토 원칙에 따라 검출 score를 정확도로 표시하거나 미검증 결과를 확정해 보이는 새 UI도 만들지 않았다.

이 12개는 기존에 오류를 조사한 작은 개발 표본이다. 일반 한국어 필기 정확도나 held-out 성능을 발표하지 않는다. 추가 전사·녹음 시험이나 설치 앱 교체는 이번 실험 범위에 포함하지 않았다.
