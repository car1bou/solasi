# 기록실

수업·회의의 원음, 전사, 자료와 노트를 연결하는 로컬 앱입니다. 수업에서는 같은 과목의 이전 회차까지 검색하고 요약·퀴즈·풀이 기록을 남깁니다. 회의에서는 현재 기록으로 회의록을 작성하고 수정·확인·Markdown 내보내기를 합니다.

공개본의 범위와 원본 개발 커밋은 [PUBLIC_EXPORT.md](PUBLIC_EXPORT.md)에 기록했습니다.

## 실행

현재 제공물은 **Apple Silicon macOS에서 확인한 소스 실행판**입니다. Python 3.12, Node.js와 npm이 필요합니다. 전사 엔진의 최초 빌드에는 Apple Command Line Tools가 필요합니다. 서명된 `.app`·설치 파일은 만들지 않았습니다.

```sh
git clone https://github.com/car1bou/solasi.git
cd solasi
python3.12 -m venv .venv
.venv/bin/python -m pip install -r requirements.lock
.venv/bin/python -m pip install --no-deps -e .
cd frontend
npm ci
npm run build
cd ..
.venv/bin/lecture-study
```

콘솔의 실행 링크로 앱에 연결합니다. loopback 주소만 사용하며 포트 충돌 시 다른 포트를 선택합니다. 앱을 종료하면 앱이 시작한 Ollama만 종료합니다.

기본 저장 위치는 `~/Library/Application Support/LectureStudy`입니다. 별도 폴더로 실행하거나 준비 상태를 읽을 수 있습니다.

```sh
.venv/bin/lecture-study --data-dir /private/tmp/lecture-study-demo
.venv/bin/lecture-study --check --data-dir /private/tmp/lecture-study-demo
```

이 작업의 검증 데이터와 이미 준비한 엔진을 열려면:

```sh
.venv/bin/lecture-study --data-dir .local-state/verification --runtime-dir .local-state/runtime
```

## 처음 사용할 때

1. **모델·키 설정 → 엔진·OCR 준비**에서 필요한 항목의 용량·라이선스·저장 위치를 확인하고 준비합니다. 전사 준비는 약 1.73GB 다운로드에 소스·빌드·임시 공간이 더 필요합니다. OCR 약 28MB, Ollama archive 약 167MB는 생성 모델 가중치를 포함하지 않습니다. 완료 전 파일·해시 실패는 준비 완료로 표시하지 않습니다.
2. 생성 기능은 API 또는 로컬 모델을 선택합니다. OpenAI·Gemini·Claude의 **API 키와 모델 ID**를 연결하거나 앱 Ollama를 시작하고 로컬 모델을 다운로드합니다. 실제 모델 접근·텍스트·이미지 지원을 확인합니다. 구독 앱의 로그인 정보를 가져오지 않습니다.
3. 의미 검색을 사용하려면 별도의 로컬 EmbeddingGemma를 준비한 뒤 **검색·개념 → 의미 색인 갱신**을 실행합니다. 준비 전에는 키워드 검색으로 동작합니다.
4. **새 기록**에서 수업 또는 회의를 만들고 자료를 연결하거나 노트를 저장합니다. 수업은 과목과 회차를 지정하면 이전 회차를 포함할 수 있습니다.
5. 기본은 **녹음 종료 후 전사**입니다. 녹음 중에는 원음을 저장하고 종료하면 전사합니다. 녹음 전에 **전사 방식 → 실시간 전사**를 선택하면 잠정·확정 전사를 녹음 중 처리합니다. 기존 파일은 **녹음 파일 연결**로 전사합니다. 입력·저장 확인이 끊기면 살아 있는 마이크로 한 번 자동 복구하고 새 녹음 구간을 만듭니다. 실패하거나 마이크가 종료되면 원음을 보존하고 **녹음 다시 시작**을 표시합니다. 확정 전사를 수정해도 원래 인식문과 이전 근거 버전이 보존됩니다. 빈 전사·반복 의심 구간은 원음과 재인식 후보를 확인하고 직접 적용할 수 있습니다.

로컬 생성 후보 Qwen3.5 4B MLX는 약 3.97GB, EmbeddingGemma는 약 0.62GB입니다. 비교용 Gemma 4 E2B MLX 약 7.48GB·EmbeddingGemma 2 약 0.44GB도 선택할 수 있습니다. E2B QAT·E4B QAT·12B MLX도 준비 목록에 있습니다. QAT 실측의 수정 헤더 artifact와 catalog의 Ollama 공식 배포물은 [비교 문서](docs/gemma4-actual-comparison.md)에서 구분합니다. 기본 모델은 유지합니다. 크기·manifest digest·라이선스는 준비 화면에서 확인합니다. 실제 PC의 생성 지연·RAM은 파일 크기와 다릅니다. 모델 다운로드는 사용자 선택으로 실행합니다.

## 자료와 출처

- PDF·PNG·JPG·UTF-8 TXT/MD는 **네이티브 파일 선택으로 원본 위치를 연결**합니다. 외부 자료와 외부 오디오 원본을 앱 폴더로 복사하지 않습니다.
- 추출 텍스트, 검색 조각, 전사와 결과를 앱 DB에 저장합니다. 페이지·그림 캐시는 필요할 때 만들고 총 256MiB를 기준으로 정리합니다. 앱이 직접 녹음한 원음은 보관합니다.
- 원본 이동·접근 거절·물리적 변경은 표시합니다. 원본이 변경되면 재추출하고 다시 선택합니다. PDF는 페이지·bbox, 전사는 원음 시간, 노트는 버전으로 근거를 엽니다.
- 기록 삭제는 앱 데이터와 연결을 정리하며 외부 원본을 삭제하지 않습니다. 여러 기록이 공유하는 자료는 다른 연결이 있으면 유지합니다.

확정 구간은 최대30초이며 긴 입력은 조용한 경계를 선택합니다. 종료 후 처리도 같은 전사 모델·확정 설정을 사용합니다. 실시간 모드의 잠정 전사는10초 주기로 요청하며 처리 중에는 최신 요청을 유지합니다. 종료 시 오래된 잠정 작업을 중단해 확정 전사를 우선합니다. [Mac 오류·지연 개선과 한계](docs/mac-asr-improvements.md).

## 질문·학습·회의·그림

- **질문:** 현재 기록/같은 과목/선택 회차의 근거를 사용합니다. 요청 시 근거 버전과 확정 전사 cutoff를 고정합니다. 같은 결과를 다시 열 때 모델을 호출하지 않습니다.
- **학습:** 전체 요약은 원문을 문맥·입력 예산별로 묶고 주어·가정·조건·예시와 정확한 원문 구절을 연결합니다. 최종 단계는 구간 항목을 선택해 주어와 사건 상태를 보존합니다. 앞·중간·뒤 누락은 최대1회 재시도하고 남은 구간을 함께 표시합니다. 근거가 부족한 해석은 원문 발췌로 남기며, 실패한 작업에서도 완료 구간을 열 수 있습니다. 처리 범위와 실제 인용은 구분합니다.
- **메모 보강:** 저장 시점과 인근 확정 전사를 연결해 별도 보강안을 만듭니다. 수정·확인한 내용을 새 노트 버전으로 추가하며 원래 노트를 보존합니다. 과거 노트는 녹음 시점을 직접 지정합니다.
- **질문 후보:** 기본은 꺼짐입니다. 켜면 로컬에서 최소 30초 간격으로 최근 확정 전사의 후보를 추출합니다. API는 직접 추출할 때만 호출합니다. 원문 인용을 확인하고 수정·고정·무시할 수 있으며 답변은 버튼으로 실행합니다.
- **퀴즈:** 5문제와 근거·정답·채점 기준을 서버에 저장합니다. 제출 전 정답·기준·해설은 화면용 응답에서 제외합니다. 객관식은 코드로 비교하고 자유 답안은 선택 모델로 채점합니다. 오답·재풀이·원래 판정·사용자 수정 이력을 보관합니다.
- **검색·개념:** 반복되는 근거는 서로 다른 설명 뒤로 보냅니다. 감지한 숫자·날짜·부정 표현이 다르면 별도로 유지하며 원문은 삭제하지 않습니다. 표준 표기·별칭·정의·근거를 직접 저장합니다. 개념 ID를 유지하면서 버전을 갱신하고 관련 문제·풀이를 다시 엽니다. 등록한 같은 과목의 표준 표기와 현재 회의 참석자는 전사 힌트에 포함됩니다. 이번 기록에 직접 입력한 명칭을 우선하고 실제 적용 힌트를 표시합니다. 힌트로 인식이 악화되는 단어도 있어 원음과 대조합니다.
- **회의록:** 참석자를 직접 입력합니다. 생성된 결정·담당자·기한은 명시적인 확정 전사 구절을 요구하고, 없는 값은 미정입니다. 날짜의 원래 표현을 보존합니다. AI 초안·편집 이력·확인 상태와 네 섹션을 내보냅니다. 생성 모델의 의미 오류까지 검증하는 장치는 아니므로 초안을 검토합니다.
- **그림:** 자료의 선택 페이지 또는 추출 그림에 질문합니다. 벡터 그림은 페이지 PNG를 사용합니다. 모델의 이미지 지원을 먼저 확인하고 선택 이미지·주변 OCR을 전달합니다. 결과는 AI 해석으로 표시합니다. WebP 추출 그림은 페이지 질문을 사용합니다. 작은 글자·손글씨·색·차트·수식은 원본과 대조합니다.
- **웹 참고:** 별도 Exa 키가 있을 때만 사용자가 입력한 검색어를 전송합니다. 실제 반환 URL·본문 구절·조회 시각을 저장하고 내부 자료와 구분합니다. 키가 없거나 검색이 실패하면 상태를 표시합니다.

확정 전사가 밀려 있으면 새 로컬 답변·요약·메모 보강·질문 후보·서술형 채점·검색 임베딩을 기다리게 하고 **전사 처리 후 실행**을 표시합니다. 대기 중 취소·같은 요청 재시도가 가능하며, 제출한 답안과 요청 당시 근거 버전은 유지합니다. 이미 실행 중인 추론과 외부 API 생성 호출은 계속합니다. 외부 API 답변도 준비 단계에 로컬 의미 검색이 필요하면 해당 임베딩은 전사를 기다립니다.

API 생성 요청은 선택한 근거와 이미지를 해당 제공자에 전송합니다. 원음은 로컬 전사합니다. API 실패를 다른 제공자로 자동 전환하지 않으며, 사용자가 준비된 로컬 모델로 명시적으로 재시도할 수 있습니다. 키는 실행 중 메모리 또는 선택한 OS 자격증명 저장소에 보관합니다.

앱 Ollama는 전용 loopback 포트와 모델 폴더, cloud 비활성화를 사용합니다. 공식 Ollama `serve`는 표준 `~/.ollama`의 identity와 서버 설정을 참조할 수 있습니다. 완전히 격리된 홈 환경은 제공하지 않습니다.
